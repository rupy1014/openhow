# OpenClaw 실전 가이드 — 핵심 추출

> 원본: `references/openclaw-guide.pdf` (CHOI 지음)

## OpenClaw가 뭔가

챗봇은 질문을 받으면 한 단락이 닫힌다. OpenClaw는 부탁을 받고, 필요한 것을 찾고, 결과를 남기고, 같은 자리에서 다시 이어 쓴다. 요즘 AI 도구가 질문 → 답에서 시작 → 진행 → 확인 → 이어쓰기 쪽으로 움직이는 이유도 여기에 있다.

메신저와 장기 세션 쪽에서 이 변화를 밀어 준다. 질문 하나를 잘 답하는 도구보다, 채널과 파일과 브라우저 위에 오래 붙어 있는 도구에 가깝다.

## 브라우저 탭형 AI vs OpenClaw 차이

| 브라우저 탭형 AI | OpenClaw |
|-------------|----------|
| 브라우저 탭 | 메신저 / 채널 |
| 질문 입력 | Gateway |
| 복사 / 붙여넣기 | 행동 수행 |
| 다른 앱으로 이동 | 기억 저장 + 다음 작업 제시 |

## OpenClaw 핵심 구조 (6가지 개념)

### 1. Gateway
Gateway는 중앙 본체다. 메신저 창이 여러 개여도 안쪽에서 요청을 받아 정리하는 곳 하나라고 생각하면 된다. 점검 명령: `doctor`, `status`, `health`.

### 2. 세션
세션은 단순히 채팅방 한 칸을 뜻하지 않는다. 같은 주제로 이어 가는 작업 묶음에 더 가깝다.

### 3. 채널
채널은 사용자가 OpenClaw를 만나는 입구다. Telegram, Slack, WhatsApp, Discord 같은 메신저가 여기에 들어간다. 브라우저에서 상태와 설정을 보는 관리 화면은 Control UI.

### 4. 에이전트
역할별 OpenClaw는 사람처럼 생긴 캐릭터가 아니라, 맡는 일과 규칙을 나눠 둔 작업 단위를 뜻한다. 설치 초반에는 여러 개보다 하나로 시작하는 편이 안전하지만, 심화 단계로 가면 역할을 나누는 이유가 분명해진다.

### 5. 스킬
스킬은 자주 쓰는 규칙과 절차를 묶어 둔 재사용 카드다. 입력 형식, 출력 형식, 금지 행동, 도구 사용 순서까지 같이 담는다.

### 6. 노드와 하네스
노드는 OpenClaw 본체에 붙어 기능을 빌려주는 주변 장치다. 하네스는 그 노드가 실제로 무엇을 누르고 읽고 찍을지 말는 연결 장치라고 생각하면 쉽다.

## 점검 순서
Gateway가 켜졌는가 → 채널에서 메시지가 들어오는가 → 세션과 기록이 남는가 → 필요한 도구가 열리는가 → 스킬과 규칙이 과하게 열려 있지 않은가

## macOS 설치 흐름

macOS는 OpenClaw를 처음 붙여 보기 가장 무난한 경로다.
목표: 오늘 안에 설치 → 온보딩 → 상태 확인까지 한 번 통과하는 것이다.

### 가장 쉬운 시작
터미널이 낯설다면 macOS용 OpenClaw 앱으로 먼저 들어가는 것이다. Codex 앱이나 Claude Code에 설치를 맡기는 방법도 좋다.

많은 개인 사용자는 작은 Mac mini 같은 장치를 책상 한쪽에 두고 OpenClaw를 오래 켜 둔다. 거대한 서버를 상상할 필요는 없다.

### 설치 명령 순서

```bash
# 1. Node와 npm 확인
node --version
npm --version

# 2. OpenClaw 설치
curl -fsSL https://openclaw.ai/install.sh | bash
# 또는
npm install -g openclaw@latest

# 3. 온보딩 실행 (기본 설정 + 데몬 설치)
openclaw onboard --install-daemon

# 4. 상태 확인
openclaw doctor
openclaw gateway status
openclaw health --json

# 5. 브라우저 화면 확인
openclaw dashboard
# → http://127.0.0.1:18789/
```

### 첫날 권장 순서
설정 → 상태 확인 → 화면 확인 흐름이다.

각 명령의 뜻: `onboard`는 기본 설정과 서비스 시작점을 만들고, `doctor`는 문제 있는 부분을 찾고, `gateway status`는 게이트웨이가 실제로 떠 있는지 확인하고, `health --json`은 상태를 항목별로 정리해 보여 주고, `dashboard`는 브라우저에서 제어 화면을 연다.

### 첫 실행의 성공 기준
`openclaw doctor`가 치명적 오류를 쏟아내지 않고, `openclaw gateway status`가 살아 있다고 나오고, 제어 화면이나 웹 채팅이 한 번 열리고, 이후 채널 연결로 넘어갈 기준선이 생기는 정도면 충분하다.

### 설정 명령

```bash
openclaw configure        # 대화형으로 설정 변경
openclaw config check     # 현재 설정 읽기
openclaw config validate  # 문법 검사
```

## 채널 연결: Telegram

Telegram은 첫 채널로 자주 쓰인다. 막연한 친숙함보다 경계가 비교적 선명하게 보이기 때문이다.

### 채널 연결 = 토큰 입력으로 끝나지 않고 연결 승인과 점검까지 가야 끝난다

BotFather 토큰을 넣고 봇이 보이기 시작하면 "연결이 끝났다"고 느끼기 쉽다. 하지만 실제로는 그때가 시작이다. 토큰은 그 봇이 정말 내 봇인지 증명할 때 쓰는 긴 비밀번호 같은 값이다.

연결 승인은 새 사용자나 새 기기가 붙으려 할 때 사람이 통과시키는 절차이고, 점검은 실제 메시지가 왕복하는지 시험해 보는 확인 과정이다.

### 점검 명령

```bash
openclaw channels status --probe   # 실제로 한 번 왕복 시험
openclaw pairing list              # 연결 승인 대기 목록
openclaw gateway status            # Gateway가 살아 있는지
```

중요한 것은 `enabled=true`보다 연결 승인 대기 상태, 점검의 실제 통과 여부, Gateway 쪽 상태다.

## 설정 파일 이해 (워크스페이스)

OpenClaw를 계속 쓰더라도 설정 파일을 전부 외울 필요는 없다. 무엇이 규칙인지, 무엇이 기록인지, 무엇이 기억인지 정도만 구분하면 된다.

### 워크스페이스 파일 지도

| 파일 | 역할 | 비유 |
|------|------|------|
| **AGENTS.md** | 하면 안 되는 일과 사람 확인이 필요한 일을 적는 규칙 파일 | 업무 규칙집 |
| **SOUL.md** | 말투와 태도, 절대 하지 말아야 할 행동 | 성격 카드 |
| **USER.md** | 사용자 배경과 선호를 적는 소개 카드 | 자기소개서 |
| **IDENTITY.md** | 정체성 | 명함 |
| **MEMORY.md** | 오래 남길 사실을 담는 장기 기억 | 영구 메모장 |
| **memory/YYYY-MM-DD.md** | 그날그날 남기는 일일 기록 | 오늘의 기록 |
| **STATE.json / TASKS.md** | 지금 어디까지 왔는지 적는 진행표 | 상태 파일 |

### 기억도 한 파일에 몰아넣지 않는 편이 좋다

MEMORY.md에는 프로젝트 개요, 중요한 결정, 자주 다시 써야 할 사실처럼 오래 남길 것을 넣고, 일일 기록은 `memory/날짜.md`에 따로 둔다. 말투와 태도, 절대 하지 말아야 할 행동은 SOUL.md 같은 별도 파일로 분리하면 덜 섞인다.

### 설정 파일 읽는 순서

가장 먼저 `openclaw.json`으로 전체 연결 상태를 보고, 그다음에 `AGENTS.md`와 `USER.md`로 규칙과 배경을 읽고, `MEMORY.md`와 일일 기록으로 실제 문맥을 확인한 뒤, 마지막에 `STATE.json`이나 `TASKS.md`로 지금 어디까지 왔는지를 보는 편이 자연스럽다.

### openclaw.json
이 파일은 모델, 채널, 샌드박스, 워크스페이스 같은 기본 규칙을 잡는다. 샌드박스는 실수해도 바깥으로 크게 번지지 않게 실행 범위를 좁혀 두는 안전 구역이고, 워크스페이스는 OpenClaw가 읽고 쓰는 작업 폴더다.

## 코덱스 vs 오픈클로 역할 분리 (웨비나 참고)

실제 사용자의 경험에서 자연스럽게 역할이 갈렸다:

| 오픈클로에 시키는 것 | Claude Code에 시키는 것 |
|----------------|---------------------|
| 자동화, 모니터링, 리뷰, 결과 보고 | 코드 작성, 버그 수정, 기능 구현 |

### 오픈클로의 4가지 핵심 기능

| # | 기능 | 하는 일 |
|---|------|---------|
| 1 | LLM Gateway | 여러 LLM 모델 중 원하는 걸 골라서 돌릴 수 있는 관문 |
| 2 | Tool Orchestration | 웹 검색, 브라우저, 쉘 명령 등 도구를 LLM이 자연어로 판단해서 실행 |
| 3 | Cron / Scheduling | 주기적으로 에이전트를 깨워서 작업 (브리핑, 모니터링) |
| 4 | Session / Multi-Agent | 대화 세션 유지 + 여러 에이전트 라우팅 |

### 코덱스 OAuth 연동
오픈클로에서 코덱스 계정으로 로그인하면 추가 API 과금 없이 사용 가능하다. Part 2에서 만든 skills/, agents/, AGENTS.md를 오픈클로가 그대로 읽는다.

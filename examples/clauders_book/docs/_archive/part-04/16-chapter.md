> "내용은 10분이면 정리되는데, 디자인에 2시간을 쓰고 있었습니다."

보고서, 기획안, 발표자료. 직장인이라면 매주 하나씩은 만드는 산출물입니다. 그런데 돌이켜보면, 정작 **내용을 정리하는 시간**보다 **포맷을 맞추고 디자인을 다듬는 시간**이 훨씬 깁니다. 슬라이드 정렬, 폰트 크기, 여백 조정 — 이런 작업에 에너지를 다 쓰고 나면, 정작 메시지가 뭐였는지 흐릿해지곤 하죠.

이 장에서는 문서 자동화의 핵심 감각을 잡습니다. AI에게 내용을 건네고, 산출물 포맷까지 만들게 하는 흐름을 직접 따라해 봅니다.

---

## 완성 기준

- [ ] 마크다운으로 보고서 초안을 정리하고, AI에게 변환을 요청할 수 있다
- [ ] 발표자료 구조를 잡고, 슬라이드 초안을 뽑아낼 수 있다
- [ ] 회사 산출물 포맷에 맞춰 결과물을 바로 붙일 수 있다

---

## STEP 1. 보고서와 기획안 초안 자동화

### 1-1. 마크다운으로 내용부터 정리하기

보고서를 만들 때 가장 먼저 해야 할 일은 파워포인트를 여는 게 아닙니다. **내용을 정리하는 겁니다.**

마크다운이라고 하면 어렵게 느껴질 수 있는데, 사실 별거 아닙니다. 제목 앞에 `#`을 붙이고, 목록은 `-`로 적는 것뿐입니다. 메모장에 적는 것과 거의 같습니다.

예를 들어, 주간 업무 보고서를 이렇게 정리한다고 해보겠습니다.

```markdown
# 주간 업무 보고 (4월 1주차)

## 이번 주 성과
- 신규 고객 미팅 3건 완료
- 제안서 초안 작성 (A사, B사)
- 내부 워크숍 자료 정리

## 다음 주 계획
- A사 제안서 최종본 제출
- 신규 채널 파트너 미팅 2건
- 분기 실적 정리 시작

## 이슈 및 요청사항
- B사 견적 회신 지연 (팔로업 필요)
- 마케팅팀과 캠페인 일정 조율 필요
```

이게 끝입니다. 디자인은 한 글자도 신경 쓰지 않았습니다. 오로지 **무슨 말을 할 것인가**에만 집중한 겁니다.

### 1-2. AI에게 보고서로 변환 요청하기

내용이 정리되었으면, AI에게 이렇게 요청합니다.

```
이 마크다운 내용으로 주간 업무 보고서를 만들어줘.
깔끔한 HTML 문서로, 인쇄해도 보기 좋게.
회사 로고 색상은 네이비(#1a365d) 계열로 맞춰줘.
```

그러면 AI가 제목, 구분선, 색상, 여백까지 알아서 잡아줍니다. 결과물이 마음에 안 들면 피드백을 주면 됩니다.

```
표 형태로 바꿔줘. 성과와 계획을 좌우 2단으로 배치하고,
이슈 사항은 빨간 박스로 강조해줘.
```

![마크다운에서 보고서로 변환](/__content__/images/ch16-01.png)

이 루프가 핵심입니다. **한 번에 완벽할 필요가 없습니다.** 내용을 던지고, 피드백을 주고, 다시 받고. 이 과정이 파워포인트에서 도형을 하나하나 옮기는 것보다 훨씬 빠릅니다.

> **확인**: 마크다운으로 내용을 정리하고, AI에게 변환을 요청해서 보고서 초안이 나왔다면 성공입니다.

---

## STEP 2. 발표자료 구조와 슬라이드 초안 자동화

### 2-1. 슬라이드를 "내용 단위"로 쪼개기

발표자료도 마찬가지입니다. 파워포인트를 열기 전에, 슬라이드별로 **어떤 메시지를 전달할 것인지**부터 정리합니다.

```markdown
# 신규 서비스 기획 발표

## 슬라이드 1: 타이틀
신규 서비스 기획안 — AI 기반 고객 응대 자동화

## 슬라이드 2: 문제 제기
현재 고객 응대의 3가지 병목
1. 반복 질문 처리에 하루 2시간 소요
2. 야간/주말 응대 공백
3. 담당자별 응대 품질 편차

## 슬라이드 3: 제안
- AI 챗봇으로 반복 질문 80% 자동 처리
- 24시간 1차 응대 가능
- 응대 이력 자동 축적 → 품질 표준화

## 슬라이드 4: 기대 효과
- 응대 시간 60% 절감
- 고객 만족도 15% 향상 (예상)
- 월 운영비 200만원 이내
```

슬라이드 번호와 제목만 적었을 뿐인데, 발표 흐름이 한눈에 보입니다.

### 2-2. AI에게 슬라이드로 변환하기

이제 이 내용을 AI에게 넘깁니다.

```
이 마크다운으로 발표자료를 만들어줘.
HTML 단일 파일, 스크롤 방식 슬라이드로.
폰트는 Noto Sans KR, 색상은 다크 네이비 계열.
각 섹션은 전체 화면(100vh)으로 구성해줘.
```

몇 초 만에 슬라이드 초안이 나옵니다. 여기서 중요한 건, **이게 최종본이 아니라는 겁니다.** 초안을 받고, 피드백을 주는 과정이 핵심이죠.

```
2번 슬라이드에 아이콘을 추가해줘.
3번 슬라이드는 카드 레이아웃으로 바꿔줘.
전체적으로 폰트 크기를 10% 키워줘.
```

![AI가 생성한 슬라이드 초안](/__content__/images/ch16-02.png)

파워포인트 없이도 발표자료가 만들어졌습니다. HTML 파일이니까 브라우저에서 바로 열 수 있고, PDF로 내보내기도 됩니다.

### 2-3. 도구 선택 — 상황에 맞게

발표자료를 만드는 방법은 여러 가지입니다. 상황에 맞게 골라 쓰면 됩니다.

| 상황 | 추천 도구 | 이유 |
|------|----------|------|
| 빠르게 한 번 만들고 싶다 | Claude Artifacts, Gamma | 브라우저에서 즉시 확인 |
| PPTX로 납품해야 한다 | MS Copilot, Manus Slides | 기존 포맷 호환 |
| 마크다운으로 계속 관리하고 싶다 | Marp, Slidev | 버전 관리 가능 |
| 기존 PPT에 AI를 붙이고 싶다 | MS Copilot | 익숙한 환경 유지 |

어떤 도구를 쓰든 핵심은 같습니다. **내용을 먼저 정리하고, 디자인은 AI에게 맡기는 것.** 이 순서만 지키면 됩니다.

> **확인**: 마크다운으로 슬라이드 구조를 잡고, AI가 변환한 발표자료를 브라우저에서 확인했다면 성공입니다.

## STEP 3. 회사 산출물 포맷에 맞춰 바로 써먹기

### 3-1. 템플릿이 있으면 품질이 달라진다

여기까지 읽으셨으면 한 가지 의문이 들 수 있습니다. "그래, AI가 예쁘게 만들어주는 건 알겠는데, 우리 회사 포맷은 정해져 있잖아요."

맞습니다. 회사마다 보고서 양식이 있고, 제안서 구조가 있고, 발표자료 템플릿이 있습니다. 자유 형식으로 만들어봤자 결국 회사 양식에 옮겨 담아야 하죠.

그래서 **템플릿을 AI에게 먼저 보여주는 겁니다.**

```
우리 회사 제안서 구조는 이래:

00. 표지
01. Executive Summary — 핵심 요약, 범위, 견적
02. 현황 분석 — 시장 분석 + 전략 방향
03. 회사 소개
04. 산출물 구성 — 각 산출물 설명 + 견적
05. 일정
06. 세부 견적
07. 클라이언트 준비 사항
08. 연락처

이 구조에 맞춰서 [프로젝트명] 제안서를 작성해줘.
```

AI는 구조를 이해하고, 각 섹션에 맞는 내용을 채워넣습니다. 빈 템플릿에 내용을 하나하나 타이핑하는 것과는 속도가 다릅니다.

### 3-2. 산출물 시안까지 미리 만들기

여기서 한 단계 더 나갈 수 있습니다. 제안서 안에 **산출물의 시안을 미리 넣는 겁니다.**

실제로 이런 방식으로 제안서를 만든 사례가 있습니다. 의료기기 마케팅 제안서인데, 제안서 본문에 "미리보기" 버튼을 달았습니다. 버튼을 누르면 브로셔 레이아웃, 영상 스토리보드, B2B 프레젠테이션 시안이 바로 열립니다.

```
일반 제안서:  "브로셔를 만들겠습니다" → 텍스트 설명
바이브 제안서: "브로셔를 만들겠습니다" → [미리보기] → 실제 시안이 보임
```

![제안서 미리보기](/__content__/images/ch16-03.png)

클라이언트 입장에서 생각해보세요. 말로만 "이렇게 만들겠습니다"라고 하는 것과, 실제 시안을 보여주는 것. 설득력이 완전히 다릅니다.

이 제안서는 실제로 수주에 성공했습니다. **산출물을 설명하지 않고, 보여줬기 때문입니다.**

### 3-3. 사람이 마지막으로 메시지를 정리하기

자동화가 아무리 빨라도, 마지막 단계는 사람의 몫입니다.

AI가 만든 보고서를 그대로 제출하면 안 됩니다. 숫자가 맞는지, 우리 팀의 맥락이 반영되어 있는지, 받는 사람이 원하는 톤인지 — 이런 판단은 AI가 대신해줄 수 없습니다.

문서 자동화의 올바른 흐름은 이렇습니다.

```
1. 내용 정리 (마크다운) ← 사람
2. 초안 생성 (AI 변환) ← AI
3. 피드백 루프 (수정 요청) ← 사람 + AI
4. 최종 검수 (메시지 확인) ← 사람
```

AI는 속도를 담당하고, 사람은 판단을 담당합니다. 이 역할 분담이 문서 자동화의 핵심입니다.

> **확인**: 회사 템플릿 구조를 AI에게 건네고, 포맷에 맞는 산출물이 나왔다면 성공입니다.

## 여기서 막혔나요?

**Q. AI가 만든 문서가 너무 일반적이에요. 우리 회사 스타일이 아닙니다.**

상황: AI가 그럴듯한 문서를 만들긴 했는데, 어딘가 "템플릿 냄새"가 나고, 우리 회사에서 쓰는 용어나 톤과 다릅니다.

원인:
- AI에게 회사의 기존 문서를 보여주지 않았습니다
- 구조만 알려주고, 톤이나 용어는 지정하지 않았습니다

해결:
1. 기존에 잘 만들어진 보고서나 제안서를 하나 골라서 AI에게 함께 보여주세요. "이 문서의 톤과 구조를 참고해서 만들어줘"라고 요청하면 품질이 확 올라갑니다.
2. 회사에서 자주 쓰는 용어 목록을 정리해서 함께 건네주세요. "ROI" 대신 "투자 수익률"을 쓴다거나, "고객" 대신 "파트너사"를 쓴다거나 — 이런 디테일이 결과물의 완성도를 결정합니다.

**Q. HTML로 만들면 결국 PPTX로 옮겨야 하잖아요?**

상황: AI가 HTML로 예쁘게 만들어줬는데, 회사에서는 파워포인트 파일을 요구합니다.

원인:
- 최종 납품 포맷을 미리 지정하지 않았습니다

해결:
1. 처음부터 "PPTX로 만들어줘"라고 요청하세요. MS Copilot은 파워포인트 안에서 바로 생성합니다. Manus Slides도 PPTX 다운로드를 지원합니다.
2. HTML 초안이 이미 있다면, "이 HTML의 내용을 그대로 PPTX로 변환해줘"라고 요청할 수도 있습니다.
3. Marp를 쓰면 마크다운에서 바로 PPTX, PDF, HTML을 모두 내보낼 수 있습니다.

**Q. 프로젝트 문서가 너무 많아서 AI가 다 읽지 못해요.**

상황: PRD, 시장분석, 경쟁사 자료, 회의록 — 문서가 수십 개인데 AI에게 매번 다 붙여넣을 수 없습니다.

원인:
- AI의 컨텍스트 창에 한계가 있습니다

해결:
1. NotebookLM 같은 도구에 프로젝트 문서를 올려두세요. 소스 기반으로 답변하기 때문에, 올려둔 문서 안에서만 정확하게 참고합니다.
2. 핵심 문서 3~5개만 골라서 AI에게 보여주세요. 전체를 다 읽힐 필요 없이, "이 프로젝트의 맥락은 이 문서에 있어"라고 좁혀주면 충분합니다.
3. 프로젝트 지식베이스를 마크다운 파일로 정리해두면, 다음에 비슷한 문서를 만들 때 그대로 재사용할 수 있습니다.

---

## 한 줄 정리

내용은 마크다운으로 정리하고, 포맷과 디자인은 AI에게 맡기세요. 템플릿까지 보여주면, 결과물을 바로 업무에 붙일 수 있습니다.

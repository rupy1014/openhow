> "아침에 눈을 떴더니 텔레그램에 뉴스 요약이 와 있었습니다. 제가 한 건 어젯밤에 '내일부터 매일 아침 보고해줘'라고 한 줄 친 것뿐이었죠."

자동화를 배웠으니 이제 실전입니다. 그런데 처음부터 거창한 걸 만들 필요는 없습니다. 뉴스봇이면 충분합니다.

1장에서 만났던 박현수 씨를 기억하시죠? 온라인 쇼핑몰을 혼자 운영하는 1인 사업자요. 고객 문의, 발주, 블로그 포스팅을 전부 혼자 하다 보니 업계 동향을 챙길 여유가 없었습니다. "경쟁 셀러가 뭘 파는지, 트렌드가 어디로 가는지 매일 아침 정리만 와 있으면 좋겠다" — 현수 씨가 원하는 게 바로 이 뉴스봇입니다.

왜 뉴스봇이냐고요? 구조가 단순하기 때문입니다. 가져온다, 고른다, 요약한다, 보낸다. 이 네 단계가 전부입니다. 그리고 이 구조는 뉴스 말고도 거의 모든 자동화에 그대로 쓸 수 있습니다. 경쟁사 모니터링, 채용공고 추적, 논문 요약, 블로그 발행 알림 전부 같은 골격이거든요.

이 장이 끝나면, 여러분의 OpenClaw가 매일 아침 알아서 뉴스를 모으고, 걸러내고, 요약해서 텔레그램으로 보내줍니다. 여러분은 커피 한 잔 마시면서 보고만 받으면 됩니다.

---

## 완성 기준

- [ ] RSS 소스 3~5개를 OpenClaw에 등록할 수 있다
- [ ] 키워드 기반 필터링 + AI 요약 파이프라인이 동작한다
- [ ] cron으로 매일 아침 자동 실행이 설정되어 있다
- [ ] 텔레그램으로 뉴스 보고를 받고, 대화형으로 상세 내용을 확인할 수 있다

---

## STEP 1. 소스를 모으고 고르기 — RSS 파이프라인의 뼈대

### 1-1. RSS가 뭔지 한 줄로 설명합니다

RSS는 "새 글이 올라오면 기계가 읽기 좋은 형태로 알려주는 구독 피드"입니다. 크롤링처럼 사이트를 직접 긁을 필요가 없습니다. 대부분의 뉴스 사이트와 블로그가 이미 RSS를 제공하고 있거든요.

자동화의 입력원은 단순할수록 좋습니다. 입력이 복잡하면 전체가 같이 어려워집니다. RSS는 그래서 첫 자동화의 데이터 소스로 딱입니다.

### 1-2. 시작은 3~5개 소스면 충분합니다

처음부터 열 개, 스무 개 넣지 마세요. 소스가 많으면 필터링 기준이 느슨해지고, 결과물도 길어지고, 읽기 싫어집니다.

3~5개로 시작해서 안정된 뒤에 하나씩 추가하는 게 맞습니다.

Claude Code를 열고 이렇게 시켜보세요.

```
OpenClaw에 뉴스 수집 스킬을 만들어줘.
아래 RSS 피드 3개를 매일 읽어서 새 글 목록을 정리하는 스킬이야.

1. https://news.ycombinator.com/rss
2. https://feeds.feedburner.com/TechCrunch
3. https://rss.nytimes.com/services/xml/rss/nyt/Technology.xml

각 항목은 제목, 링크, 발행일, 출처를 포함해줘.
```

![뉴스 수집 시작하기](/__content__/images/ch13-01.png)

Claude Code가 RSS 파싱 스킬을 만들고, OpenClaw에 등록하고, 테스트 실행까지 해줄 겁니다. 결과가 JSON 배열로 깔끔하게 나오면 첫 단계는 끝입니다.

### 1-3. 키워드 기반 필터링: 내가 볼 만한 것만 남기기

모든 뉴스를 다 읽을 수는 없습니다. 자동화의 가치는 많이 가져오는 데 있지 않고, **내가 볼 만한 것만 남기는 데** 있습니다.

Claude Code에게 필터도 시키세요.

```
방금 만든 뉴스 수집 스킬에 필터링을 추가해줘.
AI, 자동화, 코딩 도구와 관련된 것만 남기고,
관련 없는 항목은 제거하고, 과장된 마케팅 문구도 빼줘.
```

필터가 없으면 매일 수십 건이 쏟아집니다. 필터가 있으면 딱 5~7건만 남습니다. 이 차이가 "읽는 자동화"와 "안 읽는 자동화"를 가릅니다.

> **확인**: RSS 소스 3개에서 새 글이 수집되고, 키워드 기반으로 필터링된 목록이 나오면 성공입니다.

---

## STEP 2. 요약하고 초안 만들기 — AI가 쓰고, 사람이 고른다

### 2-1. 초안 포맷을 정해둡니다

필터링이 끝났으면 이제 요약입니다. 요약 포맷을 미리 정해주는 게 중요합니다. 포맷 없이 "요약해줘"라고만 하면 매일 결과물이 들쭉날쭉해지거든요. Claude Code에게 시키세요.

```
뉴스 스킬에 요약 기능을 추가해줘.
필터링된 뉴스 각각을 아래 포맷으로 요약해.

## [제목]
- 한 줄 요약: (1문장)
- 핵심 포인트: (2~3개 불릿)
- 원문 링크: [링크]
```

이렇게 하면 매일 같은 구조로 정리됩니다. 눈에 익은 포맷이 쌓이면 훑어보는 속도가 빨라집니다.

### 2-2. "[퇴고 필요]" — AI가 쓴 건 항상 검토가 필요합니다

여기서 하나 꼭 짚고 넘어갈 게 있습니다. AI가 요약한 결과를 그대로 믿으면 안 됩니다.

요약이 원문의 핵심을 빗나갈 때가 있습니다. 숫자를 틀릴 때도 있고, 맥락을 빼먹을 때도 있습니다. 그래서 AI가 만든 초안에는 항상 "[퇴고 필요]"라는 태그를 마음속에 붙여두세요. 보고를 받되, 판단은 여러분이 하는 겁니다.

사람은 보고를 받고, 판단만 하면 됩니다. 이게 자동화의 올바른 역할 분담이죠.

### 2-3. 결과물은 파일로 쌓입니다

OpenClaw는 매일의 요약 결과를 파일로 저장합니다. 오늘이 4월 7일이라면 `2026-04-07-news.md`, 다음 날은 `2026-04-08-news.md` 이런 식으로요. 매일의 기록이 쌓이면 나중에 "지난주에 어떤 뉴스가 있었지?" 하고 돌아볼 수도 있습니다.

Claude Code에게 저장 구조도 시킵니다.

```
요약 결과를 날짜별 마크다운 파일로 저장하도록 설정해줘.
파일명은 YYYY-MM-DD-news.md 형식으로, reports/ 폴더에 넣어줘.
```

![RSS 소스를 커스터마이징하기](/__content__/images/ch13-02.png)

> **확인**: 필터링된 뉴스가 정해진 포맷으로 요약되고, 날짜별 파일로 저장되면 성공입니다.

## STEP 3. OpenClaw에 cron 걸기 — 매일 아침 자동 실행

### 3-1. cron이 뭔지 한 줄로 설명합니다

cron은 "정해진 시간에 자동으로 실행되는 예약"입니다. 알람 시계라고 생각하시면 됩니다. 알람이 울리면 소리 대신 스크립트가 실행되는 거죠.

지금까지 만든 파이프라인을 여러분이 매일 아침 직접 실행할 수도 있습니다. 하지만 솔직히, 3일이면 까먹습니다. 일주일이면 귀찮아집니다. 자동화가 자동화답게 되려면, 사람이 안 눌러도 돌아야 합니다.

### 3-2. Claude Code한테 cron 등록 시키기

Claude Code에게 이렇게 말하세요.

```
OpenClaw에 cron을 등록해줘.
매일 아침 7시에 뉴스 수집 스킬을 실행해서 텔레그램으로 보고하게 해줘.
```

Claude Code가 `openclaw cron add` 명령을 실행해줍니다. 이 한 줄이면 OpenClaw가 매일 아침 7시에 알아서 RSS를 긁고, 필터링하고, 요약하고, 텔레그램으로 보내줍니다.

### 3-3. 등록 확인과 관리

등록이 잘 됐는지도 Claude Code에게 물어보세요.

```
OpenClaw에 등록된 cron 목록을 보여줘.
```

등록된 cron 목록이 보일 겁니다. 시간을 바꾸고 싶으면 이렇게 시키세요.

```
뉴스 수집 cron 시간을 아침 8시로 바꿔줘.
```

![cron으로 매일 자동 실행하기](/__content__/images/ch13-03.png)

> **확인**: `openclaw cron list`에서 등록한 작업이 보이면 성공입니다. 내일 아침을 기대해보세요.

## STEP 4. 보고 받기 — "오늘은 뭐가 있지?"

### 4-1. 아침에 텔레그램을 열어보세요

cron을 등록한 다음 날 아침입니다. 텔레그램을 열어보세요. OpenClaw가 보낸 메시지가 와 있을 겁니다.

```
📋 오늘의 뉴스 초안 5건
주요 키워드: AI 에이전트, 자동화 도구, 코딩 어시스턴트

1. OpenAI, 새로운 에이전트 프레임워크 공개
   → 기존 대비 40% 빠른 실행 속도, 멀티스텝 지원

2. GitHub Copilot, 코드 리뷰 자동화 기능 추가
   → PR 올리면 자동으로 리뷰 코멘트 생성

3. ...
```

![뉴스봇이 매일 아침 보고합니다](/__content__/images/ch13-04.png)

아무것도 안 했는데 보고가 와 있습니다. 이게 바로 "OpenClaw한테 보고 받는" 경험입니다.

### 4-2. 대화형으로 더 자세히 물어봅니다

보고를 받았는데 두 번째 뉴스가 궁금합니다. 텔레그램에서 바로 물어보세요.

```
2번째 뉴스 자세히 보여줘
```

OpenClaw가 원문 링크와 함께 상세 요약을 보여줍니다.

```
📰 GitHub Copilot 코드 리뷰 자동화

- PR을 올리면 Copilot이 자동으로 코드를 읽고 리뷰 코멘트를 남깁니다
- 보안 취약점, 성능 이슈, 코딩 컨벤션 위반을 체크합니다
- 현재 베타 기능으로, Enterprise 플랜부터 사용 가능합니다

원문: https://github.blog/...
```

"오늘 뉴스 요약해줘"라고 물어볼 수도 있고, "AI 관련 뉴스만 다시 정리해줘"라고 요청할 수도 있습니다. 채팅으로 자동화를 제어하는 겁니다. 버튼을 누르거나 대시보드를 열 필요가 없습니다.

### 4-3. 보고의 리듬이 만들어집니다

처음에는 신기합니다. "어? 진짜 왔네?" 하면서 열어봅니다.

일주일이 지나면 습관이 됩니다. 아침에 커피 내리면서 텔레그램을 훑어봅니다. 관심 가는 건 "자세히 보여줘" 한마디로 확인합니다.

한 달이 지나면 당연해집니다. reports 폴더에 30개의 파일이 쌓여 있습니다. "지난달 AI 관련 뉴스 트렌드 정리해줘"라고 하면 OpenClaw가 한 달치를 분석해줍니다.

사람은 판단만 합니다. 수집, 정리, 보고는 OpenClaw가 합니다. 이게 자동화가 만드는 리듬입니다.

> **확인**: 텔레그램으로 뉴스 보고를 받고, "자세히 보여줘"로 상세 내용을 확인할 수 있으면 완성입니다.

## 여기서 막혔나요?

**Q. RSS 피드 URL을 어디서 찾나요?**

상황: 관심 사이트의 RSS 주소를 모르겠습니다.

원인:
- 대부분의 사이트에 RSS가 있지만 눈에 잘 띄지 않습니다

해결:
1. 사이트 URL 뒤에 `/rss`, `/feed`, `/atom.xml`을 붙여보세요
2. "사이트명 + RSS"로 검색하면 대부분 나옵니다
3. Claude Code에게 "이 사이트의 RSS 피드 주소 찾아줘"라고 시키면 알아서 검색해줍니다

**Q. 요약 품질이 날마다 다릅니다.**

상황: 어떤 날은 요약이 깔끔한데, 어떤 날은 핵심이 빠져 있습니다.

원인:
- 필터링 기준이 모호하면 결과도 불안정합니다

해결:
1. 프롬프트에 구체적인 키워드와 제외 조건을 명시하세요
2. "과장된 마케팅 문구 제거", "실질적 기술 변화만 남겨줘" 같은 가이드를 추가하세요
3. 잘 나온 날의 결과물을 예시로 프롬프트에 포함시키면 품질이 안정됩니다

**Q. cron이 실행되지 않는 것 같습니다.**

상황: 시간이 지났는데 텔레그램에 아무것도 안 옵니다.

원인:
- OpenClaw가 꺼져 있거나, 네트워크 연결이 끊겼을 수 있습니다
- cron 등록 시 시간대(timezone)가 맞지 않을 수 있습니다

해결:
1. Claude Code에게 "OpenClaw 상태 확인해줘"라고 시키세요
2. "등록된 cron 목록이랑 시간 확인해줘"라고 물어보세요
3. "지금 바로 뉴스 수집해서 보고해줘"로 수동 실행을 시켜보세요
4. 수동 실행이 되면 cron 시간 설정 문제, 안 되면 파이프라인 자체 문제입니다

**Q. 소스를 너무 많이 넣었더니 결과가 길어요.**

상황: 열 개 이상의 소스를 넣었더니 요약도 길고 읽기 싫어집니다.

원인:
- 소스가 많으면 필터링이 느슨해지고 전체 양이 폭증합니다

해결:
1. 소스를 3~5개로 줄이세요. 안정된 뒤에 하나씩 추가하면 됩니다
2. "최대 5개 항목만 남겨줘" 같은 상한선을 프롬프트에 넣으세요
3. 스크롤 없이 읽을 수 있는 길이를 목표로 하세요. 길면 안 읽게 됩니다

## 한 줄 정리

뉴스봇은 자동화 첫 실전의 정석입니다. 가져오고, 고르고, 요약하고, 보내는 이 구조만 한 번 몸에 익히면, 다음 자동화는 이 골격 위에 얹기만 하면 됩니다.

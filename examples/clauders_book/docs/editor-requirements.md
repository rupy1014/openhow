# 0409 편집자 수정 목차 코멘트 정리

> 원문 기준: Google Doc의 **"0409 편집자 수정 목차" 표와 그 아래 편집자 코멘트**만 추려 정리함.  
> 이 문서는 책의 기본 소개용 메모가 아니라, **목차 수정 작업에 바로 반영할 편집 포인트**를 남기는 용도다.

## 1. 가장 중요한 편집자 지시

### 1.1 메인 도구는 코덱스로 정리
- 원문 메모: **"메인도구를 코덱스로"**
- 의미:
  - 본문 중심 실습 도구를 Codex로 통일해야 함.
  - 다른 도구 비교는 가능하지만, 책의 주축은 Codex여야 함.
  - Claude Code 중심으로 읽힐 수 있는 표현은 Codex 중심으로 재정리 필요.

### 1.2 목차 위계를 다시 정리
- 원문 메모: **"장 > 절 > 중제목 묶을 수 있는 것 묶고 위상 정리"**
- 의미:
  - 비슷한 수준의 항목은 같은 레벨로 맞춰야 함.
  - 파트/장/절이 섞여 보이지 않게 정리해야 함.
  - 중복되거나 따로 놀 수 있는 항목은 통합 검토 필요.

### 1.3 유즈케이스는 학습서 구조로 바꿔야 함
- 원문 메모 요지:
  - 이 책은 **활용서보다 입문·학습서**로 포지셔닝
  - 각 유즈케이스는 바로 사례로 들어가기보다
    **먼저 알아야 할 프로그래밍/AI 개념을 설명하고,
    그다음 실습으로 완전히 이해시키는 구조**가 좋음
- 편집자가 제시한 예시:
  - 바로 배워: 크롤링 기초, 태그와 속성 설명 → 바로 쓰는: 1년치 금시세 크롤링
  - 바로 배워: 배포, 서버, 포트 번호 → 바로 쓰는: 버셀로 일정 공지 사이트 배포

### 1.4 뒤쪽 큰 이론 파트는 앞에 녹이기
- 원문 메모: **"이건 앞에서 필요할 때 바로 설명하면 좋을 것 같아서 앞 내용에 필요한 부분에 녹여주세요."**
- 의미:
  - 기술 큰그림, 웹 구조, 디버깅, 데이터/API 같은 설명을 뒤에 몰아두지 말 것
  - 실제 실습이 나오는 장에서 필요한 만큼 분산 배치할 것

## 2. 0409 표 안에서 직접 달린 코멘트

### 2.1 Part 2 - MVP 설명은 별도 꼭지보다 앞에 흡수
- 표 위치: `02.1 AI 캐릭터 채팅 서비스 빠르게 만들어보기`
- 원문 코멘트: **"MVP는 어디까지일까 @@앞 내용에 녹여도 좋을 것 같아요"**
- 작업 지시:
  - `MVP는 어디까지인가`를 별도 독립 소절로 세우기보다
  - 캐릭터 챗 제작 흐름 안에서 자연스럽게 설명하도록 합치는 편이 좋음

### 2.2 Part 2 - 환경변수 설명도 배포 흐름 안으로 흡수
- 표 위치: `02.2 만든 서비스를 직접 배포해보기`
- 원문 코멘트: **"환경변수와 배포는 어떻게 연결될까 @@앞 내용에 녹여도 좋을 것 같아요"**
- 작업 지시:
  - 환경변수는 따로 이론 꼭지로 빼지 말고
  - Vercel 배포 실습이나 배포 과정 설명 안에 녹이는 편이 좋음

### 2.3 Part 4 - 모바일 자동화 사례 추가 검토
- 표 위치: Part 4 실전 자동화 섹션
- 원문 코멘트: **"모바일을 활용한 자동화 사례도 추가되면 좋을 것 같습니다."**
- 작업 지시:
  - 뉴스봇/유튜브/문서 자동화 외에
  - 모바일 알림, 메신저, 승인/발행 흐름 등 모바일 접점 사례를 1개 이상 검토

## 3. 0409 표 기준 파트별 수정 방향

### 3.1 Part 1
기준 방향:
- 한 줄 설치
- 블로그 자동화 맛보기
- 왕초보 개념 설명
- 웹소설 자동화

해석:
- 초반은 **설치 → 자동화 체감 → 개념 이해 → 한 번 더 다른 예제로 감각 잡기** 흐름이 중요함
- Part 1부터 바로 성공 경험이 있어야 함

### 3.2 Part 2
기준 방향:
- AI 캐릭터 채팅 서비스 만들기
- 직접 배포하기
- 나도 한번 만들어보기
- Agent.MD와 스킬

해석:
- Part 2는 작은 서비스 하나를 만들고 끝내는 것이 아니라
  **만들기 → 배포 → 내 아이디어로 확장 → 작업 규칙 문서화**까지 연결되어야 함

### 3.3 Part 3
기준 방향:
- 오픈클로 처음 시작하기
- 오픈클로 자동화 구조 읽기
- AI가 팀처럼 일하는 구조 이해
- 정확도/예외/비용 등 보완 팁

해석:
- 단순 설치 소개가 아니라
  **오픈클로의 구조적 이해**와 **운영 감각**까지 가야 함
- 표 안에 `03.1` 번호 중복, `03.2/03.3` 순서 뒤섞임이 있으므로
  최종 정리 시 번호 체계도 정상화 필요

### 3.4 Part 4
기준 방향:
- 뉴스봇과 스레드 자동화
- 유튜브 자동화
- 보고서/PPT 자동화
- 모바일 자동화 사례 추가 검토
- 내 일에 자동화 붙이기

해석:
- 단순 나열보다
  **대표 업무형 유즈케이스 → 채널 확장 → 실무 문서화 → 개인 업무 적용** 순서가 적절함

## 4. 실무 반영용 체크리스트

- [ ] 목차 설명에서 Codex가 메인 도구로 분명히 보이는가
- [ ] 장/절/중제목 레벨이 섞이지 않게 정리되어 있는가
- [ ] `MVP는 어디까지인가`를 별도 항목으로 세우지 않고 앞 내용에 흡수했는가
- [ ] `환경변수와 배포 연결`을 배포 실습 맥락 안으로 흡수했는가
- [ ] 모바일 자동화 사례를 Part 4 후보에 넣었는가
- [ ] 유즈케이스 장마다 "먼저 배울 개념 → 바로 쓰는 실습" 구조가 보이는가
- [ ] 뒤쪽 큰 이론 파트를 앞의 실습 장면으로 분산 배치했는가
- [ ] Part 3의 번호 중복/순서 꼬임을 정리했는가

## 5. 한 줄 요약

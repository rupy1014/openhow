> "보고 받는 건 13장에서 했습니다. 이번엔 지시합니다. '이것도 발행해줘' 한마디면 됩니다."

13장에서 뉴스봇이 매일 아침 텔레그램으로 보고하는 흐름을 만들었습니다. 그런데 보고만 받으면 절반입니다. "이거 좋은데? Threads에 올려줘"라고 지시하는 순간, 소비에서 발행으로 넘어갑니다. 채팅 한 줄로 콘텐츠가 세상에 나가는 경험 — 이번 장에서 직접 만들어봅니다.

---

## 완성 기준

- [ ] 콘텐츠 발행의 단계(소스 수집 → 초안 → 검토 → 승인 → 발행)를 이해한다
- [ ] 텔레그램에서 "발행해줘"를 지시하고, 초안 확인 후 승인하는 흐름을 경험한다
- [ ] 발행 후 피드백으로 품질을 개선하는 루프를 설정한다

---

## STEP 1. 초안에서 발행까지 — 어떤 단계가 있을까

### 1-1. 콘텐츠 자동화의 다섯 단계

13장에서 만든 뉴스봇은 "가져오고 → 고르고 → 요약하고 → 보내는" 구조였습니다. 발행까지 가려면 여기에 두 단계가 더 붙습니다.

1. **소스 수집** — RSS, 웹 검색 등으로 원재료를 모은다
2. **초안 생성** — AI가 발행용 글을 작성한다
3. **검토** — 사람이 읽고 판단한다
4. **승인** — "이대로 올려"라고 확인한다
5. **발행** — 실제 SNS에 게시된다

![콘텐츠 자동화 파이프라인](/__content__/images/ch14-01.png)

핵심은 3번과 4번입니다. AI가 초안을 만들고, 사람이 확인하고, 다시 AI가 실행합니다. 이 구조를 **반자동 발행**이라고 부릅니다.

"왜 완전 자동으로 안 하나요?"라고 물으실 수 있습니다. 좋은 질문입니다. 완전 자동 발행은 편해 보이지만, 한 번이라도 엉뚱한 글이 올라가면 브랜드 신뢰가 무너집니다. 사람의 눈이 한 번 거치는 것만으로도 사고를 막을 수 있습니다. 반자동이 더 안전하고, 실은 더 쓸모 있습니다.

### 1-2. 같은 소스에서 두 가지가 나온다

뉴스봇이 수집한 소스 하나로 두 가지 콘텐츠를 만들 수 있습니다.

- **Threads용 짧은 글**: 핵심만 3~4줄로 압축. 가볍게 소비되는 포맷
- **블로그/뉴스레터용 긴 글**: 배경 설명과 분석이 포함된 포맷

채널이 달라도 원재료는 같습니다. 소스를 한 번 수집해두면, 포맷만 바꿔서 여러 채널에 뿌릴 수 있다는 뜻이죠. 이걸 **멀티 채널 발행**이라고 합니다.

### 1-3. 초안 상태 관리

초안에는 두 가지 상태만 있으면 됩니다.

| 상태 | 의미 | 다음 행동 |
|------|------|----------|
| **퇴고 필요** | AI가 만든 초안. 아직 사람이 확인하지 않음 | 읽고 판단 |
| **승인됨** | 사람이 "좋아"라고 확인한 상태 | 발행 실행 |

복잡하게 만들 필요 없습니다. 처음엔 이 두 단계만으로 충분합니다. 나중에 익숙해지면 "수정 요청" 같은 중간 단계를 추가해도 되고요.

> **확인**: "소스 수집 → 초안 → 검토 → 승인 → 발행"의 다섯 단계와 반자동 발행의 이유를 이해했으면 다음으로 넘어가세요.

## STEP 2. "이것도 발행해줘" — OpenClaw에게 발행 지시하기

### 2-1. 텔레그램에서 지시 내리기

13장에서 아침마다 뉴스 보고를 받고 계시죠? 보고 메시지를 보면 뉴스 항목마다 번호가 붙어 있습니다. 이 번호를 그대로 활용합니다.

텔레그램 채팅창에 이렇게 입력하세요.

```
3번 뉴스 Threads에 올려줘
```

이 한 줄이면 됩니다. OpenClaw는 3번 뉴스의 원문을 가져와서, Threads에 맞는 짧은 글로 초안을 만듭니다.

![메신저로 발행 지시하기](/__content__/images/ch14-02.png)

### 2-2. 초안 확인하기

잠시 뒤 OpenClaw가 초안을 보내줍니다. 이런 식이죠.

```
📝 Threads 초안 (뉴스 #3)
──────────────────
AI 코딩 에이전트가 코드 리뷰도 한다.
GitHub Copilot이 PR 리뷰 기능을 추가했는데,
단순 문법 체크가 아니라 로직 오류까지 잡아준다.
개발팀 코드 리뷰 시간이 40% 줄었다는 보고.
──────────────────
👉 발행하려면 "승인"
👉 수정하려면 피드백을 보내주세요
```

여기서 여러분이 할 일은 딱 하나입니다. **읽고 판단하는 것.** AI가 글을 써주지만, "이걸 내 이름으로 올려도 되는가?"를 결정하는 건 사람의 몫입니다.

### 2-3. 승인하고 발행하기

초안이 괜찮으면 "승인"이라고 답하세요.

```
승인
```

OpenClaw가 해당 초안을 Threads API를 통해 발행합니다. 발행이 완료되면 확인 메시지가 옵니다.

```
✅ Threads 발행 완료
📎 https://threads.net/@yourhandle/post/...
```

![승인에서 발행까지](/__content__/images/ch14-03.png)

전체 흐름을 정리하면 이렇습니다.

1. 아침 뉴스 보고를 받는다 (13장에서 설정한 자동화)
2. 마음에 드는 뉴스를 골라 "발행해줘"라고 지시한다
3. OpenClaw가 초안을 만들어 보여준다
4. 읽고 "승인"이라고 답한다
5. 발행 완료

AI가 초안을 쓰고, 사람이 판단하고, 다시 AI가 실행합니다. 이게 바로 **반자동 발행**의 전부입니다.

### 2-4. 초안이 마음에 안 들면?

"승인" 대신 피드백을 보내면 됩니다.

```
톤이 좀 딱딱해. 좀 더 가볍게 고쳐줘.
```

OpenClaw가 피드백을 반영해서 수정본을 다시 보내줍니다. 마음에 들 때까지 몇 번이고 수정을 요청할 수 있습니다. 이 과정 자체가 AI의 글쓰기 품질을 올리는 훈련이 됩니다.

> **확인**: 텔레그램에서 "발행해줘 → 초안 확인 → 승인 → 발행 완료"의 흐름을 이해했으면 다음으로 넘어가세요.

## STEP 3. 발행 후 — 무엇을 확인하고 무엇을 고칠까

### 3-1. 발행 후 피드백 루프

발행이 끝이 아닙니다. 올린 글을 보고 "다음엔 이렇게 해야겠다"를 정리하는 과정이 진짜 중요합니다.

예를 들어볼까요?

- "이 글은 숫자가 없어서 밋밋했다" → 다음 초안 프롬프트에 "핵심 수치를 포함해줘" 추가
- "해시태그가 너무 많아서 지저분했다" → "해시태그 3개 이내" 규칙 추가
- "링크가 빠져서 원문을 못 찾았다" → "원문 링크를 항상 포함해줘" 조건 추가

이런 피드백을 OpenClaw의 발행 스킬에 반영하면, 다음번부터는 같은 실수를 반복하지 않습니다. 자동화의 핵심은 한 번에 완벽한 결과를 내는 게 아니라, **피드백을 쌓아서 점점 나아지는 구조**를 만드는 겁니다.

![발행 후 피드백 루프](/__content__/images/ch14-04.png)

텔레그램에서 바로 지시할 수도 있습니다.

```
앞으로 Threads 초안에는 핵심 수치를 꼭 넣어줘. 해시태그는 3개 이내로.
```

이 한 줄이 OpenClaw의 발행 규칙에 반영됩니다. 다음번 초안부터 바뀝니다.

### 3-2. 오래된 초안 정리하기

바쁜 날에는 초안을 확인하지 못하고 넘어갈 수 있습니다. 그러다 보면 "퇴고 필요" 상태의 초안이 쌓이게 되죠. 뉴스는 시간이 지나면 가치가 떨어집니다. 2주 전 뉴스를 지금 발행하는 건 의미가 없잖아요.

그래서 규칙을 하나 만들어두면 좋습니다.

```
14일 넘은 미승인 초안은 자동 삭제해줘
```

이렇게 하면 신경 쓰지 않아도 오래된 초안이 알아서 정리됩니다. 초안 목록이 깔끔하게 유지되니까 확인해야 할 것도 줄어들죠.

### 3-3. 반자동에서 정기 자동 발행으로

처음에는 매번 "승인"을 직접 해주는 게 좋습니다. AI가 어떤 톤으로 쓰는지, 어떤 실수를 하는지 감을 잡아야 하니까요.

그런데 한두 달 지나면 패턴이 보입니다. "이 정도면 대부분 괜찮다"는 감각이 생기죠. 그때부터 자동 승인 비율을 조금씩 올려볼 수 있습니다.

| 단계 | 승인 방식 | 언제 넘어가나 |
|------|----------|-------------|
| 1단계 | 매번 수동 승인 | 처음 시작할 때 |
| 2단계 | 점수 높은 초안만 자동 승인 | 2주~1달 운영 후 |
| 3단계 | 정기 자동 발행 + 예외만 수동 | 품질이 안정된 후 |

중요한 건, **1단계를 건너뛰지 않는 것**입니다. AI의 글쓰기 습관을 파악하기 전에 자동 승인을 걸면, 의도치 않은 글이 올라갈 수 있습니다. 천천히, 신뢰를 쌓으면서 넘어가세요.

> **확인**: 피드백 루프, 초안 정리, 단계적 자동화 확장의 세 가지를 이해했으면 이 장의 실습은 끝입니다.

## 여기서 막혔나요?

**Q. Threads API 연동이 어렵습니다**

상황: OpenClaw에게 발행을 시켰는데 API 오류가 나는 경우입니다.

원인:
- Threads API 접근 토큰이 만료되었거나 설정되지 않았을 수 있습니다
- Meta 개발자 계정에서 앱 권한이 부족할 수 있습니다

해결:
1. OpenClaw 설정에서 Threads API 토큰이 제대로 들어가 있는지 확인하세요
2. Meta Developer Portal에서 앱 상태가 "Live"인지 확인하세요
3. Threads가 어려우면 먼저 텔레그램 채널 발행부터 시작해도 됩니다. 채널은 바뀌어도 앞단 구조는 같거든요

**Q. 초안 품질이 기대보다 낮습니다**

상황: AI가 만든 초안이 너무 일반적이거나, 원문의 핵심을 놓치는 경우입니다.

원인:
- 초안 생성 프롬프트가 너무 짧거나 모호할 수 있습니다
- 원문 자체가 너무 길어서 AI가 요약 과정에서 핵심을 놓칠 수 있습니다

해결:
1. 발행 스킬의 프롬프트에 "핵심 수치와 고유명사를 반드시 포함해줘" 같은 구체적 지침을 추가하세요
2. 잘 나왔던 초안을 예시로 프롬프트에 넣으면 품질이 안정됩니다
3. "좋았던 이전 글처럼 써줘"라고 피드백을 보내면 OpenClaw가 참고합니다

**Q. 실수로 승인해서 발행한 글을 되돌리고 싶습니다**

상황: 확인 없이 "승인"을 눌렀는데, 발행된 글에 오류가 있는 경우입니다.

원인:
- 반자동 발행에서도 사람의 실수는 발생할 수 있습니다

해결:
1. 해당 SNS 앱에서 직접 삭제하세요. 대부분의 SNS는 게시 직후 삭제가 가능합니다
2. OpenClaw에게 "방금 발행한 Threads 글 삭제해줘"라고 지시할 수도 있습니다
3. 실수를 줄이려면, 승인 전 "초안 한 번 더 보여줘"라는 습관을 들이세요

**Q. 완전 자동 발행을 바로 하고 싶습니다**

상황: 매번 승인하는 게 번거로워서 처음부터 자동 발행을 하고 싶은 경우입니다.

원인:
- 자동화에 대한 기대가 앞서는 자연스러운 욕구입니다

해결:
1. 최소 2주는 수동 승인으로 운영하면서 초안 품질을 관찰하세요
2. 10건 중 8건 이상이 수정 없이 통과한다면, 자동 승인을 시도해볼 시점입니다
3. 자동 승인을 걸더라도 "발행 알림"은 켜두세요. 뭐가 올라갔는지는 항상 확인할 수 있어야 합니다

## 한 줄 정리

자동화의 핵심은 "보고 받고 → 판단하고 → 지시하는" 루프입니다. **초안은 AI가, 판단은 사람이, 실행은 다시 AI가.** 이 구조만 잡으면 SNS 발행도, 그 다음 자동화도 같은 패턴으로 확장할 수 있습니다.

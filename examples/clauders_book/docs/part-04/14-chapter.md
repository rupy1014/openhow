# 14장 AI가 쓴 글을 SNS에 자동으로 올리기 — Threads·Instagram API

> "좋은 정보는 나눌 때 가치가 두 배가 됩니다. 이제 우리만의 '무인 뉴스 채널'을 세상에 공개할 시간입니다."

---

## 14.1 SNS 발행 에이전트 추가하기

13장까지 잘 따라오셨습니다. 어떠신가요? 매일 아침 뉴스를 수집해서 요약하고, 내 텔레그램으로 쏙 보내주는 시스템을 갖추니 꽤 든든하시죠? 이제 여러분의 컴퓨터에는 24시간 쉬지 않고 일하는 유능한 뉴스 편집자가 한 명 살고 있는 셈입니다.

그런데 여기서 욕심이 조금 더 생깁니다. **"이 좋은 정보를 나만 보기 아깝다"**는 생각이 들거든요. 내가 정성껏 고른 키워드로 요약된 양질의 정보를 스레드(Threads)나 인스타그램(Instagram)에 올리면 어떨까요? 팔로워들에게 도움도 되고, 내 계정을 '전문가스러운' 채널로 키울 수도 있을 겁니다.

하지만 우리가 매일 수동으로 복사해서 붙여넣을 수는 없겠죠? 그건 자동화의 정신에 어긋납니다. 그래서 이번 장에서는 우리 뉴스봇 공장에 새로운 직원을 한 명 더 채용하려고 합니다. 바로 **'SNS 발행 담당 에이전트'**입니다.

---

### 기존 뉴스봇에 '발행 단계' 추가하기

우리가 13장에서 만든 뉴스봇은 일종의 '1인 기업'이었습니다. 혼자서 뉴스도 찾고, 요약도 해서 나에게 보고했죠. 하지만 규모가 커지면 역할 분담이 필요합니다.

식당으로 비유해 볼까요? 지금까지는 주방장 혼자서 재료도 사 오고(수집), 요리도 하고(요약), 서빙(보고)까지 다 했습니다. 하지만 이제 '배달 서비스(SNS 발행)'를 시작하려고 합니다. 주방장이 배달까지 가면 주방이 엉망이 되겠죠? 그래서 우리는 배달과 마케팅을 전문으로 하는 직원을 새로 뽑는 겁니다.

자동화 시스템을 설계할 때 가장 중요한 건 **'파이프라인'**을 선명하게 그리는 겁니다. 우리 뉴스봇의 공정 라인에 '발행'이라는 마지막 컨베이어 벨트를 하나 더 연결해 봅시다.

**[기존 파이프라인]**
- **1단계: 수집 담당** (RSS 피드에서 따끈따끈한 뉴스를 긁어옵니다)
- **2단계: 분류·요약 담당** (내 관심사에 맞는 것만 골라 3줄로 요약합니다)

**[새로운 파이프라인]**
- **1단계: 수집 담당** (동일)
- **2단계: 분류·요약 담당** (동일)
- **3단계: 발행 담당 (NEW!)** (요약된 내용을 SNS 성격에 맞춰 다듬고 실제로 올립니다)

여기서 3단계 발행 담당 에이전트의 역할은 아주 구체적입니다. 단순히 복사해서 붙여넣는 게 아니라, **"이 내용을 스레드 사람들이 좋아할 만한 말투로 바꿔줘"** 혹은 **"인스타그램용 이미지 문구를 만들어줘"** 같은 고난도의 편집 작업을 수행합니다.

### 왜 에이전트를 나누나요?

"그냥 요약 에이전트한테 발행까지 시키면 안 되나요?"라고 물으실 수 있습니다. 물론 가능은 합니다. 하지만 추천하지 않습니다. 왜냐하면 **'요약의 목적'과 '발행의 목적'이 완전히 다르기 때문**입니다.

- **요약 담당**: "팩트" 중심입니다. 정보가 누락되지 않았는지, 정확한지가 제일 중요합니다.
- **발행 담당**: "반응" 중심입니다. 사람들이 클릭하고 싶게 만드는지, SNS 채널의 분위기에 맞는지가 핵심입니다.

이 두 가지 일을 한 명에게 시키면 AI가 혼란을 겪습니다. 요약을 시켰는데 갑자기 "좋아요 눌러주세요!" 같은 마케팅 멘트를 본문에 섞어버릴 수도 있거든요. 그래서 우리는 `AGENTS.md` 파일에 이들의 역할을 명확히 구분해서 적어줄 겁니다.

### 채널별 포맷 규칙을 AGENTS.md에 정의하기

자, 이제 새로운 직원을 위해 '업무 매뉴얼'을 작성해 봅시다. SNS마다 사람들이 노는 방식이 다르다는 건 여러분도 잘 아실 겁니다. 에이전트에게도 이 차이를 정확히 알려줘야 합니다.

| 구분 | 스레드 (Threads) | 인스타그램 (Instagram) |
| :--- | :--- | :--- |
| **핵심 성격** | 텍스트 중심, 가벼운 소통 | 이미지 중심, 정보 저장성 |
| **글자 수** | 500자 이내 (짧을수록 좋음) | 캡션 제한은 넉넉하나 시각적 요소 중요 |
| **말투** | 반말과 존댓말 사이의 캐주얼함 | 신뢰감 있는 정보 전달 톤 |
| **필수 요소** | 해시태그 3개 이내, 질문형 마무리 | 카드 뉴스용 문구, 해시태그 5~10개 |

이 규칙을 `AGENTS.md`에 그대로 녹여내면 됩니다. 예를 들어 스레드 담당자에게는 "너는 지금부터 힙한 테크 블로거야. 뉴스 요약을 보고 친구한테 말하듯이 280자 내외로 다듬어줘"라고 지시하는 식이죠.

그런데 여기서 하나 더. 뉴스 요약 톤과 SNS 발행 톤은 완전히 다른 옷이거든요. 그래서 **톤가이드를 분리**합니다. `docs/sns-tone-guide.md`라는 파일을 따로 만들어서, 채널별 말투와 분위기를 별도로 관리하는 거죠. 이렇게 하면 나중에 새로운 채널(블로그, 유튜브 커뮤니티 등)이 추가되더라도 `AGENTS.md`를 건드릴 필요 없이 톤가이드 파일만 업데이트하면 됩니다.

### [실습] 발행 담당 에이전트 설정하기

이제 직접 코드를 만져볼 시간입니다. 겁먹지 마세요. 우리는 이미 13장에서 에이전트를 설정하는 법을 배웠습니다. 이번에는 그 지식을 바탕으로 확장만 하면 됩니다.

### STEP 1. SNS 전용 톤 가이드 만들기

가장 먼저 할 일은 말투를 정의하는 파일을 따로 분리하는 겁니다. 왜냐하면 뉴스 요약 톤과 SNS 발행 톤이 섞이면 안 되거든요. `docs/sns-tone-guide.md` 파일을 만들고 아래 내용을 복사해서 넣어보세요.

01 VS Code에서 `docs/sns-tone-guide.md` 파일을 만드세요.
02 아래 내용을 복사해서 붙여넣으세요.

```markdown
# SNS 채널별 톤 가이드

## 1. Threads (스레드)
- **컨셉**: 커피 마시며 친구와 대화하는 느낌
- **규칙**:
  - 문장은 짧고 간결하게 (최대 3문장)
  - "~네요", "~함" 같은 구어체 사용
  - 전문 용어는 쉽게 풀어서 설명
  - 마지막엔 "여러분은 어떻게 생각하세요?" 같은 질문 던지기
  - 해시태그는 딱 3개만 (#AI #테크 #자동화)

## 2. Instagram (인스타그램)
- **컨셉**: 깔끔하게 정리된 매거진 에디터
- **규칙**:
  - 첫 줄에 시선을 끄는 강렬한 헤드라인 (이모지 활용)
  - 본문은 불렛포인트로 가독성 있게 정리
  - "옆으로 넘겨서 확인하세요" 문구 포함
  - 해시태그는 관련 키워드 5~10개 묶음으로
```

### STEP 2. AGENTS.md에 발행 담당자 추가하기

이제 오픈클로(OpenClaw)의 심장부인 `AGENTS.md`를 열어봅시다. 기존의 `summarizer` 아래에 `publisher`를 추가할 겁니다.

01 프로젝트 루트 폴더에 있는 `AGENTS.md` 파일을 엽니다.
02 아래와 같이 `publisher` 에이전트 정의를 추가하세요.

```markdown
## publisher (발행 담당자)
- **역할**: 요약된 뉴스를 SNS 채널별 최적의 포맷으로 변환
- **지침**:
  - `docs/sns-tone-guide.md`의 규칙을 반드시 준수할 것
  - 원문의 핵심 정보는 절대 왜곡하지 말 것
  - 채널별로(Threads, Instagram) 각각 다른 버전을 생성할 것
  - 이미지 생성이 필요한 경우, 이미지에 들어갈 핵심 문구를 따로 추출할 것
```

### STEP 3. 폴더 구조 확인하기

자, 설정이 끝났습니다. 이제 우리 프로젝트 폴더 구조는 대략 이런 모습이 되어야 합니다.

```
/Users/user/my-news-bot/
├── AGENTS.md              # 에이전트들의 업무 지침서
├── docs/
│   └── sns-tone-guide.md  # (NEW) SNS 말투 가이드
├── content-workflow/      # 뉴스 데이터가 쌓이는 곳
└── scripts/
    └── gwrite-run.sh      # 뉴스봇 실행 스크립트
```

> **확인**: `docs/sns-tone-guide.md` 파일이 잘 만들어졌나요? 그리고 `AGENTS.md`에 `publisher` 내용이 들어갔나요? 이 두 가지만 확인하면 우리 시스템의 '지능'은 준비가 끝난 겁니다.

### 여기서 막혔나요?

**Q. 톤 가이드를 왜 굳이 따로 파일로 만드나요? `AGENTS.md`에 다 적으면 안 되나요?**

물론 `AGENTS.md`에 한꺼번에 적어도 작동은 합니다. 하지만 나중에 SNS 채널이 늘어나거나(예: 블로그, 유튜브 커뮤니티), 말투를 조금 바꾸고 싶을 때 `AGENTS.md`가 너무 길어지면 관리가 힘들어집니다. **"업무 지침(어떤 일을 할지)"은 `AGENTS.md`에, "스타일(어떻게 말할지)"은 `tone-guide.md`에** 나누어 담는 것이 고수들의 비결입니다. 그래야 에이전트가 더 명확하게 자기 할 일을 파악하거든요.

**Q. 인스타그램용 이미지는 AI가 직접 만들어주나요?**

지금 단계에서는 에이전트가 이미지에 들어갈 **'텍스트 내용'**만 뽑아줄 겁니다. 예를 들어 "카드 뉴스 1페이지 제목: 챗GPT 신기능 발표!" 이런 식으로요. 실제로 이미지를 생성하거나 캔바(Canva) 같은 툴에 자동으로 넣는 법은 뒷부분에서 더 깊게 다룰 테니, 일단은 '콘텐츠의 뼈대'를 만드는 데 집중해 봅시다.

### 한 줄 정리

SNS 발행 에이전트를 추가한다는 것은 뉴스 요약이라는 **'원재료'**를 각 SNS에 맞는 **'상품'**으로 가공하는 전문 편집자를 고용하는 것과 같으며, 이를 위해 채널별 톤 가이드를 분리하는 것이 핵심입니다.

자, 이제 우리 공장의 세 번째 직원인 '발행 담당자'가 출근 준비를 마쳤습니다. 그런데 문제가 하나 있습니다. 이 직원이 글은 참 잘 쓰는데, 실제로 인스타그램이나 스레드에 접속해서 글을 올릴 '손'이 없네요. 다음 섹션에서는 이 에이전트에게 실제 SNS 계정으로 접속할 수 있는 열쇠를 쥐여주는 법을 알아보겠습니다. 메타(Meta) 개발자 설정이라는 조금 딱딱한 과정이 기다리고 있지만, 이것만 넘어서면 여러분의 게시물이 전 세계로 실시간 발행되는 마법을 보게 될 겁니다!

## 14.2 Threads API 연결하기 — Meta 개발자 설정

자, 이제 우리 공장의 '발행 담당자'에게 실제 스레드(Threads) 계정에 글을 올릴 수 있는 '열쇠'를 쥐여줄 시간입니다. 솔직히 말씀드리면, 이 섹션이 이번 장에서 가장 고비입니다. 코딩이 어려워서가 아니라, 페이스북과 인스타그램을 운영하는 '메타(Meta)'의 설정 화면이 조금 복잡하거든요.

하지만 겁먹지 마세요. 우리가 은행에 가서 통장을 만들 때 서류 몇 장 적는 것과 비슷합니다. 한 번만 제대로 설정해두면, 그때부터는 에이전트가 여러분 대신 24시간 내내 쉬지 않고 SNS에 글을 실어 나를 겁니다. 자, 심호흡 한 번 하시고 천천히 따라와 보세요.

---

### STEP 1. Meta 개발자 계정 만들기

가장 먼저 할 일은 여러분을 '개발자'로 등록하는 겁니다. "저 개발자 아닌데요?"라고 하셔도 괜찮습니다. 메타 입장에서는 API를 쓰려는 모든 사람을 개발자로 부르니까요. 일종의 'API 사용 자격증'을 따는 과정이라고 생각하시면 됩니다.

01 브라우저를 열고 [developers.facebook.com](https://developers.facebook.com)에 접속하세요.
02 오른쪽 상단의 **[시작하기]** 또는 **[내 앱]** 버튼을 누릅니다.
03 페이스북 계정으로 로그인한 뒤, 개발자 등록 절차를 진행하세요. (이메일 인증과 직업 선택 정도만 하면 끝납니다.)

**"앱 생성 = 우리만의 통로 만들기"**

등록이 끝났다면 이제 '앱'을 만들어야 합니다. 여기서 말하는 앱은 스마트폰에 설치하는 앱이 아니라, 우리 에이전트가 메타 서버와 통신할 때 사용하는 '전용 통로'의 이름입니다.

04 **[앱 만들기]** 버튼을 클릭합니다.
05 앱 유형 선택 화면이 나오면 맨 아래에 있는 **[기타]**를 선택하고 **[다음]**을 누르세요.
06 앱 유형을 다시 물어보는데, 이때 반드시 **[Threads Content Publishing API]** (또는 유사한 명칭)가 포함된 유형을 선택해야 합니다. 만약 잘 모르겠다면 **[비즈니스]**를 선택해도 무방합니다.
07 앱 이름을 정해주세요. 'My_News_Bot'처럼 여러분이 알아보기 쉬운 이름이면 됩니다.

### STEP 2. Threads API(Meta SNS 글 올리기) 설정과 권한 요청

앱을 만들었다고 바로 글을 올릴 수 있는 건 아닙니다. "이 앱이 내 스레드 계정에 글을 써도 좋다"라는 허락을 받아야 하죠. 이걸 전문 용어로 **'권한(Scope) 설정'**이라고 부릅니다.

01 생성된 앱의 대시보드 왼쪽 메뉴에서 **[설정] > [기본 설정]**으로 들어갑니다.
02 화면 아래쪽에 **[플랫폼 추가]**를 누르고 **[웹]**을 선택하세요. (사이트 URL에는 일단 `http://localhost:3000` 같은 가짜 주소를 넣어도 괜찮습니다.)
03 다시 왼쪽 메뉴에서 **[Threads]**를 찾아 클릭하고, **[설정]** 버튼을 누릅니다.

**"열쇠의 용도를 정해주는 과정입니다."**

여기서 우리가 에이전트에게 줄 권한은 딱 세 가지입니다.
- `threads_content_publish`: 글을 올릴 수 있는 권한
- `threads_basic`: 내 프로필 정보를 읽는 권한
- `threads_manage_insights`: (선택) 내 글의 반응도를 확인하는 권한

이 세 가지만 있으면 에이전트가 여러분 대신 글을 쓰고, 잘 올라갔는지 확인까지 할 수 있습니다.

> **질문이요! '앱 검수'라는 걸 받아야 하나요?**
> 혼자 쓰실 거라면 검수가 필요 없습니다! 메타 개발자 설정에는 '개발 모드'가 있는데, 이 상태에서도 여러분 본인 계정에는 얼마든지 글을 올릴 수 있거든요. 나중에 이 봇을 다른 사람들에게 서비스할 게 아니라면, 복잡한 검수 과정은 건너뛰셔도 됩니다.

### STEP 3. 액세스 토큰(access token, API 사용 열쇠) 발급 — 60일짜리 '만능 열쇠' 만들기

자, 이제 가장 중요한 **'액세스 토큰'**을 받을 차례입니다. 토큰은 아이디와 비밀번호 대신 에이전트가 사용하는 '디지털 신분증'입니다. 이 신분증이 있어야만 메타 서버가 "아, 주인이 허락한 에이전트구나!" 하고 문을 열어주죠.

메타의 토큰은 유효 기간에 따라 두 종류로 나뉩니다.

| 종류 | 유효 기간 | 용도 |
| :--- | :--- | :--- |
| **단기 토큰** | 약 1시간 | 테스트용, 금방 만료됨 |
| **장기 토큰** | **60일** | **실제 자동화봇 운영용** |

우리는 매번 로그인을 새로 할 수 없으니, **60일 동안 유지되는 '장기 토큰'**을 만들어서 에이전트에게 쥐여줄 겁니다.

01 **[그래프 API 탐색기(Graph API Explorer)]** 도구에 접속합니다.
02 오른쪽 '사용자 또는 페이지' 항목에서 방금 만든 앱을 선택하세요.
03 'Permissions' 칸에 위에서 배운 `threads_content_publish`, `threads_basic`을 추가합니다.
04 **[Generate Access Token]** 버튼을 누릅니다. 스레드 로그인 창이 뜨면 로그인하고 권한을 승인하세요.
05 화면에 길게 나오는 문자열이 바로 **'단기 토큰'**입니다. 이걸 일단 복사해두세요.

**"단기 토큰을 장기 토큰으로 바꾸기"**

이 단기 토큰은 한 시간만 지나면 못 쓰게 됩니다. 이걸 60일짜리로 바꿔야 합니다.

06 메타 개발자 문서의 '토큰 관리' 섹션을 이용하거나, 코덱스에게 다음과 같이 부탁하세요.
> "메타에서 받은 단기 토큰이 있어. 이걸 60일짜리 장기 토큰으로 바꾸는 API 호출 주소를 알려줘. 내 App ID랑 App Secret은 여기 있어."

07 코덱스가 알려준 주소로 접속하면 드디어 **60일 동안 유효한 장기 토큰**이 나옵니다.

### STEP 4. 오픈클로에 '만능 열쇠' 등록하기

이제 보물처럼 얻은 이 토큰을 우리 에이전트가 쓸 수 있게 금고(`.env` 파일)에 넣어줍시다.

01 프로젝트 폴더의 `.env` 파일을 엽니다.
02 아래 내용을 추가하고 복사한 토큰을 붙여넣으세요.


> **주의**: `.env` 파일에 토큰을 저장했나요? 이 토큰이 외부에 노출되면 누구나 여러분의 스레드에 글을 올릴 수 있으니, 절대 깃허브(GitHub) 같은 곳에 올리지 않도록 주의하세요!

### 여기서 막혔나요?

**Q. 60일이 지나면 봇이 멈추나요?**

네, 장기 토큰도 만료일이 있습니다. 하지만 걱정 마세요! 토큰이 만료되기 전(보통 50일 차쯤)에 API를 한 번만 호출하면 다시 60일로 연장됩니다. 나중에 우리가 배울 '관리 스크립트'에 이 자동 연장 기능을 한 줄 넣어두면, 여러분이 신경 쓰지 않아도 봇은 영원히 멈추지 않고 돌아갈 겁니다.

**Q. 'App Secret'은 어디서 확인하나요?**

메타 개발자 대시보드의 **[설정] > [기본 설정]**에 가시면 '앱 비밀번호'라는 항목이 있습니다. [보기] 버튼을 누르면 비밀번호를 확인할 수 있어요. 이건 앱의 인감도장 같은 거라 아무에게도 알려주면 안 됩니다.

**Q. 스레드 계정이 개인 계정인데 괜찮나요?**

네, 스레드 API는 개인 계정도 지원합니다. 다만 인스타그램의 경우엔 다음 섹션에서 배울 것처럼 '비즈니스 계정'으로 전환해야 하는 차이가 있어요. 스레드는 지금 상태 그대로 진행하셔도 충분합니다.

고생하셨습니다! 가장 까다로운 설정의 절반을 넘으셨네요. 이제 에이전트는 스레드라는 넓은 바다로 나갈 준비를 마쳤습니다. 그런데 요즘 SNS는 하나만 해서는 부족하죠? 인스타그램이라는 더 큰 세상이 기다리고 있습니다. 다음 섹션에서는 비슷하지만 조금 다른, **인스타그램 그래프 API(Instagram Graph API, 인스타그램 자동 게시)**를 연결하는 법을 알아보겠습니다. 스레드 설정을 해보셨으니 인스타그램은 훨씬 수월하게 느껴지실 겁니다!

## 14.3 Instagram Graph API 연결하기 — 비즈니스 계정 설정

스레드(Threads) 설정, 생각보다 금방 끝나서 놀라셨죠? "이 정도면 인스타그램도 껌이겠는데?"라고 생각하셨다면... 죄송하지만 잠시만 마음을 다잡아주세요. 솔직히 말씀드리면, 인스타그램 연결은 이번 장에서 가장 고비가 되는 구간입니다.

"그냥 인스타그램 계정만 있으면 되는 거 아니야?"라고 물으실 수 있습니다. 하지만 메타(Meta)라는 거대한 왕국의 입장에서 보면, 개인 사용자와 '자동화 봇'은 엄격히 구분됩니다. 우리가 만든 에이전트가 인스타그램에 사진을 올리려면, 마치 정식 사업자 등록을 하듯 몇 가지 까다로운 절차를 거쳐야 하거든요.

하지만 걱정하지 마세요. 저와 함께 한 단계씩 밟아가면 결국 성공하실 겁니다. 자, 인스타그램이라는 더 큰 바다로 나가기 위한 '비즈니스 세팅'을 시작해 봅시다.

### 계정 전환: 내 인스타그램에 '사업자 등록' 하기

가장 먼저 해야 할 일은 여러분의 인스타그램 계정을 **'비즈니스 계정'**으로 바꾸는 겁니다. 우리가 평소에 친구들과 사진을 공유하는 '개인 계정' 상태로는 API라는 도구를 쓸 수 없기 때문이죠.

**"비즈니스 계정으로 바꾸면 돈이 드나요?"** 아니요, 전혀 그렇지 않습니다. 무료로 전환할 수 있고, 나중에 언제든 다시 개인 계정으로 돌아올 수 있으니 안심하셔도 됩니다.

### STEP 1. 프로페셔널 계정으로 전환하기

01 스마트폰에서 인스타그램 앱을 열고 [프로필] 페이지로 들어갑니다.
02 오른쪽 상단의 [줄 세 개(메뉴)] 버튼을 누르고 **[설정 및 개인정보]**를 선택하세요.
03 아래로 쭉 내려서 **[내 콘텐츠를 공유하고 볼 수 있는 사람]** 섹션 근처에 있는 **[계정 유형 및 도구]**를 누릅니다.
04 **[프로페셔널 계정으로 전환]**을 누르고 안내에 따라 진행하세요. 카테고리는 '디지털 크리에이터'나 '블로거' 중 아무거나 선택하셔도 무방합니다.

> **확인**: 설정이 끝나면 내 프로필에 '대시보드'라는 버튼이 생겼나요? 그렇다면 1단계 통과입니다!

### Facebook 페이지 연결: "왜 인스타그램을 하는데 페이스북이 필요하죠?"

이 질문, 제가 강의할 때마다 백 번은 듣는 질문입니다. 결론부터 말씀드리면 **"인스타그램의 주인은 메타(Meta)이고, 메타의 모든 비즈니스 도구는 페이스북 페이지를 중심으로 돌아가기 때문"**입니다.

비유하자면 이렇습니다. 인스타그램이 '가게 안의 진열대'라면, 페이스북 페이지는 '가게의 사업자 등록증'과 같습니다. 사업자 등록증이 있어야 카드 단말기(API)를 설치할 수 있는 것과 같은 이치죠.

### STEP 2. 페이스북 페이지와 연결하기

01 페이스북(Facebook)에 로그인하고 왼쪽 메뉴에서 **[페이지]**를 선택합니다.
02 **[새 페이지 만들기]**를 눌러 아주 간단한 페이지를 하나 만드세요. 이름은 '내 뉴스봇' 정도로 하시면 충분합니다. (실제로 운영할 필요는 없습니다.)
03 페이지가 만들어지면 [설정] > [연결된 계정] 메뉴로 들어갑니다.
04 **[Instagram 연결]** 버튼을 누르고, 방금 비즈니스 계정으로 전환한 인스타그램 계정으로 로그인하세요.

**"이 과정이 제일 중요합니다."** 여기서 인스타그램과 페이스북 페이지가 단단하게 묶여야만, 나중에 에이전트가 "나는 이 인스타그램 계정의 주인인 페이스북 페이지로부터 허락받았어!"라고 증명할 수 있거든요.

### Graph API 권한 설정: 에이전트에게 '열쇠' 넘겨주기

이제 다시 메타 개발자(Meta for Developers) 대시보드로 돌아올 시간입니다. 스레드 때와 비슷하지만, 인스타그램은 더 정교한 '열쇠'가 필요합니다. 바로 **인스타그램 그래프 API(Instagram Graph API)**입니다.

에이전트가 내 계정에 사진을 올리고 글을 쓰려면, 메타로부터 "이 봇은 글을 쓸 권한이 있어"라는 허락을 받아야 합니다. 이걸 전문 용어로 '권한(Permissions) 설정'이라고 부릅니다.

### STEP 3. 인스타그램 제품 추가 및 권한 요청

01 [Meta 개발자 대시보드](https://developers.facebook.com/)에서 우리가 만든 앱을 선택합니다.
02 왼쪽 메뉴의 **[제품 추가]**를 누르고 **[Instagram Graph API]**를 찾아 [설정] 버튼을 누르세요.
03 이제 가장 중요한 순간입니다. 에이전트에게 줄 권한 목록을 체크해야 합니다. 아래 표를 보고 정확히 선택해 주세요.

| 권한 이름 | 역할 | 왜 필요한가요? |
| :--- | :--- | :--- |
| **instagram_basic** | 계정의 기본 정보 읽기 | 내 계정 ID를 확인하기 위해 필수 |
| **instagram_content_publish** | **콘텐츠 발행** | 에이전트가 직접 사진과 글을 올리는 핵심 열쇠 |
| **pages_read_engagement** | 페이지 정보 읽기 | 인스타그램과 연결된 페이스북 페이지를 찾기 위함 |
| **pages_show_list** | 페이지 목록 보기 | 내가 관리하는 페이지 목록을 불러오기 위함 |

**"권한이 너무 많은 것 같은데 괜찮나요?"** 네, 걱정 마세요. 우리가 직접 만든 앱이고, 우리 계정에만 쓸 것이니까요. 이 네 가지 권한이 없으면 에이전트는 "글을 올릴 권한이 없습니다"라는 에러 메시지만 뱉어낼 겁니다.

04 권한을 선택했다면 [Graph API 탐색기(Explorer)]로 이동합니다.
05 오른쪽 [User or Page] 메뉴에서 방금 만든 **페이스북 페이지**를 선택하세요.
06 [Get Token] 버튼을 눌러 **'페이지 액세스 토큰'**을 발급받습니다.

> **저자의 팁: 토큰의 종류를 헷갈리지 마세요!**
> 인스타그램 자동화에서 가장 많이 실수하는 부분이 '사용자 토큰'을 받는 겁니다. 우리는 **'페이지 액세스 토큰'**을 받아야 합니다. 그래야 봇이 페이지를 거쳐 인스타그램에 글을 올릴 수 있거든요.

### 여기서 막혔나요?

**Q. 페이스북 페이지를 꼭 새로 만들어야 하나요? 기존에 있던 건 안 되나요?**

기존에 관리하시던 페이지가 있다면 그걸 쓰셔도 됩니다. 다만, 그 페이지가 인스타그램 계정과 '연결'되어 있어야 한다는 점만 기억하세요. 깨끗한 시작을 원하신다면 테스트용으로 하나 새로 만드시는 걸 추천합니다.

**Q. 권한 설정 중에 'App Review'가 필요하다고 나오는데 어떡하죠?**

당황하지 마세요! 그건 이 서비스를 전 세계 사람들에게 배포할 때 필요한 절차입니다. 우리는 '개발 모드(Development Mode)'에서 내 계정만 쓸 것이기 때문에 별도의 리뷰를 받을 필요가 없습니다. 앱 상태를 '라이브(Live)'로 바꾸지 않아도 여러분의 계정에는 글이 잘 올라갑니다.

**Q. "Instagram Business Account not found"라는 에러가 떠요.**

두 가지를 확인해 보세요. 첫째, 인스타그램 계정이 정말 '비즈니스 유형'인지(크리에이터 유형은 가끔 에러가 납니다). 둘째, 페이스북 페이지 설정에서 인스타그램 연결이 '승인 대기 중'은 아닌지 확인해 보세요. 대부분 여기서 해결됩니다.

### 한 줄 정리

인스타그램 자동화의 핵심은 **비즈니스 계정 전환**과 **페이스북 페이지 연결**, 그리고 **콘텐츠 발행 권한(instagram_content_publish)**을 확보하는 것입니다.

고생하셨습니다! 이제 여러분은 스레드와 인스타그램이라는 두 개의 거대한 SNS로 통하는 문을 모두 열었습니다. 설정이 조금 복잡하고 지루하셨죠? 하지만 이 과정을 견뎌낸 덕분에, 이제부터는 '코딩'과 '자동화'라는 즐거운 실습만이 남아있습니다.

자, 이제 문을 열었으니 실제로 들어가 볼 시간입니다. 다음 섹션에서는 오픈클로(OpenClaw)에 우리가 발급받은 이 소중한 토큰들을 등록하고, 에이전트에게 "자, 이제 네가 직접 SNS에 연결해 봐!"라고 시켜보겠습니다. 드디어 여러분의 에이전트가 세상과 처음 소통하는 순간이 다가오고 있습니다!

## 14.4 [실습] MCP로 오픈클로에 SNS API 연결하기

앞에서 우리는 메타(Meta)의 복잡한 미로를 뚫고 소중한 '열쇠'들을 챙겨왔습니다. 스레드용 토큰, 인스타그램용 토큰... 이름만 들어도 머리가 지끈거리시죠? 고생 많으셨습니다. 하지만 이제부터는 정말 신나는 시간입니다. 이 열쇠들을 우리 조수, 오픈클로(OpenClaw)의 손에 쥐여줄 거거든요.

열쇠만 있다고 문이 열리는 건 아닙니다. 열쇠를 구멍에 넣고 돌려야 하죠. 오픈클로에게 이 열쇠를 전달하고, 실제로 SNS라는 외부 세계와 소통하게 만드는 기술이 바로 **MCP(Model Context Protocol)**입니다.

### MCP: 조수에게 '스마트폰'을 사주는 법

이전에 제가 MCP를 **'USB-C'**에 비유했던 것 기억하시나요? 예전에는 조수에게 "스레드에 글 좀 올려줘"라고 시키려면, 스레드 전용 앱을 깔고, 복잡한 코드를 짜서 연결해야 했습니다. 하지만 MCP라는 표준 규격이 나오면서 모든 게 간단해졌습니다.

**"MCP는 조수에게 SNS 앱이 깔린 스마트폰을 쥐여주는 것과 같습니다."**

조수는 이제 여러분이 준 토큰(비밀번호)을 이용해 스마트폰을 켜고, 스레드에 접속해 글을 남길 수 있게 됩니다. 우리가 직접 코드를 한 줄 한 줄 짤 필요가 없어요. 이미 잘 만들어진 '스마트폰(MCP 서버)'을 조수에게 건네주기만 하면 됩니다.

### STEP 1. Threads MCP 서버 설정하기

가장 먼저 스레드부터 연결해 봅시다. 스레드는 텍스트 중심이라 테스트하기에 아주 좋습니다. 오픈클로가 이 기능을 쓰려면 "나 이제 스레드 쓸 줄 알아!"라고 인식시켜줘야 합니다.

#### 1-1. 토큰을 안전하게 숨기기 (.env 설정)

조수에게 열쇠를 줄 때, 아무 데나 던져주면 안 됩니다. 우리 프로젝트 폴더 안에 있는 금고, `.env` 파일에 잘 넣어둬야 하죠.

01 프로젝트 루트 폴더(예: `my-news-bot/`)에 있는 `.env` 파일을 엽니다.
02 14.2에서 발급받은 스레드 액세스 토큰을 아래 형식으로 추가합니다.

```env
# Threads API 설정
THREADS_ACCESS_TOKEN=여기에_여러분의_발급_토큰을_붙여넣으세요
THREADS_USER_ID=여러분의_스레드_사용자_ID
```

> **잠깐! 사용자 ID는 어디서 보나요?**
> 메타 개발자 센터의 'Threads' 설정 화면이나, API 탐색기에서 내 정보를 조회했을 때 나오는 숫자 형태의 ID를 적으시면 됩니다.

#### 1-2. 오픈클로에게 스레드 기능 추가하기

이제 터미널을 열고 오픈클로(코덱스)에게 새로운 도구를 장착해 줍시다. 아래 명령어를 딱 한 줄만 복사해서 붙여넣으세요.

```bash
codex mcp add threads --env THREADS_ACCESS_TOKEN=$THREADS_ACCESS_TOKEN -- npx -y @modelcontextprotocol/server-threads
```

01 위 명령어를 입력하고 Enter를 누릅니다.
02 잠시 기다리면 "MCP server 'threads' added successfully"라는 메시지가 뜹니다.

> **확인**: 이제 오픈클로는 스레드에 글을 쓸 수 있는 '손'을 가지게 되었습니다. 정말 그런지 확인해 볼까요? 터미널에 `/mcp`라고 쳐보세요. 목록에 `threads`가 보인다면 성공입니다!

### STEP 2. Instagram MCP 서버 설정하기

스레드를 성공했다면 인스타그램은 식은 죽 먹기입니다. 방식은 똑같거든요. 다만 인스타그램은 '페이스북 페이지'를 거쳐야 한다는 점만 기억하시면 됩니다.

#### 2-1. 인스타그램 열쇠 등록하기

01 다시 `.env` 파일을 엽니다.
02 14.3에서 챙겨온 인스타그램용 페이지 액세스 토큰과 비즈니스 계정 ID를 넣습니다.

```env
# Instagram API 설정
INSTAGRAM_PAGE_ACCESS_TOKEN=여기에_인스타그램_연결용_토큰을_넣으세요
INSTAGRAM_BUSINESS_ACCOUNT_ID=여러분의_인스타그램_비즈니스_ID
```

#### 2-2. 인스타그램 도구 장착

이번에도 터미널 명령 한 줄로 끝냅니다. 인스타그램 전용 MCP 서버를 연결하는 과정입니다.

```bash
codex mcp add instagram --env INSTAGRAM_TOKEN=$INSTAGRAM_PAGE_ACCESS_TOKEN -- npx -y @modelcontextprotocol/server-instagram
```

01 명령어를 실행하고 성공 메시지를 확인합니다.
02 다시 한번 `/mcp`를 입력해 보세요. 이제 `threads`와 `instagram`이 나란히 여러분의 명령을 기다리고 있을 겁니다.

**"이제 여러분의 조수는 양손에 강력한 SNS 도구를 쥐었습니다."**

#### 3-1. 스레드에 첫 인사 건네기

### MCP로 연결하면 뭐가 더 좋은가요?

단순히 "글을 올린다"는 것 이상의 의미가 있습니다. MCP로 연결된 순간, 오픈클로는 이런 일들도 할 수 있게 됩니다.

- **실시간 반응 모니터링**: "내 스레드 게시물에 달린 댓글들 요약해 줘."
- **자동 답장**: "질문 댓글이 달리면 내가 작성한 FAQ 문서를 참고해서 정중하게 답장 달아줘."
- **성과 분석**: "지난 일주일 동안 어떤 게시물이 가장 좋아요를 많이 받았는지 표로 정리해 줘."

단순히 글을 쓰는 '타자기'가 아니라, 채널을 관리하는 **'SNS 매니저'**를 한 명 채용하신 것과 다름없습니다.

| | 기존 방식 (수동) | MCP + 오픈클로 방식 |
|---|---|---|
| **발행** | 직접 앱 켜서 복사/붙여넣기 | 말 한마디로 자동 발행 |
| **포맷팅** | 채널별로 일일이 수정 | 에이전트가 알아서 변환 |
| **관리** | 24시간 확인해야 함 | 조수가 보고해주고 대응함 |

### 여기서 막혔나요?

**Q. `codex mcp add` 명령어를 쳤는데 "command not found"라고 나와요.**

`codex` 명령어(코덱스)가 제대로 설치되지 않았거나 터미널이 인식하지 못하는 상태입니다. 01장의 설치 과정을 다시 확인하시거나, 터미널을 완전히 껐다 켜보세요.

**Q. "Invalid OAuth Access Token"이라는 에러가 뜨면서 글이 안 올라가요.**

열쇠가 잘못되었습니다. 14.2, 14.3에서 복사해 온 토큰에 공백이 포함되지는 않았는지, 혹은 유효기간이 만료된 건 아닌지 확인해 보세요. 특히 '페이지 액세스 토큰'이 아니라 '사용자 토큰'을 넣었을 때 이런 에러가 자주 납니다.

**Q. 조수가 도구는 쓰는데 "권한이 없다"고 거절당해요.**

메타 개발자 설정에서 `threads_content_publish`나 `instagram_content_publish` 권한을 체크했는지 다시 확인해 보세요. 권한을 추가한 뒤에는 토큰을 새로 발급받아야 적용되는 경우도 있습니다.

### 한 줄 정리

MCP는 오픈클로에게 스레드와 인스타그램이라는 스마트폰을 쥐여주는 핵심 기술이며, **명령어 한 줄로 연결하고 말 한마디로 발행하는 '무인 발행 시스템'의 심장**입니다.

고생하셨습니다! 이제 여러분의 조수는 세상을 향해 소리칠 수 있는 강력한 확성기를 얻었습니다. 하지만 아직 한 가지가 부족합니다. 조수는 지금 "무엇을" 올려야 할지 모릅니다. 우리가 직접 문장을 불러줘야만 하죠.

자, 이제 진정한 자동화의 꽃을 피울 시간입니다. 다음 섹션에서는 13장에서 만든 '뉴스봇'과 지금 만든 '발행 도구'를 하나로 합쳐보겠습니다. 뉴스를 수집하고, 요약하고, 이제는 우리가 시키지 않아도 알아서 스레드와 인스타그램에 올리는 **'자율 주행 뉴스봇'**을 완성하러 가봅시다!

## 14.5 [실습] 뉴스봇 요약을 Threads에 발행해보기

자, 드디어 올 것이 왔습니다. 지금까지 우리 조수는 텔레그램이라는 '밀실'에서 우리에게만 정보를 속삭였습니다. 이제는 그 조수의 입을 열어 세상 밖으로 외치게 할 시간입니다.

사실 이 단계가 자동화의 꽃입니다. 내가 잠든 사이에도 조수가 뉴스를 긁어오고, 예쁘게 다듬어서, 스레드(Threads)에 딱 올리는 장면. 상상만 해도 짜릿하지 않나요?

하지만 조수에게 무작정 "야, 아무거나 올려"라고 하면 큰일 납니다. 우리 조수는 유능하지만 눈치가 없거든요. 그래서 우리는 조수에게 '홍보 담당자'라는 새 명찰을 달아주고, 어떤 말투로 글을 써야 하는지 '브랜드 가이드북'을 쥐여줄 겁니다.

---

### 발행 담당 에이전트가 하는 일

우리가 13장에서 만든 뉴스봇은 '수집'과 '요약'까지는 아주 잘합니다. 하지만 SNS에 글을 올리는 건 또 다른 영역이죠. 텔레그램에 보내는 딱딱한 요약문을 스레드에 그대로 올리면 아무도 읽지 않을 겁니다.

그래서 우리는 **'발행 담당 에이전트'**를 추가할 겁니다. 이 친구의 역할은 명확합니다.

1. 13장 조수가 만든 '뉴스 요약'을 가져온다.
2. `docs/sns-tone-guide.md`를 읽고 SNS 성격에 맞게 말투를 바꾼다.
3. 14.4에서 연결한 MCP 도구를 써서 실제로 글을 올린다.

여기서 핵심은 **'톤 가이드'**입니다. 뉴스봇이 사실을 전달하는 기자라면, 발행 에이전트는 조회수를 부르는 마케터가 되어야 하거든요.

---

### STEP 1. SNS 전용 말투 장착하기

가장 먼저 할 일은 조수가 참고할 '말투 설명서'를 만드는 겁니다. `docs/` 폴더 안에 `sns-tone-guide.md` 파일을 하나 만들어봅시다.

01 VS Code에서 `docs/sns-tone-guide.md` 파일을 만드세요.
02 아래 내용을 복사해서 붙여넣으세요.

```markdown
# SNS 발행 톤 가이드

## Threads 포맷
- **길이**: 공백 포함 500자 이내 (한 포스트 기준)
- **말투**: "~해요", "~군요" 같은 친근한 구어체.
- **구조**:
  1. 강렬한 한 줄 (훅)
  2. 뉴스 핵심 내용 3문장
  3. 질문이나 의견 (소통 유도)
  4. 해시태그 3~5개 (#AI뉴스 #자동화 #바이브코딩)

## 금지 사항
- "안녕하십니까", "전해드립니다" 같은 딱딱한 말투 금지
- 전문 용어만 나열하기 금지
- 링크만 띡 던지기 금지
```

> **확인**: 가이드북이 준비되었나요? 이제 조수는 이 문서를 보고 "아, 스레드에서는 이렇게 말해야 하는구나!"라고 깨닫게 됩니다.

### STEP 2. [실습] "오늘의 AI 뉴스" 스레드에 올리기

이제 본격적으로 일을 시켜봅시다. 13장에서 만든 뉴스 요약 파일이 `content-workflow/` 폴더에 있다고 가정하고 진행합니다.

01 터미널에서 `codex`를 실행하세요.
02 조수에게 다음과 같이 지시하세요.

> "뉴스 요약 파일을 읽고, `docs/sns-tone-guide.md` 규칙에 맞춰서 Threads용 포스팅 문구를 만들어줘. 다 만들었으면 14.4에서 설정한 Threads MCP를 써서 실제로 발행해줘."

03 조수가 작업을 시작합니다. 먼저 파일을 읽고, 문장을 다듬은 뒤, MCP 도구를 호출할 겁니다.

### STEP 3. 하네스 적용 — 발행 전 미리보기, 승인, 그리고 발행

자, 그런데 여기서 잠깐! 만약 조수가 뉴스를 잘못 해석해서 엉뚱한 글을 올리면 어떡하죠? 혹은 아직 공개하면 안 되는 정보를 실수로 올린다면요?

그래서 우리는 13.4에서 배웠던 **'하네스(안전장치)'** 패턴을 여기에도 적용할 겁니다. 조수가 글을 바로 올리는 게 아니라, 나에게 먼저 보여주고 "승인"을 받아야만 발행되게 만드는 거죠.

01 조수에게 명령을 수정해서 내립니다.
> "Threads에 올릴 글을 먼저 **텔레그램으로 나에게 보내줘.** 내가 보고 '발행해'라고 답장하면 그때 올려줘."

02 조수는 이제 다음과 같은 순서로 움직입니다.
- **문구 작성**: 뉴스 요약을 보고 SNS용 문구를 만든다.
- **승인 요청**: 텔레그램으로 나에게 문구를 보낸다.
- **대기**: 내 답장을 기다린다.
- **최종 발행**: 내가 "OK" 하면 그때 스레드에 올린다.

**"이게 진짜 무서운 점입니다. 나는 침대에 누워서 스마트폰으로 조수의 보고를 받고, '발행' 버튼 하나로 세상을 움직이는 거죠."**

### 여기서 막혔나요?

**Q. 조수가 글을 만들긴 하는데 MCP 도구를 안 써요.**

조수에게 명확하게 다시 말해주세요. "만든 문구만 보여주지 말고, 반드시 `threads_post` 도구를 실행해서 실제로 올려줘"라고요. 가끔 조수가 너무 조심스러워서 보고만 하고 멈추는 경우가 있습니다.

**Q. 텔레그램 승인 메시지가 안 와요.**

13장에서 설정한 `TELEGRAM_CHAT_ID`와 `BOT_TOKEN`이 `.env` 파일에 정확히 들어있는지 확인하세요. 텔레그램 봇이 잠들어 있을 수도 있으니 봇에게 먼저 "/start"를 보내보세요.

**Q. 글자 수가 너무 길어서 발행이 실패해요.**

스레드는 한 포스트에 500자 제한이 있습니다. `sns-tone-guide.md`에 "반드시 400자 이내로 짧게 써줘"라고 더 엄격한 규칙을 추가해 보세요. 조수는 규칙이 엄격할수록 말을 더 잘 듣습니다.

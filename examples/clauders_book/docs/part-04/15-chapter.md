> 유튜브 자동화는 글 자동화와 다릅니다. 파이프라인을 먼저 설계해야 합니다.

13장에서 뉴스봇이 매일 아침 보고를 보내고, 14장에서 SNS 발행까지 자동화했습니다. 글 기반 자동화는 "텍스트를 만들고, 텍스트를 보내는" 구조여서 한 번 흐름을 잡으면 비교적 깔끔하게 돌아갑니다.

그런데 영상은 다릅니다. 대본이 있어야 하고, 대본에서 장면을 나눠야 하고, 음성을 만들어야 하고, 화면을 렌더링해야 합니다. 단계가 많습니다. 그래서 영상 자동화는 "자동화"라기보다 **파이프라인**에 가깝습니다.

1장에서 만났던 이도현 씨를 기억하시죠? 유튜브 콘텐츠를 만들고 싶은데 촬영도 편집도 혼자 해야 하는 대학생이었습니다. "대본이라도 AI가 써주면 시간이 반으로 줄 텐데"라고 했었죠. 이번 장이 바로 도현 씨를 위한 장입니다. 대본부터 렌더링까지의 파이프라인을 이어붙이고, 어디까지 자동화하고 어디서 사람이 판단해야 하는지를 정리합니다.

---

## 완성 기준

- [ ] 반복 가능한 영상 포맷이 왜 먼저인지 이해했다
- [ ] 대본 → 씬 스펙 → TTS → 렌더링의 흐름을 따라갈 수 있다
- [ ] 자동화의 경계선 — 사람이 판단해야 할 지점을 알고 있다

---

## STEP 1. 반복 가능한 영상 포맷 정하기

### 1-1. 포맷이 있어야 자동화가 붙습니다

영상 자동화에서 가장 흔한 실수는 "AI가 영상을 만들어주겠지"라고 기대하는 겁니다. 사실 AI는 영상 전체를 한 번에 만들지 못합니다. 대본은 쓸 수 있고, 음성은 만들 수 있고, 화면 렌더링도 가능합니다. 하지만 이것들이 하나로 이어지려면 **정해진 틀**이 필요합니다.

신문 기사를 생각해보세요. 기사에는 헤드라인, 리드, 본문, 인용문이라는 포맷이 있잖아요. 그래서 기자가 바뀌어도 기사가 나옵니다. 영상도 마찬가지입니다.

예를 들어 10분짜리 강의 영상이라면 이런 포맷이 가능합니다.

| 구간 | 시간 | 역할 |
|------|------|------|
| 프리훅 | 0:00~0:15 | 가장 인상적인 결과를 먼저 보여줍니다 |
| 셋업 | 0:15~1:00 | 왜 이 이야기를 하는지 설명합니다 |
| 본론 | 1:00~8:00 | 핵심 내용을 단계별로 풀어갑니다 |
| 클로징 | 8:00~10:00 | 한 줄 인사이트로 여운을 남깁니다 |

![영상 포맷 타임라인](/__content__/images/ch15-01.png)

이 포맷이 한 번 정해지면, 대본 작성을 AI에게 맡길 수 있습니다. "이 포맷에 맞춰서 써줘"라고 할 수 있으니까요. 포맷 없이 "유튜브 대본 써줘"라고 하면, 매번 다른 구조가 나옵니다. 그러면 이후 단계도 매번 다르게 처리해야 합니다. 자동화가 안 됩니다.

### 1-2. 씬 타입을 정해두세요

포맷을 정했으면, 영상 안에서 반복되는 화면 유형도 미리 정의해둡니다. 실제로 영상 파이프라인을 돌려본 경험에서 나온 씬 타입은 이런 것들입니다.

| 씬 타입 | 용도 | 예시 |
|---------|------|------|
| narration | 설명 장면 | 화자가 개념을 풀어줄 때 |
| stats | 숫자 강조 | "시장 규모 8조 원" 같은 임팩트 장면 |
| comparison | 비교 | A vs B를 나란히 보여줄 때 |
| screenshot | 화면 캡처 | 실제 도구 사용 장면 |
| code | 코드 보여주기 | 명령어나 설정 파일 |
| greeting | 인사 | 캐릭터가 등장하는 오프닝 |

이렇게 정해두면 대본을 쓸 때 "이 대사는 stats 타입이야"라고 지정할 수 있고, 렌더링할 때 씬 타입별로 화면 레이아웃이 자동으로 결정됩니다. 매번 편집자가 "이 장면은 어떤 화면으로 할까?" 고민할 필요가 없어집니다.

> **확인**: 영상 포맷(시간 구조)과 씬 타입(화면 유형)이 정리되어 있으면, 다음 단계로 넘어갈 준비가 된 겁니다.

## STEP 2. 대본, 장면, TTS, 렌더 연결하기

### 2-1. 대본 작성 — AI가 초안을 씁니다

포맷이 정해졌으니, AI에게 대본을 맡깁니다. OpenClaw에 대본 작성 스킬을 붙이면 이런 흐름이 가능합니다.

```
주제를 입력하면 →
로컬 문서 + 웹 리서치 + 이전 에피소드 톤을 참조해서 →
초안을 작성하고 →
퇴고까지 한 번에 돌아갑니다.
```

퇴고 단계에서 하는 일이 의외로 중요합니다.

- **TTS 발음 검수**: "AI"를 "에이아이"로, "39%"를 "삼십구퍼센트"로 바꿉니다. 음성 합성 엔진이 읽을 수 있는 형태로 만드는 겁니다.
- **학습 연속성 체크**: 질문자가 모르는 용어를 설명 없이 쓰진 않았는지 확인합니다.
- **이미지 소싱**: 대본에서 언급하는 화면이나 다이어그램을 미리 찾아둡니다.

대본이 완성되면 분량, 이미지 수, TTS 위반 건수까지 요약해서 보여줍니다.

### 2-2. 씬 스펙으로 변환 — 대본이 설계도가 됩니다

대본을 그냥 읽을 수는 있지만, 렌더링 엔진은 대본을 못 읽습니다. 대본을 **씬 스펙**(YAML 형식)으로 변환해야 합니다. 각 대사가 어떤 화면 타입으로 보일지, BGM은 어디에 깔릴지, 메타데이터까지 한 번에 정의됩니다.

```yaml
scenes:
  - id: "stats-1"
    type: "stats"
    speaker: "instructor"
    tts: "작년 에이아이 코딩 시장이 팔조 원을 넘었어요."
    display_text: "작년 AI 코딩 시장이 8조 원을 넘었어요."
    stat: "8조 원"
```

여기서 핵심은 `tts`와 `display_text`가 분리되어 있다는 겁니다. 음성은 한글 발음으로 쓰고, 화면에 보이는 자막은 원래 표기를 유지합니다. 이렇게 해야 나중에 자막을 뽑을 때 "에이아이"가 자동으로 "AI"로 복원됩니다.

![대본에서 씬 스펙으로 변환](/__content__/images/ch15-02.png)

### 2-3. TTS 생성 — 음성을 만듭니다

씬 스펙이 완성되면 TTS(Text-to-Speech)로 음성 파일을 만듭니다.

화자가 두 명이라면 각각 다른 TTS 서비스를 쓸 수 있습니다. 예를 들어 강의자는 고품질 서비스(ElevenLabs 등)를 쓰고, 질문자는 저렴한 서비스(Fish Audio 등)를 씁니다. YAML의 `speaker` 필드만 보고 자동으로 분기됩니다.

비용도 미리 확인할 수 있습니다. 실제로 API를 호출하지 않고 예상 비용만 계산하는 dry run 기능을 쓰면 됩니다.

```
예상 비용:
  강의자 (고품질 TTS): $0.3~1.0
  질문자 (경량 TTS):   $0.01~0.05
  합계: $0.3~1.0 수준
```

TTS 서비스와 요금제에 따라 다르지만, 10분짜리 에피소드 하나에 수백 원에서 천 원 이내가 현실적인 범위입니다. 생각보다 저렴하죠.

TTS 생성 후에는 **오디오 후처리**가 들어갑니다. 1.1배속으로 올리고, 앞뒤 무음 구간을 잘라내고, 화자별 말하기 속도를 균일하게 맞춥니다. 이 과정도 명령어 하나로 자동 처리됩니다.

### 2-4. 렌더링 — 영상으로 합칩니다

모든 재료가 준비되면 렌더링입니다. 타임라인을 빌드하고, 미리보기로 확인하고, 최종 MP4를 뽑습니다.

![영상 파이프라인 전체 흐름](/__content__/images/ch15-03.png)

전체 파이프라인을 정리하면 이렇습니다.

| 단계 | 하는 일 | 비용 |
|------|---------|------|
| 대본 작성 | AI에게 주제 입력 | 무료 (AI 구독 비용 별도) |
| 씬 스펙 | 대본 → YAML 변환 | 무료 |
| TTS | 음성 파일 생성 | $0.3~1.0/편 |
| 오디오 후처리 | 배속, 무음 제거, 속도 균일화 | 무료 |
| 타임라인 빌드 | YAML + 오디오 → JSON | 무료 |
| 렌더링 | 최종 MP4 출력 | 무료 (로컬 컴퓨터 리소스) |
| 자막 | SRT/VTT 파일 생성 | 무료 |

10분짜리 영상 하나를 처음부터 끝까지 만드는 데 드는 실비용은 대략 수백 원에서 천 원 수준입니다. 전통적으로 외주 편집비가 10만 원 이상인 것과 비교하면 상당히 큰 차이죠.

> **확인**: 대본 → 씬 스펙 → TTS → 렌더링의 흐름이 이어지는 그림이 머릿속에 그려지면, 이 단계는 완료입니다.

## STEP 3. 어디까지 자동화하고 어디서 멈출까

### 3-1. 자동화해도 되는 단계

파이프라인의 대부분은 자동화가 가능합니다. 대본 초안, TTS 발음 변환, 오디오 후처리, 타임라인 빌드, 자막 생성 — 이것들은 규칙이 명확하고, 매번 같은 패턴으로 돌아갑니다.

수정도 빠릅니다. 캡컷이나 프리미어에서 대사 한 줄을 수정하려면 클립을 찾아서 교체하고, 앞뒤 타이밍을 재조정하고, 자막도 따로 고쳐야 합니다. 30분에서 1시간은 걸립니다. 파이프라인 방식에서는 YAML에서 한 줄 고치고 TTS 재생성하고 다시 렌더링하면 끝입니다. 5분에서 10분이면 됩니다.

### 3-2. 사람이 판단해야 하는 단계

그런데 모든 것을 자동화할 수는 없습니다. 아래 세 가지는 사람의 판단이 끝까지 남습니다.

**첫째, 대본의 방향 결정입니다.**

AI가 대본 초안을 쓸 수 있지만, "이번 영상에서 뭘 말할 것인가"는 사람이 정해야 합니다. 어떤 인사이트를 전달할지, 어떤 사례를 쓸지, 어떤 순서로 풀지 — 이건 도메인 지식과 판단의 영역입니다.

**둘째, 렌더링 전 미리보기 검수입니다.**

타임라인 스튜디오에서 프레임 단위로 확인하는 과정을 건너뛰면 안 됩니다. 체크할 것들이 있습니다.

- 오디오가 끊기는 구간은 없는지
- 이미지가 제대로 로딩되는지
- BGM 페이드인/아웃이 자연스러운지
- 씬 전환 타이밍이 어색하지 않은지

이건 기계가 판단하기 어렵습니다. "자연스럽다"는 감각이 필요하니까요.

![TTS와 렌더링 과정](/__content__/images/ch15-04.png)

**셋째, 썸네일과 업로드 판단입니다.**

썸네일은 영상의 클릭률을 결정합니다. AI가 후보를 만들어줄 수 있지만, 최종 선택은 사람이 해야 합니다. 업로드 타이밍, 제목의 뉘앙스, 설명란의 문구도 마찬가지입니다. 이건 시청자와의 감각적 접점이고, 채널의 톤을 결정하는 부분이니까요.

### 3-3. 자동화의 경계선을 그리세요

정리하면 이렇습니다.

| 단계 | 자동화 가능? | 판단 |
|------|-------------|------|
| 대본 초안 | O | AI가 씁니다 |
| 대본 방향/기획 | **X** | 사람이 정합니다 |
| 씬 스펙 변환 | O | 규칙 기반 변환 |
| TTS 생성 | O | 명령어 실행 |
| 오디오 후처리 | O | 자동 파이프라인 |
| 타임라인 빌드 | O | 자동 빌드 |
| 미리보기 검수 | **X** | 사람이 확인합니다 |
| 렌더링 | O | 명령어 실행 |
| 자막 생성 | O | 자동 변환 |
| 썸네일 선택 | **X** | 사람이 고릅니다 |
| 업로드/제목/설명 | **X** | 사람이 결정합니다 |

11장에서 다뤘던 이야기가 여기서도 똑같이 적용됩니다. 자동화는 한 번에 완성되지 않고, 사람이 판단해야 할 단계는 끝까지 남습니다. 유튜브 자동화도 예외가 아닙니다.

> **확인**: "이 단계는 자동화하고, 이 단계는 내가 직접 봐야 해"라는 경계선이 그려졌다면, 이 장의 목표를 달성한 겁니다.

## 여기서 막혔나요?

**Q. TTS 음성이 로봇 같아서 쓸 수 없을 것 같습니다.**

상황: TTS로 만든 음성이 부자연스러워서 실제 영상에 쓰기 어렵다고 느끼는 경우입니다.

원인:
- TTS 서비스에 따라 한국어 품질 차이가 큽니다
- 텍스트가 발음용으로 변환되지 않았을 수 있습니다 (영문/숫자 그대로 입력)

해결:
1. ElevenLabs, 수퍼톤(Supertone) 같은 고품질 서비스를 먼저 테스트해보세요. 무료 티어로도 확인 가능합니다.
2. 대본을 쓸 때 "AI"를 "에이아이"로, 숫자를 한글로 바꾸는 발음 변환 과정을 넣으세요. 이것만으로도 자연스러움이 크게 올라갑니다.
3. 오디오 후처리(배속 조절, 무음 트리밍)를 적용하면 더 자연스러워집니다.

**Q. Remotion 같은 도구를 설치하고 세팅하는 게 너무 어려워 보입니다.**

상황: 파이프라인 자체를 구축하는 진입장벽이 높다고 느끼는 경우입니다.

원인:
- Remotion은 React 기반이라 개발 환경 세팅이 필요합니다
- 처음부터 전체 파이프라인을 갖추려 하면 부담이 됩니다

해결:
1. 처음부터 풀 파이프라인을 만들 필요 없습니다. 대본 작성 + TTS만 자동화해도 충분히 가치가 있습니다.
2. 렌더링은 캡컷이나 프리미어로 하되, 대본과 음성만 AI가 만들게 하는 것도 좋은 시작입니다.
3. 파이프라인은 나중에 영상 제작이 반복되면서 자연스럽게 확장하면 됩니다.

**Q. 영상 퀄리티가 전문 편집자가 만든 것보다 떨어지지 않나요?**

상황: 자동화로 만든 영상이 직접 편집한 영상보다 품질이 낮을 거라 걱정하는 경우입니다.

원인:
- 자동화 파이프라인은 "반복 가능한 포맷"에 최적화되어 있습니다
- 매번 다른 연출이 필요한 영상에는 적합하지 않습니다

해결:
1. 이 방식은 강의형, 해설형, 뉴스 요약형 영상에 적합합니다. 브이로그나 시네마틱 영상에는 맞지 않습니다.
2. 포맷이 고정된 영상이라면 오히려 일관된 품질을 유지할 수 있습니다. 사람이 매번 편집하면 컨디션에 따라 품질이 들쭉날쭉하거든요.
3. 핵심은 "프로 편집자를 대체하는 것"이 아니라 "혼자서 꾸준히 영상을 내는 것"입니다. 주 1회 업로드를 혼자 지속하려면 파이프라인이 필수입니다.

**Q. 대본에서 씬 스펙으로 변환하는 과정이 잘 이해되지 않습니다.**

상황: 글로 쓴 대본이 어떻게 YAML이라는 설계도로 바뀌는지 감이 안 오는 경우입니다.

원인:
- YAML 자체가 낯설 수 있습니다
- 대본의 어느 부분이 어떤 씬 타입에 대응하는지 모를 수 있습니다

해결:
1. YAML은 들여쓰기로 구조를 표현하는 텍스트 파일입니다. JSON보다 사람이 읽기 쉬운 형식이에요.
2. 변환 규칙은 단순합니다. "숫자를 강조하는 대사 → stats 타입", "화면을 보여주는 대사 → screenshot 타입" 이런 식입니다.
3. AI에게 "이 대본을 씬 스펙으로 변환해줘"라고 하면, 포맷만 정해져 있으면 알아서 변환합니다. 직접 YAML을 쓸 필요는 없습니다.

---

## 한 줄 정리

유튜브 자동화의 핵심은 영상 전체를 AI에게 맡기는 것이 아니라, 반복 가능한 포맷을 정하고 파이프라인을 연결하되, 방향 결정과 최종 검수는 사람이 하는 것입니다.

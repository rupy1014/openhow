# 02장 개요 — AI 캐릭터 채팅 — 30분 만에 서비스 만들기

## 장의 역할
"진짜 서비스"를 30분 만에 만들어보며, 화면·서버·데이터·API의 역할을 체험한다. LLM API와 시스템 프롬프트로 캐릭터에 성격을 입히는 첫 "아하!" 경험.

## 독자가 읽고 남겨야 할 변화
- 동작하는 채팅 서비스가 로컬에서 돌아가는 상태
- "시스템 프롬프트로 성격이 바뀌네!"라는 체험
- 서비스의 네 가지 역할(화면/서버/데이터/API)을 감각적으로 이해

## 핵심 메시지
- 완성본을 먼저 보여주고, "이걸 만들 거야"
- 이미지를 주면 화면이 나온다 — 코덱스의 힘
- LLM API = 대화 능력. 시스템 프롬프트 = 캐릭터 성격
- MVP는 "동작하는 최소 단위"

## 소단원별 전개
### 02.1 완성된 화면부터 보기
완성된 채팅 화면 스크린샷. "이걸 30분 만에 만들 거야."

### 02.2 [실습] 이미지 주고 화면 만들기
레퍼런스 이미지(카카오톡 스타일 채팅 UI) → 코덱스에게 "이렇게 만들어줘" → 결과 확인.

### 02.3 화면·서버·데이터·API — 서비스의 네 가지 역할
방금 만든 서비스를 분해해서 설명. 비유: 식당의 홀(화면), 주방(서버), 냉장고(데이터), 배달앱(API).

### 02.4 [실습] 캐릭터에 성격 입히기 — LLM API와 시스템 프롬프트
OpenRouter API 키 발급 → 시스템 프롬프트로 "츤데레 고양이" 성격 설정 → 대화해보기. "같은 모델인데 성격이 바뀌네!"

### 02.5 MVP는 어디까지인가
지금 만든 것이 MVP. 뭘 빼도 되고 뭘 넣으면 안 되는지. "더 하고 싶은 마음을 참는 게 핵심."

## 꼭 넣을 장면 / 사례 / 실습
- 완성 화면 스크린샷 (결과부터)
- 이미지 → 화면 생성 실습
- 시스템 프롬프트 바꿔서 성격 변화 체험
- "더 넣고 싶은데..." 하는 순간 → MVP 경계

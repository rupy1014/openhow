# 06장 내 서비스에 진짜 링크가 생긴다 — 배포

> "링크를 보내는 순간, 여러분의 프로젝트는 '작품'이 됩니다."

---

자, 이제 여러분은 나만의 캐릭터와 대화하는 멋진 서비스를 하나 가지게 되었습니다. PRD도 다듬고, 피드백 루프도 돌려봤죠. 뿌듯하시죠?

그런데 솔직히 말씀드릴게요. 이 서비스가 여러분의 컴퓨터 안에서만 돌아가는 한, 아직은 '일기장'에 불과합니다. 진짜 서비스가 되려면, 전 세계 누구나 접속할 수 있는 **'주소'**가 있어야 합니다. `https://내-캐릭터-채팅.vercel.app` 같은 진짜 인터넷 링크 말이죠.

이 장에서는 여러분이 만든 서비스를 세상 밖으로 꺼내는 법을 배웁니다. 카톡으로 링크 하나만 보내면 부모님도, 친구도, 어디서든 여러분의 캐릭터와 대화할 수 있게 됩니다. 드디어 여러분의 작품이 세상 밖으로 나갈 시간입니다!

---

## 06.1 [실습] Vercel로 배포하기 — 내 서비스에 진짜 링크가 생긴다

### Vercel(무료 웹 배포 서비스) = GitHub 코드를 웹사이트로 바꿔주는 마법

우리가 만든 캐릭터 채팅 서비스를 친구에게 보여준다고 상상해 보세요. "내 컴퓨터에 있는 파일을 메일로 보낼 테니까 한번 열어봐"라고 하면 친구가 좋아할까요? 아마 "귀찮게 뭘 그런 걸 보내..."라며 읽지 않을 가능성이 큽니다.

하지만 카톡으로 `https://my-character-chat.vercel.app` 같은 짧은 링크 하나만 딱 보낸다면 어떨까요? 친구는 그냥 클릭만 하면 됩니다. 스마트폰에서도, 태블릿에서도 여러분의 캐릭터와 바로 대화를 나눌 수 있죠.

이게 바로 **'배포(Deploy)'**의 힘입니다. 내 컴퓨터라는 좁은 방 안에서만 돌아가던 프로그램을 전 세계 사람들이 접속할 수 있는 공용 공간으로 끌어올리는 작업이죠.

**Vercel(버셀)**은 GitHub에 올라가 있는 코드를 가져와서 `https://내-프로젝트.vercel.app`이라는 주소로 자동 변환해주는 서비스입니다. 무엇보다 개인용으로는 **평생 무료**로 쓸 수 있다는 점이 우리 같은 입문자들에게는 가장 큰 매력입니다.

### 배포 3단계 — 터미널에서 바로

원래 배포는 꽤 까다로운 작업입니다. 터미널에 복잡한 명령어를 치고, 설정을 맞추고, 에러가 나면 구글을 뒤져야 하죠. 하지만 우리에게는 코덱스가 있습니다.

#### STEP 1. Vercel 가입 (GitHub 계정으로)

01 브라우저를 열고 [vercel.com](https://vercel.com/signup)에 접속하세요.

02 **'Continue with GitHub'** 버튼을 누르세요.

03 깃허브 로그인 창이 뜨면 승인 버튼을 누릅니다.

이게 끝입니다. 이제 Vercel과 GitHub은 서로 '아는 사이'가 되었습니다. 여러분이 GitHub에 코드를 넣으면, Vercel이 슬쩍 보고 "오, 새 코드가 들어왔네? 내가 웹사이트로 만들어줄게!"라고 반응할 준비를 마친 겁니다.

#### STEP 2. 코덱스에게 "Vercel로 배포해줘"

**"배포의 전 과정도 코덱스에게 통째로 맡기면 됩니다."**

01 VS Code를 열고 터미널에서 `codex`를 실행하세요.

02 코덱스에게 다음과 같이 지시하세요.
> "지금 내가 만든 캐릭터 채팅 서비스를 Vercel로 배포하고 싶어. Vercel CLI를 설치하고 로그인하는 것부터 실제 배포까지 네가 다 알아서 진행해줘."

03 코덱스가 알아서 'Vercel CLI'라는 도구를 설치하기 시작할 겁니다. 중간에 "이걸 설치할까요?"라고 물어보면 "Yes"를 선택하세요.

04 자동으로 열리는 브라우저 창에서 **'Verify'** 버튼만 누르면 로그인 완료입니다.

> **🙋 코덱스가 질문을 하는데 뭐라고 대답해야 하죠?**
>
> 보통 이런 순서로 물어볼 거예요.
> 1. Set up and deploy? → **y**
> 2. Which scope? → **Enter (기본값)**
> 3. Link to existing project? → **n (새로 만들기)**
> 4. Project name? → **Enter (기본값 쓰거나 이름 짓기)**
> 5. Code directory? → **Enter (현재 폴더)**
>
> 잘 모르겠다면 코덱스에게 "질문이 이렇게 나오는데 뭐라고 대답해?"라고 물어보세요. 조수가 다 가르쳐줄 겁니다.

<!-- IMG: VS Code 터미널에서 vercel 명령어가 실행되며 배포가 진행되는 과정 -->

#### STEP 3. URL 확인 → 스마트폰으로 접속

배포가 끝나면 터미널에 파란색 글씨로 **'Production'**이라는 글자와 함께 링크 하나가 뜰 겁니다.

01 터미널에 뜬 `https://...vercel.app` 링크를 Ctrl(맥은 Cmd)을 누른 채 클릭해 보세요.

02 브라우저에 여러분이 만든 서비스가 뜨나요? 축하합니다! 이제 이건 '진짜 웹사이트'입니다.

03 스마트폰을 꺼내서 브라우저 주소창에 그 링크를 직접 쳐보세요.

04 내 휴대폰에서 캐릭터가 말을 거는 걸 보면, 그 짜릿함은 이루 말할 수 없을 겁니다.

### 환경변수(.env)를 따로 넣는 이유

여기서 아주 중요한 포인트가 하나 있습니다. 우리가 04장에서 API 키를 `.env`라는 파일에 넣었던 거 기억하시죠? 그런데 **.env 파일은 절대 GitHub에 올리지 않는 게 철칙**입니다. 비밀번호를 전단지에 인쇄해서 동네방네 붙이고 다니면 안 되잖아요?

자, 여기서 문제가 생깁니다.
1. GitHub에는 API 키가 없습니다. (비밀이니까요)
2. Vercel은 GitHub에서 코드를 가져옵니다.
3. 결과적으로 Vercel도 API 키가 뭔지 모릅니다!

그래서 배포된 웹사이트에서 대화를 시도하면 에러가 날 겁니다. 이걸 해결하려면 **Vercel 대시보드에 직접 비밀번호를 알려줘야** 합니다.

**"환경변수(Environment Variables) 설정은 Vercel에게 열쇠를 따로 건네주는 과정입니다."**

01 Vercel 사이트(vercel.com)에서 방금 만든 프로젝트를 클릭합니다.

02 상단 메뉴 중 **'Settings'** → 왼쪽 메뉴에서 **'Environment Variables'**를 찾으세요.

03 **Key** 칸에 `OPENAI_API_KEY`를, **Value** 칸에 실제 API 키를 붙여넣으세요.

04 **'Add'** 버튼을 누르고, "환경변수 설정했으니 다시 배포해줘"라고 코덱스에게 시키면 됩니다.

## 06.2 링크를 보내고 반응을 받기

### 가족, 친구, 단톡방에 링크 공유

자, 이제 떨리는 마음으로 생성된 주소를 복사하셨나요? 이 주소는 단순한 인터넷 글자가 아닙니다. 전 세계 어디서든, 누구든 여러분의 서비스를 만날 수 있는 **'초대장'이자 '문'**입니다.

처음에는 이 링크를 누군가에게 보내는 게 참 부끄럽고 망설여지실 거예요. "디자인이 너무 투박한데...", "버그가 나면 어떡하지?" 하는 생각이 꼬리에 꼬리를 물죠. 하지만 이 단계에서 가장 큰 실수는 완벽하게 만들어서 보여주려고 하는 겁니다. **일단 보내세요. 거기서부터 진짜 공부가 시작되거든요.**

01 Vercel 대시보드에서 `Visit` 버튼을 눌러 내 서비스로 접속합니다.

02 브라우저 주소창의 URL을 복사합니다.

03 카카오톡이나 메시지 창을 열고 링크를 붙여넣으세요.

04 **"내가 만든 AI 캐릭터랑 대화해보는 앱인데, 1분만 써보고 솔직하게 말해줘."**라고 덧붙여 보세요.

여기서 핵심은 **"솔직하게"**라는 단어입니다. 그냥 "어때?"라고 물으면 백이면 백 "우와, 신기하다!"라는 영혼 없는 칭찬만 돌아옵니다.

<!-- IMG: 스마트폰 카카오톡 화면에 배포된 서비스 링크를 공유하고 친구와 대화하는 장면 -->

### 예상치 못한 반응들

링크를 공유하고 나면 여러분의 예상과는 전혀 다른 반응들이 쏟아질 겁니다. 제가 처음 서비스를 배포했을 때도 그랬어요. 저는 "AI가 얼마나 똑똑한지" 자랑하고 싶었는데, 친구들은 "글씨가 너무 작아서 안 보여"라거나 "배경색이 눈 아파" 같은 말을 먼저 하더라고요.

피드백은 크게 네 가지 종류로 나뉩니다.

| 반응 종류 | 실제 목소리 예시 | 우리가 해야 할 일 |
| :--- | :--- | :--- |
| **응원** | "와, 직접 만든 거야? 대단하다!" | 기분 좋게 에너지를 충전합니다. |
| **버그 제보** | "버튼을 눌렀는데 반응이 없어." | 최우선으로 고쳐야 할 '숙제'입니다. |
| **성능 피드백** | "대답이 너무 늦게 와.", "입력창이 어디 있는지 모르겠어." | 서비스의 '품격'을 높이는 힌트입니다. |
| **기능 제안** | "대화 내용을 저장할 순 없어?", "사진도 보내고 싶어." | '아이디어 창고'에 넣어둡니다. |

### 자동 재배포: 코드 수정 → git push → Vercel이 알아서 새 버전 배포

자, 친구가 "글씨가 너무 작아"라고 말했습니다. 이제 고쳐야겠죠? 여기서 Vercel의 진짜 매력이 드러납니다.

코드를 수정하고 `git push`만 하면, Vercel이 알아서 새 버전을 빌드하고 배포합니다. 1~2분이면 전 세계에 배포된 여러분의 서비스가 **최신 버전으로 자동 업데이트**됩니다. 친구에게 "방금 고쳤어, 다시 들어가 봐!"라고 말할 수 있는 거죠.

```bash
git add .
git commit -m "디자인 수정 및 글씨 크기 확대"
git push
```

이 세 줄이면 세상이 바뀝니다. 이런 속도감을 한 번 맛보고 나면 코딩이 마치 실시간 게임처럼 느껴질 겁니다.

## 06.3 [실습] 반응을 반영해서 다시 만들기 — 바이브코딩 실전 루프

### 실사용자 피드백을 의도로 바꾸기

링크를 보내고 나면, 아마 핸드폰 진동이 멈추지 않을 겁니다. "우와, 이거 네가 만든 거야?"라는 칭찬부터 "야, 이거 글씨가 너무 작아서 안 보여" 같은 냉정한 평가까지 쏟아지겠죠.

**"사실, 이때부터가 진짜 바이브코딩의 시작입니다."**

처음에 만든 건 그냥 '가설'일 뿐입니다. 진짜 사용자가 내 앱을 만지는 순간, 우리가 미처 생각하지 못했던 수많은 빈틈이 보이기 시작하거든요.

피드백을 들을 때 가장 중요한 건, 그들의 말을 그대로 받아적는 게 아니라 **PRD(기획서)의 언어**로 번역하는 겁니다.

- **피드백**: "모바일에서 글씨가 너무 작아."
  → **PRD에 반영**: "모바일 반응형 필수" 추가

- **피드백**: "캐릭터 목록이 있으면 좋겠다."
  → **PRD에 반영**: 기능 추가 (단, "안 만들 것"도 다시 점검)

**"기획자는 사용자의 투덜거림에서 보석 같은 요구사항을 캐내는 사람입니다."**

---

### [실습] PRD 수정 → 코덱스에게 다시 시키기 → 재배포

#### 1단계: PRD.md 파일 업데이트하기

01 VS Code에서 프로젝트 폴더에 있는 `PRD.md` 파일을 엽니다.

02 피드백받은 내용을 '핵심 기능'이나 '사용자 흐름'에 추가합니다.

03 파일을 저장합니다.

**수정된 핵심 기능 (예시)**
1. 캐릭터 선택 카드 UI 추가 (메인 화면)
2. 모바일 반응형 디자인 강화 (큰 폰트, 큰 버튼)
3. 대화창 상단에 선택한 캐릭터 이름 표시

#### 2단계: 코덱스에게 다시 시키기

01 터미널에서 `codex`를 실행합니다.

02 코덱스에게 업데이트된 PRD를 보여주며 말합니다.
> "방금 PRD를 수정했어. 사용자 피드백을 반영해서 캐릭터 선택 기능을 추가하고 모바일에서 보기 편하게 고치고 싶어. 수정한 PRD 내용을 바탕으로 전체 코드를 다시 작성해줘."

**확인**: 코덱스가 수정을 마치면 `npm run dev`로 내 컴퓨터에서 먼저 확인해 보세요. 친구가 말했던 불편함이 사라졌나요?

#### 3단계: git push만 하면 Vercel이 자동 재배포

05장에서 배운 피드백 루프를 실제 사용자 반응으로 돌리는 겁니다.

01 `git add .`

02 `git commit -m "캐릭터 선택 기능 추가 및 모바일 UI 개선"`

03 `git push`

**"이게 끝입니다. 정말로요."** 5분 만에 반영됩니다.

이제 1~2분만 기다려 보세요. Vercel이 알아서 최신 버전으로 바꿔버립니다. 친구에게 "지금 다시 들어가 봐!"라고 말해 보세요.

### MVP 고도화의 감각

바이브코딩의 핵심은 완벽한 앱을 한 번에 만드는 게 아닙니다. **'만들고 → 보여주고 → 고치는' 루프를 얼마나 빠르게 돌리느냐**가 실력입니다.

**"한 번에 딱 한 가지 피드백만 반영하세요."**

한 번에 다 고치려고 하면 지쳐서 포기하게 됩니다. 글씨 크기가 작다는 말이 제일 많았나요? 그럼 그것만 고쳐서 바로 `git push` 하세요. 캐릭터 목록이 필요하다는 말이 다음인가요? 그럼 다음 루프에서 그것만 고치세요.

| 단계 | 행동 | 소요 시간 |
|---|---|---|
| 1회차 | 핵심 기능 구현 (MVP) | 30분 |
| 2회차 | 버그 수정 (글씨 깨짐 등) | 10분 |
| 3회차 | 디자인 개선 (색상, 배치) | 15분 |
| 4회차 | 편의 기능 추가 (캐릭터 선택) | 20분 |
| 5회차 | 문구 다듬기 (말투 수정) | 10분 |

이 루프를 한 번 돌 때마다 여러분의 서비스는 '진짜 쓸모'에 가까워집니다. 떡집 사장님의 주문 정리 앱도 처음엔 그냥 텍스트 박스 하나였지만, 이런 루프를 거치며 "주소 자동 완성", "주문 내역 엑셀 다운로드" 같은 강력한 기능이 붙게 되는 거죠.

### 결제가 필요하다면 — 부록 A 참고

이렇게 서비스를 다듬다 보면, 주변에서 "이거 돈 내고 쓰고 싶은데?"라는 반응이 나올 때가 있습니다. 혹은 "이 기능을 쓰려면 비용이 드는데, 사용자한테 돈을 좀 받아야 할 것 같아"라는 생각이 들 수도 있죠.

**"사람들이 돈 내고 쓰겠다는 확인이 되면, 그때 결제를 붙이면 됩니다."**

지금 당장은 결제 버튼을 넣기보다, "이 서비스가 유료라면 얼마를 내실 용의가 있나요?"라고 물어보는 것만으로도 충분합니다. 그 가치가 증명되었을 때 **부록 A (PG 연동 실전)**를 펴보세요. 테스트 결제까지 실습할 수 있습니다.

## 여기서 막혔나요?

**Q. 버셀 배포 중에 "Build Failed"라고 빨간 글씨가 떠요.**

**A.** 보통 두 가지 이유입니다. 첫째, 코덱스가 코드를 짜면서 오타를 냈거나 필요한 파일을 빠뜨린 경우입니다. 터미널에 뜬 에러 메시지 전체를 복사해서 코덱스에게 "이것 때문에 배포가 안 된대. 고쳐줘"라고 하세요. 둘째, `package.json` 파일에 설정이 빠졌을 때입니다. "Vercel 배포용 설정 파일을 다시 확인해줘"라고 시키면 해결해 줍니다.

**Q. 링크에 들어갔더니 화면은 뜨는데 AI가 답장을 안 해요.**

**A.** 99% 환경변수 문제입니다. Vercel 대시보드에서 환경변수 설정을 제대로 했는지, 그리고 `OPENAI_API_KEY`라는 이름이 코드 안에서 쓰는 이름과 똑같은지 확인하세요. 대소문자 하나만 틀려도 AI는 길을 잃습니다.

**Q. `git push`를 했는데 Vercel 사이트에 변화가 없어요.**

**A.** Vercel 대시보드의 **'Deployments'** 탭을 클릭해서 새로운 빌드가 진행 중인지 확인해 보세요. 만약 아무런 기록이 없다면, VS Code에서 수정한 내용을 저장했는지 먼저 확인하고 다시 `git add . → git commit → git push`를 입력해 보세요.

**Q. 피드백을 반영했더니 전보다 더 이상해졌어요.**

**A.** 걱정하지 마세요! 우리에게는 **Git이라는 타임머신**이 있잖아요. 코덱스에게 "방금 수정한 게 마음에 안 들어. 이전 버전 코드로 다시 돌려줘"라고 하면 됩니다. 실패를 두려워하지 말고 마음껏 수정해 보세요.

**Q. 배포 링크 주소를 제가 원하는 걸로 바꿀 수 있나요?**

**A.** 네! Vercel 설정(Settings)의 **'Domains'** 메뉴에서 바꿀 수 있습니다. `my-sweet-chat` 같은 예쁜 이름을 선점해 보세요.

## 한 줄 정리

링크 공유는 완성의 끝이 아니라 **진짜 쓸모 있는 서비스를 만드는 대화의 시작**이며, `git push` 한 줄로 세상을 즉시 바꾸는 경험이 바로 바이브코딩의 본질입니다.

자, 이제 여러분의 서비스는 살아있는 생명체처럼 사용자의 반응을 먹고 쑥쑥 자라기 시작했습니다. 기획하고, 만들고, 배포하고, 피드백 받고, 다시 만드는 전체 사이클을 경험하신 겁니다. Part 1은 여기까지입니다. 다음 Part에서는 이 루프를 AI가 알아서 돌려주는 '스킬과 에이전트'의 세계로 넘어가 보겠습니다. 기대하셔도 좋습니다!

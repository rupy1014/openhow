# 09장 오픈클로 설치하고 첫 대화하기

> "여러분이 잠든 사이에도, 오픈클로는 쉬지 않고 일합니다."

---

자, 이제 진짜 '자동화의 심장'을 만날 시간입니다. 

지난 장에서 우리는 자동화의 설계 도면을 그리는 법을 배웠습니다. '체인'을 엮고 '루프'를 돌리며, 우리가 원하는 결과물을 만들어내는 마법 같은 패턴들을 살펴봤죠. 그런데 여러분, 냉정하게 한번 생각해봅시다. 지금 우리가 만든 이 멋진 뉴스봇, 누가 실행시키나요? 

네, 바로 여러분입니다. 여러분이 직접 노트북을 열고, 터미널을 켜고, "뉴스 요약해줘"라고 타이핑해야 돌아갑니다. 이건 반쪽짜리 자동화입니다. 진정한 자동화라면 내가 비행기를 타고 있거나, 푹 자고 있거나, 심지어 술 한잔하고 있을 때도 알아서 척척 돌아가야 하거든요.

그래서 오늘 우리는 **'오픈클로(OpenClaw)'**라는 녀석을 우리 팀에 정식으로 채용할 겁니다. 코덱스가 여러분 옆에서 함께 일하는 '천재 컨설턴트'라면, 오픈클로는 회사에 24시간 상주하며 모든 일을 처리하는 '만능 운영팀장'입니다. 

---

## 09.1 코덱스와 뭐가 다른가 — 24시간 돌아가는 로컬 에이전트

"이미 코덱스가 있는데 왜 오픈클로가 또 필요한가요?"

스터디를 운영하다 보면 가장 많이 듣는 질문 중 하나입니다. 결론부터 말씀드리면, **둘은 사는 곳도, 일하는 방식도 완전히 다릅니다.**

### 코덱스 vs 오픈클로: 비서와 직원의 차이

코덱스(Codex)는 여러분의 노트북 안에 사는 비서입니다. 여러분이 노트북 뚜껑을 닫으면 비서도 퇴근합니다. 반면 오픈클로(OpenClaw)는 별도의 '서버'나 '미니 PC'에 설치해서 24시간 내내 켜두는 직원입니다. 

이해를 돕기 위해 표로 한번 정리해볼까요?

| 비교 항목 | 코덱스 (Codex) | 오픈클로 (OpenClaw) |
| :--- | :--- | :--- |
| **주된 거처** | 내 노트북 (MacBook, Gram 등) | 맥미니, 미니 PC, 클라우드 서버 |
| **작동 조건** | 노트북 뚜껑이 열려 있어야 함 | 365일 24시간 언제나 |
| **실행 방식** | 내가 직접 명령어를 칠 때 | 정해진 시간(Cron)에 스스로 실행 |
| **주요 역할** | 코드 짜기, 파일 수정, 기획하기 | 모니터링, 자동 보고, 24시간 대응 |

**"코덱스로 만들고, 오픈클로로 운영한다."** 

이것만 기억하시면 됩니다. 노트북에서 코덱스와 함께 자동화 파이프라인을 뚝딱뚝딱 만들고 다듬습니다. "오, 이제 잘 돌아가네?" 싶으면 그 결과물을 오픈클로에게 넘겨주는 거죠. 그러면 오픈클로는 여러분이 신경 쓰지 않아도 매일 아침 뉴스를 긁어오고, 블로그를 발행하고, 텔레그램으로 보고서를 보냅니다.

### 권한이 크니까 격리가 필요하다

오픈클로는 코덱스보다 훨씬 힘이 셉니다. 여러분 대신 파일을 읽고 쓰고, 외부 인터넷을 돌아다니며 정보를 가져오고, 심지어 터미널 명령어를 직접 내리기도 하죠. 

그런데 힘이 세다는 건 그만큼 위험할 수도 있다는 뜻입니다. 만약 오픈클로가 실수로 여러분의 중요한 개인 사진 폴더를 지워버리거나, 엉뚱한 설정을 건드리면 어떻게 할까요? 그래서 우리는 오픈클로에게 **'전용 놀이터(워크스페이스)'**를 만들어줘야 합니다.

**"워크스페이스 = 오픈클로의 활동 구역"**입니다. 

오픈클로는 우리가 지정해준 폴더 밖으로는 절대로 나갈 수 없습니다. 담장 밖의 파일은 건드릴 수도 없죠. 또한 '위험 명령 허용 목록'이라는 규칙을 정해서, 아무리 똑똑한 AI라도 함부로 내 컴퓨터의 시스템 설정을 바꾸지 못하게 꽉 묶어둘 겁니다. 안심하셔도 됩니다. 저도 제 소중한 맥미니에 오픈클로를 돌리고 있지만, 단 한 번도 사고가 난 적이 없거든요.

### 지갑을 지켜주는 효자, 코덱스 OAuth 연동

솔직히 말씀드리면, AI를 24시간 돌릴 때 가장 걱정되는 게 뭘까요? 맞습니다. 바로 **돈(API 비용)**입니다. 

보통 AI 에이전트를 하나 만들어서 밖에서 돌리려면 매달 수십 달러의 구독료를 내거나, 쓰는 만큼 돈이 나가는 API 키를 등록해야 합니다. 하지만 오픈클로는 다릅니다. 우리에게는 이미 **코덱스(Codex)**라는 든든한 아군이 있잖아요?

오픈클로에는 '코덱스 로그인(OAuth 연동)' 기능이 있습니다. 오픈클로 설정창에서 여러분의 코덱스 계정으로 로그인만 하면, 추가 비용 없이 코덱스의 지능을 그대로 빌려 쓸 수 있습니다. 

**"이미 낸 구독료, 200% 뽕을 뽑는 비결입니다."**

여러분이 잠든 사이 오픈클로가 수백 번 뉴스를 요약해도, 코덱스 구독 범위 안이라면 추가 과금은 0원입니다. 지갑은 가볍게, 자동화는 강력하게 만드는 오픈클로만의 필살기죠.

### 몸은 바뀌어도 머리는 그대로: 설정의 재사용

우리가 Part 2에서 땀 흘려 만들었던 것들 기억하시나요? `.agent/skills/` 폴더에 넣었던 '뉴스 요약 지침서', `.agent/agents/`에 저장한 '까칠한 편집장 페르소나', 그리고 `AGENTS.md`에 적어둔 우리만의 업무 규칙까지... 

오픈클로는 똑똑하게도 이 폴더들을 그대로 읽어 들입니다. 새로 코드를 짤 필요가 전혀 없어요. 코덱스에서 썼던 그 폴더를 오픈클로의 작업 공간(워크스페이스)에 복사해서 붙여넣기만 하면 끝입니다.

```text
```
# 오픈클로가 읽어가는 마법의 폴더 구조

**01 소상공인 사장님의 '카톡 비서'**
고객에게 카톡이 오면, 오픈클로가 내용을 읽고 1초 만에 답장합니다. 사장님이 운전 중이거나 요리 중일 때도 예약 문의에 친절하게 응대할 수 있죠.

**02 마케터의 '뉴스 클리핑 봇'**

운영 중인 서비스에 에러가 나지는 않는지, 서버 상태는 괜찮은지 오픈클로가 5분마다 체크합니다. 문제가 생기면 즉시 알람을 보내주니, 밤에 다리 뻗고 편하게 잘 수 있습니다.

자, 이제 오픈클로가 어떤 녀석인지 감이 좀 오시나요? 백문이 불여일견입니다. 말로만 들으면 복잡해 보여도 직접 내 컴퓨터에 깔아보면 "에이, 별거 아니네!" 하실 거예요. 자, 그럼 본격적으로 우리만의 24시간 조수를 채용하러 가볼까요? 다음 섹션에서 오픈클로 설치를 시작해봅시다!


## 09.2 [실습] 오픈클로 설치하기 (macOS / Windows)

> "설치가 끝나면 여러분의 컴퓨터에는 이제 퇴근하지 않는 직원이 앉아 있게 됩니다."

자, 이제 진짜 '채용'을 시작할 시간입니다. 오픈클로(OpenClaw)라는 직원을 우리 컴퓨터에 모셔오는 과정이죠.

솔직히 말씀드리면, 이 과정이 누군가에게는 이 책에서 가장 큰 고비일 수도 있습니다. 터미널이 익숙하지 않은 분들은 검은 화면에 영어 몇 줄만 떠도 머릿속이 하얘지곤 하거든요. 하지만 걱정 마세요. 제가 옆에서 하나하나 짚어드릴 테니까요. **"복사하고 붙여넣기만 하면 끝납니다."** 그때부터는 모든 게 쉬워집니다. 설치만 끝나면 박사급 인력이 여러분의 컴퓨터에 상주하며 24시간 일을 시작할 테니까요.

## 설치 전 준비물: 엔진과 화물차

오픈클로를 설치하기 전에 우리 컴퓨터에 먼저 깔아둬야 할 '기초 공사'가 두 가지 있습니다. 바로 **Node.js**와 **Git**입니다.

생활 비유를 들어볼까요? 오픈클로가 달리는 '자동차'라면, **Node.js는 그 자동차를 움직이게 하는 '엔진'**입니다. 엔진이 없으면 아무리 좋은 차체도 굴러가지 않죠. 그리고 **Git은 필요한 부품을 안전하게 실어 나르는 '화물차'**라고 생각하시면 됩니다. 이 두 가지만 있으면 어떤 자동화 도구든 거침없이 돌릴 수 있습니다.

### 01 Node.js 확인하기 (엔진 체크)
여러분의 컴퓨터에 이미 엔진이 있을 수도 있습니다. 먼저 확인해 봅시다.
- 터미널(macOS는 Terminal, Windows는 PowerShell)을 열고 `node -v`라고 입력한 뒤 Enter를 누르세요.
- `v20.10.0`처럼 숫자가 나오면 합격입니다. 오픈클로는 최신형 엔진을 좋아하므로, 버전 숫자가 **20 이상**이어야 합니다.
- 만약 "command not found"라고 나오거나 버전이 낮다면, [Node.js 공식 홈페이지](https://nodejs.org/)에서 'LTS'라고 적힌 버튼을 눌러 설치 파일을 받아 깔면 됩니다.

### 02 Git 확인하기 (화물차 체크)
마찬가지로 터미널에 `git --version`이라고 쳐보세요.
- 버전 숫자가 나온다면 이미 준비된 겁니다. 
- 안 나온다면 당황하지 마세요. macOS 사용자는 터미널에 `brew install git`을 치거나, Windows 사용자는 [git-scm.com](https://git-scm.com/)에서 'Download'를 눌러 설치하면 끝납니다.

> **🙋 잠깐! 저는 터미널 자체가 너무 무서워요.**
> 괜찮습니다. 터미널은 그냥 컴퓨터와 채팅하는 창일 뿐입니다. 우리가 코덱스에게 말하듯이, 터미널에게도 "이것 좀 깔아줘"라고 명령을 내리는 거예요. 제가 드리는 명령어를 복사해서 붙여넣고 당당하게 엔터를 누르세요!

## macOS에서 한 줄로 설치하기

맥(Mac) 사용자라면 정말 쉽습니다. 제가 가장 추천하는 방법은 **'한 줄 설치 스크립트'**를 쓰는 겁니다. 복잡한 설정을 오픈클로가 알아서 다 해주거든요.

01 터미널을 열고 아래 명령어를 딱 한 줄만 복사해서 붙여넣으세요. 
```bash

02 설치가 진행되는 동안 잠시 기다립니다. 중간에 비밀번호를 물어보면 여러분의 맥 로그인 비밀번호를 입력하세요. **이때 글자가 화면에 안 보여도 입력되고 있는 것이니** 당황하지 말고 입력 후 엔터를 누르시면 됩니다.

## Windows에서 설치하기: '집 안의 집' 만들기

윈도우(Windows) 사용자는 조금 더 세심한 준비가 필요합니다. 오픈클로는 리눅스라는 환경에서 가장 잘 돌아가는데, 윈도우 안에 리눅스를 설치하는 **WSL(Windows Subsystem for Linux)**이라는 기능을 쓸 겁니다.

비유하자면, **윈도우라는 아파트 거실 한복판에 '리눅스'라는 전용 작업실**을 하나 차리는 것과 같습니다. 이 작업실 안에서 오픈클로가 마음껏 일하게 해주는 거죠.

### 1-1. WSL 설치하고 접속하기

01 윈도우 검색창에 'PowerShell'을 치고 **'관리자 권한으로 실행'**을 누르세요.

02 아래 명령어를 입력하고 엔터를 누릅니다.
```powershell
wsl --install

03 설치가 끝나면 컴퓨터를 한 번 껐다 켭니다. 그 후 시작 메뉴에서 'Ubuntu'라는 앱을 찾아 실행하세요. 처음 실행하면 사용자 이름과 비밀번호를 정하라고 나오는데, 여러분이 기억하기 쉬운 걸로 정하시면 됩니다.

```
### 1-2. 리눅스 환경에서 설치하기

이제부터는 macOS와 거의 비슷합니다. 방금 연 우분투(Ubuntu) 창에 설치 명령어를 입력합니다.

01 설치 스크립트 실행
```bash
curl -fsSL https://openclaw.ai/install.sh | bash

02 윈도우에서는 환경 변수 설정이 꼬이는 경우가 종종 있습니다. 설치 후 명령어가 안 먹는다면 아래 명령어를 한 번 더 쳐주세요.
```bash
npm install -g openclaw@latest

```
### 1-3. 윈도우 사용자를 위한 꿀팁
WSL을 쓰다 보면 파일 경로가 헷갈릴 수 있습니다. 윈도우 탐색기 주소창에 `\\wsl$`라고 치면 리눅스 안의 파일들을 윈도우 폴더 보듯 편하게 볼 수 있습니다. 오픈클로가 작업하는 파일을 직접 보고 싶을 때 아주 유용합니다.

## 여기서 막혔나요?

**Q. `openclaw`라고 쳤는데 "command not found"가 나와요.**

**A.** 터미널을 완전히 껐다가 다시 열어보세요. 보통 설치 후에 경로가 바로 반영되지 않아서 생기는 일입니다. 그래도 안 된다면 설치 과정에서 에러가 있었는지 다시 확인해 보세요.

**Q. macOS에서 비밀번호를 입력하는데 아무 글자도 안 떠요. 고장 난 건가요?**

**A.** 보안을 위해 원래 그렇습니다. 별표(*)조차 표시되지 않는 게 정상이에요. 당황하지 마시고 비밀번호를 끝까지 치신 뒤 **엔터(Enter)**를 꾹 누르시면 됩니다.

**Q. `openclaw doctor`를 했는데 빨간 글씨가 가득해요.**

**A.** 대부분 Node.js 버전 문제입니다. `node -v`를 쳤을 때 버전이 20 미만이라면 반드시 최신 버전으로 업데이트하셔야 합니다. 엔진이 구형이면 최신 자동차는 달릴 수 없으니까요.

**Q. 윈도우에서 대시보드 주소로 들어갔는데 화면이 안 떠요.**

**A.** WSL 안에서 오픈클로가 실제로 켜져 있는지 확인해 보세요. `openclaw gateway status`를 쳤을 때 'running'이라고 나와야 합니다. 만약 'stopped'라면 `openclaw gateway start`를 입력해 직접 깨워주세요.

## 한 줄 정리

오픈클로 설치는 **'Node.js 엔진'**과 **'Git 화물차'**를 준비하고, **'한 줄 명령어'**로 채용을 완료한 뒤, **'대시보드'**라는 통제실을 여는 과정입니다.

자, 이제 우리 컴퓨터에 듬직한 직원이 출근했습니다. 그런데 이 직원, 아직은 아무 일도 안 하고 가만히 앉아 있을 거예요. 왜냐고요? 우리가 아직 '무전기'를 쥐여주지 않았거든요. 이 친구와 대화하려면 전용 무전 채널이 필요합니다. 바로 우리가 매일 쓰는 **'텔레그램'**이죠. 다음 섹션에서는 텔레그램을 연결해서 오픈클로에게 첫 지시를 내려보겠습니다!


## 09.3 [실습] 채널 연결하고 첫 메시지 보내기

대시보드까지 떴다면 이제 우리 컴퓨터에 상주하는 인턴 사원, '오픈클로'를 부를 준비가 끝난 겁니다. 그런데 이 친구, 화면만 띄워놓는다고 해서 바로 일을 시작하지는 않습니다. 우리도 회사에서 메신저나 이메일로 대화하듯, 오픈클로와 소통할 '무전 채널'을 열어줘야 하거든요.

이걸 오픈클로에서는 **'채널(Channel)'**이라고 부릅니다. 텔레그램, 슬랙, 디스코드처럼 우리가 매일 쓰는 메신저들이 그 통로가 되죠. 이번 섹션에서는 그중에서도 가장 연결이 쉽고 무료인 **'텔레그램'**을 통해 오픈클로에게 첫 지시를 내려보겠습니다.

## 채널: 오픈클로와 대화하는 무전기

오픈클로를 직접 터미널 창에서 부르는 건, 마치 매번 서버실 문을 열고 들어가서 대화하는 것과 같습니다. 너무 번거롭죠. 

**"채널은 오픈클로를 만나는 입구이자, 무전기입니다."**

우리가 텔레그램으로 "오늘 뉴스 요약해줘"라고 보내면, 오픈클로는 그 메시지를 받아 작업을 수행하고 다시 텔레그램으로 결과를 보내줍니다. 우리는 그냥 친구와 채팅하듯 자동화를 부릴 수 있게 되는 거죠. 이 책에서 텔레그램을 쓰는 이유는 명확합니다. 봇을 만드는 과정이 복잡한 허가 절차 없이 단 1분 만에 끝나기 때문입니다.

## STEP 1. 텔레그램의 아버지, BotFather 만나기

텔레그램 봇을 만들려면 먼저 텔레그램의 '관리자'를 만나야 합니다. 이름부터 위엄 있는 **'BotFather(봇파더)'**입니다. 이 친구에게 부탁해서 우리만의 전용 봇 계정을 하나 발급받아 봅시다.

01 텔레그램 검색창에 `@BotFather`를 검색하고, 공식 체크 표시가 붙은 계정을 선택하세요.
02 채팅창 하단의 **[시작(Start)]** 버튼을 누릅니다.
03 `/newbot`을 입력하고 엔터를 누르세요. 
04 봇의 이름을 정해달라고 합니다. "바이브 비서"처럼 한글로 자유롭게 입력하세요.
05 그다음은 봇의 'ID(Username)'를 정할 차례입니다. 반드시 영어로 써야 하며, 끝이 `_bot`으로 끝나야 합니다. (예: `my_openclaw_bot`, `vibecoding_bot`)
06 성공하면 긴 영문과 숫자가 섞인 **'API Token(토큰)'**을 줍니다.

> **확인**: `12345678:ABCdefGHI...` 같은 형태의 긴 토큰이 나왔나요? 이 토큰은 봇의 비밀번호이자 VIP 패스입니다. 절대 남에게 알려주지 마세요!

---

## STEP 2. 오픈클로에게 무전기 쥐여주기

자, 이제 발급받은 토큰을 오픈클로에게 등록할 시간입니다. 이 과정은 마치 신입 사원에게 사내 메신저 계정을 연동해주는 것과 같습니다.

01 터미널을 열고 아래 명령어를 입력하세요.
```bash
openclaw configure
02 화살표 키로 내려가 **[Channels]**를 선택하고 엔터를 누릅니다.
03 다시 **[Telegram]**을 선택하세요.
04 `Enable Telegram?` 질문에 **[Yes]**를 선택합니다.
05 아까 봇파더에게 받은 **API 토큰**을 그대로 복사해서 붙여넣고 엔터를 누르세요.
06 설정이 끝나면 오픈클로를 다시 깨워줘야 합니다. 아래 명령어를 입력하세요.
```bash
openclaw gateway restart

```
**"토큰 입력은 한 글자만 틀려도 먹통이 됩니다."**

가장 많이 하시는 실수가 앞뒤에 공백이 들어가거나, 한 글자를 빼먹고 복사하는 겁니다. 꼭 메모장에 한 번 붙여넣어 확인한 뒤 통째로 옮기세요.

## STEP 3. 대망의 첫 대화, "안녕, 넌 누구야?"

01 텔레그램에서 아까 여러분이 만든 봇의 ID(Username)를 검색해서 들어갑니다.
02 **[시작]** 버튼을 누르거나 `/start`를 보냅니다.
03 오픈클로에게 말을 걸어보세요. "안녕? 넌 누구야?"라고 보내봅니다.
04 잠시 기다리면 오픈클로가 응답을 보내옵니다. "안녕하세요! 저는 오픈클로 에이전트입니다. 무엇을 도와드릴까요?"라는 답장이 오면 성공입니다!

## 여기서 막혔나요?

**Q. 봇파더에게 토큰을 받았는데 오픈클로가 응답이 없어요.**

**A.** 가장 먼저 확인해야 할 건 '게이트웨이'가 실제로 켜져 있는지입니다. 터미널에 `openclaw gateway status`를 쳐보세요. 만약 'stopped'라고 나온다면 `openclaw gateway start`로 깨워주셔야 합니다. 무전기 본체가 꺼져 있으면 아무리 메시지를 보내도 들리지 않으니까요.

**Q. 토큰을 제대로 넣었는데도 에러 메시지가 떠요.**

**A.** `openclaw doctor` 명령어를 활용해 보세요. 오픈클로가 자체적으로 진단을 시작합니다. 만약 "Invalid Token"이라는 빨간 글씨가 보인다면 토큰 오타일 확률 100%입니다. 봇파더의 메시지를 다시 확인해 보세요.

**Q. 메시지를 보냈는데 한참 뒤에 답장이 오거나 아예 안 와요.**

**A.** 여러분의 컴퓨터(맥미니나 미니PC)가 인터넷에 잘 연결되어 있는지 확인해 보세요. 특히 맥미니를 쓰시는 분들은 '잠자기 모드'로 들어갔을 때 인터넷이 끊기는 경우가 많습니다. 앞 장에서 배운 `sudo pmset -a sleep 0` 명령어로 잠자기를 완전히 꺼두셨는지 다시 한번 체크해 보세요!

**Q. 터미널 로그를 직접 보고 싶어요. 방법이 있나요?**

**A.** 아주 좋은 질문입니다! 문제가 생겼을 때 속 시원하게 확인하는 방법이 있죠. 아래 명령어를 치면 오픈클로가 실시간으로 무슨 생각을 하고 있는지 로그를 보여줍니다.
```bash
openclaw logs --follow

```

## 한 줄 정리

채널 연결은 **'봇파더'**에게서 무전기 비밀번호(토큰)를 받아, **'configure'** 명령어로 오픈클로에게 입력하고, **'메시지'**를 보내 실제 응답을 확인하는 과정입니다.

자, 이제 여러분은 언제 어디서든 스마트폰만 꺼내면 내 컴퓨터에 있는 인턴 사원에게 일을 시킬 수 있게 되었습니다. 밖에서 밥을 먹다가도 "어제 쓴 글 좀 요약해서 보내줘"라고 텔레그램으로 툭 던지면, 집에 있는 오픈클로가 파일을 뒤져서 답장을 보내줄 겁니다. 

그런데 이 인턴 사원, 아직은 개성이 좀 부족하죠? 그냥 딱딱한 대답만 할 뿐입니다. 다음 장에서는 이 친구에게 '영혼'을 불어넣고, 우리가 원하는 말투와 성격을 가진 진짜 '비서'로 꾸미는 법을 배워보겠습니다!

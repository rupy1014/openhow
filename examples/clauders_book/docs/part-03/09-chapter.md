> "자동화의 시작은 거창한 코딩이 아닙니다. 매니저 한 명을 앉히는 것부터입니다."

Part 1에서 설치하고, Part 2에서 서비스를 만들고 배포까지 해봤습니다. 기획도 해봤고, API도 붙여봤고, 결제까지 연동해봤죠.

그런데 한 가지 빠진 게 있습니다. 이 모든 걸 **누가 관리하느냐**는 겁니다. 여러분이 직접 터미널을 열고, 스크립트를 돌리고, 결과를 확인하고 있잖아요. 그건 자동화가 아니라 수동화입니다.

1장에서 만났던 윤지영 씨를 기억하시죠? 매일 아침 경쟁사 블로그 다섯 곳을 돌며 새 글을 확인하던 마케터요. Part 1-2를 거치면서 지영 씨도 꽤 많은 걸 할 수 있게 됐습니다. AI한테 뉴스를 요약해달라고 시키고, 간단한 도구도 만들어봤죠. 그런데 여전히 매일 아침 직접 터미널을 열어야 합니다. "이걸 내가 안 해도 돌아가게 할 수는 없나?" — 그게 바로 이번 장의 출발점입니다.

이번 장에서는 OpenClaw를 설치하고, 텔레그램으로 첫 메시지를 주고받는 것까지 해봅니다. 10분이면 됩니다. 그리고 이 10분이 끝나면, "아, 이걸로 자동화를 연결할 수 있겠구나"라는 감각이 생길 겁니다.

## 완성 기준

- [ ] 내 컴퓨터에 OpenClaw가 설치되어 있다
- [ ] `openclaw doctor`로 정상 동작을 확인했다
- [ ] 텔레그램 봇을 만들고 OpenClaw와 연결했다
- [ ] 텔레그램에서 메시지를 보내고 AI 응답을 받았다

## STEP 1. AI 비서는 왜 따로 필요한 걸까

### 1-1. 직원은 있는데 매니저가 없다

Part 1-2를 거치면서 여러분은 꽤 많은 걸 만들었습니다.

- 파일을 정리하는 스크립트
- 뉴스를 요약하는 자동화
- 웹 서비스를 배포하는 경험

이것들은 하나하나가 유능한 직원입니다. 시키면 잘합니다. 그런데 문제가 있죠. 매일 아침 여러분이 직접 출근시켜야 합니다. "너 이거 해", "너 저거 해" 일일이 지시하고, 결과도 직접 확인해야 하고요.

회사로 치면, 직원은 다섯 명인데 매니저가 없는 상태입니다. 사장이 모든 직원한테 하나하나 말하고 있는 거예요.

### 1-2. OpenClaw는 사무실 매니저입니다

OpenClaw가 하는 일은 이겁니다.

- 누가 언제 무엇을 할지 정리합니다
- 여러분 대신 지시를 내립니다
- 결과를 모아서 보고합니다
- 여러분이 잘 때도 돌아갑니다

Codex나 Claude Code는 "일을 시키는 도구"입니다. 반면 OpenClaw는 "일이 돌아가게 관리하는 시스템"입니다. 이 차이가 중요합니다. (참고로 OpenClaw는 Paperclip이라는 오픈소스 에이전트 관리 프로젝트를 기반으로 만들어졌습니다. 10장에서 이 구조를 더 자세히 살펴봅니다.)

여러분이 매번 터미널을 열 필요 없이, 텔레그램으로 "오늘 뉴스 요약해줘"라고 말하면 OpenClaw가 알아서 처리하고 결과를 보내줍니다. 그게 이번 장에서 만들 첫 번째 모습입니다.

![AI 팀 조직도 — 매니저와 직원의 관계](/__content__/images/ch09-01.png)

> **확인**: "스크립트는 직원, OpenClaw는 매니저"라는 비유가 와닿으면 다음으로 넘어가세요.

## STEP 2. Claude Code한테 OpenClaw 설치 시키기

### 2-1. "설치해줘" 한마디면 됩니다

Part 1에서 설치한 Claude Code, 기억하시죠? 여러분의 터미널에서 `claude`를 치면 나오는 그 조수입니다. OpenClaw도 직접 설치할 필요 없습니다. 조수한테 시키면 됩니다.

터미널에서 `claude`를 실행한 뒤, 이렇게 말해보세요.

```
OpenClaw를 내 컴퓨터에 설치해줘.
Homebrew로 설치하고, 초기 설정(onboard)까지 진행해줘.
```

![OpenClaw 설치 — hands-on 세팅](/__content__/images/ch09-02.png)

Claude Code가 알아서 `brew install openclaw`을 실행하고, `openclaw onboard`까지 돌려줍니다. 중간에 몇 가지 질문이 나오면 Claude Code가 안내해줄 겁니다.

- 어떤 AI 모델을 쓸 건지 (GPT-4o, Claude Sonnet 등 — 원하는 모델을 고르면 됩니다)
- API 키는 무엇인지 (OpenAI 또는 Anthropic 등 선택한 모델의 API 키)
- 기본 설정을 어디에 저장할지

대부분 기본값으로 엔터만 눌러도 괜찮습니다. Claude Code가 "이거 이렇게 할까요?"라고 물어보면 확인만 해주세요.

### 2-2. 보안 설정 — 설치 직후에 가장 먼저 할 일

OpenClaw는 여러분의 API 키로 AI를 호출하고, 파일을 읽고, 외부 서비스에 메시지를 보냅니다. 편리하지만, 그만큼 **보안이 중요합니다.** 집에 유능한 매니저를 들였는데, 금고 열쇠를 아무 데나 놔두면 안 되는 것과 같습니다.

설치가 끝나면 Claude Code에게 바로 이렇게 시키세요.

```
OpenClaw 보안 설정을 확인해줘.
API 키가 안전하게 저장됐는지,
권한 설정이 적절한지 체크해줘.
```

Claude Code가 확인해줄 핵심 세 가지가 있습니다.

**첫째, API 키 보호입니다.**

API 키는 여러분의 지갑과 같습니다. 이 키가 노출되면 누군가가 여러분의 돈으로 AI를 마음껏 쓸 수 있습니다. 최근 보안 조사들에서, AI 코딩 도구가 생성한 코드에서 노출된 API 키가 예상보다 자주 발견되고 있습니다. 사고는 대부분 키를 코드에 직접 적어두거나, 설정 파일을 공개 저장소에 올리는 실수에서 시작됩니다.

Claude Code에게 이렇게 시키세요.

```
OpenClaw 설정 파일에서 API 키가 환경변수로 분리돼 있는지 확인해줘.
코드나 설정 파일에 키가 직접 적혀 있으면 환경변수로 바꿔줘.
```

**둘째, 권한 범위 설정입니다.**

OpenClaw가 접근할 수 있는 범위를 정해줘야 합니다. 보안 업계에서는 이걸 **"최소 권한 원칙"**이라고 부릅니다. 필요한 것만 딱 열어주고, 나머지는 잠그는 겁니다. AI 에이전트도 외부 계약자와 같다고 생각하세요 — 사무실 전체 열쇠를 주는 게 아니라, 맡은 방 열쇠만 주는 겁니다.

```
OpenClaw가 접근할 수 있는 디렉터리를 현재 프로젝트 폴더로 제한해줘.
홈 디렉터리나 시스템 폴더에는 접근하지 못하게 설정해줘.
```

**셋째, 외부 발신 전 승인입니다.**

OpenClaw가 텔레그램 메시지를 보내거나, 외부 API를 호출하거나, 파일을 삭제할 때는 여러분의 승인을 거치게 설정하세요. 처음에는 번거롭게 느껴지지만, AI가 잘못된 판단으로 고객에게 엉뚱한 메시지를 보내는 사고를 막아줍니다.

```
OpenClaw에서 외부로 메시지를 보내거나 파일을 삭제할 때는
반드시 내 승인을 받도록 설정해줘.
```

![보안 3대 원칙 — 승인과 권한 관리](/__content__/images/ch09-03.png)

이 세 가지만 해두면 "유능하지만 안전한 매니저"가 완성됩니다. 보안은 나중에 하는 게 아니라, 설치 직후에 하는 겁니다.

> **참고**: AI 에이전트 보안에 대해 더 알고 싶다면, Anthropic의 "Claude Code auto mode" 문서나 OWASP의 "Top 10 for Agentic Applications"를 참고하세요. 핵심은 같습니다 — AI를 신뢰하되, 검증 구조를 갖추는 것입니다.

### 2-3. 설정 파일 확인

보안 설정까지 끝났으면, 설정 파일을 한번 들여다봅시다. Claude Code에게 이렇게 시키면 됩니다.

```
OpenClaw 설정 파일 내용을 보여줘.
```

`~/.openclaw/openclaw.json` 파일이 열릴 겁니다. 이 파일이 OpenClaw의 두뇌 같은 역할을 합니다.

```json
{
  "model": "gpt-4o",
  "api_key_env": "OPENCLAW_API_KEY",
  "permissions": {
    "directory_scope": "./",
    "require_approval": ["send_message", "delete_file", "external_api"]
  },
  "channels": [],
  "skills": []
}
```

`api_key_env`가 환경변수 이름으로 되어 있는 게 보이시죠? 키 값이 직접 적혀 있지 않고, 환경변수를 참조하는 구조입니다. `permissions`에는 방금 설정한 보안 규칙이 들어 있습니다. `channels`와 `skills`는 비어 있는 게 정상입니다. 채널은 이 장에서, 스킬은 다음 장들에서 하나씩 채워나갈 겁니다.

### 2-4. 설치 확인

Claude Code에게 건강 검진도 시켜봅시다.

```
openclaw doctor를 실행해서 설치 상태를 확인해줘.
```

모든 항목에 초록색 체크가 뜨면 성공입니다.

```
✅ OpenClaw CLI ... OK
✅ Config file ... OK
✅ API key ... OK
✅ Permissions ... OK
✅ Model connection ... OK
```

![트러블슈팅 흐름도](/__content__/images/ch09-04.png)

> **확인**: `openclaw doctor` 결과가 모두 OK이면 설치 완료입니다.

### 2-5. Gateway 시작

이제 OpenClaw의 엔진을 켭니다. Claude Code에게 시키세요.

```
OpenClaw gateway를 시작해줘.
```

터미널에 로그가 흐르기 시작합니다. "어? 뭔가 돌아가기 시작했다"는 느낌이 드실 겁니다. 이게 맞습니다. OpenClaw가 메시지를 받을 준비를 하고 있는 겁니다.

```
🚀 OpenClaw Gateway started on port 3100
🔒 Permissions: approval required for external actions
📡 Waiting for channel connections...
```

보안 설정이 적용된 상태에서 시작되는 것도 확인할 수 있습니다. 이 터미널은 닫지 마세요. Gateway가 켜져 있어야 메시지를 주고받을 수 있습니다.

:::tip Windows / Linux 사용자
macOS 외 환경에서는 설치 방법이 조금 다릅니다. Claude Code에게 "내 운영체제에 맞게 OpenClaw 설치해줘"라고 하면 환경에 맞는 방법을 알아서 선택합니다. npm으로 설치하는 방법도 있습니다: `npm install -g @openclaw/cli`
:::

## STEP 3. 채널 하나 연결하고 메시지 보내기

### 3-1. 텔레그램 봇 만들기

OpenClaw는 여러 채널을 지원하지만, 가장 빠르게 시작할 수 있는 건 텔레그램입니다. 5분이면 됩니다.

01 텔레그램 앱을 열고 검색창에 **@BotFather**를 입력합니다.

02 BotFather에게 `/newbot` 명령어를 보냅니다.

03 봇 이름을 정합니다. 아무거나 괜찮습니다. 예: "내 비서봇"

04 봇 username을 정합니다. 끝에 `bot`이 붙어야 합니다. 예: `my_assistant_2024_bot`

05 BotFather가 토큰을 줍니다. `110201543:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw` 같은 긴 문자열이에요. 이걸 복사해두세요.

![메신저 채널 연결하기](/__content__/images/ch09-05.png)

> **확인**: 토큰을 복사해뒀으면 성공입니다.

### 3-2. Claude Code한테 텔레그램 연결 시키기

새 터미널 창을 하나 더 엽니다. Gateway가 돌아가고 있는 창은 그대로 두세요. `claude`를 실행한 뒤 이렇게 말해보세요.

```
OpenClaw에 텔레그램 채널을 연결해줘.
방금 BotFather에서 받은 토큰은 이거야: [토큰 붙여넣기]
```

Claude Code가 `openclaw channels login telegram`을 실행하고 토큰을 입력해줍니다.

```
🔑 Telegram bot token configured
✅ Telegram channel connected!
📱 Bot username: @my_assistant_2024_bot
```

연결이 되면 Gateway 터미널에도 변화가 보입니다.

```
📡 Channel connected: telegram (@my_assistant_2024_bot)
```

### 3-3. 첫 메시지 보내기

자, 이제 진짜 순간입니다.

01 텔레그램에서 방금 만든 봇을 검색합니다.

02 대화창을 열고 메시지를 보냅니다.

```
안녕, 비서님
```

03 잠시 기다립니다. 1~2초 후...

```
안녕하세요! 무엇을 도와드릴까요?
```

![텔레그램에서 AI 비서와 첫 대화](/__content__/images/ch09-06.png)

됐습니다. 진짜 대답합니다.

여러분의 컴퓨터에서 돌아가고 있는 OpenClaw가, 텔레그램 메시지를 받아서, AI 모델에게 전달하고, 응답을 다시 텔레그램으로 보내준 겁니다. 이 모든 게 방금 여러분이 설치한 시스템 위에서 일어났습니다.

몇 가지 더 말해보세요.

```
오늘 날씨가 어떨까?
```

```
이번 주에 해야 할 일을 정리해줘
```

지금은 단순한 채팅처럼 보일 겁니다. 맞습니다, 지금은 채팅입니다. 하지만 이건 시작점이에요.

> **확인**: 텔레그램에서 메시지를 보내고 AI 응답을 받았으면 이 장의 핵심 실습은 완료입니다.

## STEP 4. 이게 왜 자동화의 시작점인가

### 4-1. 채팅에서 시스템으로

"그냥 ChatGPT랑 뭐가 다르지?"라는 생각이 드실 수 있습니다. 좋은 질문입니다.

지금 상태에서는 차이가 거의 없습니다. 그런데 OpenClaw에는 지금 비어 있는 두 가지 칸이 있었죠.

```json
{
  "permissions": { ... },      // ← 보안 설정 완료
  "channels": ["telegram"],    // ← 방금 채웠습니다
  "skills": []                 // ← 여기가 비어 있죠
}
```

보안은 잡았고, 채널도 연결했습니다. 이 `skills`에 하나씩 채워 넣으면, 단순한 채팅이 자동화 시스템으로 바뀝니다.

- **cron** — 매일 아침 8시에 뉴스를 수집해서 보고하게 만들 수 있습니다
- **스킬** — "이거 블로그에 올려줘"라고 말하면 실제로 발행하게 만들 수 있습니다
- **standing orders** — 항상 지켜야 할 규칙(보안 포함)을 설정할 수 있습니다

Part 1-2에서 만든 스크립트들이 직원이었다면, 이제 매니저가 사무실에 앉은 겁니다. 다음 장부터는 이 매니저에게 업무 매뉴얼을 만들어줄 차례입니다.

### 4-2. 다음 장 미리보기

10장에서는 OpenClaw의 구조를 읽습니다. 스킬이 뭔지, cron이 뭔지, 하트비트가 뭔지. 구조를 알면 "이걸 내 업무에 어떻게 붙이지?"라는 설계 감각이 생깁니다.

지금은 매니저를 앉혔을 뿐입니다. 다음 장에서는 이 매니저한테 사무실 안내도를 보여줄 겁니다.

## 여기서 막혔나요?

**Q. Claude Code에게 설치를 시켰는데 에러가 납니다.**

상황: `Error: No formulae found in taps` 같은 메시지가 뜹니다.

원인:
- Homebrew가 설치되지 않았거나 오래된 버전일 수 있습니다
- OpenClaw tap이 등록되지 않은 상태일 수 있습니다

해결:
1. Claude Code에게 이렇게 말하세요: "Homebrew를 업데이트하고 OpenClaw를 다시 설치해줘"
2. Claude Code가 `brew update` → `brew tap openclaw/tap` → `brew install openclaw` 순서로 시도해줍니다
3. 그래도 안 되면 "npm으로 OpenClaw 설치해줘"라고 하세요. Claude Code가 `npm install -g @openclaw/cli`로 대체합니다

**Q. API 키를 어디서 받는지 모르겠습니다.**

상황: 초기 설정에서 API 키를 입력하라는데 뭘 넣어야 할지 모르겠습니다.

원인:
- OpenAI 또는 Anthropic의 API 키가 필요합니다

해결:
1. OpenAI를 쓸 경우: [platform.openai.com](https://platform.openai.com)에서 가입 후 API Keys 메뉴에서 발급하세요
2. Claude를 쓸 경우: [console.anthropic.com](https://console.anthropic.com)에서 발급하세요
3. 발급받은 키를 설정할 때 붙여넣으면 됩니다
4. **중요**: 키를 발급받을 때 권한 범위를 최소한으로 설정하세요. 전체 권한 키 대신, 채팅 API만 호출할 수 있는 제한된 키를 만드는 게 안전합니다

**Q. 보안 설정이 제대로 됐는지 어떻게 확인하나요?**

상황: 설정은 했는데 정말 안전한 건지 확신이 없습니다.

원인:
- 보안 설정을 한 번도 점검해본 적이 없는 경우입니다

해결:
1. Claude Code에게 "OpenClaw 보안 상태를 점검해줘"라고 시키세요
2. API 키가 환경변수로 분리되어 있는지, 디렉터리 접근 범위가 제한되어 있는지, 외부 발신 승인이 켜져 있는지 확인됩니다
3. `openclaw doctor`에서 Permissions 항목이 OK인지도 체크하세요

**Q. Gateway는 켰는데 텔레그램에서 응답이 없습니다.**

상황: 메시지를 보냈는데 봇이 아무 대답을 안 합니다.

원인:
- Gateway 터미널이 닫혔거나 에러가 났을 수 있습니다
- 텔레그램 토큰이 잘못 입력됐을 수 있습니다
- 봇을 찾을 때 다른 봇을 선택했을 수 있습니다

해결:
1. Claude Code에게 "OpenClaw gateway 상태 확인해줘"라고 시키세요
2. "텔레그램 채널이 연결돼 있는지 확인해줘"라고 물어보세요
3. 토큰이 틀렸으면 "텔레그램 토큰을 다시 설정해줘"라고 하면 됩니다
4. 텔레그램에서 봇 username이 맞는지 확인하세요

**Q. "이거 그냥 ChatGPT 아닌가요?"**

상황: 설치는 했는데 ChatGPT랑 뭐가 다른지 모르겠습니다.

원인:
- 지금 상태에서는 정상입니다. 채널만 연결했고 스킬은 아직 비어 있으니까요.

해결:
1. 지금은 "매니저가 출근한 첫날"이라고 생각하세요
2. 10장에서 구조를 읽고, 13장부터 실제 자동화를 붙이면 차이가 확 느껴집니다
3. 이 장의 목적은 "연결 확인"입니다. 진짜 활약은 다음부터 시작됩니다

## 한 줄 정리

OpenClaw는 자동화 스크립트들을 묶어주는 매니저입니다. Claude Code한테 설치를 시키고, 보안을 잡고, 텔레그램을 연결하면 — 여러분의 자동화 시스템에 "안전하게 대화할 수 있는 창구"가 생깁니다.

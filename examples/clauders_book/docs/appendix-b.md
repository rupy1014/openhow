# [부록 B] 용어사전 + 온라인 리소스

이 책을 읽다 보면 생소한 기술 용어가 슬금슬금 등장합니다. 처음 보는 단어가 나올 때마다 구글을 검색하는 건 너무 피곤한 일이죠. 그래서 이 책에 등장하는 주요 용어를 한데 모아 정리했습니다. 

각 용어 옆의 숫자는 **이 책에서 처음 등장하는 장 번호**입니다. "이 단어가 어디서 나왔더라?" 싶을 때 해당 장으로 돌아가면 맥락과 함께 이해할 수 있습니다.

> **온라인 버전**: clauders.ai/glossary 에서 검색 가능한 최신 용어사전을 제공합니다. 책 출간 이후 추가된 용어도 계속 업데이트됩니다.

## B.1 용어사전 — 비개발자를 위한 기술 용어 140선

### 🔤 ㄱ

**개발자 등록** `13장`
외부 서비스의 API를 사용하기 위해 개발자 계정을 만드는 과정입니다. 메타(Meta) 개발자 센터에 가입하는 것이 대표적인 예시입니다.

**경로 (Path)** `01장`
컴퓨터에서 파일이나 폴더가 어디에 있는지 나타내는 주소입니다. `/Users/홍길동/Desktop/my-project` 같은 형태로, 사람으로 치면 "서울시 강남구 테헤란로 123번지" 같은 것입니다.

**권한 (Permission)** `01장`
컴퓨터에서 특정 작업을 할 수 있는 자격입니다. "이 파일을 수정해도 되는 권한", "이 프로그램을 실행해도 되는 권한" 같은 것이죠. 윈도우에서 "관리자 권한으로 실행"이 바로 이것입니다.

**깃 (Git)** `05장`
파일의 변경 이력을 기록해주는 시스템입니다. 게임의 '세이브 포인트'와 비슷합니다. 언제든 과거 버전으로 되돌아갈 수 있어요.

**깃허브 (GitHub)** `05장`
깃으로 관리하는 코드를 인터넷에 보관하는 서비스입니다. '온라인 금고'라고 생각하시면 됩니다. 전 세계 개발자들이 코드를 공유하는 곳이기도 합니다.

**깃허브 액션 (GitHub Actions)** `14장`
깃허브에서 제공하는 무료 자동 실행 서비스입니다. "매일 아침 8시에 이 스크립트를 돌려줘"라고 설정해두면 24시간 무중단으로 작업을 실행해줍니다.

### 🔤 ㄴ

**노드 (Node.js)** `01장`
코덱스(Codex)를 돌리는 데 필요한 '엔진'입니다. 자동차를 움직이려면 엔진이 필요하듯, 코덱스가 작동하려면 Node.js가 필요합니다. 한 번만 설치하면 됩니다.

**뉴스봇 (Newsbot)** `08장`
뉴스를 자동으로 수집하고 요약해서 카톡이나 슬랙으로 보내주는 자동화 시스템입니다. 24시간 무인 정보 공장이라고 할 수 있죠.

---

### 🔤 ㄷ

**대시보드 (Dashboard)** `05장`
서비스의 상태를 한눈에 보여주는 관리 화면입니다. 자동차의 계기판처럼, 배포 상태·환경변수·에러 등을 확인하고 설정할 수 있습니다.

**데이터 (Data)** `03장`
서비스가 저장하고 처리하는 정보입니다. 식당으로 비유하면 '식재료'에 해당합니다. 회원 정보, 게시글, 뉴스 기사 등이 모두 데이터입니다.

**데이터베이스 (Database)** `03장`
데이터를 체계적으로 저장하고 관리하는 시스템입니다. 엑셀 시트를 아주 크고 빠르게 만들어놓은 것이라고 생각하시면 됩니다.

**도메인 (Domain)** `05장`
인터넷에서 서비스를 찾아갈 수 있는 '주소'입니다. `my-app.vercel.app` 같은 것이죠. 사람으로 치면 집 주소에 해당합니다.

**디렉토리 (Directory)** `01장`
'폴더'의 다른 이름입니다. 터미널에서는 폴더를 디렉토리라고 부릅니다. 같은 것을 가리키는 두 가지 이름이에요.

---

### 🔤 ㄹ

**레퍼런스 (Reference)** `06장`
에이전트가 작업할 때 참고하는 문서입니다. 톤 가이드, 용어 맵 등이 이에 해당합니다. 신입 사원에게 주는 '업무 참고자료'와 같습니다.

**로그 (Log)** `11장`
시스템이 작동하면서 남기는 기록입니다. 비행기의 '블랙박스'처럼, 무슨 일이 있었는지 나중에 확인할 수 있게 해줍니다.

**로그인 (Login)** `05장`
내가 누구인지 증명하고 서비스에 접속하는 과정입니다. 아이디와 비밀번호를 입력하거나, 구글 계정으로 인증하는 것이 대표적입니다.

**로컬 (Local)** `05장`
'내 컴퓨터'를 뜻합니다. "로컬에서 테스트한다"는 것은 인터넷에 올리기 전에 내 컴퓨터에서 먼저 확인한다는 뜻입니다.

**루프 (Loop)** `07장`
같은 과정을 반복하는 것입니다. '피드백 루프'는 결과를 확인하고 개선하는 과정을 반복하는 것, '품질 루프'는 점수가 부족하면 다시 쓰는 과정을 반복하는 것입니다.

**리포지토리 (Repository)** `05장`
깃허브에서 하나의 프로젝트를 보관하는 공간입니다. 줄여서 '레포'라고도 합니다. 한 프로젝트의 모든 파일과 변경 이력이 담겨 있습니다.

---

### 🔤 ㅁ

**마크다운 (Markdown / .md)** `01장`
글에 간단한 서식을 넣을 수 있는 텍스트 형식입니다. `#`은 제목, `**굵게**`는 굵은 글씨, `-`는 목록. 복잡한 서식 도구 없이 텍스트만으로 깔끔한 문서를 만들 수 있습니다.

**멀티 에이전트 (Multi-Agent)** `06장`
여러 AI 전문가가 각자의 역할을 나눠서 일하는 방식입니다. 한 명이 글을 쓰고, 다른 한 명이 교정하고, 또 다른 한 명이 검수하는 식이죠.

**모델 (Model)** `02장`
AI의 '두뇌 등급'입니다. GPT-4o는 박사급, o3-mini는 대리급, Haiku는 인턴급처럼, 모델마다 똑똑함의 수준이 다릅니다. 똑똑할수록 느리고 비쌉니다.

**무인 (Unattended)** `08장`
사람이 지켜보지 않아도 자동으로 작동하는 상태입니다. "무인 공장"처럼, 잠자는 사이에도 뉴스봇이 돌아가는 것이 대표적인 예입니다.

### 🔤 ㅂ

**바이브코딩 (Vibe Coding)** `04장`
AI에게 "이런 느낌으로 만들어줘"라고 의도를 전달해서 소프트웨어를 만드는 방식입니다. 직접 코드를 짜는 대신, AI에게 원하는 결과물의 '분위기(vibe)'를 알려주는 것이죠.

**배포 (Deploy / Deployment)** `05장`
내 컴퓨터에서만 보이던 서비스를 인터넷에 올려서 누구나 접속할 수 있게 만드는 과정입니다. 집에서 만든 요리를 식당에 내놓는 것과 비슷합니다.

**백엔드 (Backend)** `03장`
사용자 눈에 보이지 않는 서비스의 뒷면입니다. 식당으로 비유하면 '주방'에 해당합니다. 데이터 처리, 계산, 저장 같은 일을 담당합니다.

**봇 (Bot)** `08장`
특정 작업을 자동으로 수행하는 프로그램입니다. 텔레그램 봇, 뉴스봇, 챗봇 등 다양한 종류가 있습니다.

**봇파더 (BotFather)** `09장`
텔레그램에서 봇을 만들 때 사용하는 공식 관리자 계정입니다. 이 계정에게 말을 걸어 새 봇을 생성하고 API 토큰을 발급받습니다.

**브라우저 (Browser)** `01장`
인터넷 웹사이트를 보는 프로그램입니다. 크롬, 사파리, 엣지 같은 것들이죠. 우리가 평소에 "인터넷 켜서 보자"라고 할 때 여는 바로 그것입니다.

**빌드 (Build)** `05장`
소스 코드를 실행 가능한 서비스로 변환하는 과정입니다. 밀가루 반죽을 오븐에 넣어 빵으로 굽는 것과 비슷합니다. "빌드 실패"는 반죽이 잘못되어 빵이 안 구워진 상황입니다.

### 🔤 ㅅ

**서버 (Server)** `03장`
서비스를 실행하는 컴퓨터입니다. 식당의 '주방'처럼 뒤에서 일하며, 사용자가 요청하면 결과를 내어줍니다. "서버가 다운됐다"는 주방이 문을 닫았다는 뜻입니다.

**스케줄러 (Scheduler)** `14장`
정해진 시간에 자동으로 작업을 실행하는 시스템입니다. '알람시계'와 같은 역할을 합니다.

**스킬 (Skill)** `06장`
코덱스에게 주는 '업무 매뉴얼'입니다. 한 번 만들어두면 매번 똑같은 지시를 반복하지 않아도 됩니다. "블로그 글 쓸 때는 이 톤으로, 이 분량으로, 이 형식으로"라는 지침을 저장해둔 것이죠.

**스크립트 (Script)** `11장`
컴퓨터가 순서대로 실행할 명령을 적어놓은 파일입니다. 요리 레시피처럼, "1번 하고, 2번 하고, 3번 해"라는 지시가 담겨 있습니다.

**슬랙 (Slack)** `08장`
팀 커뮤니케이션 도구입니다. 카카오톡의 업무용 버전이라고 생각하시면 됩니다. 뉴스봇의 보고서를 받는 채널로 사용합니다.

**승인 (Approval)** `11장`
에이전트가 중요한 작업을 실행하기 전에 사람에게 "이거 해도 될까요?"라고 확인받는 과정입니다. 위험한 행동을 방지하는 안전장치입니다.

---

### 🔤 ㅇ

**에이전트 (Agent)** `06장`
특정 역할과 성격을 부여받은 AI 전문가입니다. '집필 에이전트', '검수 에이전트'처럼 각자 맡은 일이 다릅니다. 회사로 치면 직원 한 명에 해당합니다.

**에러 (Error)** `01장`
프로그램이 실행 중 문제가 생긴 상태입니다. "command not found"는 명령어를 못 찾겠다는 에러, "permission denied"는 권한이 없다는 에러입니다.

**엔드포인트 (Endpoint)** `03장`
API가 요청을 받아들이는 주소입니다. 식당의 '주문 접수처'라고 생각하시면 됩니다. 각 기능마다 별도의 엔드포인트가 있습니다.

**오픈클로 (OpenClaw)** `09장`
24시간 상주하는 AI 에이전트 시스템입니다. 코덱스가 "필요할 때 부르는 전문가"라면, 오픈클로는 "사무실에 항상 앉아 있는 상근 비서"입니다.

**온프레미스 / 로컬 설치** `09장`
서비스를 남의 서버가 아니라 내 컴퓨터(또는 내 서버)에 직접 설치하는 것입니다. 렌터카 대신 내 차를 사는 것과 비슷합니다.

**워크스페이스 (Workspace)** `09장`
에이전트가 일할 수 있는 지정된 폴더 범위입니다. "너는 이 폴더 안에서만 놀아!"라고 활동 범위를 정해주는 것이죠.

**웹훅 (Webhook)** `13장`
어떤 이벤트가 발생하면 자동으로 알림을 보내주는 기술입니다. "택배가 도착하면 문자를 보내줘"와 같은 원리입니다.

**유저 인터페이스 (UI)** `03장`
사용자가 서비스와 상호작용하는 화면입니다. 버튼, 텍스트, 이미지 등 눈에 보이는 모든 요소를 포함합니다.

**인증 (Authentication)** `05장`
"나는 이 계정의 주인입니다"라고 신분을 증명하는 과정입니다. 로그인, API 키, OAuth 등이 인증 방법입니다.

---

### 🔤 ㅈ

**자동화 (Automation)** `02장`
사람이 반복하던 작업을 컴퓨터가 알아서 처리하게 만드는 것입니다. "입력 → 처리 → 출력"의 흐름을 한 번 설계해두면, 매번 사람이 손대지 않아도 됩니다.

**절대 경로 (Absolute Path)** `12장`
파일 위치를 루트(최상위)부터 전체 주소로 표시하는 방식입니다. `/Users/홍길동/automation/news-bot` 같은 형태입니다. 상대 경로와 반대되는 개념입니다.

**주방 비유** `03장`
이 책에서 자주 쓰는 비유입니다. 서비스의 구조를 식당에 빗대어, 화면은 홀, 서버는 주방, 데이터는 식재료, API는 주문서로 설명합니다.

---

### 🔤 ㅊ

**채널 (Channel)** `09장`
에이전트와 대화하는 통로입니다. 텔레그램, 슬랙, 디스코드 같은 메신저가 채널이 됩니다. '무전기'라고 생각하시면 됩니다.

**처리 (Process)** `02장`
자동화의 세 단계(입력→처리→출력) 중 가운데 단계입니다. 재료를 가져와서 AI가 분석하고 변환하는 과정이죠. 식당에서 요리하는 단계에 해당합니다.

---

### 🔤 ㅋ

**코덱스 (Codex)** `01장`
여러분의 컴퓨터에서 직접 파일을 만들고 수정하는 AI 비서입니다. ChatGPT가 '말만 하는 상담사'라면, 코덱스는 '직접 손발을 움직이는 실행형 비서'입니다.

**코드 꼬임** `04장`
AI가 작성한 코드를 사람이 직접 수정하면서 구조가 엉켜버리는 현상입니다. 코덱스가 이해하기 어려워지고, 이후 수정이 점점 힘들어집니다.

**콘솔 (Console)** `01장`
터미널과 비슷한 의미로, 컴퓨터에게 텍스트로 명령을 내리는 창입니다. 맥에서는 '터미널', 윈도우에서는 '명령 프롬프트' 또는 'PowerShell'이라고 부릅니다.

**컨텍스트 윈도우 (Context Window)** `02장`
AI가 한 번에 기억할 수 있는 정보의 양입니다. '화이트보드'에 비유하면, 보드가 가득 차면 예전에 쓴 것을 지워야 새 내용을 쓸 수 있습니다. 대화가 길어지면 AI가 앞부분을 잊어버리는 이유입니다.

**크론 (Cron)** `11장`
유닉스/리눅스에서 정해진 시간에 자동으로 명령을 실행하는 스케줄러입니다. "매일 아침 9시에 뉴스를 수집해"같은 예약 실행을 가능하게 합니다. `0 9 * * *`처럼 시간을 숫자로 표현합니다.

**크론탭 (Crontab)** `11장`
크론의 설정 파일입니다. 어떤 시간에 어떤 명령을 실행할지 적어놓는 '알람 목록표'와 같습니다.

**클라우드 (Cloud)** `05장`
인터넷에 있는 다른 사람의 컴퓨터를 빌려 쓰는 것입니다. 내 컴퓨터가 아닌 어딘가의 서버에서 서비스를 돌리는 것을 "클라우드에 올린다"고 합니다.

### 🔤 ㅌ

**터미널 (Terminal)** `01장`
컴퓨터에게 글자로 명령을 내리는 검은 창입니다. 식당에서 요리사들이 소통하는 '주방 인터컴'과 비슷합니다. 겁먹지 마세요. 우리는 여기서 AI에게 "해줘"라고 말하기만 하면 됩니다.

**텔레그램 (Telegram)** `09장`
무료 메신저 앱입니다. 오픈클로와 대화할 때 주로 사용합니다. 봇 만들기가 쉽고 무료라서 자동화 도구와 궁합이 좋습니다.

**토큰 (Token)** `02장`

**톤 가이드 (Tone Guide)** `06장`
글의 말투·분위기·금지 표현 등을 정리한 문서입니다. 에이전트가 글을 쓸 때 이 파일을 참고해서 일관된 느낌을 유지합니다.

### 🔤 ㅍ

**파이프라인 (Pipeline)** `02장`
자동화의 전체 흐름을 뜻합니다. 공장의 조립 라인처럼, 수집 → 분류 → 요약 → 발송 등의 단계가 순서대로 이어지는 구조입니다.

**파일 (File)** `01장`
컴퓨터에 저장된 하나의 문서입니다. `자기소개.md`, `index.html`, `.env` 같은 것들이 모두 파일입니다.

**패턴 (Pattern)** `02장`
AI가 텍스트에서 학습한 통계적 규칙성입니다. AI는 이 패턴을 바탕으로 다음에 올 단어를 예측합니다. AI가 "똑똑해 보이는" 이유이자, 가끔 틀리는 이유이기도 합니다.

**퍼블리싱 / 발행 (Publishing)** `13장`
콘텐츠를 SNS나 블로그에 올려서 사람들에게 보이게 하는 것입니다. 자동 발행은 이 과정을 AI가 알아서 해주는 것이죠.

**페르소나 (Persona)** `09장`
에이전트에게 부여하는 '인물 설정'입니다. "까칠한 편집장", "친절한 한국어 비서" 같은 역할입니다. 같은 AI라도 페르소나에 따라 완전히 다른 결과물을 만들어냅니다.

**폴더 (Folder)** `01장`
파일을 담는 상자입니다. 코덱스는 이 폴더 단위로 일합니다. "프로젝트 = 폴더 하나"라고 기억하시면 됩니다.

**프로덕션 (Production)** `05장`
실제 사용자가 접속하는 실서비스 환경입니다. "프로덕션에 올렸다"는 것은 개발이 끝나고 세상에 공개했다는 뜻입니다.

**프롬프트 (Prompt)** `01장`
AI에게 주는 지시·요청·질문입니다. "자기소개 파일을 만들어줘"가 프롬프트이고, 프롬프트를 얼마나 명확하게 쓰느냐에 따라 결과물의 질이 달라집니다.

**프론트엔드 (Frontend)** `03장`
사용자 눈에 보이는 서비스의 앞면입니다. 식당으로 비유하면 손님이 앉아서 주문하는 '홀'에 해당합니다. HTML, CSS, JavaScript로 만듭니다.

**피드백 (Feedback)** `04장`
결과물을 본 사람이 주는 의견이나 반응입니다. "이 부분이 좋다", "이건 바꿨으면 좋겠다" 같은 것이죠. 바이브코딩에서 피드백은 개선의 재료입니다.

**피드백 루프 (Feedback Loop)** `04장`
만들기 → 보여주기 → 피드백 받기 → 개선하기를 반복하는 과정입니다. 한 번에 완벽하게 만드는 게 아니라, 빙글빙글 돌면서 점점 나아지는 것이 핵심입니다.

**확장 프로그램 (Extension)** `01장`

웹 페이지의 디자인을 담당하는 언어입니다. 색상, 글꼴, 배치 등 '꾸미기'를 담당합니다. HTML이 뼈대라면, CSS는 옷이라고 생각하시면 됩니다.

깃허브와 연동해서 웹사이트를 자동으로 배포해주는 서비스입니다. `git push`만 하면 알아서 빌드하고 인터넷에 올려줍니다. 무료로 시작할 수 있습니다.

**VS Code (Visual Studio Code)** `01장`
마이크로소프트가 만든 무료 코드 에디터입니다. AI 작업의 '작업대'로, 파일 탐색기(냉장고), 에디터(도마), 터미널(가스레인지)을 한 화면에서 볼 수 있습니다.

**YAML / YML** `14장`
설정 파일에 사용하는 텍스트 형식입니다. GitHub Actions의 워크플로우 파일(`.yml`)이 대표적입니다. 들여쓰기로 구조를 표현합니다.

## B.2 프롬프트 모음 + 완성 코드 안내

### 챕터별 핵심 프롬프트

이 책에서 사용한 핵심 프롬프트를 챕터별로 정리했습니다. 복사해서 바로 사용할 수 있습니다.

> **온라인 버전**: clauders.ai/prompts 에서 복사 가능한 최신 프롬프트를 제공합니다.

#### Part 1: 시작하기

**01장 — 첫 파일 만들기**
```
자기소개.md 파일을 만들어줘. 이름은 홍길동, 직업은 떡집 사장님, 취미는 등산이야.
```

```
오늘할일.md 파일을 만들어줘. 체크리스트 형식으로 부탁해. 떡 주문 확인하기, 쌀 씻기, 등산화 챙기기 이렇게 세 개 넣어줘.
```

**03장 — MVP 기획**
```
[서비스 이름]의 MVP를 만들어줘.
핵심 기능: [기능 1], [기능 2], [기능 3]
절대 넣지 않을 기능: 로그인, 데이터베이스, 결제
```

**04장 — PRD 작성**
```
아래 PRD를 읽고 서비스를 만들어줘.
---
[PRD 내용]
---
```

#### Part 2: 자동화의 뼈대

**06장 — 스킬 만들기**
```
.codex/skills/write/SKILL.md 파일을 만들어줘.
블로그 글 작성 스킬이야. 톤은 친절한 경어체, 분량은 2000자, 마크다운 형식으로 출력해줘.
```

**07장 — 파이프라인 설계**
```
$write "오늘의 주제"
```

#### Part 3: 오픈클로

**09장 — 오픈클로 설치**
```
/newbot
```
(텔레그램 BotFather에게 보내는 봇 생성 명령)

**10장 — 워크스페이스 설정**
```
SOUL.md를 만들어줘. 
이름: 목우, 성격: 까칠하지만 실력 있는 편집장, 
말투: 반말+존댓말 섞어 쓰기
```

#### Part 4: 실전 자동화

**13장 — SNS 자동 발행**
```
뉴스 요약 결과를 Threads에 자동 발행해줘.
톤: 짧고 임팩트 있게, 해시태그 3개, 이모지 적당히
```

**14장 — 전체 파이프라인 실행**
```
npm run fetch && npm run summarize -- --notify-telegram
```

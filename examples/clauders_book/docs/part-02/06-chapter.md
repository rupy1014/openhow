> "내 컴퓨터에서 되는 건 아무도 모릅니다. 링크가 생겨야 비로소 '서비스'가 됩니다."

5장에서 캐릭터 채팅 서비스를 만들어봤죠? 로컬에서 테스트하면서 꽤 뿌듯했을 겁니다. 그런데 한 가지 아쉬운 점이 있습니다. 이 서비스를 친구에게 보여주려면 어떻게 해야 할까요? "내 컴퓨터로 와서 봐"라고 할 수는 없잖아요.

이 장에서는 내 컴퓨터 안에 갇혀 있던 서비스를 인터넷에 올려서, 누구나 접속할 수 있는 링크로 바꿀 겁니다. 생각보다 훨씬 쉽습니다. 진짜요.

---

## 완성 기준

- [ ] Git으로 코드를 저장(커밋)하고 GitHub에 올리기
- [ ] Vercel에서 배포하여 `.vercel.app` 주소 받기
- [ ] 환경변수를 설정해서 배포된 서비스가 정상 작동하는지 확인하기
- [ ] 핸드폰으로 내 서비스에 접속해보기

---

## STEP 1. Git과 GitHub — 코드의 세이브 포인트

배포 이야기를 하기 전에, 먼저 알아야 할 게 있습니다. 바로 **Git**이에요.

### 1-1. Git은 게임의 세이브 기능입니다

RPG 게임을 해보신 분이라면 아실 겁니다. 보스 전투 직전에 꼭 하는 게 있죠? 바로 '저장'입니다. 혹시 죽더라도 그 시점으로 돌아가려고요.

코딩도 똑같습니다. "자, 이제 로그인 기능을 손볼 건데, 혹시 망치면 돌아가야 하니까 여기서 한번 저장해두자." 이걸 프로그래밍에서는 **커밋(Commit)**이라고 부릅니다.

- **게임**: Save Point 1, Save Point 2...
- **코딩**: Commit 1, Commit 2...

지금은 딱 이것만 기억하세요. **커밋 = 세이브 포인트 찍기**입니다.

### 1-2. 세이브 포인트 만들어보기

터미널을 열고 5장에서 작업하던 프로젝트 폴더로 이동하세요. 그리고 아래 세 줄을 차례로 입력합니다.

01 **파일 담기** — 수정한 파일을 세이브 목록에 넣습니다.

```bash
git add .
```

02 **세이브 포인트 찍기** — 이름표를 붙여서 저장합니다.

```bash
git commit -m "캐릭터 채팅 서비스 완성"
```

> **확인**: `1 file changed` 같은 메시지가 뜨면 성공입니다. 이제 이 시점으로 언제든 돌아올 수 있어요.

### 1-3. GitHub에 올리기 — 구름 위의 보관함

내 컴퓨터에만 저장하면 노트북이 고장 났을 때 끝입니다. 그래서 **GitHub**라는 클라우드 보관함에 백업을 해둡니다.

01 [github.com](https://github.com)에 가입하세요. (이미 있다면 로그인만 하면 됩니다)

02 오른쪽 위 `+` 버튼 → `New repository`를 클릭하세요. 이름은 `character-chat` 정도면 좋습니다.

03 저장소가 만들어지면 화면에 나오는 명령어 세 줄을 복사해서 터미널에 붙여넣으세요.

```bash
git remote add origin https://github.com/내아이디/character-chat.git
git branch -M main
git push -u origin main
```

![Git 저장소의 기본 개념](/__content__/images/ch06-01.png)

04 GitHub 페이지를 새로고침해보세요. 내 코드가 그대로 올라가 있을 겁니다.

앞으로 코드를 수정할 때마다 이 세 단계만 반복하면 됩니다.

```
담기(add) → 찍기(commit) → 올리기(push)
```

이 리듬만 몸에 익혀두세요. 배포의 기초 체력이 됩니다.

> **확인**: GitHub 저장소 페이지에서 내 파일 목록이 보이면 성공입니다.

## STEP 2. 어디에 배포할까 — Vercel부터 시작하기

코드가 GitHub에 올라갔으니, 이제 이걸 인터넷에 공개할 차례입니다. "배포"라고 하면 거창하게 느껴지지만, 핵심은 간단합니다. **내 코드를 서버에 올려서 URL을 받는 것**이에요.

### 2-1. 배포 플랫폼이 여러 개인 이유

배포할 수 있는 곳이 꽤 많습니다. 이름만 들어도 머리가 아플 수 있는데, 걱정하지 마세요. 바이브코딩 수준에서 고를 때 기준은 하나입니다. **얼마나 쉽게 올릴 수 있느냐.**

| 플랫폼 | 난이도 | 무료 범위 | 추천 상황 |
|--------|--------|-----------|-----------|
| **Vercel** | 쉬움 | 개인 프로젝트 충분 | Next.js, 프론트엔드 MVP |
| **Netlify** | 쉬움 | 넉넉 | 정적 사이트, 블로그 |
| **Cloudflare Pages** | 중간 | 넉넉 | Worker + 글로벌 서비스 |
| **AWS / GCP** | 어려움 | 1년 프리티어 | 회사 인프라, 대규모 서비스 |

AWS나 GCP는 강력하지만, 콘솔에 들어가는 순간 설정 화면만 몇십 개입니다. 바이브코딩에서 쓸 이유가 없습니다.

**우리는 Vercel로 갑니다.** 이유는 명확합니다.

- GitHub 연결하면 배포가 끝납니다.
- Next.js를 만든 회사라서 Next.js 프로젝트 배포가 완벽합니다.
- 개인 프로젝트 수준이면 무료 플랜으로 충분합니다.

"나중에 돈 내야 하면 어쩌죠?" 그때쯤이면 사용자가 늘어서 수익이 나고 있을 겁니다. 지금은 신경 쓰지 마세요.

### 2-2. Vercel에 배포하기

정말 클릭 몇 번이면 됩니다.

01 [vercel.com](https://vercel.com)에 **GitHub 계정으로 가입**하세요. 별도 회원가입이 필요 없습니다.

02 대시보드에서 **"Add New → Project"**를 클릭하세요.

03 GitHub 저장소 목록에서 방금 올린 `character-chat`을 찾아 **Import**를 누르세요.

![배포 플랫폼으로 서비스 올리기](/__content__/images/ch06-02.png)

04 설정 화면이 나오면 — 아직 **Deploy 버튼을 누르지 마세요.** 바로 다음 단계에서 해야 할 일이 있습니다.

> **확인**: Import까지 완료되어 배포 설정 화면이 보이면 성공입니다.

## STEP 3. 환경변수와 배포는 어떻게 연결될까

여기가 초보자분들이 가장 많이 넘어지는 지점입니다. 환경변수를 빠뜨리고 Deploy를 눌러서 에러가 나는 거죠.

### 3-1. 환경변수가 뭔가요?

로컬에서 개발할 때 `.env.local` 파일에 API 키 같은 비밀 정보를 넣어두었죠? 그 파일은 **내 컴퓨터에만** 있습니다. GitHub에는 올라가지 않습니다. 보안을 위해 `.gitignore`로 막아뒀거든요.

문제는 Vercel도 그 비밀번호를 모른다는 겁니다. 그래서 Vercel에도 따로 알려줘야 합니다.

비유하자면 이렇습니다. 여러분의 서비스는 자물쇠가 달린 금고를 쓰고 있는데, 로컬에서는 열쇠가 `.env.local` 파일에 있었습니다. 배포 서버에는 그 열쇠가 없으니 금고를 열 수 없는 거죠.

### 3-2. Vercel에 환경변수 넣기

아까 Deploy 버튼을 누르기 직전이었죠? 그 화면에서 **Environment Variables** 메뉴를 펼치세요.

01 `.env.local` 파일을 열어보세요. 거기 적혀 있는 내용을 하나씩 복사합니다.

02 Vercel의 환경변수 입력 칸에 **Key**와 **Value**를 넣으세요.

| Key | Value |
|-----|-------|
| `OPENROUTER_API_KEY` | (내 OpenRouter API 키) |
| (기타 사용 중인 서비스 키) | (해당 값) |

> 사용하는 서비스에 따라 필요한 환경변수가 다릅니다. `.env.local`에 있는 내용을 그대로 옮기면 됩니다. 데이터베이스(Supabase 등)를 추가로 사용했다면 그 키도 함께 넣어주세요.

03 다 넣었으면 이제 **Deploy** 버튼을 누르세요!

![배포 환경 설정하기](/__content__/images/ch06-03.png)

빌드가 시작되면 1~2분 정도 기다리세요. 화면에 초록색 체크 표시가 뜨면 배포 성공입니다.

### 3-3. 환경변수 하나 빠지면 이런 일이 벌어집니다

사실 저도 처음 배포할 때 환경변수를 빠뜨렸습니다. Deploy를 누르자마자 빨간 글씨로 **"Build Failed"**가 떴죠. 로그를 열어보면 이런 메시지가 나옵니다.

```
Error: Missing environment variable: OPENROUTER_API_KEY
```

당황할 필요 없습니다. 해결 방법은 간단합니다.

01 Vercel 프로젝트 → **Settings** → **Environment Variables**로 가세요.

02 빠진 환경변수를 추가하세요.

03 **Deployments** 탭에서 **Redeploy**를 누르세요.

Vercel이 다시 빌드를 시작하고, 이번에는 성공할 겁니다.

혹시 에러 메시지가 영어로 길게 나와서 뭔 소린지 모르겠다면, 그 로그를 통째로 복사해서 Claude에게 붙여넣으세요. "Vercel 배포 중에 이런 에러가 났어. 원인이랑 해결 방법 알려줘."라고 하면 됩니다. AI가 어디를 고쳐야 하는지 정확하게 알려줄 겁니다.

> **확인**: 초록색 체크 표시와 함께 `.vercel.app` 주소가 나타나면 성공입니다.

## STEP 4. 내 서비스를 링크로 공개하기

배포가 성공하면 Vercel이 URL을 하나 줍니다. `https://character-chat-xxxx.vercel.app` 같은 주소예요.

### 4-1. 첫 번째 확인 — 브라우저에서 열어보기

01 Vercel이 준 URL을 클릭하세요.

02 화면이 뜨면, 캐릭터를 선택하고 대화를 시도해보세요.

정상적으로 동작하나요? 축하드립니다. 여러분의 서비스가 인터넷에 올라갔습니다.

![배포 완료 — 내 서비스가 세상에 공개되다](/__content__/images/ch06-04.png)

### 4-2. 두 번째 확인 — 핸드폰으로 접속하기

이게 진짜 감동이 오는 순간입니다.

01 핸드폰을 꺼내세요.

02 카카오톡이든 메모장이든, 방금 받은 URL을 입력하고 접속해보세요.

03 캐릭터 채팅이 핸드폰에서도 되나요?

됩니다. 여러분이 만든 서비스가 지금 이 순간 전 세계 어디서든 접속할 수 있는 상태입니다. 내 컴퓨터 안에 갇혀 있던 것이 링크 하나로 세상에 나온 거예요.

이 링크를 친구에게 보내보세요. "나 이거 만들었어"라고요. 그 반응을 보는 순간, 배포가 왜 중요한지 온몸으로 느끼게 될 겁니다.

### 4-3. 코드를 고치면 자동으로 다시 배포됩니다

배포 후에 수정할 게 생기면 어떡할까요? 걱정 없습니다. 코드를 고치고 GitHub에 push만 하면 됩니다.

```bash
git add .
git commit -m "채팅 UI 색상 변경"
git push
```

이 세 줄을 실행하면, Vercel이 자동으로 감지하고 1~2분 안에 새 버전을 배포합니다. 별도로 Vercel에서 뭘 할 필요가 없어요. 이게 정말 편한 점입니다.

> **확인**: 코드 수정 후 push → Vercel 대시보드에 새 배포가 자동으로 시작되면 성공입니다.

## 여기서 막혔나요?

**Q. `git push`를 했는데 인증 에러가 나요.**

상황: 이런 메시지가 뜹니다.
```
remote: Permission to username/repo.git denied to username.
fatal: unable to access 'https://github.com/...': The requested URL returned error: 403
```

원인:
- GitHub에 로그인이 안 된 상태입니다.
- 예전에 저장해둔 인증 정보가 만료되었을 수 있습니다.

해결:
1. GitHub에서 **Personal Access Token**을 발급받으세요. (Settings → Developer settings → Personal access tokens)
2. `git push`를 다시 실행하면 비밀번호를 물어봅니다. 그때 토큰을 붙여넣으세요.
3. 잘 모르겠으면 Claude에게 "GitHub push 인증 에러 해결 방법 알려줘"라고 물어보세요.

**Q. Vercel에서 "Build Failed"가 떠요.**

상황: Vercel 대시보드에 빨간 글씨로 이런 메시지가 보입니다.
```
Error: Build failed
Exit code: 1
```

원인:
- 환경변수를 빠뜨렸을 가능성이 높습니다.
- 로컬에서는 잘 되지만 배포 환경에서 타입 에러가 발생할 수 있습니다.

해결:
1. Vercel의 빌드 로그를 열어서 에러 메시지를 확인하세요.
2. 에러 로그를 통째로 복사해서 Claude에게 "이 에러 원인이랑 해결 방법 알려줘"라고 붙여넣으세요.
3. 코드를 수정하고 `git add . → git commit → git push`를 하면 Vercel이 자동으로 다시 배포합니다.

**Q. 배포는 성공했는데 사이트가 안 열려요.**

상황: URL에 접속하면 빈 화면이거나 에러 페이지가 뜹니다.

원인:
- 환경변수 값이 잘못 입력되었을 수 있습니다. (오타, 앞뒤 공백 등)
- 백엔드(Supabase 등)에서 배포 주소를 허용하지 않았을 수 있습니다.

해결:
1. Vercel의 **Settings → Environment Variables**에서 값을 다시 확인하세요.
2. Supabase를 쓰고 있다면, **Authentication → URL Configuration**에 Vercel 주소를 추가하세요.
3. **Redeploy**를 눌러 다시 배포하세요.

**Q. "무료라고 했는데 나중에 요금 폭탄 맞으면 어떡하죠?"**

상황: 배포는 했지만 요금이 걱정됩니다.

원인:
- 개인 프로젝트 수준에서 Vercel 무료 플랜 한도를 넘기는 건 사실상 어렵습니다.

해결:
1. Vercel 무료 플랜은 월 100GB 대역폭, 100회 배포를 지원합니다. 개인 프로젝트에는 충분합니다.
2. 혹시 불안하다면 Vercel 대시보드의 **Usage** 탭에서 현재 사용량을 확인할 수 있습니다.
3. 트래픽이 폭발적으로 늘어날 때쯤이면 이미 수익화를 고민할 단계입니다. 그때 유료 플랜으로 전환해도 늦지 않습니다.

## 한 줄 정리

`git push` 한 번이면 내 코드가 세상에 나갑니다. 환경변수만 잊지 않으면 배포는 생각보다 쉽습니다.

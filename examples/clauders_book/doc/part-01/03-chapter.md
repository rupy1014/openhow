# 3장 — 배포해서 세상에 보여주기

자, 지난 시간에 드디어 우리만의 캐릭터 AI 챗 MVP(최소 기능 제품)를 만들었죠? 화면도 그럴싸하게 나왔고, 내가 설정한 캐릭터와 대화도 아주 잘 통합니다. 뿌듯하시죠? 그런데 한 가지 결정적인 문제가 있습니다. 이 멋진 앱을 볼 수 있는 사람은 지금 지구상에서 딱 한 명, 바로 여러분뿐이라는 거예요.

주소창을 한번 보세요. `localhost:5173` 혹은 `localhost:3000`이라고 되어 있을 겁니다. 여기서 'localhost'는 말 그대로 '내 컴퓨터'라는 뜻이에요. 친구에게 이 주소를 카톡으로 보내줘 봐야 그 친구 컴퓨터에는 아무것도 뜨지 않습니다. 

우리가 만든 이 서비스를 친구에게, 혹은 세상에 자랑하려면 '인터넷 주소'가 필요합니다. 누구나 접속할 수 있는 공개된 문을 만드는 과정, 이걸 우리는 '배포'라고 부릅니다. 오늘 우리는 이 문을 열어볼 거예요. 겁내지 마세요. 예전처럼 서버를 사고 복잡한 설정을 할 필요가 전혀 없거든요.

---

## 03.1 git과 GitHub — 무한 세이브 슬롯과 온라인 보관함

배포를 하기 전에 꼭 거쳐야 하는 관문이 있습니다. 바로 'git(깃)'과 'GitHub(깃허브)'입니다. 개발자들이 가장 많이 쓰는 도구인데, 이름이 비슷해서 헷갈리시죠? 아주 쉽게 비유해 드릴게요.

### git은 '무한 세이브 슬롯'입니다
게임을 하다가 어려운 보스 몬스터를 만나기 직전, 우리는 뭘 하죠? 맞습니다. '세이브'를 합니다. 혹시나 보스한테 져서 아이템을 다 잃더라도, 세이브했던 시점으로 되돌아가기 위해서죠.

코딩도 똑같습니다. AI와 함께 신나게 기능을 만들다 보면, 어느 순간 코드가 꼬여서 화면이 안 나올 때가 있어요. 이때 git이 없으면 "아까 잘 됐을 때로 돌아가고 싶다!"라고 울부짖어도 소용이 없습니다. 하지만 git을 쓰면 기능 하나를 만들 때마다 '세이브 포인트'를 찍어둘 수 있습니다. 언제든 원하는 시점으로 코드를 되돌릴 수 있는 마법의 시간 여행 장치인 셈이죠.

### GitHub은 '온라인 보관함'입니다
git이 내 컴퓨터 안에 있는 세이브 슬롯이라면, GitHub은 이 세이브 파일들을 인터넷 세상에 올려두는 보관소예요. 내 컴퓨터가 고장 나도 GitHub에 올려두면 코드는 안전합니다. 그리고 오늘 우리가 할 '배포'도 바로 이 GitHub에 올라온 코드를 가져다가 쓰게 됩니다.

<!-- IMG: [내 컴퓨터의 코드가 git을 통해 GitHub이라는 구름 모양 저장소로 올라가는 개념도] -->

### 실습: 첫 번째 세이브 포인트 찍기 (git commit)

자, 이제 Codex(또는 Cursor) 하단의 터미널을 보세요. 보통 `git`은 이미 설치되어 있을 겁니다. 아주 간단한 명령어 네 가지만 기억하세요. 딱 이 흐름대로만 하면 됩니다.

1. **상태 확인**: `git status` (지금 어떤 파일이 바뀌었는지 봅니다)
2. **담기**: `git add .` (바뀐 파일들을 세이브할 가방에 넣습니다)
3. **세이브 이름 붙이기**: `git commit -m "캐릭터 챗 첫 완성"` (이 세이브 파일의 이름을 붙입니다)
4. **온라인으로 보내기**: `git push` (GitHub으로 쏩니다)

처음 하시는 분들은 GitHub 계정을 만들고 내 컴퓨터와 연결하는 과정이 필요할 거예요. 이 과정은 Codex에게 이렇게 물어보세요. "내 컴퓨터의 프로젝트를 GitHub에 새로 만든 저장소(Repository)에 올리고 싶어. 단계별로 알려줘."라고요. 시키는 대로 클릭 몇 번만 하면 금방 끝납니다.

## 03.2 Vercel로 배포하기 — 내 서비스에 진짜 링크가 생긴다

GitHub에 코드를 무사히 올렸나요? 그럼 이제 진짜 마법을 부릴 시간입니다. 'Vercel(버셀)'이라는 서비스를 쓸 거예요. Vercel은 GitHub에 있는 내 코드를 가져와서, 전 세계 누구나 접속할 수 있는 `https://내-프로젝트.vercel.app` 같은 예쁜 주소를 만들어주는 곳입니다.

심지어 개인용으로는 무료예요! 예전에는 서버 한 대 빌리는 데 한 달에 몇만 원씩 들기도 했는데, 세상 참 좋아졌죠?

### Vercel 배포 3단계

1. **로그인**: [vercel.com](https://vercel.com)에 접속해서 'Continue with GitHub'으로 로그인합니다.
2. **프로젝트 연결**: 'Add New' 버튼을 누르고 'Project'를 선택하세요. 방금 여러분이 GitHub에 올린 저장소가 목록에 보일 겁니다. 'Import' 버튼을 누르세요.
3. **환경변수 입력 (중요!)**: 화면 중간에 'Environment Variables'라는 메뉴가 보일 거예요. 여기에 지난번에 우리 `.env` 파일에 넣었던 `OPENAI_API_KEY` 값을 똑같이 넣어줘야 합니다. 이 과정을 건너뛰면 배포는 되지만 AI가 대답을 못 해요.
4. **Deploy 클릭**: 이제 'Deploy' 버튼만 누르면 끝!

<!-- IMG: [Vercel 대시보드에서 GitHub 저장소를 선택하고 Deploy 버튼을 누르기 직전의 스크린샷] -->

잠시만 기다려 보세요. 화면에 불꽃놀이가 터지면서 "Congratulations!"라는 문구가 뜰 겁니다. 그리고 그 밑에 보이는 주소가 바로 여러분의 서비스 주소예요. 

자, 이제 스마트폰을 꺼내서 그 주소로 접속해 보세요. 내 컴퓨터가 꺼져 있어도, 전 세계 어디서든 여러분이 만든 캐릭터가 반갑게 인사할 겁니다. 진짜 서비스가 탄생한 순간입니다!

## 03.3 환경변수와 배포는 왜 따로 챙겨야 할까?

여기서 잠깐, 왜 환경변수를 Vercel 설정에서 따로 넣어줘야 했을까요? `.env` 파일에 이미 있는데 말이죠.

이건 보안 때문입니다. GitHub은 기본적으로 (설정에 따라 다르지만) 다른 사람도 코드를 볼 수 있는 공간이에요. 그런데 거기에 내 소중한 OpenAI API 키(돈 나가는 열쇠!)가 그대로 적힌 파일을 올리면 어떻게 될까요? 누군가 내 키를 훔쳐서 엄청나게 써버릴 수도 있겠죠.

그래서 보통 `.env` 파일은 GitHub에 올리지 않는 것이 철칙입니다. (`.gitignore`라는 파일이 이 역할을 해줍니다). 코드는 GitHub에 안전하게 올리고, 실제 서비스가 돌아가는 Vercel 서버에만 "비밀번호는 이거야"라고 살짝 알려주는 방식인 거죠. 배포할 때 환경변수를 챙기는 습관, 이건 꼭 기억하셔야 합니다.

## 03.4 링크를 보내고 반응을 받기 — 이제부터가 진짜 시작

배포 URL이 생겼다면, 이제 가장 가슴 떨리는 시간입니다. 가족이나 친구, 혹은 단톡방에 그 링크를 툭 던져보세요. 

"내가 AI 캐릭터 챗 하나 만들었는데, 한번 대화해 봐!"

<!-- IMG: [카카오톡 채팅방에 Vercel 주소를 공유하고 대화 내용이 미리보기로 뜨는 장면] -->

링크를 보내는 순간, 여러분은 '개발자'를 넘어 '서비스 운영자'가 됩니다. 그리고 예상치 못한 반응들이 오기 시작할 거예요.

- "와, 이거 진짜 너가 만든 거야? 신기하다!" (응원)
- "어, 그런데 내 폰에서는 화면이 좀 잘리는데?" (버그 제보)
- "답변 속도가 조금 느린 것 같아." (성능 피드백)
- "여기에 사진 업로드 기능도 있으면 좋겠다." (기능 제안)

혼자 만들 때는 "이 정도면 완벽해!"라고 생각했을지 모릅니다. 하지만 사용자를 만나는 순간, 우리가 미처 몰랐던 구멍들이 보이기 시작합니다. 배포는 단순히 기술적인 마무리가 아니에요. 내 아이디어가 현실에서 어떻게 작동하는지 점검받는 '진짜 공부'의 시작입니다.

## 여기서 막혔나요?

배포 후에 당황스러운 상황을 겪는 분이 꼭 계십니다. 대표적인 질문들을 모아봤습니다.

**Q. 배포는 성공했다고 뜨는데, 들어가면 화면이 하얗게만 나와요.**
**A.** 보통 '빌드 설정' 문제입니다. Vercel 설정에서 'Output Directory'가 제대로 되어 있는지 확인해 보세요. Vite를 썼다면 보통 `dist`, Next.js라면 `.next`입니다. Codex에게 "Vercel 배포했는데 화면이 하얗게 나와. 빌드 설정을 어떻게 확인해야 할까?"라고 물어보세요.

**Q. 버튼을 눌렀는데 AI가 대답을 안 해요. 에러가 난대요.**
**A.** 99% 환경변수 문제입니다. Vercel 대시보드 → Settings → Environment Variables에 가서 API 키가 정확히 입력되었는지, 오타는 없는지 확인해 보세요. 수정한 후에는 반드시 'Redeploy'를 해줘야 적용됩니다.

**Q. 모바일에서 보니까 버튼이 너무 작고 레이아웃이 깨져요.**
**A.** 내 컴퓨터의 넓은 화면만 보고 만들어서 그렇습니다. Codex에게 "지금 배포한 주소인데, 모바일에서 레이아웃이 깨져. 반응형으로 수정해줘."라고 요청하고, 수정된 코드를 다시 git에 담아서 보내보세요(push). GitHub에 올리기만 하면 Vercel이 알아서 새 버전으로 다시 배포해 줍니다. 이게 바로 자동 배포의 맛이죠!

## 한 줄 정리

git으로 세이브하고, GitHub에 보관하고, Vercel로 주소를 만듭니다. 주소가 생겨야 진짜 서비스입니다.

자, 이제 여러분의 첫 서비스가 세상에 나왔습니다. 어떠신가요? 코딩 한 줄 몰라도 AI와 대화하며 뚝딱뚝딱 만들어서 배포까지 마쳤습니다. 

여기까지 오셨으면 궁금해지실 겁니다. "그럼 나도 내가 원하는 걸 만들 수 있을까?" 다음 장에서는 바로 그 질문에 답합니다. AI에게 일을 잘 시키는 감각, 내가 풀고 싶은 문제를 찾는 법, 그리고 작게 시작해서 끝까지 가는 방법을 정리해 보겠습니다.

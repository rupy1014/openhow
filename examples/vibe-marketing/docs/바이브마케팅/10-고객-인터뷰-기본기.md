**데이터는 '무엇'을 보여주지만, 인터뷰는 '왜'를 들려준다.**

---

## 먼저 이 장면부터 보자

TeamNoteAI 팀은 확신이 있었다.
"우리 제품의 핵심 가치는 회의록 자동 정리야."

그래서 랜딩 페이지에도, 광고에도 '회의록 자동 정리'를 크게 썼다.

그런데 실제로 고객 5명에게 물어보니 이런 말이 돌아왔다.

> "회의록이 아니라 후속 메일을 빨리 보내고 싶었어요."
> "녹음 파일 다시 듣기 귀찮아서 썼어요."
> "신입 온보딩할 때 FAQ 만들기가 너무 오래 걸려서요."

팀이 생각한 이유와 고객이 말한 이유가 달랐다.
이 차이를 찾는 게 인터뷰의 목적이다.

---

## 핵심 개념

**고객 인터뷰는 '확인'이 아니라 '발견'이다.**

우리가 만든 가설을 확인하려고 하면, 듣고 싶은 말만 듣게 된다.
인터뷰의 목표는 고객의 실제 단어를 그대로 수집하는 것이다.

### 확인 질문 vs 발견 질문

| 유형 | 예시 | 문제점 |
|------|------|--------|
| 확인 질문 | "이 기능이 좋으세요?" | 고객이 "네"라고 답하기 쉽다 |
| 확인 질문 | "회의록 정리가 핵심이죠?" | 우리 가설을 강요한다 |
| 발견 질문 | "이 문제를 처음 느낀 게 언제였나요?" | 고객의 맥락이 나온다 |
| 발견 질문 | "지금은 어떻게 해결하고 있나요?" | 대안과 불편이 드러난다 |

핵심 규칙 하나만 기억하자.
**"이 기능이 좋으세요?"라고 묻지 않는다.** 그건 발견이 아니라 확인이다.

### 초보자를 위한 인터뷰 질문 5개

이 다섯 개만 순서대로 물어도 충분하다.

| 순서 | 질문 | 알 수 있는 것 |
|------|------|--------------|
| 1 | 이 문제를 처음 느낀 게 언제였나요? | 트리거 상황 |
| 2 | 지금은 어떻게 해결하고 있나요? | 현재 대안과 한계 |
| 3 | 가장 불편한 순간이 언제인가요? | 핵심 페인포인트 |
| 4 | 이 도구를 쓰기 전에 뭘 비교했나요? | 경쟁 구도와 선택 기준 |
| 5 | 써보고 나서 가장 달라진 게 뭔가요? | 실제 가치와 표현 |

TeamNoteAI 예시로 보면 이렇다.

- 질문 1 응답: "분기 리뷰 준비할 때 녹음 파일 5개를 다시 들어야 했어요."
- 질문 3 응답: "고객이 뭐라고 했는지 정확히 기억 안 나서 메일을 못 보내는 순간이요."
- 질문 5 응답: "이제 통화 끝나고 10분 안에 후속 메일을 보내요."

이 응답들이 랜딩 페이지 카피, 광고 문구, 블로그 제목의 재료가 된다.

## 이렇게 정리하면 된다

인터뷰 후 아래 표에 고객의 말을 그대로 옮겨 적는다.

| 항목 | 고객 A | 고객 B | 고객 C |
|------|--------|--------|--------|
| 처음 문제를 느낀 상황 | | | |
| 현재 해결 방법 | | | |
| 가장 불편한 순간 | | | |
| 비교한 대안 | | | |
| 쓰고 나서 달라진 점 | | | |

3명만 해도 패턴이 보이기 시작한다.
같은 단어가 반복되면 그게 고객 언어다.

## 보통 어디서 막히나

**Q. 인터뷰 대상은 어떻게 구하나요?**
가장 쉬운 방법은 최근 가입자 또는 최근 문의한 고객에게 메일을 보내는 것이다. "15분 통화로 제품 개선에 도움 주실 수 있나요?"라고 쓰면 된다. 5명이면 충분하다.

**Q. 고객이 말을 잘 안 해요.**
"좀 더 구체적으로 말씀해 주실 수 있나요?"보다는 "그때 상황을 처음부터 설명해 주실 수 있나요?"가 낫다. 상황을 떠올리게 하면 자연스럽게 말이 나온다.

**Q. 인터뷰 내용을 어디에 기록하나요?**
노션, 구글 시트, 어디든 상관없다. 중요한 건 고객의 원래 표현을 그대로 적는 것이다. 요약하지 않는다.

## Micro-Action

> 우리 제품에 맞는 인터뷰 질문 5개 초안을 작성해 보자. 위의 5개 질문을 그대로 써도 되고, 우리 상황에 맞게 바꿔도 된다. 종이 한 장이면 된다. 5분이면 충분하다.

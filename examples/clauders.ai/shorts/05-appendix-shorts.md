## [MCP 기초] 1. 엠씨피가 충전기랑 똑같다고요?

**훅:** 엠씨피? 어렵게 들리죠. 충전기 하나만 떠올리면 끝나요.

클로드 코드는 기본으로 내 컴퓨터 안에서만 놀아요.

파일 읽고, 쓰고, 터미널 명령어 돌리는 정도죠.

근데 엠씨피를 꽂으면
바깥 세상이랑 소통해요.

비유하면 유에스비 씨예요.

예전엔 기기마다 충전기가 다 달랐잖아요.

유에스비 씨가 나오니까
하나로 다 꽂죠.

엠씨피도 똑같아요.

예전엔 에이아이 도구마다
슬랙 연동을 따로 만들었어요.

엠씨피가 나오니까
하나의 규격으로 뭐든 연결해요.

노션, 슬랙, 구글 드라이브까지
이백 개 넘는 서비스에 그냥 꽂혀요.

**한 줄 정리:** 엠씨피는 에이아이용 유에스비 씨. 하나의 규격으로 바깥 서비스에 다 꽂아요.

**화면 키워드:** MCP = USB-C, 하나의 규격, 200+ 서비스, 바깥 세상과 연결

## [MCP 기초] 2. 연결은 진짜 딱 한 줄이에요

**훅:** 외부 서비스 연동, 복잡할 것 같죠? 터미널에 한 줄이면 끝나요.

엠씨피 연결은 어렵지 않아요.

클로드 코드 터미널에
명령어 한 줄만 치면 돼요.

노션을 붙이고 싶으면
`claude mcp add`로 노션 주소를 넣어요.

그게 끝이에요.

연결한 다음엔
클로드 코드를 다시 시작해요.

그리고 `/mcp`를 쳐보면
연결된 서버 목록이 나와요.

이제부터는 그냥 말로 시키면 돼요.

오늘 회의 내용 정리해서
노션에 새 페이지로 만들어줘.

이렇게요.

그럼 클로드가 노션에 직접 접근해서 처리해요.

**한 줄 정리:** 연동은 `claude mcp add` 한 줄, 확인은 `/mcp`. 그다음은 말로 시켜요.

**화면 키워드:** claude mcp add, 재시작, /mcp 확인, 말로 시키기

## [MCP 기초] 3. 엠씨피, 지금 당장 안 꽂아도 돼요

**훅:** 엠씨피 많이 꽂을수록 좋을 것 같죠? 오히려 헷갈려져요.

처음부터 엠씨피가 필요하진 않아요.

기본 도구만으로도
충분히 많은 걸 해요.

파일 읽기, 쓰기, 터미널 실행.

노션이나 슬랙 연동이
정말 필요해질 때,

그때 연결하면 돼요.

오히려 과하게 꽂아두면
`/mcp` 목록이 복잡해져요.

목록이 복잡해지면
클로드도 헷갈려해요.

그리고 헷갈리기 쉬운 게 하나 더 있어요.

엠씨피랑 에이전트는 달라요.

에이전트는 일을 맡는 담당자고,

엠씨피는 일할 때 바깥으로 뻗는 팔이에요.

담당자가 노션이 필요하면
엠씨피를 통해 노션을 쓰는 거죠.

**한 줄 정리:** 엠씨피는 필요할 때 꽂아요. 에이전트는 담당자, 엠씨피는 그 담당자의 팔이에요.

**화면 키워드:** 필요할 때 연결, 과하면 헷갈림, 에이전트=담당자, MCP=바깥으로 뻗는 팔

## [브라우저 자동화] 1. 사이트 열어서 스크린샷? 프롬프트 한 줄이면 돼요

**훅:** 매일 반복하는 브라우저 작업, 클로드한테 한 줄로 시켜보세요.

손으로 매일 반복하는 일들 있잖아요.

로그인하고,
데이터 긁고,
폼 제출하고,
스크린샷 찍고.

이걸 프롬프트 한 줄로 끝낼 수 있어요.

준비는 간단해요.

프로젝트 폴더에서
`npm install playwright`.

이게 전부예요.

그다음 클로드한테 이렇게 말해요.

플레이라이트로 네이버 열어서
스크린샷 찍어줘.

스크립트 짜서 노드로 실행해.

그럼 클로드가 스크립트를 쓰고,
노드로 실행하고,
스크린샷 파일까지 저장해서 보여줘요.

마우스로 클릭하던 일이
말 한마디로 끝나는 거예요.

**한 줄 정리:** 브라우저 반복 작업은 클로드한테 맡겨요. `npm install playwright` 한 줄이면 시작이에요.

**화면 키워드:** 로그인·스크린샷·폼 제출, npm install playwright, 프롬프트 한 줄, node 실행

## [브라우저 자동화] 2. 엠씨피랑 씨엘아이, 뭘 골라야 해요?

**훅:** 브라우저 자동화 방식이 두 갠데요. 대부분은 한쪽이 정답이에요.

브라우저 자동화엔 두 가지 방식이 있어요.

엠씨피 방식과
씨엘아이 방식이에요.

엠씨피는
클릭 하나마다 클로드가 왕복해요.

클릭했어, 결과 봤어, 다음 뭐 하지.

동작이 열 개면 왕복도 열 번.

그만큼 토큰을 많이 먹어요.

씨엘아이는 달라요.

스크립트를 한 번 짜고
노드로 한 번에 실행해요.

동작이 열 개든 백 개든
토큰은 비슷해요.

그래서 결론은 씨엘아이예요.

빠르고, 안정적이고, 저렴해요.

브라우저 자동화의 구십 퍼센트는
씨엘아이로 충분해요.

화면 보면서 조건부로 판단해야 할 때만
엠씨피를 쓰면 돼요.

**한 줄 정리:** 브라우저 자동화는 씨엘아이가 기본. 화면 보며 판단할 때만 엠씨피예요.

**화면 키워드:** MCP=클릭마다 왕복, CLI=한 번에 실행, CLI가 빠르고 저렴, 90%는 CLI

## [멀티 툴 공유 설정] 1. 에이아이 툴 여러 개 쓰면 설정부터 어긋나요

**훅:** 클로드에 커서에 코덱스까지. 설정 따로 관리하면 무조건 망해요.

에이아이 코딩 툴은 저마다
설정 폴더가 달라요.

클로드 코드는 `.claude`,
코덱스는 `.codex`,
커서는 또 따로예요.

같은 워크플로우를
여기저기 복사해두면 어떻게 될까요?

한쪽만 고치고 다른 쪽은 잊어요.

내용이 어긋나죠.

사람이 이걸 실수 없이 동기화할 수 있을까요?

없어요.

그래서 정본을 한 벌만 둬요.

`.agents` 폴더 하나에
워크플로우를 모아두는 거예요.

그리고 나머지 툴 폴더는
심볼릭 링크로 그 정본을 가리켜요.

이제 `.agents` 파일 하나만 고치면
클로드에서도, 코덱스에서도 바로 반영돼요.

**한 줄 정리:** 여러 에이아이 툴 설정은 `.agents` 정본 한 벌 + 심볼릭 링크. 따로 두면 어긋나요.

**화면 키워드:** 툴마다 다른 폴더, .agents 정본 한 벌, 심볼릭 링크로 연결, 한 번 고치면 전부 반영

## [멀티 툴 공유 설정] 2. AGENTS.md랑 CLAUDE.md, 뭘 어디에 넣어요?

**훅:** 설정 파일이 둘인데 충돌 안 하냐고요? 경계만 지키면 깔끔해요.

설정 파일이 두 개 있어요.

`AGENTS.md`랑 `CLAUDE.md`예요.

`AGENTS.md`는
여러 에이아이 툴이 공통으로 읽는 파일이에요.

코덱스, 코파일럿, 커서가
네이티브로 지원하는 업계 표준이죠.

`CLAUDE.md`는
클로드만 읽는 전용 파일이고요.

그럼 뭘 어디에 넣을까요?

공용 규칙은 `AGENTS.md`에 넣어요.

워크플로우 목록,
실행 조건,
가드레일 같은 거요.

클로드만 아는 건 `CLAUDE.md`에 넣어요.

프로젝트 구조,
개발 명령어 같은 거죠.

둘 다 있어도 충돌 안 해요.

근데 클로드 코드가 직접 읽는 건
`CLAUDE.md` 하나예요.

그래서 `AGENTS.md`를 같이 쓰려면,
`CLAUDE.md` 안에서
`@AGENTS.md`로 불러오면 돼요.

그럼 코덱스랑 커서는 `AGENTS.md`를 그대로 쓰고,
클로드는 `CLAUDE.md`로 같은 내용을 끌어와요.

이 경계만 지키면 깔끔해요.

**한 줄 정리:** 클로드 코드는 CLAUDE.md만 직접 읽어요. 공용 규칙은 AGENTS.md에 두고, CLAUDE.md에서 `@AGENTS.md`로 임포트해 같이 써요.

**화면 키워드:** AGENTS.md=공용 표준, CLAUDE.md=클로드 전용, 클로드는 CLAUDE.md만 직접 읽음, @AGENTS.md 임포트

**리뷰가 다듬어졌어. 이제 눈으로 한번 보고, 실제로 보내는 거야.**

---

## 왜 승인 단계가 필요하냐

AI가 쓴 글을 그대로 발송하면 가끔 사고가 나.

- 원문을 잘못 해석해서 반대로 쓴 리뷰
- 없는 기능을 있다고 소개
- 어제 뉴스를 오늘 뉴스처럼 보내기

그래서 **보내기 전에 한번 훑어보는 습관**이 중요해.

개인 봇이면 간단해. `content-workflow/` 폴더를 열어서 리뷰 제목이랑 한줄 요약만 훑어봐. 이상한 거 없으면 보내.

```bash
# 리뷰 목록 확인
ls content-workflow/*.md
```

나중에 팀에서 쓸 때는 Slack에 미리보기를 올리고 승인 버튼을 달 수도 있어. 하지만 지금은 눈으로 확인하는 것만으로 충분해.

---

## 어디로 보내냐 — 쉬운 것부터

보내는 방법은 채널마다 달라. 쉬운 것부터 정리하면:

### Slack / Discord 웹훅이 제일 쉬워

**웹훅 URL 하나면 끝이야.**

슬랙이나 디스코드 설정에서 "수신 웹훅"을 만들면 URL이 하나 나와. 그 URL로 메시지를 보내면 채널에 알림이 와.

```
> 슬랙 웹훅으로 매일 뉴스레터를 보내는 기능 만들어줘.
> 웹훅 URL은 .env에 SLACK_WEBHOOK_URL로 넣을게.
```

OAuth 같은 복잡한 인증이 없어. URL 하나면 돼.

:::info 웹훅이 뭐야?
"이 주소로 메시지를 보내면 채널에 알림이 뜨게 해줘" 하는 URL이야. 슬랙이나 디스코드 채널 설정에서 만들 수 있어.
:::

### 카카오톡 나에게 보내기는 어떻게 하냐

카카오 API를 써야 해. 단계가 좀 있지만 Claude Code가 안내해줘:

```
> 카카오톡 나에게 보내기로 뉴스레터를 전송하는 기능 만들어줘.
> 카카오 API 설정 방법도 알려줘.
```

**Step 1.** [Kakao Developers](https://developers.kakao.com/)에서 앱 만들기

**Step 2.** "카카오톡 메시지" 권한 활성화

**Step 3.** OAuth 토큰 발급

**Step 4.** `.env`에 토큰 저장

바이브코딩에서 `.env`에 API 키 넣어봤잖아. 같은 거야. "카카오 API의 임시 비밀번호"를 `.env`에 넣는 거야.

:::info 토큰이 뭐야?
API를 쓰기 위한 임시 비밀번호야. "나 인증된 사람이야"를 증명하는 거야. 바이브코딩에서 Vercel에 환경변수 넣었잖아. 그거랑 같은 개념이야.
:::

### Threads는 뭐가 더 필요하냐

Meta에서 제공하는 API야. Instagram 계정 + Meta Developer 앱이 필요해.

```
> Threads API로 포스팅하는 기능 만들어줘.
> 쓰레드 형식으로 280자씩 이어서 올리게.
```

OAuth 인증이 필요해서 슬랙보다 복잡하지만, Claude Code가 셋업 과정을 안내해줘.

### 웹사이트에 올리려면 어떻게 하냐

바이브코딩에서 Vercel 배포 해봤잖아. 같은 방식이야.

리뷰를 Supabase DB에 넣으면 웹사이트에 자동으로 뜨게 할 수 있어:

```bash
./scripts/deploy-content.sh --new-only
```

---

## 뭐부터 시작하면 좋냐

| 난이도 | 채널 | 필요한 것 |
|--------|------|----------|
| 쉬움 | Slack / Discord | 웹훅 URL 하나 |
| 보통 | 카카오톡 | Kakao Developer 앱 + 토큰 |
| 보통 | 이메일 | SMTP 설정 또는 SendGrid API |
| 어려움 | Threads | Meta Developer 앱 + OAuth |
| 이미 해봤음 | 웹사이트 | Supabase + Vercel |

**추천: Slack 웹훅부터 시작해.** 5분이면 되고, 성공하면 다른 채널도 같은 패턴이야.

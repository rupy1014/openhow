**KIMES 세미나에서 실제로 쓴 24장짜리 인터랙티브 발표 자료. PPT 안 열었어.**

스크롤하면 텍스트가 등장하고, 차트가 그려지고, 로고가 펼쳐져.
이걸 Claude Code한테 만들게 했어.

## 앞에서 배운 거랑 뭐가 달라?

[바이브 PPT 기본편](/AI로일하기-바이브PPT)에서는 마크다운 → HTML 한 파일로 뽑았잖아.

그건 내부 발표나 빠른 공유용으로 충분해.
근데 **컨퍼런스 무대**에서 쓰려면 이 정도론 부족해.

```
기본편:
  마크다운 → HTML 단일 파일 → 정적 슬라이드

프로편:
  사업 문서 + 요구사항 → React 앱 → 스크롤 애니메이션, 인터랙션
```

차이가 뭐냐:

| | 기본편 | 프로편 |
|---|---|---|
| 결과물 | HTML 파일 1개 | React 웹앱 |
| 애니메이션 | 없음 | 스크롤 트리거 애니메이션 |
| 네비게이션 | 수동 스크롤 | 스크롤 스냅 + 키보드 + 인디케이터 |
| 디자인 | AI 자유 재량 | 디자인 시스템 (Carbon) + 브랜드 컬러 |
| 용도 | 내부 공유, 빠른 발표 | 컨퍼런스, 세미나, 고객 프레젠테이션 |

## 어떻게 만들었어?

세 단계야.

**Step 1.** 사업 문서를 마크다운으로 정리해

발표에 들어갈 내용을 마크다운 파일로 써.
슬라이드별 내용이 아니라, **사업 도메인 문서**를 먼저 만들어.

```
business docs/
├── 닥톡예약 개요.md        ← 서비스별 설명
├── 닥톡광고 개요.md
├── 닥톡AI 의료광고 자동심의 개요.md
├── 닥톡AI 환자메세지 개요.md
└── 닥프렌즈 비지니스 개요.md  ← 전체 사업 맥락
```

이게 핵심이야. 슬라이드를 먼저 생각하지 마. **내용을 먼저 정리해.**

AI가 이 문서들을 읽고 슬라이드에 들어갈 핵심 메시지를 뽑아.

**Step 2.** 요구사항 문서(requirement.md)를 써

이게 PPT의 기획서 역할이야. 각 슬라이드 섹터별로 이렇게 써:

```markdown
## Slide Sector 1. 8조 의료 광고 시장의 맹점

### 비주얼 지시사항
- **좌측:** 시장 규모 인포그래픽
- **중앙:** 파편화된 광고 채널 로고 나열
- **우측:** '데이터 사일로'를 상징하는 단절된 기둥들
- **하단:** 연결 고리 아이콘 배치

### 스크립트
> 우리나라 의료 광고 시장은 8조 원 규모로 성장했고,
> 그중 5조 원이 온라인에서 집행되고 있습니다.
> 하지만 클릭은 많은데 실제 예약은 얼마나 된 거지?...
```

포인트가 세 가지야:

1. **비주얼 지시사항** — 레이아웃, 위치, 강조할 수치를 구체적으로
2. **스크립트** — 발표자가 할 말. AI가 여기서 핵심 텍스트를 추출해
3. **디자인 규칙** — 브랜드 컬러, 폰트, 간격을 문서 상단에 한번 정의해놓으면 전체에 적용돼

**Step 3.** Claude Code에 생성 요청해

```
> business docs/ 폴더의 사업 문서들과 requirement.md를 읽고
> 웹 기반 세미나 슬라이드를 만들어줘.
> React + Vite로, 슬라이드당 100vh 전체화면,
> 스크롤 스냅으로 넘어가게.
> GSAP으로 스크롤 시 요소가 등장하는 애니메이션 넣어줘.
```

그러면 이런 구조가 나와:

```
app/src/components/slides/
├── Slide01_Title.jsx
├── Slide02_MarketEnv.jsx
├── Slide03_MarketSize.jsx
├── ...
└── Slide17_OutroVision.jsx   ← 24개 슬라이드
```

## AI가 만든 코드가 어떻게 생겼어?

슬라이드 하나를 보면 이래:

```jsx
export default function Slide01_Title() {
  const ref = useRef(null)

  // 스크롤하면 애니메이션 시작
  useSlideAnimation(ref, (gsap) => {
    const tl = gsap.timeline({ defaults: { ease: 'power3.out' } })
    tl.from('.s01-bg', { opacity: 0, duration: 1.5 })
      .from('.s01-title', { opacity: 0, y: 30, duration: 0.8 }, '-=0.4')
      .from('.s01-subtitle', { opacity: 0, y: 20, duration: 0.6 }, '-=0.4')
  })

  return (
    <section ref={ref} className="slide">
      <h1 className="s01-title">2026년 병원 경영의 뉴노멀</h1>
      <p className="s01-subtitle">내원 환자를 늘리는 플랫폼 예약과...</p>
    </section>
  )
}
```

`useSlideAnimation`이라는 커스텀 훅이 있어.
슬라이드가 화면에 들어오면 GSAP 타임라인이 실행돼서 요소들이 순서대로 나타나.

이 패턴이 24개 슬라이드에 반복돼. AI가 한번 패턴을 잡으면 나머지는 찍어내.

## 이 방식의 핵심이 뭐야?

**requirement.md가 PPT 기획서를 대체해.**

기존 방식은 이래:

```
PPT 기획서 (워드) → 디자이너한테 전달 → 시안 → 수정 → 수정 → 완성
```

바이브 방식은 이래:

```
requirement.md + 사업 문서 → Claude Code → 웹앱 → 피드백 → 바로 수정
```

requirement.md를 잘 쓰면 디자이너 없이 컨퍼런스급 발표자료가 나와.
"잘 쓴다"는 건 이런 거야:

| 이렇게 쓰면 | AI가 이렇게 해석해 |
|---|---|
| "허브 앤 스포크 구조로" | 중앙에 핵심, 주변에 연결 요소 배치 |
| "좌측에 플랫폼, 우측에 EMR 파트너" | 2단 레이아웃 |
| "신규 환자 14% 성장 강조" | 큰 폰트 + 브랜드 컬러 + 화살표 |
| "Flow Chart: 광고 노출 → 클릭 → 예약 → 접수" | 수평 흐름도 컴포넌트 |

**비주얼을 말로 설명**하는 거야. AI가 그걸 코드로 바꿔.

## 피드백 루프는 어떻게 돌려?

한 번에 완벽하게 안 나와. 당연해.

```
> 3번 슬라이드 숫자가 너무 작아. 8조를 3배 크게 키워줘.
> 로고 순서를 네이버 → 카카오 → 당근 → 강남언니 순으로 바꿔.
> 6번 슬라이드 애니메이션이 너무 빨라. 0.3초씩 더 느리게.
```

PPT에서 마우스로 드래그하고 정렬하는 거랑 비교해봐.
**말로 수정**하는 게 훨씬 빨라. 특히 일관된 수정(전체 폰트 크기, 색상 톤)은 한마디면 돼.

## 꼭 React를 써야 해?

아니. React는 선택지 중 하나야.

| 스택 | 장점 | 언제 써 |
|------|------|---------|
| **HTML 단일 파일** | 가장 간단. 바로 열 수 있어 | 내부 공유, 빠른 발표 |
| **React + Vite** | 컴포넌트 재사용, 애니메이션 자유도 | 컨퍼런스, 세미나 |
| **Slidev (Vue)** | 마크다운 기반, 라이브 코딩 지원 | 개발자 밋업 |
| **Reveal.js** | 플러그인 풍부, 설치 간단 | 범용 |

핵심은 도구가 아니야. **requirement.md를 얼마나 구체적으로 쓰냐**가 결과물 품질을 결정해.

## 한 줄 정리

사업 문서 + 요구사항 문서를 잘 쓰면, AI가 컨퍼런스급 인터랙티브 발표 자료를 만들어줘. 디자이너 없이.

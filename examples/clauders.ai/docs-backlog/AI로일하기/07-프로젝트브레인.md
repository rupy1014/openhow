**5년간 모은 자료 1,300건, CSV 파일, 분석 리포트 — 이걸 AI가 통째로 이해하고 있으면?**

숙제를 하나 받았다고 치자. 기획자 커뮤니티에서 5년 동안 1,300건의 실무 자료를 모았어. 면접 준비, UX 가이드, 기획서 샘플, IT 트렌드까지. 이걸 기반으로 구독서비스를 만들어야 해. 방향성을 잡아야 돼 — 어떤 식으로 설계해야 사람들이 참여하고, 매출도 올리고, 좋은 생태계를 만들 수 있을까?

혼자 머리 싸매고 기획하는 대신, NotebookLM에 소스를 올리고, 더 찾게 시키고, MCP로 데이터를 땡겨와서 **내 프로젝트만의 AI 두뇌**를 만드는 거야.

---

## NotebookLM이 뭐냐

Google이 만든 AI 리서치 도구야. [notebooklm.google.com](https://notebooklm.google.com)

핵심은 **소스 기반 답변**이야. 네가 올린 문서만 근거로 답변해. 헛소리(할루시네이션)가 거의 없어.

| 일반 AI 채팅 | NotebookLM |
|-------------|------------|
| 학습된 지식으로 답변 | **네가 올린 문서**로만 답변 |
| 출처 불명확 | 출처(소스) 표시됨 |
| 프로젝트 맥락 모름 | 프로젝트 전체를 이해한 상태 |

PDF, Google Docs, 웹페이지 URL, 텍스트 — 다 올릴 수 있어. 올리면 AI가 전부 읽고, 그 안에서 답변해줘.

---

## 뭐가 만들어지냐

실제 프로젝트 하나를 예시로 보여줄게.

**맥비(macbe)** — 기획자 커뮤니티에서 5년간 모은 자료를 정리하는 프로젝트야. 구독서비스를 만들기 위해 전수조사부터 시작했어.

```
프로젝트 문서들:
├── data/
│   ├── cleaned_resources.csv   ← 정제된 데이터 (1,324건)
│   └── VALIDATION_REPORT.md    ← 링크 검증 리포트
├── docs/report-202604/
│   ├── data-report-202604.md   ← 전수조사 결과 보고서
│   ├── 01_전체자료/             ← 검증 완료 894건 CSV
│   ├── 02_수동검토필요/         ← 수동 확인 필요 149건
│   ├── 03_카테고리별/           ← 12개 주제별 분류
│   ├── 05_본문텍스트/           ← 894개 본문 마크다운
│   └── 06_PDF원본/             ← Drive에서 받은 PDF 36건
└── scripts/                    ← 데이터 파이프라인
```

1,324건을 정제하고 링크를 검증해서 894건이 살아있었어. 12개 카테고리로 분류하고, 품질 등급(A~D)까지 매겼어. 여기에 전수조사 보고서, 카테고리 분석, 한계점까지 정리한 문서가 있어.

이걸 전부 NotebookLM에 올리면, AI가 프로젝트 전체를 이해한 상태에서 답변해.

"894건 중 A+B 등급 자료만으로 구독서비스를 설계하려면 어떤 카테고리에 집중해야 해?"라고 물으면, 데이터 + 보고서를 다 읽은 상태에서 대답해줘.

## 어떻게 NotebookLM에 올리냐

**Step 1.** NotebookLM에서 새 노트북을 만들어

```
> NotebookLM에 "macbe-brain"이라는 노트북 만들어줘.
```

**Step 2.** 프로젝트 핵심 문서를 소스로 추가해

```
> 이 파일들을 소스로 올려줘:
> - data-report-202604.md (전수조사 결과 보고서)
> - cleaned_resources.csv (1,324건 정제 데이터)
> - VALIDATION_REPORT.md (링크 검증 결과)
```

:::info 뭘 올려야 해?
코드 파일 말고, **프로젝트를 설명하는 문서**를 올려. 전수조사 보고서, 데이터 CSV, 분석 자료. AI가 "이 프로젝트가 뭘 하려는 건지, 데이터가 어떤 상태인지" 이해할 수 있는 것들이야.
:::

**Step 3.** 올린 소스를 확인해

```
> macbe-brain 노트북에 소스가 잘 올라갔는지 확인해줘.
```

여기까지가 기본 세팅이야. 이제 NotebookLM이 너의 프로젝트를 "읽은" 상태야.

---

## 더 찾게 시키면 뭐가 달라지냐

소스만 올리면 NotebookLM은 올린 문서 안에서만 답해.

근데 **리서치 기능**을 쓰면 웹에서 관련 자료를 더 찾아와.

**Step 1.** 리서치를 시작해

```
> macbe-brain 노트북에서 리서치 시작해줘.
> 주제: "기획자/PM 대상 구독 서비스 사례, 큐레이션 뉴스레터 수익 모델, 커뮤니티 기반 유료화 전략"
```

NotebookLM이 웹에서 관련 기사, 블로그, 논문을 찾아서 노트북에 추가해.

**Step 2.** 리서치 결과를 확인해

```
> 리서치 상태 확인해줘. 끝났으면 어떤 자료를 찾았는지 알려줘.
```

이제 전수조사 보고서 + 1,324건 데이터 + **웹에서 찾은 구독서비스 사례**까지 합쳐진 상태야.

"우리 자료의 77%가 2021년 이전인데, 이 한계를 감안하면 어떤 구독 모델이 맞아?"라고 물으면, 내 데이터의 현실 + 외부 사례를 같이 참고해서 답해줘.

## NotebookLM MCP가 뭐냐

여기가 핵심이야. NotebookLM에 쌓인 지식을 **내 작업 환경으로** 가져오는 거야.

[notebooklm-mcp](https://github.com/PleasePrompto/notebooklm-mcp) — NotebookLM을 Claude Code에서 직접 쓸 수 있게 해주는 MCP 서버야.

설치는 한 줄이야:

```bash
claude mcp add notebooklm -- npx -y notebooklm-mcp
```

이러면 Claude Code 안에서 노트북을 만들고, 소스를 올리고, 질문하고, 리서치를 시키는 게 전부 가능해져.

위에서 한 작업을 터미널 떠나지 않고 다 할 수 있어.

---

## MCP로 데이터를 어떻게 땡겨오냐

MCP가 설치돼 있으면, Claude Code 안에서 바로 질문하고 답변을 파일로 저장할 수 있어.

```
> macbe-brain 노트북에 물어봐:
> "894건 중 A+B 등급 자료만으로 구독서비스를 설계하려면
> 어떤 카테고리에 집중해야 해?"
> 답변을 docs/subscription-roadmap.md로 저장해.
```

이렇게 하면 NotebookLM에 쌓인 지식이 프로젝트 안에 마크다운 파일로 정리돼. 꼬리질문으로 기획을 구체화하면서, 의사결정의 근거가 자동으로 문서화되는 거야.

**핵심은 CLAUDE.md야.** 정리된 파일 경로를 적어두면, Claude Code가 프로젝트 시작할 때 자동으로 참고해.

```markdown
## 프로젝트 지식베이스
- docs/data-report-202604.md — 전수조사 결과
- docs/subscription-roadmap.md — 콘텐츠 로드맵
```

더 깊이 들어가면 전처리 → 벡터 DB → RAG 파이프라인도 가능한데, 그건 별도 아티클에서 다룰게.

## 한 줄 정리

1,300건의 자료와 전수조사 보고서를 NotebookLM에 올리고, 구독서비스 사례를 더 찾게 시키고, MCP로 가져와서 기획 문서로 정리하면 — AI가 네 데이터의 현실(한계 포함)을 이해한 상태에서 기획을 도와줘. 다음은 이걸 자동화하는 거야.

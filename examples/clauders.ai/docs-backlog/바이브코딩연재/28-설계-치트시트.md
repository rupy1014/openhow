## 자료구조 선택 가이드

| 상황 | 자료구조 | 예시 |
|------|----------|------|
| 순서대로 나열 | **배열** | 할 일 목록, 댓글, 주문 내역 |
| 이름표로 찾기 | **객체** | 사용자 정보, 앱 설정, 폼 데이터 |
| 계층 구조 (그룹 안에 그룹) | **트리** (배열 + parentId) | 카테고리, 댓글-대댓글, 조직도 |
| 중복 없는 목록 | **Set** | 태그, 좋아요한 유저 ID |
| 빠른 검색 (키→값) | **Map** | 캐시, ID로 데이터 조회 |
| 순서대로 처리 | **큐** (FIFO) | 이메일 발송, 주문 처리, 알림 |
| 최근 거 먼저 | **스택** (LIFO) | Undo, 뒤로가기, 최근 기록 |

**가장 많이 쓰는 조합:** 배열 안에 객체

```json
[
  { "id": 1, "title": "밥 먹기", "completed": false },
  { "id": 2, "title": "코딩하기", "completed": true }
]
```

## 아키텍처 패턴 비교

| 패턴 | 구조 | 언제 쓰냐 | AI한테 말하는 법 |
|------|------|-----------|----------------|
| **레이어드** | UI → 서비스 → 데이터 | 대부분의 프로젝트 (처음 시작할 때) | "레이어드로 폴더 나눠줘" |
| **MVC** | Model-View-Controller | 프론트엔드 (화면+로직 분리) | "MVC 패턴으로 분리해줘" |
| **클린** | 핵심 로직 ↔ 외부 기술 분리 | 파일 50개 이상, 기술 스택 바꿀 수 있을 때 | "클린 아키텍처로 리팩토링 제안해줘" |

**레이어드 폴더 구조 (가장 자주 씀):**

```
프로젝트/
├── components/     ← 1층: UI (화면)
│   ├── TodoList/
│   ├── TodoForm/
│   └── TodoItem/
├── services/       ← 2층: 비즈니스 로직
│   └── todoService.ts
├── lib/            ← 3층: 데이터 (DB 접근)
│   └── supabase.ts
└── store/          ← 상태 관리
    └── useTodoStore.ts
```

**규칙:** UI → 서비스 → 데이터. 위에서 아래로만 호출. UI가 DB에 직접 접근 금지.

## 디자인 패턴 빠른 참조

### 팩토리 (Factory) -- 비슷한 걸 찍어내기

```typescript
// 버튼 타입별 생성
function createButton(type: 'primary' | 'secondary' | 'danger') {
  const styles = {
    primary:   { bg: 'blue',  text: 'white' },
    secondary: { bg: 'gray',  text: 'black' },
    danger:    { bg: 'red',   text: 'white' },
  }
  return styles[type]
}
```

**언제:** 버튼/카드/알림 여러 종류. "팩토리 패턴으로 타입별 생성해줘"

### 옵저버 (Observer) -- 하나 바뀌면 전체 업데이트

```typescript
// zustand가 옵저버 패턴을 구현해줌
const useStore = create((set) => ({
  user: null,
  setUser: (user) => set({ user }),  // user 바뀌면 구독자 전체 업데이트
}))
```

**언제:** 로그인/장바구니/실시간 알림. "옵저버 패턴으로 자동 업데이트되게"

### 전략 (Strategy) -- 같은 목적, 다른 방법

```typescript
// 결제 전략
interface PaymentStrategy {
  pay(amount: number): Promise<void>
}

class CardPayment implements PaymentStrategy { /* ... */ }
class BankTransfer implements PaymentStrategy { /* ... */ }
class KakaoPay implements PaymentStrategy { /* ... */ }

// 사용: 전략만 교체
async function checkout(strategy: PaymentStrategy, amount: number) {
  await strategy.pay(amount)
}
```

**언제:** 결제 수단/정렬 기준/로그인 방법 여러 개. "전략 패턴으로 해줘"

### Container-Presenter -- 로직과 UI 분리

```
TodoListContainer.tsx  → 데이터 가져오기, 상태 관리 (로직)
TodoListPresenter.tsx  → 받은 데이터로 화면만 그리기 (UI)
```

**언제:** 프론트엔드 컴포넌트 대부분. "Container-Presenter로 분리해줘"

### 싱글톤 (Singleton) -- 딱 하나만

**언제:** 로그인 상태, 앱 설정, DB 연결. "앱 전체에서 하나만 만들어줘"

## 상태 관리 결정 트리

```
이 데이터를 다른 기기에서도 봐야 해?
├── YES → 서버 DB (Supabase, Firebase 등)
└── NO
    └── 새로고침해도 유지되어야 해?
        ├── YES → localStorage
        └── NO
            └── 여러 페이지/컴포넌트에서 같이 써?
                ├── YES → 전역 상태 (zustand, Context)
                └── NO  → 로컬 상태 (useState)
```

**실전 조합 패턴:**

| 데이터 | 조합 | 이유 |
|--------|------|------|
| 로그인 상태 | 전역 + localStorage + DB | 앱 공유 + 새로고침 유지 + 서버 인증 |
| 장바구니 (비로그인) | 전역 + localStorage | 앱 공유 + 새로고침 유지 |
| 장바구니 (로그인) | 전역 + DB | 앱 공유 + 다른 기기 동기화 |
| 다크모드 | 전역 + localStorage | 앱 공유 + 새로고침 유지 |
| 검색창 입력 | 로컬 상태 | 잠깐 쓰고 버림 |
| 게시글 작성 중 | 로컬 → localStorage(임시저장) → DB(완료) | 단계별로 다름 |

## AI 설계 지시 템플릿

### 프로젝트 시작할 때

```
나: "{서비스명} 만들 건데, {프론트엔드} + {백엔드} 쓸 거야.

    아키텍처: 레이어드 (components / services / lib)
    상태 관리: {도구} (전역: 로그인, 장바구니 / 로컬: 입력 폼)
    DB: {서비스}의 {테이블명} 테이블

    구조부터 정하고 만들자."
```

### 기능 추가할 때

```
나: "{기능} 추가할 건데,
    데이터는 {자료구조}로 관리해줘.
    {패턴} 패턴으로 만들어줘.
    상태는 {저장위치}에 둘 거야."
```

### 리팩토링할 때

```
나: "{파일/폴더}가 복잡해졌어.
    {현재 문제} 때문에 수정하기 어려워.
    {원하는 구조}로 정리해줘."
```

### 실전 예시 (할 일 관리 앱)

```
나: "할 일 관리 웹앱 만들 건데, Next.js + Supabase + zustand 쓸 거야.

    아키텍처: 레이어드 (components / services / lib)
    상태: zustand(전역: user, todos) + Supabase(DB: 영구 저장)
    컴포넌트: Container-Presenter 패턴으로 분리
    데이터: todos는 배열, 각 항목은 객체 { id, title, is_completed }

    기능 단위로 하나씩 만들자. 로그인부터."
```

## 설계 대화 5단계 체크리스트

```
□ 1단계: 기술 스택 정했나? (프론트/백엔드/상태관리/DB)
□ 2단계: 아키텍처 정했나? (레이어드 폴더 구조)
□ 3단계: 데이터 설계했나? (테이블 + 자료구조 + 상태 위치)
□ 4단계: 컴포넌트 구조 정했나? (패턴 적용)
□ 5단계: 기능별로 만들고 확인했나? (한 번에 다 만들지 않기)
```

**잊지 마:** "만들어줘" 전에 구조부터. 기능 하나 만들 때마다 직접 확인.

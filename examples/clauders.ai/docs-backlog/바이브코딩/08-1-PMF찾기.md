**MVP는 3일이면 돼. 근데 MLP로 키우는 건 3개월이야.**

바이브코딩의 진짜 병목은 코딩이 아니야. **MVP를 사랑받는 제품(MLP)으로 키우는 것**이야.

---

## MVP 3일, MLP 3개월

MVP를 배포했어. 5명한테 피드백도 받았어.

근데 여기서 끝이 아니야. 여기서부터가 진짜 시작이야.

| 단계 | 걸리는 시간 | 하는 일 |
|------|-----------|--------|
| MVP 만들기 | 3일 | 아이디어 → 기획 → 빌드 → 배포 |
| **MLP로 키우기** | **3개월** | **피드백 → 다듬기 → 유통 → 매출 → 반복** |
| 스케일업 | 그 이후 | 사용자 확장, 기능 추가, 팀 빌딩 |

이 3개월 여정의 목표가 **PMF**(Product-Market Fit) = 제품-시장 적합성.

쉽게 말하면: **"사람들이 네 제품을 필요로 하는 상태."** MVP가 MLP가 되고, PMF에 도달하면 성공이야.

Marc Andreessen(a16z 공동창업자)이 이렇게 말했어:

> "PMF를 찾으면 느껴진다. 고객이 만드는 속도만큼 빠르게 사간다."

반대로, PMF가 없으면? 아무리 홍보해도 안 써. 할인해도 안 써. 기능 추가해도 안 써. **시장이 원하는 게 아니니까.**

---

## 바이브코딩에서 왜 여기가 제일 오래 걸려?

만드는 건 AI가 해줘. 3일이면 MVP가 나와.

근데 MLP로 키우는 건 AI가 못 해줘. **사람이 해야 해.**

```
AI가 해주는 것: 코드 작성, 버그 수정, UI 다듬기
사람이 해야 하는 것: 누가 쓸지, 왜 쓸지, 어디서 알릴지, 얼마에 팔지
```

바이브코딩으로 만든 앱이 쏟아져. 비슷한 거 10개 중 1~2개만 살아남아. 살아남는 건 코드가 좋아서가 아니야. **시장을 찾아서야.**

---

## PMF를 어떻게 알아?

감으로는 몰라. 숫자로 봐.

**1. Sean Ellis 테스트 — "없으면 실망해?"**

사용자한테 물어봐:

```
"이 서비스가 내일 사라지면 어떨 것 같아?"
- 매우 실망할 거야
- 좀 실망할 거야
- 별로 상관없어
```

**"매우 실망"이 40% 넘으면 PMF야.** 이게 가장 검증된 지표야.

20% 이하면? 방향을 바꿔야 해. 20~40%면? 다듬으면 가능성 있어.

**2. 돌아오는지 — "두 번째도 쓰냐?"**

처음 써보는 건 호기심이야. **두 번째 쓰는 건 필요해서야.**

```
❌ 100명이 가입했는데 2주 뒤에 5명만 남았어
✅ 30명이 가입했는데 2주 뒤에도 15명이 매일 써
```

AI 제품에서는 이걸 **second-bite usage**라고 불러. 첫 번째 작업이 끝나고 "다음 것도 여기서 하자"고 돌아오는 비율.

**3. 돈을 내는지 — "지갑을 여냐?"**

"좋아요" 100개보다 **결제 1건**이 더 강한 신호야.

무료로 쓰는 건 쉬워. 돈을 내는 건 "이거 없으면 안 돼"라는 증거야.

---

## 3개월 동안 뭘 해?

PMF는 한 번에 찾는 게 아니야. **반복해서 찾아가는 거야.**

### 1단계: 다듬기 (1~4주)

MVP를 배포하고 피드백을 받았어. 이제 **경험을 다듬어.** MVP를 MLP로 키우는 단계야.

```
❌ 기능을 추가해 (로그인, 결제, 다크모드...)
✅ 기존 기능을 좋게 만들어 (속도, UX, 문구, 첫인상)
```

"대화가 재밌는데 로딩이 느려" → 로딩을 잡아.
"첫 화면이 뭔지 모르겠어" → 온보딩을 다듬어.
"답변이 딱딱해" → 프롬프트를 고쳐.

이 단계에서 기능 추가 충동을 참아야 해. **넓게 퍼지지 말고 깊게 파.**

### 2단계: 유통 (2~6주)

좋은 제품도 아무도 모르면 안 써.

**바이브코딩으로 만든 제품의 유통 채널:**

| 채널 | 어떻게 | 효과 |
|------|--------|------|
| 지인 공유 | "이거 써봐" 직접 보내기 | 첫 50명 |
| 커뮤니티 | 디스코드, 슬랙, 레딧, 블라인드 | 관심 있는 사람들이 모여있어 |
| SNS | X(트위터), 인스타, 스레드 | 만드는 과정을 공유하면 관심 생겨 |
| Product Hunt | 런칭 페이지 올리기 | 해외 사용자 유입 |
| 블로그/뉴스레터 | "이걸 왜 만들었는지" 글쓰기 | 검색으로 장기 유입 |

**"만드는 과정을 공유하는 것" 자체가 마케팅이야.** Build in Public이라고 해.

"오늘 이 기능 다듬었어" 한 줄이 광고 100만원보다 나을 수 있어.

### 3단계: 검증 (4~8주)

숫자를 보기 시작해.

```
- 주간 활성 사용자 (WAU) 가 늘고 있어?
- 돌아오는 사용자 비율이 30% 넘어?
- "매우 실망" 비율이 40% 향해 가고 있어?
- 유료 전환이 생기고 있어?
```

수치가 안 오르면? **두 가지 중 하나야:**

```
A. 제품이 아직 부족해 → 다듬기로 돌아가 (1단계)
B. 시장이 아니야 → 방향을 바꿔 (피벗)
```

피벗은 실패가 아니야. 3개월 안에 방향을 바꾸는 건 빠른 거야.

### 4단계: 첫 매출 (8~12주)

PMF의 가장 확실한 증거는 **돈을 내는 사람이 있다는 거야.**

```
목표:
- 의미 있는 첫 매출 (유료 사용자 10명)
- 또는 충성 사용자 100명 (매일 쓰는 사람)
```

첫 매출 10건이면 "이 방향이 맞다"는 확신이 생겨.

100명이 매일 쓰면? 유료 전환은 시간문제야.

---

## 1,000명의 진짜 팬

Kevin Kelly(Wired 공동창업자)의 유명한 글이 있어:

> "1,000명의 진짜 팬만 있으면 먹고살 수 있다."

진짜 팬 = 네가 만드는 건 뭐든 쓰는 사람. 유료 구독자, 매일 접속하는 사용자.

1,000명 × 월 $10 = 월 $10,000. 1인 서비스로 충분한 수익이야.

바이브코딩으로 만든 서비스의 목표는 100만 명이 아니야.

**1,000명이 진짜로 좋아하는 서비스.**

```
❌ 100만 명이 한 번 써보는 서비스
✅ 1,000명이 매일 쓰는 서비스
```

---

## 바이브코딩의 강점이 여기서 빛나

이 3개월 동안 바이브코딩의 진짜 강점이 나와.

전통적으로는 피드백 받고 → 개발팀한테 요청 → 2주 뒤에 반영.

바이브코딩은? 피드백 받고 → AI한테 "이거 고쳐" → **30분 뒤에 반영.**

```
전통 방식: 피드백 → 2주 → 반영 → 2주 → 피드백 (월 2회 반복)
바이브코딩: 피드백 → 30분 → 반영 → 피드백 (하루 5회 반복 가능)
```

**3개월 동안 반복 속도가 10배 빨라.** 같은 기간에 다른 사람의 10배를 시도할 수 있어.

이게 PMF를 찾을 확률을 높이는 거야.

---

## 한 줄 정리

MVP 3일, MLP 3개월. 만드는 건 AI가 해주지만, 사랑받는 제품으로 키우는 건 네가 해.

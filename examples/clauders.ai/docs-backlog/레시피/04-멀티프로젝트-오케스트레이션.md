**프로젝트가 여러 개면 Codex 하나로는 안 돼.**

앞에서 Claude + Codex 2인 체제를 배웠어.
근데 실무에서는 프로젝트가 하나가 아니거든.

---

## 어떤 상황이야?

쇼핑몰을 만들고 있다고 치자. API 3개, 프론트 2개, 공유 데이터 1개.

```
my-shop/
├── projects/
│   ├── shop-api/       ← 고객용 API
│   ├── admin-api/      ← 관리자용 API
│   ├── noti-api/       ← 알림 API
│   ├── shop-web/       ← 고객 페이지
│   └── admin-web/      ← 관리 페이지
└── _shared/
    └── models/         ← 3개 API가 공유
```

이걸 한 곳에서 관리하면서 Codex를 프로젝트별로 보내야 해.

---

## 뭐가 문제야?

두 가지야.

**1. 매번 전체 경로를 쳐야 해.** 5개 프로젝트면 5번.

**2. 공유 데이터.** `_shared/models`에서 상품 모델을 수정하면 3개 프로젝트가 영향받아. 근데 Codex는 자기 디렉토리만 보니까 그걸 몰라.

---

## 어떻게 해결해?

**프로젝트 레지스트리**를 만들어. 프로젝트 이름, 경로, 공유 관계를 JSON 하나에 정리해. 래퍼 스크립트가 이걸 읽고 자동으로 처리해.

```json
{
  "projects": {
    "shop-api": { "path": "projects/shop-api", "type": "express", "shared": ["models"] },
    "admin-api": { "path": "projects/admin-api", "type": "express", "shared": ["models"] },
    "shop-web": { "path": "projects/shop-web", "type": "next", "shared": [] }
  },
  "aliases": { "shop": "shop-api", "admin": "admin-web" },
  "shared_modules": {
    "models": { "path": "_shared/models", "consumers": ["shop-api", "admin-api", "noti-api"] }
  }
}
```

이 파일이 있으면:
1. **단축명** — `shop`만 쳐도 `projects/shop-api`로 변환
2. **공유 모듈 경고** — `_shared/models` 수정하면 "영향받는 프로젝트: 3개" 자동 안내
3. **관계 파악** — Claude가 프로젝트 간 연결을 알 수 있어

---

## 실행 패턴 2가지

### 패턴 1: 순차 (API → 프론트)

API를 먼저 만들고, 그 결과를 프론트에 넘겨.

```bash
# 1단계: API 먼저
bash scripts/run-codex.sh shop-api "리뷰 등록/조회 API 구현" > "$WORK/step1.json"

# 2단계: API 완료되면 프론트
bash scripts/run-codex.sh shop-web \
  "상품 상세에 리뷰 섹션 추가. CONTEXT: 리뷰 API 완료됨"
```

핵심은 **1단계 결과를 2단계 CONTEXT에 넘기는 거야.**

### 패턴 2: 병렬 (독립 프로젝트)

서로 안 건드리는 프로젝트는 동시에 돌려.

```bash
bash scripts/run-codex.sh shop-web "메인 배너 슬라이더 추가" &
bash scripts/run-codex.sh admin-web "주문 통계 차트 추가" &
wait
```

:::warning
**같은 프로젝트 내 작업은 병렬 금지.** 두 Codex가 같은 파일을 건드리면 나중 거가 먼저 걸 덮어써.
**공유 모듈은 반드시 순차.** 먼저 수정하고, 소비자 프로젝트를 업데이트해.
:::

---

## 공유 모듈은 어떻게 처리해?

래퍼 스크립트가 자동으로 **경고를 프롬프트에 주입**해:

```
⚠️ 이 모듈은 공유 모듈(_shared/models)이야.
영향받는 프로젝트: shop-api, admin-api, noti-api
수정할 때 이 프로젝트들과의 호환성을 반드시 유지해.
```

Codex가 이걸 보면 호환성을 깨는 수정을 안 해.

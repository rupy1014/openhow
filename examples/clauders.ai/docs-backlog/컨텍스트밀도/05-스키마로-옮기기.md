**enum 이 5 곳에 박혀있다면 다음에 새 값 추가할 때 분명히 한 곳을 잊어.**

:::success 이 페이지가 끝나면
- MD 에 박힌 enum/상수를 단일 진실 원천(SSOT)으로 옮길 수 있어
- 검증 스크립트가 스키마를 소비하게 만들 수 있어
- "스키마만 수정하면 모든 곳이 따라온다" 상태를 만들 수 있어
:::

**사람이 하는 것**: SSOT 위치 결정, 어떤 enum 을 옮길지 지정
**AI 가 하는 것**: 스키마 작성, MD 에서 enum 제거, 검증 스크립트 작성
**해결 방식**: 엔지니어링
**걸리는 시간**: 1시간 (enum 1개 기준)

:::info 사전 지식
- JSON 또는 YAML 읽을 줄 알면 OK
- TypeScript/Zod 코드는 예시로만 등장 — 못 읽어도 흐름은 따라가짐
- shell `grep` / `jq` 한 번이라도 써본 정도면 충분
:::

## 단계

1. **흩어진 곳 찾기**
2. **단일 출처(SSOT) 만들기**
3. **MD 를 SSOT 로 가리키기**
4. **검증으로 못 박기**

---

## 1. 흩어진 곳 찾기

예를 들어 `status` enum 이 5 곳에 박혀있는 상황:

```
prd.md             - State Transitions 테이블
prd-modes/new.md   - frontmatter 설명
prd-modes/reference.md - iteration 카운터
scripts/validate.sh - VALID_STATUSES="seed|exploring|..."
docs/dashboard.md  - 예시 테이블
```

찾는 법:

```bash
grep -rn "seed\|exploring\|clarified\|building\|done\|killed" \
  CLAUDE.md commands/ scripts/ docs/ 2>/dev/null
```

→ **5 곳에 박힌 enum** 이 보이면 SSOT 후보.

---

## 2. 단일 출처(SSOT) 만들기

`schemas/intent.schema.json`:

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "properties": {
    "status": {
      "enum": ["seed", "exploring", "clarified", "building", "done", "killed"]
    },
    "iteration": { "type": "integer", "minimum": 0 },
    "created": { "type": "string", "pattern": "^\\d{4}-\\d{2}-\\d{2}$" }
  },
  "required": ["status", "iteration", "created"]
}
```

**JSON Schema 외 옵션:**

| 언어 | 도구 |
|------|------|
| TypeScript | Zod, `as const satisfies` |
| Python | Pydantic |
| Go | 구조체 + `validate` 태그 |
| 언어 무관 | JSON Schema, Protocol Buffers |

shell 스크립트가 소비해야 하면 → JSON Schema. TypeScript 프로젝트면 → Zod.

---

## 3. MD 를 SSOT 로 가리키기

기존:

```markdown
| status | seed/exploring/clarified/building/done/killed |
| iteration | 정수, 0부터 시작 |
| created | YYYY-MM-DD 형식 |
```

→ 한 줄로:

```markdown
frontmatter 스펙: `schemas/intent.schema.json` 참조
```

**중요**: AI 는 `schemas/intent.schema.json` 을 직접 읽을 수 있어. MD 에 enum 을 다시 적을 필요 없어.

---

## 4. 검증으로 못 박기

**드리프트 방지 = SSOT 의 진짜 목적.** 사람이 SSOT 만 수정하고 다른 곳을 잊어도 검증이 잡아줘.

```bash
# 이전 — 하드코딩 (드리프트 위험)
VALID_STATUSES="seed|exploring|clarified|building|done|killed"

# 이후 — 스키마에서 jq 로 추출
VALID_STATUSES=$(jq -r '.properties.status.enum | join("|")' "$SCHEMA_PATH")
REQUIRED_FIELDS=($(jq -r '.required[]' "$SCHEMA_PATH"))
```

→ enum 추가 시 **스키마만** 수정하면 검증도 자동으로 새 값 인정.

---

## AI 한테 시키는 법 (프롬프트 예시)

```
status enum 이 다음 5곳에 박혀있어:
  - commands/prd.md (State Transitions 표)
  - commands/prd-modes/new.md (frontmatter 설명)
  - commands/prd-modes/reference.md
  - scripts/validate.sh (VALID_STATUSES)
  - docs/dashboard.md

다음을 해줘:
1. schemas/intent.schema.json 만들어 (JSON Schema draft-07)
2. validate.sh 가 jq 로 스키마에서 enum 을 읽도록 수정
3. 위 5개 MD 에서 enum 나열을 "schemas/intent.schema.json 참조" 한 줄로 교체
4. status 에 잘못된 값을 넣은 테스트 파일로 검증 동작 확인
```

→ 사람은 위치만 지정. AI 가 옮김.

---

## 점검 — 잘 됐나?

```bash
# 잘못된 값 넣고 검증이 잡는지 확인
echo "---
status: explring   # 오타
---" > /tmp/bad.md
bash scripts/validate.sh /tmp/bad.md
# → ERROR: status 'explring' 허용값 아님 ...
```

이게 뜨면 성공. 사람의 오타가 **실행 전**에 잡혀.

---

:::info 이 시리즈를 만든 프로젝트도 같은 작업을 했어
[oh-my-jobdori](https://github.com/ehowlsla/oh-my-jobdori) 라는 프로젝트가 본인 인텐트 시스템에 이 패턴을 적용했어. 결과:
- `schemas/intent.schema.json` 단일 출처
- `validate-intent.sh` 가 `jq` 로 스키마 소비
- 5 곳 MD 에서 enum 나열 제거 → "스키마 참조" 한 줄

라우터 파일이 229 → 189 줄로 줄었고, `status: explring` 같은 오타가 실행 전에 잡혀.
:::

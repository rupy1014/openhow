# 시작하기 쇼츠 대본

## GS-00. 클로더즈는 강의가 아니에요

- **Source**: `getting-started/00-welcome.md`
- **Hook**: 바이브코딩 강의가 아니에요. 완주 코스예요.
- **시청자 고통**: 강의를 듣고도 결과물이 안 남는 불안
- **팩트체크/보강**: 내부 커리큘럼 문서 기준. “배포 링크+피드백+데모”를 결과물로 유지.
- **Script**:

```text
바이브코딩을 배우는 강의가 아니에요.

여러분의 프로젝트 하나를 4주 안에 끝까지 밀어주는 코스예요.

처음엔 설치하고,
그다음 Claude Code랑 말해보고,
자동화 레시피를 한 번 돌려보고,
마지막엔 여러분의 아이디어로 MVP를 배포해요.

끝에 남는 건 수료증이 아니에요.

배포 링크,
써본 사람의 피드백,
그리고 데모나잇에서 말할 수 있는 여러분의 결과물이에요.

강의를 많이 들은 사람이 이기는 게 아니에요.
끝까지 낸 사람이 이겨요.
```

- **Visual**: 4주 타임라인 → 배포 링크 → 피드백 메모 → 발표 화면
- **CTA**: 저장해두고 4주 뒤 결과물 기준으로 다시 보세요.

## GS-01. AI로 할 수 있는 건 두 가지예요

- **Source**: `getting-started/01-what-ai-can-do.md`
- **Hook**: AI로 할 수 있는 건 결국 두 가지예요.
- **시청자 고통**: AI로 뭘 해야 할지 모르는 막막함
- **팩트체크/보강**: AI가 결정을 대신한다는 식의 과장 금지. 시간 절약/수익 가능성은 커리큘럼 프레이밍.
- **Script**:

```text
AI로 무엇을 할 수 있냐고요?

결국 두 가지예요.

시간을 아끼거나,
돈을 벌 가능성을 만들거나.

회사에서 매번 하던 보고서,
정리,
메일,
자료조사.

이건 시간을 아끼는 쪽이에요.

반대로 여러분의 아이디어를 작은 웹서비스로 만들고,
사람에게 보여주고,
돈 낼지 물어보는 건 수익화 쪽이에요.

그런데 둘 다 핵심은 같아요.

AI가 대신 결정하는 게 아니에요.
여러분이 방향을 주면 AI가 초안, 구현, 수정 속도를 올려주는 거예요.
```

- **Visual**: 화면 좌측 `시간 절약`, 우측 `수익 가능성`; 가운데 `내가 방향을 준다`
- **CTA**: 여러분은 시간 절약 쪽인가요, 수익화 쪽인가요?

## GS-02. 설치는 한 줄이면 돼요

- **Source**: `getting-started/02-install.md`
- **Hook**: Claude Code 설치, 겁먹을 필요 없어요.
- **시청자 고통**: 터미널 설치에서 막힐 것 같은 공포
- **팩트체크/보강**: Claude Code 설치 방식은 공식 문서 화면을 촬영 직전에 확인. 명령어를 대본에 고정하지 않음.
- **Script**:

```text
터미널 처음 보면 무서울 수 있어요.

그런데 오늘 할 건 하나예요.

설치 방식은 운영체제마다 다를 수 있어요.

공식 설치 화면을 열고,
거기 나온 한 줄을 복사해서 붙여넣으면 돼요.

그다음 `claude`를 한 번 실행해보면 돼요.

여기서 중요한 건 명령어를 외우는 게 아니에요.

여러분의 컴퓨터 안에서 AI가 파일을 읽고,
만들고,
고칠 수 있는 상태가 됐다는 감각이에요.

설치가 끝나면 이제 웹 채팅이 아니라,
여러분의 작업 폴더 안에서 AI랑 같이 일하게 돼요.
```

- **Visual**: 터미널에 설치 스크립트 붙여넣기 → `claude` 실행 화면
- **CTA**: 설치에서 막히면 화면 캡처하고 에러 그대로 물어보세요.

## GS-03. 왜 굳이 터미널로 하나요?

- **Source**: `getting-started/03-why-cli.md`
- **Hook**: 터미널은 어렵게 보이지만, 제일 직접적인 길이에요.
- **시청자 고통**: 웹 채팅과 로컬 작업 도구의 차이를 모름
- **팩트체크/보강**: Claude Code는 터미널 기반 에이전트 워크플로우와 IDE 통합을 제공한다는 공식 설명과 정합.
- **Script**:

```text
왜 굳이 터미널로 하나요?

그냥 앱에서 채팅하면 안 되나요?

앱은 말하기 좋아요.
그런데 프로젝트를 끝까지 만들려면 파일을 읽고,
고치고,
실행하고,
에러를 봐야 해요.

Claude Code는 그걸 여러분의 컴퓨터 안에서 바로 해요.

터미널은 검은 화면이라 무서워 보일 뿐이에요.

실제로는 이렇게 말하는 창이에요.

“이 폴더에서 작업해주세요.”

이 감각만 잡으면 돼요.
```

- **Visual**: 웹 채팅창 vs VS Code 터미널 비교
- **CTA**: 터미널은 코딩 시험장이 아니라 작업 요청창이라고 기억해두세요.

## GS-04. 프로젝트는 그냥 큰 폴더예요

- **Source**: `getting-started/04-create-project.md`
- **Hook**: 프로젝트라고 해서 거창한 거 아니에요.
- **시청자 고통**: 프로젝트라는 말이 너무 개발자처럼 느껴짐
- **팩트체크/보강**: CLAUDE.md/프로젝트 메모리처럼 파일 기반 지침을 두는 Claude Code 사용 패턴과 정합.
- **Script**:

```text
프로젝트는 그냥 큰 폴더예요.

그런데 아무 폴더가 아니에요.

Claude가 읽을 자료,
작업할 파일,
지켜야 할 규칙이 같이 들어 있는 작업 구역이에요.

웹 채팅은 대화가 흘러가면 기억이 흐려져요.

그런데 프로젝트 폴더 안에 문서를 남겨두면 달라져요.

Claude가 다시 읽을 수 있어요.

그래서 첫 프로젝트는 코드를 만드는 게 아니라,
AI가 일할 작업실을 만드는 거예요.
```

- **Visual**: 빈 폴더 → `CLAUDE.md`, `docs/`, `drafts/`가 생기는 애니메이션
- **CTA**: 오늘은 코드보다 폴더 하나를 제대로 만들어보세요.

## GS-05. 터미널과 익스텐션은 뭐가 다를까요?

- **Source**: `getting-started/05-terminal-vs-extension.md`
- **Hook**: 같은 Claude인데, 쓰임이 달라요.
- **시청자 고통**: 터미널과 익스텐션 중 뭘 써야 할지 헷갈림
- **팩트체크/보강**: VS Code 확장은 보기와 수정 확인에 강하고, CLI는 명령 실행과 자동화 흐름 설명에 적합하다는 실무 판단으로 정리.
- **Script**:

```text
VS Code 안에서 Claude를 쓰는 방법은 두 가지예요.

익스텐션은 보기 편해요.
옆 패널에서 대화하고,
파일도 눈으로 보기 좋아요.

터미널은 덜 예뻐요.
그런데 프로젝트 전체를 다루기 좋아요.

명령 실행,
프로젝트 전체 작업,
에러 확인,
자동화 흐름은 터미널이 강해요.

그래서 처음엔 이렇게 생각하면 돼요.

익스텐션은 보기 좋은 조수예요.
터미널은 진짜 작업 요청창이에요.

클로더즈는 작업을 끝내야 하니까 터미널 감각을 먼저 잡는 거예요.
```

- **Visual**: VS Code 패널과 터미널을 좌우 비교
- **CTA**: 편한 확인은 익스텐션, 끝까지 미는 작업은 터미널로 가세요.

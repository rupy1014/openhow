- 훅은 첫 15초 안에 시선을 잡아야 합니다.

- 대본은 유튜브용 존댓말 내레이션으로 유지합니다.

## 쇼츠별 검수

### GS-00. 클로더즈는 강의가 아닙니다

판정: 내부 문서 기준 OK.

보강: “수료증”보다 “배포 링크, 피드백, 데모나잇 결과물”이 남는다는 문장을 유지했습니다.

### GS-01. AI로 할 수 있는 건 두 가지입니다

판정: 커리큘럼 프레이밍으로 OK.

주의: AI가 수익을 보장한다는 식으로 말하면 안 됩니다. 그래서 “돈을 벌 가능성”으로 유지했습니다.

### GS-02. 설치는 한 줄이면 됩니다

판정: 보강 필요 후 수정.

수정: “한 줄이면 무조건 설치”가 아니라 “공식 설치 화면을 촬영 직전에 확인하고, 거기 나온 한 줄을 복사”로 바꿨습니다.

### GS-03. 왜 굳이 터미널로 하나요?

판정: 공식 Claude Code 사용 방식과 정합.

보강: 터미널은 “검은 화면”이 아니라 프로젝트 작업 요청창이라는 메시지를 유지했습니다.

### GS-04. 프로젝트는 그냥 큰 폴더입니다

판정: Claude Code 프로젝트 메모리/지침 파일 사용 패턴과 정합.

보강: “프로젝트=AI 작업실” 비유를 유지했습니다.

### GS-05. 터미널과 익스텐션은 뭐가 다를까요?

판정: 보강 필요 후 수정.

수정: 익스텐션은 확인과 보기, 터미널은 전체 작업과 자동화에 강하다는 실무 판단으로 완화했습니다.

### CC-01. AI는 도구로 이해하는 게 안전합니다

판정: 보강 필요 후 수정.

수정: “똑똑한 앵무새”를 사실 주장처럼 말하지 않고, 비유라고 먼저 밝혔습니다. 중요한 내용은 근거 확인이 필요하다는 안전 문구도 추가했습니다.

### CC-02. 좋은 결과는 한 번에 나오지 않습니다

판정: OK.

보강: 완벽한 프롬프트보다 왕복 피드백 루프가 중요하다는 메시지를 유지했습니다.

### CC-03. 매번 설명하지 말고 문서로 남겨요

판정: Claude Code 지침 파일 사용 패턴과 정합.

보강: 매번 긴 프롬프트를 반복하지 말고 프로젝트 문서로 빼는 장면을 유지했습니다.

### AU-01. 자동화를 만드는 4가지 장치

판정: 보강 필요 후 수정.

수정: 단순 `agents` 표현을 `subagents`로 정리하고, 공식 Claude Code 요소에 가까운 `skills`, `subagents`, `hooks`, `slash commands` 중심으로 바꿨습니다.

### AU-02. 워크플로우는 반복 업무의 레시피입니다

판정: 내부 제작 프레임으로 OK.

주의: 워크플로우를 공식 제품 기능처럼 말하지 않고, 반복 업무 설계 방식으로 설명했습니다.

### AU-03. 자동화 패턴은 다섯 개면 충분합니다

판정: 교육용 분류로 OK.

주의: 체인/분류/동시처리/지휘자/반복개선은 공식 API 분류가 아니라 강의용 사고 프레임입니다.

### AU-04. 숙제는 자동화 하나를 끝까지 돌리는 것입니다

판정: 내부 커리큘럼 기준 OK.

보강: 샘플, 기준 문서, 실행, 결과 검수, 기준 수정 루프를 유지했습니다.

### BS-00. AI 시대엔 더 작게 검증해야 합니다

판정: 린 스타트업 프레임과 정합.

보강: “AI로 더 크게”가 아니라 “더 작게 검증”이라는 반전 훅을 유지했습니다.

### BS-01. 아이디어는 대박 예감이 아닙니다

판정: OK.

보강: 아이디어를 고객/문제/해결 가설로 좁히는 방향을 유지했습니다.

### BS-02. 기획은 정답 문서가 아닙니다

판정: OK.

보강: PRD, IA, 와이어프레임을 정답 절차가 아니라 의도 표현 방식으로 설명했습니다.

### BS-03. PRD는 대화 뒤에 만듭니다

판정: OK.

주의: AI가 PRD를 완성해준다는 과장은 피하고, 대화 정리 결과물로 설명했습니다.

### BS-04. 기술 선택은 멋진 스택 고르기가 아닙니다

판정: OK.

보강: MVP에서 기술은 고객 반응을 보기 위한 최소 장비라는 프레임을 유지했습니다.

### BS-05. 프론트엔드와 백엔드는 이렇게 나뉩니다

판정: 입문용 설명으로 OK.

보강: API 키와 비밀값은 화면에 두면 안 되고 백엔드에서 다룬다는 방향을 유지했습니다.

### BS-06. Git은 세이브 포인트입니다

판정: Git 공식 개념과 정합.

보강: commit을 “여기까지 정상” 기록으로 설명하는 비유를 유지했습니다.

### BS-07. 에러는 망한 게 아니라 단서입니다

판정: OK.

보강: “고쳐주세요”만 반복하지 말고 작업 상황, 현상, 기대 결과, 로그를 같이 전달하도록 정리했습니다.

### BS-08. 배포는 고객 검증의 문입니다

판정: 보강 필요 후 수정.

수정: Vercel을 과하게 단정하지 않고 “Vercel 같은 배포 서비스”로 완화했습니다. 환경변수는 로컬과 배포 환경에 따로 넣어야 한다는 점을 추가했습니다.

### BS-09. 피드백은 칭찬 받는 시간이 아닙니다

판정: 보강 필요 후 수정.

수정: “어때요?” 대신 막힌 지점, 최근 행동, 다시 열 이유, 지불 조건처럼 더 구체적인 질문으로 바꿨습니다.

### BS-10. PMF는 “좋아요”가 아닙니다

판정: OK.

보강: PMF 신호를 칭찬보다 반복 사용, 지불, 추천 같은 행동으로 설명했습니다.

### BS-11. 모객은 링크 뿌리기가 아닙니다

판정: OK.

주의: 채널별 성공을 보장하지 않고, 고객이 모여 있는 곳에서 유용한 사람이 되는 방향으로 유지했습니다.

### BS-12. 첫 돈은 결제 기능이 아니라 제안에서 나옵니다

판정: 보강 필요 후 수정.

수정: 특정 결제 링크명 나열을 줄이고, 수동 결제 → 반복 판매 → PG 자동화 흐름으로 정리했습니다. Bootpay 언급은 “프론트 결제 + 서버 검증” 중심으로 안전하게 바꿨습니다.

### DN-01. 데모나잇은 축제이자 증명입니다

판정: 내부 데모나잇 문서 기준 OK.

보강: 완성품 자랑이 아니라 문제, 고객, 데모, 피드백, 다음 계획을 보여주는 무대로 정리했습니다.

### DN-02. 졸업은 끝이 아니라 시작입니다

판정: 내부 졸업 문서 기준 OK.

보강: 한 사이클을 끝낸 사람이라는 메시지를 유지했습니다.

### OP-01. 클로더즈는 프로젝트 완주 코스입니다

판정: 내부 index 기준 OK.

보강: 수강량보다 배포 링크, 피드백, 데모를 남기는 구조를 유지했습니다.

### OP-02. 목차는 외우는 게 아니라 위치 확인용입니다

판정: 내부 toc 기준 OK.

보강: 목차는 학습량이 아니라 현재 위치와 다음 인증물을 확인하는 지도라는 메시지를 유지했습니다.

### OP-03. 기수제는 강의가 아니라 마감 시스템입니다

판정: 내부 운영 문서와 YouTube 채널 포지셔닝 기준 OK.

보강: 의지가 아니라 마감, 동료, 무대가 완주를 만든다는 메시지를 유지했습니다.

### OP-04. 4주 프로젝트는 한 가지 동작이면 됩니다

판정: 프로젝트 범위 가이드 기준 OK.

보강: “한 가지 동작”과 “안 만들 것”을 강조했습니다.

### OP-05. 인증 템플릿은 운영을 가볍게 만듭니다

판정: 마일스톤 템플릿 기준 OK.

보강: 운영자와 수강생 모두 덜 헷갈리게 하는 장치로 설명했습니다.

### OP-06. 평가표는 줄 세우는 표가 아닙니다

판정: 평가 기준표 문서 기준 OK.

보강: 점수보다 다음 단계 판단과 피드백 속도 목적을 강조했습니다.

### OP-07. MCP는 Claude에게 외부 도구를 연결하는 규격입니다

판정: 보강 필요 후 수정.

수정: “AI용 USB-C” 비유를 줄이고, AI 앱과 외부 도구/데이터 소스를 연결하는 표준 규격으로 설명했습니다.

### OP-08. 브라우저 자동화는 클릭 노동을 줄이는 법입니다

판정: Playwright 공식 기능 범위와 정합.

보강: 클릭, 입력, 스크린샷 같은 반복 작업을 스크립트로 남기면 재사용하기 쉽다는 문장으로 바꿨습니다.

### OP-09. AI 툴 설정은 한 벌만 관리합니다

판정: 로컬 운영 패턴으로 OK.

주의: 공식 표준처럼 말하지 않고, 프로젝트 운영 전략으로 유지했습니다.

### OP-10. 후기는 결과보다 전환을 보여줍니다

판정: 내부 운영 관점으로 OK.

보강: 좋은 후기는 감상이 아니라 Before/After 전환을 보여준다는 메시지를 유지했습니다.

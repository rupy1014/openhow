# 자동화 입문 쇼츠 대본

## AU-01. 자동화를 만드는 4가지 장치

- **Source**: `automation/01-four-features.md`
- **Hook**: Claude Code 자동화는 네 가지로 시작해요.
- **시청자 고통**: 자동화 기능 이름이 많아 헷갈림
- **팩트체크/보강**: Claude Code 공식 요소 기준으로 skills/subagents/hooks/slash commands로 정리. “agents” 단독 표현은 subagents로 보강.
- **Script**:

```text
Claude Code 자동화는 네 가지 장치로 시작해요.

skills.
반복 업무를 패키지로 묶는 장치예요.

subagents.
역할별 담당자를 나누는 방식이에요.

hooks.
특정 순간에 자동으로 실행되는 장치예요.

slash commands.
자주 쓰는 일을 짧게 부르는 입구예요.

그런데 이름을 외우는 게 핵심은 아니에요.

핵심은 이거예요.

어떤 일을 맡길 때,
무슨 문서를 읽고,
어떤 순서로 처리하고,
어떤 기준으로 확인할지 묶어두는 것.

그게 자동화예요.
```

- **Visual**: skills/subagents/hooks/slash commands 카드 4장
- **CTA**: 여러분의 반복 업무는 이 네 장치 중 어디에 들어갈까요?

## AU-02. 워크플로우는 반복 업무의 레시피예요

- **Source**: `automation/02-delegate-blog.md`
- **Hook**: 반복되는 결과물이 있으면, 자동화 후보예요.
- **시청자 고통**: 자동화를 거창한 개발로 오해함
- **팩트체크/보강**: 워크플로우는 공식 기능명이 아니라 제작 프레임. 반복 산출물 레시피로 설명.
- **Script**:

```text
워크플로우는 어려운 말이 아니에요.

반복되는 결과물이 나오기까지의 과정을 묶어둔 레시피예요.

예를 들어 블로그 글을 매주 쓴다고 해보세요.

톤을 맞추고,
자료를 읽고,
초안을 쓰고,
검수하고,
발행용으로 다듬어야 해요.

이걸 매번 말로 설명하면 힘들어요.

대신 필요한 문서,
담당자,
순서를 정해두면 돼요.

그러면 다음부터는 한 줄로 부를 수 있어요.

블로그가 아니어도 같아요.
회의록, 제안서, 고객 메일도 전부 레시피가 될 수 있어요.
```

- **Visual**: 반복 업무 → 문서 → 담당자 → 한 줄 명령
- **CTA**: 여러분이 매주 만드는 산출물 하나를 골라보세요.

## AU-03. 자동화 패턴은 다섯 개면 충분해요

- **Source**: `automation/03-patterns.md`
- **Hook**: 자동화 흐름은 다섯 패턴으로 거의 설명돼요.
- **시청자 고통**: 내 업무를 어떤 흐름으로 자동화할지 모름
- **팩트체크/보강**: 5패턴은 교육용 분류. 공식 제품 기능처럼 말하지 않도록 보강 메모 필요.
- **Script**:

```text
자동화 패턴은 처음부터 많이 알 필요 없어요.

다섯 개면 충분해요.

첫째, 체인.
순서대로 처리하는 일.

둘째, 분류.
들어온 내용에 따라 길이 갈리는 일.

셋째, 동시처리.
서로 기다릴 필요 없는 일을 나눠 하는 것.

넷째, 지휘자.
상황을 보고 필요한 담당자를 부르는 것.

다섯째, 반복개선.
만들고, 평가하고, 고치는 루프.

자동화는 마법이 아니에요.
목차와 담당자를 어떤 순서로 움직일지 정하는 설계도예요.
```

- **Visual**: 5패턴 아이콘 플로우
- **CTA**: 여러분의 업무는 체인인지, 반복개선인지 먼저 골라보세요.

## AU-04. 숙제는 자동화 하나를 끝까지 돌리는 거예요

- **Source**: `automation/04-homework.md`
- **Hook**: 읽고 넘어가면 여러분 것이 안 돼요.
- **시청자 고통**: 읽기만 하고 실제 자동화로 연결하지 못함
- **팩트체크/보강**: 숙제는 내부 커리큘럼 기준. 샘플+기준 문서+실행+수정 루프를 유지.
- **Script**:

```text
자동화 입문 숙제는 하나예요.

반복해서 만드는 산출물 하나를 골라.

예를 들면 주간 보고서,
블로그 글,
회의록,
고객 메일.

그다음 샘플을 준비해요.
AI가 따라할 기준이 필요하거든.

그리고 업무 문서 세 개를 만들어보세요.

이 프로젝트는 무엇인가.
시청자나 독자는 누구인가.
좋은 결과물 기준은 무엇인가.

마지막으로 한 번 실행해보고,
결과를 읽어요.

이게 별로면 AI 탓만 하지 말고 기준 문서를 고쳐요.

자동화는 실행보다 기준을 고치는 과정에서 좋아져요.
```

- **Visual**: 산출물 선택 → 샘플 → 기준 문서 → 실행 → 기준 수정
- **CTA**: 오늘 반복 업무 하나만 자동화 후보로 적어보세요.

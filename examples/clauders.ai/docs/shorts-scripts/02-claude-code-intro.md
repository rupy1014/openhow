# 초보 개념잡기 쇼츠 대본

## CC-01. AI는 도구로 이해하는 게 안전해요

- **Source**: `claude-code-intro/01-model-choice.md`
- **Hook**: AI를 사람처럼 믿으면 꼬여요.
- **시청자 고통**: AI를 사람처럼 믿었다가 틀린 답에 당함
- **팩트체크/보강**: “앵무새”는 비유. 모델이 틀릴 수 있으므로 중요한 내용은 근거 확인이 필요하다는 안전 문구 추가.
- **Script**:

```text
이건 비유예요.
AI는 사람처럼 모든 걸 이해한다고 믿기보다,
패턴을 바탕으로 답을 만드는 도구에 가깝게 보는 편이 안전해요.

엄청 많은 패턴을 보고,
그럴듯한 다음 말을 조합해요.

그래서 잘 맞을 때는 박사처럼 보이고,
틀릴 때는 너무 당당하게 틀려요.
그래서 중요한 내용은 근거를 같이 확인해야 해요.

처음엔 회사, 제품, 모델만 구분하면 돼요.

Anthropic은 회사.
Claude는 제품.
Opus, Sonnet, Haiku는 모델.

클로더즈에선 처음에 제일 똑똑한 모델로 시작해요.

도구 탓을 줄이고,
여러분이 일을 맡기는 감각부터 잡으려는 거예요.
```

- **Visual**: 회사 → 제품 → 모델 계층도
- **CTA**: 모델 이름 외우지 말고, 구조만 기억해요.

## CC-02. 좋은 결과는 한 번에 안 나와요

- **Source**: `claude-code-intro/02-direction.md`
- **Hook**: “해줘” 한 번으로 끝날 거라 기대하면 안 돼요.
- **시청자 고통**: 프롬프트 한 번으로 완벽한 결과를 기대함
- **팩트체크/보강**: 반복 요청과 피드백 루프는 Claude Code 사용 권장 흐름과 정합. 완벽한 프롬프트 환상 제거.
- **Script**:

```text
Claude한테 일을 잘 맡기는 사람은 프롬프트 천재가 아니에요.

왕복을 잘하는 사람이에요.

처음엔 작게 맡겨요.
결과를 보세요.
마음에 안 드는 지점을 말해요.
다시 고쳐요.

이 과정을 몇 번 돌리면 결과가 좋아져요.

처음부터 완벽한 요청을 쓰려고 하면 손이 멈춰요.

대신 세 가지만 붙이면 돼요.

상황,
원하는 결과,
판단 기준.

이 세 개만 있어도 AI는 훨씬 덜 헤매요.
```

- **Visual**: 요청 → 결과 → 피드백 → 수정 루프
- **CTA**: 다음 요청엔 상황, 결과, 기준 세 줄만 붙여보세요.

## CC-03. 매번 설명하지 말고 문서로 남겨요

- **Source**: `claude-code-intro/03-good-prompts.md`
- **Hook**: 매번 같은 설명을 반복하고 있다면, 문서가 필요해요.
- **시청자 고통**: 매번 같은 업무 설명을 반복함
- **팩트체크/보강**: CLAUDE.md와 프로젝트 지침 파일을 두는 패턴과 정합. 반복 설명을 문서화하는 쪽으로 보강.
- **Script**:

```text
AI한테 매번 이렇게 말하고 있죠?

우리 서비스는 이렇고,
톤은 이렇고,
고객은 이렇고,
이건 하지 말고.

그 설명을 대화창에 계속 치면 언젠가 빠져요.

그래서 프로젝트 안에 업무매뉴얼을 만들어보세요.

`CLAUDE.md`는 첫 장이에요.

내가 하는 일,
결과물 기준,
금지 사항,
자주 쓰는 흐름을 적어둬요.

그러면 Claude는 매번 새로 추측하지 않고,
프로젝트 문서를 읽고 일할 수 있어요.

프롬프트를 잘 쓰는 것보다,
일할 환경을 잘 만드는 게 더 오래 가요.
```

- **Visual**: 긴 프롬프트 반복 → `CLAUDE.md`로 정리
- **CTA**: 여러분이 자주 설명하는 말부터 문서로 빼보세요.

# 기수제 전환 개선안

## 핵심 요약

**이 문서의 결론부터 말하면 이거야. 클로더즈는 “커리큘럼 많이 듣는 코스”가 아니라 “네 프로젝트 하나를 4주 안에 완주하게 만드는 코스”로 잡아야 해.**

겉으로는 운영 문서처럼 보여도, 사실은 "왜 이 기수가 이런 순서로 짜였는지"를 속 시원하게 설명해주는 문서라고 생각하면 돼.

> **주의**
> - 자동화 입문은 **초보 개념잡기 확인차 블록**. `/write 1화`까지 손으로 한 번 돌려 "배운 개념이 레시피에 어떻게 들어갔나" 감만 잡고 서비스 만들기로 넘어간다
> - 공개 배포 데이·피드백 루프·마감 퀄리티 감각은 **데모나잇(본격 바이브 코딩 뒤)** 로 분리. 구 자동화 입문이 맡던 "배포·피드백"은 여기로 이동
> - Part 5(19~20장) 및 OpenClaw 자동화 운영 전반은 클로더즈 범위 밖. 자동화 입문 3강 사례 모음에서 확장 감각만 전달
> - 구 시작하기 5강 브리지 세션(린스타트업 + 파이프라인 지도 + PRD 워크샵)은 서비스 만들기 전반(1강~3강)으로 흡수
> - 구 Pre-week(설치·개념·용어·CLAUDE.md 초안)는 시작하기(설치·CLI·폴더) + 초보 개념잡기(방향·업무매뉴얼·CLAUDE.md)로 분할 흡수
> - 인강은 이 문서 범위 밖. 클로더즈 1기 운영 피드백 후 설계
> - 이해관계 분리 원칙: 클로더즈 공식 자료·커뮤니티에 인강 언급·판촉 금지

## 문서 읽는 순서

이 문서는 4부로 구성돼. 처음부터 끝까지 정독해도 좋지만, 지금 궁금한 파트부터 골라 읽어도 흐름은 잡히게 짜여 있어.

- **Part A. 기수제 설계** — 유튜브 체제에서 기수제로 옮길 때 무엇을 바꿀지
- **Part B. 본문 구조 리뷰** — 현재 20장 본문을 읽은 후 발견한 이슈 + 최우선 개선
- **Part C. Anthropic 레퍼런스 코스 참조** — Claude 101·Claude Code 101 두 코스에서 무엇을 빌려올지
- **Part D. 결론 + 다음 액션** — 실행 체크리스트

# Part A. 기수제 설계

## 왜 재조직이 필요한가

유튜브 알고리즘 기반 공개 콘텐츠와 기수제 유료 코스는 설계 지표 자체가 달라. 겉보기엔 둘 다 "콘텐츠" 같아도, 실제로 굴리는 방식은 완전히 다르거든.

| 항목 | 유튜브(알고리즘) | 기수제(커밋) |
| --- | --- | --- |
| 핵심 지표 | CTR·시청시간 | 완주율·결과물 제출률 |
| 설계 단위 | 개별 영상 | 주차 |
| 진입 장벽 | 첫 3초 훅 | 시작하기 중도이탈 |
| 성공 신호 | 구독·조회수 | 배포 링크·인증샷 |

유튜브 체제에서는 "자기소개 페이지 30분 데모"처럼 훅 강한 장부터 원 포인트로 뽑아야 해. 기수제는 반대야. 이미 결제하고 들어온 사람한텐 **조회수보다 완주 설계**가 더 중요해.

## 주차 재배분 (시작하기 → 초보 개념잡기 → 자동화 입문 → 서비스 만들기 → 본격 바이브 코딩 → 데모나잇)

6개 파트 순서를 **"시작하기 → 초보 개념잡기 → 자동화 입문 → 서비스 만들기 → 본격 바이브 코딩 → 데모나잇"** 으로 정리해. 시작하기는 설치·VS Code·CLI 당위성·신규 프로젝트 폴더 생성까지 맡고, 초보 개념잡기는 **AI 기초(회사/제품/모델·등급·용어)** 오리엔테이션을 깔아 기대치를 먼저 맞춘 뒤, 작은 요청으로 감을 잡고 프로젝트 업무매뉴얼과 `CLAUDE.md` 초안까지 만든다. 자동화 입문은 **초보 개념잡기 확인차 블록** 으로, 새 개념을 쏟아붓는 자리가 아니라 방금 만든 프로젝트 업무매뉴얼과 담당자 감각이 `/write` 같은 완성된 레시피에서 어떻게 한 덩어리로 조립돼 돌아가는지 손으로 한 번 돌려본다. 서비스 만들기 전반에서 린스타트업·PRD→개발 파이프라인을 지도로 제시하고, 같은 파트 후반에 직접 부딪혔던 문제를 복기하며 프롬프트·프로젝트 방법론을 심화해. **본격 바이브 코딩까지 바이브코딩으로 MVP 배포를 끝내**. 공개 배포 데이·피드백 루프·마감 퀄리티 감각은 본격 바이브 코딩 뒤 **데모나잇**으로 분리해서 외부 관객 앞에서 증명한다.

Part 5(19~20장) 및 **OpenClaw** 자동화 운영 전반은 클로더즈 범위 밖. 자동화 입문 사례 모음(vibe-codex-book 뉴스봇 → Threads 자동화 등)에서 "네 프로젝트에 자동화 1건 붙이면 이렇게 돼"는 확장 감각만 전달한다.

| 시점 | 원 목차 매핑 + 보강 | 세션 성격 | 바이브 코딩 4단계 | 마일스톤(인증물) |
| --- | --- | --- | --- | --- |
| **시작하기 — 환경 셋업** | 01~02장(설치·VS Code, + 구 부록 C도구 비교 흡수) + **신규: 왜 CLI 써야 하는지** + 신규 프로젝트 폴더 생성 + "해줘" 실습 | 비동기 4강 | 사전 준비 | 환경 스크린샷 + 신규 프로젝트 폴더 + 첫 요청 결과 |
| **초보 개념잡기 — AI 기초·감 잡기·일 잘 시키기** | AI 기초 + 작은 요청으로 감 잡기 + 회사 산출물 기반 업무매뉴얼 | 비동기 3강 | 사전 준비 | CLAUDE.md 초안 + `docs/` 업무 문서 1개 |

## 핵심 설계 원칙 6가지

### 1. 시작하기 = 설치 + CLI 당위성 + 프로젝트 폴더 생성

시작하기는 **환경이 아니라 진입 장벽 제거**에 집중해. 추가로 **"왜 CLI 써야 하는지"** 섹션을 보강해, 설치가 끝나자마자 “왜 이 도구를 쓰는지”까지 납득하게 만들어.

- 개념보다 먼저 **설치·VS Code·신규 프로젝트 폴더·첫 요청 결과**를 손에 남겨
- 시작하기 인증물은 작고 분명해야 한다: 환경 스크린샷 + 신규 프로젝트 폴더 + 첫 요청 결과
- 여기서 못 잡히면 다음 파트에서 계속 밀리므로, 시작하기 제출 미완료자는 바로 체크해
- 방향·업무매뉴얼·CLAUDE.md는 다음 파트인 초보 개념잡기로 넘겨 흐름을 분리해

시작하기 제출 미완료자는 초보 개념잡기 라이브 시작 전 1:1 체크. 여기서 못 잡으면 이탈 거의 확정.

### 2. 초보 개념잡기 = AI 기초 + 감 잡기 + 일 잘 시키기

이 파트는 **기대치 정리 + 일 시키는 감각 + 프로젝트 업무매뉴얼 초안**을 맡는다. 브리프·PRD·Plan Mode·배포는 뒤 파트에서 실제 작업으로 다룬다.

- **비동기 3강**: AI 기초 + 작은 요청으로 감 잡기 + 회사 산출물 기반 업무매뉴얼
- **핵심 감각**: "AI가 내 일을 이해하려면 맥락이 필요하다"를 체감해
- **PRD와 배포는 아직 없어**: 구조화와 링크 만들기는 서비스 만들기·본격 바이브 코딩에서 다룬다

### 3. 자동화 입문 = 초보 개념잡기 확인차 레시피

이 파트는 **새 개념을 쏟아붓는 자리가 아니라, 초보 개념잡기에서 만든 프로젝트 업무매뉴얼과 담당자 감각이 실제 완성된 레시피 안에서 어떻게 한 덩어리로 조립돼 돌아가는지 확인하는 자리**다. 직접 만드는 게 아니라 `/write` 같은 이미 돌아가는 레시피를 한 번 손으로 굴려보고 감을 잡는다.

- **1강 4장치 오리엔테이션** — commands/agents/skills/hooks가 각각 무엇을 맡는지. 초보 개념잡기 어느 강과 맞물리는지 매핑 (commands↔3강 업무매뉴얼 · agents↔2강 일 시키는 법 · skills/hooks↔프로젝트 문서)
- **2강 `/write 1화` 실습** — 완성된 블로그 자동화 레시피를 내 환경에서 한 번 돌려봐. "프롬프트를 레시피가 어떻게 대신 써주는가"를 관찰
- **3강 멀티에이전트 흐름 감상** — content-writer → script-writer → proofreader 같은 다단 파이프라인이 어떻게 넘겨받는지 구경
- **4강 자동화 패턴 사례 모음** — 구 부록 D 직무·상황별 자동화 후보 표 + vibe-codex-book 뉴스봇 → Threads 사례 개관 ("네 프로젝트에 자동화 1건 붙이면 어디에?")
- **5강 복기 숙제** — 돌려본 레시피에서 빌려갈 규칙 1~2개를 내 CLAUDE.md에 추가
- 인증물: `/write 1화` 실행 기록 + CLAUDE.md 규칙 추가분
- **핵심 감각**: "이해한 개념 → 진짜 돌아가는 시스템"으로 한 번 건너갔다는 감. 구현 자체는 숙제 아님

### 4. 서비스 만들기 = PRD·복기·심화 (지도 제시 → 실전 심화를 한 주차에)

서비스 만들기는 **전반(Plan) + 후반(Plan → Code 1)** 으로 나눠 돌려. 전반은 구 시작하기 5강 브리지 세션을 흡수한 "지도 제시" 블록, 후반은 초보 개념잡기에서 막힌 지점을 교재로 쓰는 "복기·심화" 블록.

**전반**

- **린스타트업** — 작게 만들고 반응 보고 고치는 루프. 수직 슬라이싱·MVP·피드백 루프의 뿌리 (vibe-codex-book `concept.md`·Part 1-2 내용 참조)
- **파이프라인 지도** — 05장(PRD) → 06장(프롬프트) → 08장(CLAUDE.md) → 09장(한 입씩) → 10-15장(구현) → 14장(Git) → 16장(배포) 을 **각 단계 한 문장씩** 압축. 수강생은 이 지도만 보고 다음 단계부터 하나씩 밟아
- **PRD 워크샵** — Plan Mode 시연 + 부록 A(PRD 샘플) 펼쳐서 **자기 프로젝트 PRD 1장** 현장 작성 (중간 게이트)

**후반**

- **프롬프트 복기** — 초보 개념잡기에서 실제 나온 "안 먹힌 프롬프트" 3개를 앞에 두고 증상→진단→처방 표로 재작성. Claude 101 `Challenge/What's happening/Try this` 포맷 차용. 이 결과로 초보 개념잡기에서 만든 **CLAUDE.md의 "하지 마" 리스트를 증강**
- **수직 슬라이싱** — "내 프로젝트 기능 3개로 쪼개기". 1순위는 린스타트업에서 잡은 "먼저 검증하고 싶은 한 가지"
- **1기능 작동** — 10장(UI) 또는 11장(저장 DB) 중 하나를 골라 첫 구현 기능 완성

인증물: PRD 1장 + CLAUDE.md 증강본 + UI·저장 중 1기능 작동.

**핵심 메시지**: "초보 개념잡기에서 AI가 해주던 수준을 서비스 만들기부터는 PRD·규칙서로 방향·구조를 주면서 끌어올린다"

### 5. 본격 바이브 코딩 = 본격 바이브코딩 (MVP 완성까지)

Part 3 후반(12~16장) 을 **4개 코어 레슨**으로 다시 묶어서 돌아가. 13장(로그인) 은 독립 강이 아니라 **1강 API 안의 선택 분기**로 넣어. 이 주차는 여전히 **바이브코딩 위주** 로 유지하되, 수강생이 “외부 연동·인증·저장·디버깅·배포”를 한 흐름으로 묶어 보게 만드는 데 초점을 둔다.

- **1강 API·인증 선택** — 공개 API 또는 AI API 중 하나를 붙이고, 계정이 꼭 필요한 프로젝트만 최소 인증을 넣어
- **2강 Git 세이브** — `add → commit → push` 루프를 익혀 기능 끝마다 저장해
- **3강 디버깅** — WHAT / WHY / WHERE로 에러를 읽고 AI 질문 카드로 복구해
- **4강 배포** — 로컬 확인 → 환경 변수 등록 → 배포 → 배포 후 검증까지 끝내
- 인증물: **외부 연동 1개 + Git 히스토리 + 배포 링크**
- 자동화 감각은 **앞 자동화 입문에서 `/write 1화`로 이미 한 번 돌려본 상태**. 이 파트는 그 감각을 내 프로젝트에 외부 연동·인증·저장·디버깅·배포로 실제 끌고 오는 단계다.

### 6. 데모나잇 = 공개 배포 데이 + 피드백 루프 + 외부 관객 무대

본격 바이브 코딩에서 MVP 배포까지 끝낸 뒤, **데모나잇은 그 결과물을 사람들 앞에서 증명하는 무대**다. 구 자동화 입문이 맡던 "배포·피드백·마감 퀄리티" 감각은 전부 여기로 이동한다.

- **공개 배포 데이 (데모나잇 사전 1주)** — 수강생끼리 링크 공유 + 서로 써보고 피드백. 합평 워크숍 톤
- **데모나잇 본편** — 외부 관객 앞에서 5분 피치 + 2분 Q&A + 라이브 시연
  - 관객: 다음 기수 관심자 + 잡돌쌤 네트워크(멘토·예비 창업자) + 수강생 가족·지인
  - 덱 템플릿 6~8장(Problem → Demo → Ask)
  - 당일 운영: 리허설 → 타임박스 → 녹화 셋업
- 기수제 최대 이벤트. 수료증 대신 **"써본 사람 + 본 사람"** 을 동시에 만든다
- 녹화된 피치는 2기 모객·포트폴리오·인강 자료로 재활용

최종 인증물: **수정 배포 링크 + 피드백 1회 반영(Before/After) + 자동화 확장 아이디어 1건**.

## 기수제에서만 박아야 할 자산

현재 목차에 없고 신규로 준비해야 할 것들.

- **시작하기 자료 세트** — 01~04장 사전 영상 가이드 + "왜 CLI 써야 하는지" 섹션 + 환경 세팅 체크리스트 + 업무매뉴얼 템플릿 + CLAUDE.md 최소 템플릿
- **자동화 입문 `/write 1화` 운영 가이드** — 레시피 셋업 스크립트 + commands/agents/skills/hooks 매핑표 + 직무별 자동화 후보 표(구 부록 D) + 복기 템플릿(빌려갈 규칙 1~2개)
- **서비스 만들기 전반 자료** — 린스타트업 1페이지 요약 + 파이프라인 지도 1장 + 서비스 만들기 자료에 붙어 있는 캐릭터 챗 PRD 샘플(구 부록 A) 펼치기 가이드 + Plan Mode 라이브 시연 스크립트
- **서비스 만들기 후반 복기 운영 방식** — 서비스 만들기 중 나온 요청 실패 사례를 수강생에게서 미리 수집·익명 공유·재작성 실습 + CLAUDE.md "하지 마" 증강 템플릿
- **데모나잇 자산 세트** — 5분 피치 스크립트 + 덱 템플릿(6~8장) + 당일 운영 체크리스트(리허설·타임박스·녹화 셋업)
- **주차 인증 제출 규칙** — 어디에, 어떤 포맷으로 (링크·스크린샷·Git repo URL)
- **피어 리뷰 페어링** — 서비스 만들기 한 번, 데모나잇 공개 배포 데이
- **공개 배포 데이 운영 스크립트** — 데모나잇 사전 1주 + 본편. 기수제 최대 이벤트
- **중도이탈 방어막** — 시작하기 끝, 초보 개념잡기 끝 인증 미제출자 1:1 체크

### 2. 선행학습·순서 문제

- **07장** — HTML/CSS 사전 설명 없이 "만들어줘"로 시작. 비개발자에게 "결과만 봐" 원칙은 맞지만, 한두 문장 배경은 필요해. ("HTML은 레고 블록, CSS는 색칠하기" 수준)
- **09장** — "작은 성공을 이어가"고 하는데 **Git(14장)이 아직 안 나와** 저장 방법이 모호. "다음에 Git으로 남기게 돼"는 한 문장 예고 필요
- **12장** — API 응답 처리에 비동기 개념이 숨어 있음. "기다린다"는 유추에 의존

### 3. 누락된 장

현재 목차에 없지만 비개발자·1인 창업자 대상 기수제에선 필수.

- **비용/한도 기초** — 토큰·API 요금·Rate limit. 장기 자동화(19장) 고려하면 "무료 tier 한계"는 입문 후반에 반드시 필요
- **보안 기초** — API 키 관리, `.env` 파일, GitHub 커밋 전 민감정보 제거. 13장(로그인)은 "누구인가"만 다루고 여기가 비어있음
- **웹 에러 사전** — 15장은 "AI와 함께 고쳐"에 집중. 404·CORS·스택 트레이스 읽기 같은 **에러 자체 해석**이 없음
- **스택 선택 의사결정** — 06장(프롬프트)이나 08장(CLAUDE.md)에서 "이번엔 Vanilla JS로 간다 vs React로 가" 판단 틀이 빠져 있음

**개선 방향**
- 12장 뒤 또는 16장 앞에 **"배포 전 체크리스트" 장 신설** — 비용 한도, API 키, 환경 변수
- 15장 말미에 **"웹 에러 사전" 박스**

### 4. 메시지 중복

- **"방향을 준다"** 가 03장·06장·08장에 **각기 다른 톤으로 산재**. 세 장이 누적되면 하나의 원칙으로 수렴해야 하는데 그러지 못함
- **데이터 저장** 이 11장(DB)과 13장(로그인) 양쪽에서 겹침
- **"섹션 나누기 → 더미 내용"** 패턴이 07장·10장 양쪽 동일. 뒤 장은 앞 장 참조로 축약해야 함

**개선 방향**
- 08장 CLAUDE.md와 06장 프롬프트를 "**같은 원칙의 다른 층**"으로 명시적 연결
- 10장 도입에 "07장처럼 3단계로 가" 한 줄 참조

### 5. 산출물 공백

- **09장 (한 입씩)** — 방법론이지 산출물이 없어. "피자 1조각 단위로 저장"이라는데 뭘 저장할지 모호 (Git 아직 안 배움)
- **19장 (자동화)** — "입력-처리-출력" 프레임만 있고 **동작하는 자동화 1건**을 만들게 하지 않음. 부록 D도 아이디어만

**개선 방향**

### 6. 기수제 준비도 공백

- **15장** — "AI와 함께 원인 좁히기"만 있고, **막혔을 때 어떻게 물어야 하는지** 구체적 대화 카드가 없어

**개선 방향**

## C-1. Claude 101에서 빌려올 틀

Claude 101은 톤이 건조한 교과서지만 **학습자 진입 템플릿이 정형화**되어 있어.

### 1. 매 장 상단 템플릿 고정

Claude 101의 모든 장은 이 순서로 열려.

```
Estimated time: 15 minutes
Learning objectives
  By the end of this lesson, you will be able to:
  - ...
Key takeaways
  - ...
```

우리 책에 입히는 형태.

```markdown
> **예상 시간**: 25분
> **이번 장 끝나면 할 수 있는 것**
> - ...
> **이번 장 인증물**
> - ...
```

### 2. 증상 → 진단 → 처방 표 포맷

Claude 101 3장의 `Challenge / What's happening / Try this` 구조를 잡돌 톤으로 헤더만 바꿔 써.

| 이렇게 말했는데 | 왜 이런 결과가 나오지 | 이렇게 바꿔봐 |

적용 대상 장: **06장**(프롬프트), **15장**(디버깅), **18장**(AI만든 티)

### 3. 마지막 장에 리캡 + 다음 여정

Claude 101 13장의 "Congratulations + What you've learned + Additional resources + A word of encouragement" 구조. 우리는 20장 뒤에 **"수료 + 다음 여정"** 장을 신설해 심화반·자동화 확장으로 연결해.

## C-3. Claude Code 101에서 빌려올 틀 ★

**이쪽이 더 직접적이야.** 우리 책이 실제로 다루는 도구가 Claude Code이기 때문. Claude Code 101의 구조·워크플로·명령어를 본문에 매핑해.

### 1. "Explore → Plan → Code → Commit" 4단계 프레임워크 ★★

Claude Code 101 5장의 핵심. **이것이 잡돌 책이 산재해 있던 원칙들을 하나로 묶는 이름표**가 돼.

```
Explore (탐색) → Plan (기획) → Code (구현) → Commit (저장)
```

우리 책에 이미 흩어져 있는 조각들.

| 4단계 | 매핑되는 잡돌 장 |
| --- | --- |
| Explore (탐색) | 05장 도입 — "내 문제에서 주제 찾기" |
| Plan (기획) | 05장 PRD + 06장 프롬프트 + 08장 CLAUDE.md |
| Code (구현) | 09장 한 입 크기 + 10~13장 |
| Commit (저장) | 14장 Git + 16장 배포 |

**개선 방향**
- 이 4단계를 **"바이브 코딩 4단계"로 공식 이름**을 박아
- **매 장 상단 템플릿에 "지금 어느 단계"** 라벨 추가 (예: `[Plan 단계]`)
- 학습자가 **막혔을 때 돌아갈 루프**가 된다 — "지금 Code에서 꼬였으면 Plan으로 돌아가"

### 2. Plan Mode (Shift+Tab)

Claude Code 101 4·5장. **Claude Code의 실제 도구** — Shift+Tab으로 전환하는 모드.

- **읽기 전용**으로 탐색만 하고 계획을 먼저 세운다
- 입문자가 "코드부터 쓰지 말자"는 원칙을 **입으로 말하는 게 아니라 도구로 체험**해
- 적용: **05장 또는 09장**에 Plan Mode 사용법 섹션 신설

### 3. Permissions (Auto-accept / Approval / Plan)

Claude Code 101 2·4장. 3가지 권한 모드.

- **Approval** — 매번 허가 요청 (기본값, 초보 권장)
- **Auto-accept** — 파일 편집은 자동 승인, 명령어만 허가
- **Plan mode** — 읽기 전용

**개선 방향**
- **01장 또는 02장**에 "**Approval 모드로 시작해**" 경고 박스
- 초보자가 "실수로 파일 날아갔다"는 첫 사고를 막는 안전망

### 4. Context 관리 명령어 (/compact, /clear, /context)

Claude Code 101 6장. 비개발자가 "왜 갑자기 Claude가 까먹지?"라고 느끼는 순간의 정답.

- `/context` — 현재 컨텍스트 사용량 확인
- `/compact` — 대화 요약 후 공간 확보 (같은 기능 유지)
- `/clear` — 완전 초기화 (새 기능 시작할 때)

**개선 방향**
- **04장**(개념) 또는 **08장**(CLAUDE.md) 말미에 "컨텍스트 3대 명령어" 박스
- "이 명령어 하나가 하루를 구해"급 실용 가치

### 5. 서브에이전트 코드 리뷰

Claude Code 101 7장. `--from-pr`, `/commit-push-pr` 같은 스킬도 있음.

**개선 방향**
- 입문 본문에는 부담. **심화 부록**에 보관
- 단, **15장(디버깅)** 끝에 "**신선한 눈으로 리뷰**시키는 방법" 한 박스 추가는 가치 있음

### 6. Hooks

Claude Code 101 10장. PostToolUse·PreToolUse 같은 결정적(deterministic) 자동화.

**개선 방향**
- 입문 기수에는 부담. **부록 D(자동화 아이디어) 심화편**으로 이동
- 또는 **심화반(9~10주차)** 주제

## C-5. 참조 원칙 (공통)

- **필사 금지** — Anthropic 공식 코스를 그대로 옮기면 저작권·톤 둘 다 문제. 개념 뼈대만 빌리고 비유·예시는 잡돌 것으로 갈아낀다
- **비유 유지** — Claude 101/Code 101은 건조한 서술. 우리는 "운전·신입사원·세이브 시스템" 비유를 덮어씌운다
- **출처 표기** — 개념 단위로 빌린 장에는 본문 끝 "더 읽을거리"에 Anthropic 원문 링크

## C-6. 수용하지 않을 것

- **제품 투어 방식** — Claude 101의 "Projects → Artifacts → Skills → Connectors" 순서. 우리는 **학습자 결과물** 중심이라 이 구조 따라가면 코스가 약해져
- **직무별 Use case 나열** — Claude 101 11장의 Sales/HR/Legal 포맷은 B2B도입용. 잡돌 타깃(비개발자 개인·1인 창업자)과 맞지 않음
- **건조한 교과서 톤** — 잡돌 책의 감성·비유가 경쟁력
- **Hooks·Subagent 심화 기능** — 기수 기본반에는 부담. **심화반 또는 부록**으로 분리

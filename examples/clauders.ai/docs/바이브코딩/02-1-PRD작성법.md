**PRD 한 장이면 AI가 딴짓을 안 해.**

"기획해줘"라고 했는데 AI가 쓸데없는 걸 잔뜩 넣어?

PRD를 제대로 쓰면 그런 일이 없어.

---

## PRD가 뭐야?

Product Requirements Document. 거창하게 들리지만 별거 아니야.

**"이 서비스는 뭐고, 뭘 해야 하고, 뭘 안 해야 하는지"** 적은 문서야.

A4 한 장이면 돼. 10장짜리 기획서가 아니야.

---

## 좋은 PRD에 뭐가 있어?

6가지만 있으면 돼:

| 항목 | 쉽게 말하면 | 예시 |
|------|-----------|------|
| 한 줄 설명 | 이 서비스는 뭐야? | "AI 캐릭터 5명과 대화하는 웹앱" |
| 대상 사용자 | 쓰는 사람이 누구야? | "AI 캐릭터에 관심 있는 사람" |
| 핵심 기능 | MVP에 꼭 필요한 것만 | 캐릭터 선택, 채팅, 한국어 |
| 안 만들 것 | 이번에 안 할 것 | 로그인, 대화 저장, 관리자 |
| 사용자 흐름 | 어떤 순서로 쓰냐 | 캐릭터 선택 → 대화 → 종료 |
| 성공 기준 | 어떻게 되면 완성이야 | "캐릭터 골라서 10번 대화 가능" |

더 쓸 필요 없어. 이 6개면 AI가 방향을 잡아.

---

## AI한테 PRD를 쓰게 하는 법

**Step 1.** 아이디어를 말로 써

완벽하지 않아도 돼. 두세 줄이면 충분해.

```text:Claude 프롬프트
나 AI 캐릭터 채팅 서비스 만들고 싶어.
- 캐릭터 5명이 있어 (각각 성격이 달라)
- 하나를 골라서 대화할 수 있어
- 한국어로 대화해
- AI는 OpenRouter API 써
```

**Step 2.** PRD를 써달라고 해

```text:Claude 프롬프트
위 내용으로 PRD.md를 만들어줘.
한 줄 설명, 대상 사용자, 핵심 기능, 안 만들 것,
사용자 흐름, 성공 기준 — 이 6가지를 포함해서.
코드는 아직 짜지 마.
```

**Step 3.** 받은 PRD를 검토해

AI가 PRD를 내놓으면 이 3가지를 확인해:

- **핵심 기능이 3~5개야?** → 많으면 줄여
- **"안 만들 것"이 있어?** → 없으면 추가 요청
- **사용자 흐름이 단순해?** → 5단계 넘으면 줄여

```
핵심 기능에서 "사용자 프로필"은 빼줘. MVP에 필요 없어.
"안 만들 것"에 다크모드, 다국어 지원 추가해줘.
```

**Step 4.** 확정하면 저장해

```
이 PRD 최종 확정이야. PRD.md로 저장해줘.
```

이제 이 PRD를 기준으로 코드를 짜게 할 수 있어.

---

## 복사해서 바로 쓰는 프롬프트

```text:복사해서 바로 쓰는 프롬프트
[여기에 네 아이디어를 2~3줄로 써]

위 내용으로 PRD.md를 만들어줘.
다음 6가지를 포함해서:

1. 한 줄 설명
2. 대상 사용자
3. 핵심 기능 (최대 5개)
4. 안 만들 것 (최소 3개)
5. 사용자 흐름 (최대 5단계)
6. 성공 기준

코드는 아직 짜지 마.
```

이 프롬프트를 복사해서 아이디어만 바꾸면 돼.

---

## 실전 예시: PRD가 다르면 결과가 달라

같은 "채팅 서비스"라도 PRD를 어떻게 쓰느냐에 따라 나오는 게 달라.

복사해서 네 프로젝트에 맞게 바꿔봐.

### AI 캐릭터 채팅

```markdown:PRD — AI 캐릭터 채팅
# PRD: AI 캐릭터 채팅

## 한 줄 설명
AI 캐릭터 5명 중 하나를 골라 한국어로 대화하는 웹앱.

## 대상 사용자
AI 캐릭터 대화에 관심 있는 일반 사용자.

## 핵심 기능
1. 캐릭터 선택 화면 (카드 5개)
2. 채팅 화면 (말풍선 UI)
3. OpenRouter API로 AI 응답
4. 한국어 대화

## 안 만들 것
- 로그인/회원가입
- 대화 기록 저장 (새로고침 시 초기화)
- 캐릭터 생성/편집
- 음성 대화
- 관리자 페이지

## 사용자 흐름
캐릭터 선택 → 대화 시작 → 메시지 입력 → AI 응답 확인

## 성공 기준
캐릭터를 골라서 10번 이상 대화할 수 있으면 완성.

## 기술 스택
Next.js + API Route + Vercel 배포
```

**포인트:** "안 만들 것"이 5개. AI가 딴짓할 여지를 막아놨어.

### 포트폴리오 사이트

```markdown:PRD — 포트폴리오
# PRD: 개인 포트폴리오

## 한 줄 설명
내 프로젝트 3개를 보여주는 1페이지 포트폴리오.

## 대상 사용자
채용 담당자, 협업 파트너.

## 핵심 기능
1. 프로필 섹션 (사진 + 한 줄 소개)
2. 프로젝트 카드 3개 (이미지 + 설명 + 링크)
3. 연락처 섹션 (이메일 + GitHub)

## 안 만들 것
- 블로그
- CMS (내용은 HTML에 직접 작성)
- 방문자 통계
- 댓글
- 다국어
- 다크모드

## 사용자 흐름
페이지 접속 → 프로필 확인 → 프로젝트 클릭 → 연락처 확인

## 성공 기준
URL로 접속해서 프로젝트 3개가 보이면 완성.

## 기술 스택
HTML + CSS (파일 2개) + GitHub Pages 배포
```

**포인트:** 기술이 HTML+CSS뿐이야. AI가 React를 꺼내들 여지가 없어.

### 팀 TODO 리스트

```markdown:PRD — 팀 TODO
# PRD: 팀 TODO 리스트

## 한 줄 설명
팀원들이 할 일을 공유하는 간단한 웹앱.

## 대상 사용자
5명 이하 소규모 팀.

## 핵심 기능
1. 할 일 추가/완료/삭제
2. 팀원 이름 태그
3. 실시간 동기화 (새로고침 없이)

## 안 만들 것
- 로그인 (URL 공유로 접근)
- 마감일/캘린더
- 파일 첨부
- 알림
- 히스토리/되돌리기

## 사용자 흐름
URL 접속 → 할 일 추가 → 이름 태그 → 완료 체크

## 성공 기준
두 명이 동시에 접속해서 할 일을 추가/완료할 수 있으면 완성.

## 기술 스택
Next.js + Supabase (실시간 DB) + Vercel 배포
```

**포인트:** "실시간 동기화"가 필요해서 DB가 들어가. 근데 그 외엔 다 뺐어.

---

## PRD 쓸 때 흔한 실수

| 실수 | 왜 문제야 | 어떻게 고쳐 |
|------|---------|-----------|
| 핵심 기능이 10개 | MVP가 아니야 | 5개 이하로 줄여 |
| "안 만들 것"이 없어 | AI가 알아서 추가해 | 최소 3개 적어 |
| 성공 기준이 모호해 | 언제 끝인지 몰라 | 숫자로 적어 ("10번 대화 가능") |
| 기술을 미리 정해 | AI가 더 잘 아는 영역 | 옵션을 물어봐 |
| 디자인까지 적어 | PRD는 기능 문서야 | 디자인은 레퍼런스로 |

---

## 한 줄 정리

아이디어 2줄 + PRD 프롬프트 = AI가 기획서를 써. 예시를 참고해서 "안 만들 것"부터 채워.

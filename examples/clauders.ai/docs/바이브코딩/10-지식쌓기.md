**AI는 대화가 끝나면 다 까먹어. 근데 기억력을 만들어줄 수 있어.**

ChatGPT든 Claude든, 파일을 올리면 매번 새로 읽어. 대화가 끝나면 전부 사라져. 다음 대화에서 같은 질문을 하면 또 처음부터야.

2026년 4월, Andrej Karpathy(바이브코딩 만든 사람)가 이 문제를 정리했어. **LLM Wiki**라는 이름으로.

---

## 지금 방식이 왜 비효율적이야?

파일 5개를 올려서 질문하면, AI가 매번 5개를 전부 읽어. 10번 질문하면 50번 읽는 거야.

근데 더 큰 문제가 있어. **지식이 안 쌓여.**

5개 문서에서 중요한 점을 종합해서 답해줬는데, 다음 대화에선 그 종합이 사라져. 또 처음부터 종합해야 해.

```
지금 방식:
문서 → AI가 읽기 → 답변 → 까먹기 → 또 읽기 → 또 답변 → 또 까먹기

쌓이는 게 없어.
```

---

## LLM Wiki가 뭐야?

AI한테 **위키를 쓰게** 하는 거야.

새 자료를 주면 AI가 읽고, 핵심을 뽑아서 위키에 정리해. 다음에는 원본 대신 정리된 위키를 읽어.

```
LLM Wiki 방식:
문서 → AI가 읽기 → 위키에 정리 → 다음엔 위키를 읽기 → 지식이 쌓임
```

위키가 점점 두꺼워져. 자료를 10개 넣으면, 10개의 지식이 교차 참조되고 연결된 상태로 남아.

---

## 어떤 구조야?

3개 층이야.

```
┌─────────────────────────┐
│  원본 자료 (Raw Sources) │ ← 네가 모은 자료. AI는 읽기만 해.
├─────────────────────────┤
│  위키 (Wiki)            │ ← AI가 쓰고 유지보수하는 정리된 문서.
├─────────────────────────┤
│  규칙서 (Schema)        │ ← 위키를 어떻게 정리할지 규칙. CLAUDE.md 같은 거.
└─────────────────────────┘
```

**원본 자료** — 네가 모은 것들. 기사, 논문, 메모, 스크린샷. AI는 이걸 읽기만 하고 수정 안 해.

**위키** — AI가 만들고 관리하는 마크다운 파일들. 요약, 인물 페이지, 개념 페이지, 비교표. AI가 새 자료를 넣을 때마다 기존 위키를 업데이트해.

**규칙서** — 위키를 어떻게 정리할지 적어둔 파일. 우리가 배운 CLAUDE.md가 바로 이거야. "요약은 3줄 이내", "날짜를 꼭 넣어", "모순이 있으면 표시해" 같은 규칙.

---

## AI가 뭘 해?

3가지를 해.

**1. 넣기 (Ingest)**

새 자료를 주면 AI가 읽고, 요약을 쓰고, 관련 페이지를 업데이트해.

```text:Claude 프롬프트
이 기사를 읽고 위키에 반영해줘.
요약 페이지 만들고, 관련 개념 페이지도 업데이트해.
```

자료 1개를 넣으면 위키 페이지 10~15개가 업데이트될 수 있어. 교차 참조까지 자동으로.

**2. 질문 (Query)**

위키를 기반으로 답변해. 원본을 매번 다시 읽는 게 아니라, 이미 정리된 위키에서 찾아.

```text:Claude 프롬프트
이 주제에 대해 지금까지 정리된 내용을 알려줘.
```

좋은 답변이 나오면? 그것도 위키에 새 페이지로 저장해. 질문할수록 위키가 풍부해져.

**3. 점검 (Lint)**

가끔 AI한테 위키를 점검시켜.

```text:Claude 프롬프트
위키를 점검해줘.
모순, 오래된 내용, 빈 링크, 빠진 개념이 있는지 확인해.
```

사람은 위키 유지보수가 귀찮아서 결국 포기해. AI는 안 귀찮아해. **유지보수 비용이 거의 0이야.**

---

## 어디에 쓸 수 있어?

| 분야 | 뭘 하냐 |
|------|---------|
| **개인 기록** | 목표, 건강, 자기개발 — 저널이나 메모를 모아 구조화된 나만의 기록 |
| **공부/연구** | 논문, 기사를 읽으면서 주제별 위키를 키워가기 |
| **책 읽기** | 챕터별 정리, 등장인물, 테마 연결 — 팬위키 같은 걸 혼자 만들기 |
| **팀/회사** | 미팅 기록, 슬랙 대화, 고객 통화를 AI가 내부 위키로 정리 |
| **바이브코딩** | 프로젝트의 결정 사항, 배운 것, 구조를 위키로 유지 |

---

## 바이브코딩이랑 무슨 관련이야?

우리가 배운 프로세스가 이미 LLM Wiki의 시작이야.

| 우리가 배운 것 | LLM Wiki에서는 |
|--------------|---------------|
| PRD.md 만들기 | 규칙서(Schema) 작성 |
| CLAUDE.md에 규칙 넣기 | 위키 운영 규칙 정의 |
| 기능마다 정리하기 | Ingest — 새 지식을 위키에 반영 |
| 배운 것 기록하기 | Learnings — 위키가 진화하는 엔진 |
| 에러 고치고 메모하기 | Query → 답변을 위키에 저장 |

**차이는 규모야.** 바이브코딩에서는 한 프로젝트 안에서 정리해. LLM Wiki는 프로젝트를 넘어서 지식을 계속 쌓아.

---

## 시작하는 법

지금 당장 거창하게 안 해도 돼. 이것만 해봐.

**Step 1.** 프로젝트에 `docs/` 폴더를 만들어.

**Step 2.** 기능 하나 끝날 때마다 AI한테 정리시켜.

```text:Claude 프롬프트
지금까지 만든 기능을 docs/progress.md에 정리해줘.
뭘 만들었고, 배운 것, 다음에 할 것.
기존 내용이 있으면 업데이트해.
```

**Step 3.** 새 대화를 시작할 때 이 문서를 참고하게 해.

```text:Claude 프롬프트
docs/progress.md를 먼저 읽고 시작해줘.
```

이것만으로도 AI가 "까먹는" 문제의 절반은 해결돼.

프로젝트가 커지면 `docs/progress.md` 하나에서 여러 페이지로 쪼개면 돼. 그게 위키의 시작이야.

---

## 왜 이게 작동하냐?

> "위키를 유지하는 건 사람한테 너무 귀찮아. AI는 안 귀찮아해."
> — Andrej Karpathy

사람이 위키를 포기하는 이유는 **유지보수**야.

교차 참조 업데이트, 요약 갱신, 모순 확인 — 이 지루한 작업이 쌓이면 결국 방치해.

AI는 파일 15개를 한 번에 업데이트해도 불평 안 해. **유지보수 비용이 거의 0**이니까 위키가 계속 살아있어.

사람의 역할은? 자료를 모으고, 좋은 질문을 하고, 방향을 정하는 거야.

AI의 역할은? 정리하고, 교차 참조하고, 일관성을 유지하는 거야.

이건 1945년 Vannevar Bush의 "Memex" 아이디어와 같아. 개인 지식 저장소에서 문서 간 연결을 탐색하는 거야. 그때는 유지보수를 누가 하냐가 문제였는데, AI가 그걸 해결한 거야.

---

## 한 줄 정리

AI한테 위키를 쓰게 하면 지식이 쌓여. 까먹지 않는 AI를 만드는 방법이야.

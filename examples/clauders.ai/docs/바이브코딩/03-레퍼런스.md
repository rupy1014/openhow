**"예쁘게 해줘"보다 "이거랑 비슷하게 해줘"가 10배 빨라.**

AI한테 맥락을 잘 주면 결과가 달라져.

맥락 없이 "만들어줘"하면 AI가 혼자 상상해서 만들어. 그게 네 생각이랑 다를 확률이 높아.

---

## 레퍼런스가 뭐야?

AI한테 "이런 느낌으로 해줘"라고 보여주는 참고 자료야.

사진, 스크린샷, 비슷한 서비스 URL, 와이어프레임 — 다 레퍼런스야.

말로 100줄 설명하는 것보다 스크린샷 1장이 낫다.

---

## 어떤 레퍼런스를 줘?

| 레퍼런스 종류 | 언제 쓰면 좋아 | 예시 |
|-------------|-------------|------|
| 스크린샷 | UI 디자인을 정하고 싶을 때 | "이 사이트 캡처해서 비슷하게" |
| 비슷한 서비스 | 전체 느낌을 전달할 때 | "당근마켓 채팅처럼" |
| 와이어프레임 | 레이아웃을 직접 그렸을 때 | 손그림이라도 돼 |
| 색상/폰트 | 브랜드 느낌을 잡을 때 | "#FF6B35, 나눔고딕" |
| 데이터 구조 | 어떤 정보를 다루는지 | "상품엔 이름, 가격, 이미지가 있어" |

## 스크린샷이 제일 강력해

:::steps

### 비슷한 서비스를 찾아

네가 만들고 싶은 것과 비슷한 서비스를 브라우저에서 열어.

### 스크린샷을 찍어

- **Windows**: `Win + Shift + S` → 영역 선택
- **Mac**: `Cmd + Shift + 4` → 영역 선택

### Claude한테 보여줘

```
이 스크린샷처럼 만들어줘.
근데 색상은 파란색 계열로, 폰트는 좀 더 둥글게.
```

Claude Code는 이미지를 읽을 수 있어. 스크린샷을 보고 비슷한 레이아웃을 만들어.

글로 "헤더가 있고, 왼쪽에 사이드바가 있고, 가운데에 카드가 3열로..."라고 설명하는 것보다 훨씬 정확해.

:::

## 규칙 파일로 맥락을 박아둬

레퍼런스를 매번 말로 주면 피곤해. 반복되는 규칙은 파일로 만들어두면 돼.

**CLAUDE.md** — 프로젝트의 규칙서야.

이 파일에 적어두면 Claude가 매번 읽어. 대화할 때마다 설명 안 해도 돼.

```markdown:CLAUDE.md
# 프로젝트 규칙

## 기술 스택
- HTML + CSS + 바닐라 JS
- 외부 라이브러리 사용 금지

## 디자인 규칙
- 색상: #2563EB (파란), #F3F4F6 (배경)
- 폰트: 시스템 기본 폰트
- 모바일 우선

## 금지 사항
- React, Vue 등 프레임워크 사용 금지
- npm, 빌드 도구 사용 금지
```

이렇게 해두면 Claude가 React를 꺼내들지 않아.

"바닐라 JS로 해줘"를 매번 말할 필요 없어.

## "안 할 것"을 더 넓게 써

[안 만들 것](./02-2-안만들것)에서 기능 범위를 정했잖아. CLAUDE.md에는 **그 너머의 경계**까지 적어.

Intent Engineering이라는 접근법에서는 이걸 **Not 레이어**라고 불러. 기능뿐 아니라 보안, 품질, 금지 패턴까지 포함해.

```markdown:CLAUDE.md에 추가
## 보안 경계
- API 키는 반드시 환경변수로. 코드에 하드코딩 금지
- 사용자 입력은 항상 검증

## 품질 기준
- 페이지 로딩 3초 이내
- 에러 발생 시 사용자에게 안내 메시지 표시

## 금지 패턴
- console.log 디버깅 코드 남기지 않기
- any 타입 사용 금지 (TypeScript일 때)
- 한 파일에 300줄 넘기지 않기
```

왜 이게 중요해?

AI는 시키지 않으면 **합리적으로 보이는 판단**을 혼자 해. 근데 네 기준이랑 다를 수 있어.

"API 키를 코드에 넣지 마"를 안 적으면 → AI가 편의상 하드코딩할 수 있어.

"300줄 넘지 마"를 안 적으면 → AI가 1,000줄짜리 파일을 만들 수 있어.

**경계를 적어야 AI가 그 안에서 움직여.**

---

## 문서 자동 정돈 규칙을 넣어

CLAUDE.md에 **문서 정돈 규칙**까지 넣으면, AI가 작업할 때마다 자동으로 프로젝트를 정리해.

```markdown:CLAUDE.md에 추가
## 문서 정돈 규칙
- 코드 변경 후 관련 문서가 있으면 함께 업데이트
- 한 파일이 300줄 넘으면 분할
- 새 기능 추가 시 README에 반영
- 배운 것은 LEARNINGS.md에 날짜와 함께 기록
```

이게 왜 강력하냐?

보통 AI한테 코드를 시키면, 코드만 바꾸고 문서는 안 건드려. 근데 이 규칙을 CLAUDE.md에 넣어두면, **AI가 코드를 고칠 때마다 관련 문서도 같이 업데이트해.**

프로 개발 팀에서는 이걸 **훅(Hook)**이라고 불러. "코드가 바뀌면 자동으로 이것도 해"라는 규칙이야.

CLAUDE.md에 정돈 규칙을 넣으면, Claude Code가 매번 그 규칙을 따라. 별도 설정 없이 파일 하나로 자동화되는 거야.

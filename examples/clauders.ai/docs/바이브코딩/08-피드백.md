**배포했으면 끝? 아니야. 피드백 받아야 진짜 시작이야.**

URL이 생겼어. 이제 사람들한테 보여줘야 해.

---

## 왜 피드백이야?

혼자 만들면 "이게 좋을 거야"라고 착각해.

실제로 보여주면 "이거 왜 이래?"가 나와.

6개월 만들고 아무도 안 쓰는 것보다, 1주 만에 틀린 방향을 아는 게 낫잖아.

근데 요즘은 "방향이 맞아?"만으로는 부족해. 사용자 기대치가 높아졌거든.

---

## 기대치가 달라졌어

2020년에 "AI 채팅"을 보여주면 "오 이것도 돼?"였어.

지금은 ChatGPT, Claude를 매일 써. Notion도 써봤고, Linear도 써봤어.

사용자의 기준이 **이미 높아져 있어.**

| 옛날 | 지금 |
|------|------|
| "돌아가네? 신기하다" | "이거 왜 이렇게 느려?" |
| "AI가 답변을 하네" | "답변이 왜 이렇게 딱딱해?" |
| "무료라 감사" | "무료여도 불편하면 안 써" |

바이브코딩으로 만든 앱은 쏟아져. 비슷한 거 10개 중에 사람들이 쓰는 건 1~2개야.

그 1~2개는 기능이 많아서가 아니야. **써보니까 좋아서야.**

## 어떻게 물어봐?

:::steps

### URL을 보내

```
"나 이거 만들었어. 1분만 써보고 솔직하게 말해줘."
https://my-app.vercel.app
```

**"솔직하게"를 꼭 넣어.** 안 넣으면 "좋아~"만 나와.

친구들은 기분 안 상하게 하려고 칭찬만 해. "솔직하게"가 있어야 진짜가 나와.

### "돌아가?"보다 "좋아?"를 물어봐

기능 검증(돌아가?)은 기본이야. MLP는 여기서 한 발 더 나가.

```
[기능 검증 — 돌아가?]
"써보니까 어땠어? 불편한 거 없었어?"
"중간에 그만두고 싶었던 적 있어?"

[경험 검증 — 좋아?]
"이거 다른 사람한테 보여주고 싶어?"
"비슷한 거 있으면 이거 쓸 것 같아, 그거 쓸 것 같아?"
"첫인상이 어땠어? 솔직하게."
"돈 내고 쓸 것 같아?"
```

**"다른 사람한테 보여주고 싶어?"가 MLP의 핵심 질문이야.** "응"이 나오면 그 제품은 저절로 퍼져.

그냥 "어때?"라고 물으면 진짜 피드백이 안 나와.

### 기록하기

```
- 지현: "캐릭터 귀여웠어. 근데 결제 화면에서 나갔어"
- 민수: "입력이 좀 귀찮았어"
- 수진: "끝까지 했어. 근데 가격이 비싸"
```

Claude한테 정리시켜도 돼:

```text:Claude 프롬프트
이 피드백들 정리해줘.
공통된 불만이 뭔지, 다음에 뭘 고쳐야 하는지 포함해서.
코드는 짜지 마.
```

:::

## 가설이 맞았어? + 사랑받았어?

아이디어 단계에서 세운 핵심 가정을 확인해. 근데 두 가지를 봐야 해.

**1. 방향 검증 — 가설이 맞아?**

```
✅ 맞았다 → 2번으로
❌ 틀렸다 → 방향 전환 (피벗)
🔶 애매하다 → 사람을 더 모아서 테스트
```

**2. 경험 검증 — 써보고 좋아?**

```
✅ "다른 사람한테 보여주고 싶어" → 마케팅 시작
🔶 "괜찮은데..." → 완성도를 올려 (디자인, 속도, 문구)
❌ "비슷한 다른 거 쓸래" → 차별점을 다시 잡아
```

방향이 맞아도 경험이 별로면 안 퍼져. **기능 추가보다 기존 경험을 다듬는 게 먼저야.**

---

## 틀려도 괜찮아

방향 전환(피벗)은 실패가 아니야.

```
6개월 만들고 틀린 거 알면? → 6개월 날림
1주 만들고 틀린 거 알면? → 1주만 날리고 방향 수정
```

바이브코딩으로 만들었으니까 잃는 건 시간뿐이야.

그 시간에 배운 건 남아.

---

## 고치고 다시 돌려

피드백 반영해서 고치고, 다시 배포하고, 다시 물어봐.

```
만들기 → 배포 → 피드백 → 고치기 → 다시 배포 → 다시 피드백
```

이 사이클을 빨리 돌릴수록 좋은 서비스가 돼.

근데 "고치기"에서 많이 실수해. 피드백 받으면 기능을 추가하고 싶어져.

```
❌ "결제 기능도 넣어야 하나..."
❌ "다크모드도 있으면 좋겠는데..."
✅ "대화 응답이 느리다고 했으니 속도부터 잡자"
✅ "첫 화면이 허전하다고 했으니 디자인 다듬자"
```

**기능 추가는 참고, 기존 경험부터 다듬어.** 하나를 제대로 좋게 만드는 게 열 개를 대충 만드는 것보다 낫거든.

**Vercel 무료 URL로 배포한 거랑, 실제 서비스를 운영하는 건 달라.**

배포는 실험이야. 라이브 출시는 실사용자를 받는 거야. 그 사이에 **보안 점검**이 있어.

---

## MVP 배포 vs 라이브 출시

| | MVP 배포 | 라이브 출시 |
|---|---|---|
| **URL** | `xxx.vercel.app` | `myservice.com` |
| **사용자** | 테스트 5명 | 실사용자 |
| **에러 대응** | 직접 확인 | 알림이 와야 해 |
| **모니터링** | 없음 | 에러 추적 |
| **목적** | "이거 되나?" 검증 | "이걸로 사업 하겠다" |

MVP로 검증이 끝났으면, 이제 진짜로 전환할 차례야.

---

## 출시 전 보안 점검

바이브코딩 앱 5,600개를 스캔한 결과, **2,000개 이상에 보안 취약점**이 있었어. 400개 이상의 노출된 비밀 키, 175건의 개인정보 노출.

MVP 단계에서는 테스트 사용자 5명이니까 괜찮아. 근데 라이브로 넘어가면 모르는 사람이 들어와. 이 3가지만 확인하면 대부분 막을 수 있어.

:::steps

### API 키가 코드에 있는지

```
❌ const API_KEY = "sk-or-v1-abc123..."
✅ const API_KEY = process.env.OPENROUTER_API_KEY
```

코드에 직접 적혀있으면 GitHub에 올라가. 누구나 볼 수 있어. 남이 내 돈으로 API를 쓸 수 있어.

```text:Claude 프롬프트
이 프로젝트에서 API 키, 비밀번호, 토큰이 코드에 하드코딩된 곳을 찾아줘.
.env 파일이 .gitignore에 포함되어 있는지도 확인해줘.
```

### 로그인 우회가 되는지

로그인 기능이 있는데, URL을 직접 치면 로그인 없이 들어갈 수 있는 경우가 있어. AI가 인증 체크를 빼먹는 경우가 꽤 많아.

```text:Claude 프롬프트
인증 없이 접근할 수 있는 API 엔드포인트나 페이지가 있는지 확인해줘.
```

### 남의 데이터가 보이는지

할 일 앱을 만들었는데, URL에서 ID를 바꾸면 남의 할 일이 보여? 그게 이 문제야.

```text:Claude 프롬프트
사용자 A가 사용자 B의 데이터에 접근할 수 있는 경우가 있는지 확인해줘.
```

:::

3가지를 한꺼번에 확인하고 싶으면:

```text:Claude 프롬프트
이 프로젝트 전체 보안 점검을 해줘.
1. API 키, 비밀번호가 코드에 노출되어 있는지
2. 인증 없이 접근 가능한 페이지나 API가 있는지
3. 다른 사용자의 데이터에 접근할 수 있는지
```

## 출시 준비

보안 점검이 끝났으면, 서비스로서의 준비를 해.

**커스텀 도메인** — `xxx.vercel.app`은 기억하기 어려워. Vercel 프로젝트 → Settings → Domains에서 내 도메인을 추가하면 돼. 도메인은 가비아, Namecheap, Cloudflare 같은 데서 사.

**에러 모니터링** — 실사용자가 쓰다 에러가 나면, 내가 알아야 해. Vercel Analytics를 켜기만 하면 기본 분석이 가능해. 사용자가 늘면 Sentry를 추가해.

**무료 플랜 한계** — 사용자 100명 이하면 Vercel 무료 플랜으로 충분해. 그 이상이면 Pro 플랜($20/월)을 고려해.

## 언제 라이브로 가?

3가지 조건이 맞으면 가.

**1. 피드백 루프를 2~3회 돌렸어.**

배포 → 피드백 → 수정 → 다시 배포. 이 사이클을 최소 2번은 돌려야 해.

**2. 보안 점검을 했어.**

API 키 노출, 인증 우회, 데이터 접근. 위의 3가지를 확인했어.

**3. "돈 내고 쓸 것 같아?"에 "응"이 나왔어.**

5명 중 2~3명이 "이거 좋은데?"라고 하면 가능성이 있어. 전원이 "음..."이면 아직이야.

## 라이브 이후에는?

출시가 끝이 아니야. 이제 시작이야.

```
출시 → 사용자 피드백 → 기능 추가/수정 → 다시 배포
```

이 루프가 계속 돌아. 바이브코딩으로 만들었으니까 수정이 빨라. 그게 강점이야.

사용자가 10명, 100명, 1000명으로 늘면 새로운 문제가 생겨. 그때 [한계와 다음](./11-한계와다음)을 읽어봐.

**구조화 전에 먼저 청소.**

:::success 이 페이지가 끝나면
- 200줄 한도 안으로 들어와
- 중복 파일이 한 개로 합쳐져
- 죽은 문서가 활성 영역에서 빠져
:::

**사람이 하는 것**: 어디를 자를지 결정, 어떤 정책이 살아있는지 판단
**AI 가 하는 것**: 실제 분리/이동 작업 수행
**해결 방식**: 사람 판단 + AI 작업
**걸리는 시간**: 30분 \~ 1시간

---

## [02. 진단](./02-내-프로젝트-진단) 결과를 손에 들고 시작

진단표를 다시 펴봐. 어떤 패턴이 본인 상황에 맞는지가 결과로 결정돼:

| 진단 결과 | 추천 패턴 |
|----------|----------|
| 한 파일이 300줄+ | **패턴 A** (라우터 + 모드별) |
| CLAUDE.md 가 100\~200줄인데 인덱스 역할 함 | **패턴 B** (인덱스 + 리프) |
| 산문으로 된 조건부 설명이 많음 | **패턴 C** (산문 → 표) |
| 중복 파일 (CLAUDE.md ≒ AGENTS.md) | **2번 통합** |

---

## 패턴 A: 라우터 + 모드별 파일

긴 명령어 MD 를 라우터(짧은 lookup) 로 만들고 상세는 분리.

```
prd.md (470줄)              prd.md (190줄, 라우터)
  ├ Create 모드 (100줄)  →   prd-modes/new.md (100줄)
  ├ Update 모드 (90줄)   →   prd-modes/update.md (90줄)
  └ Kill 모드 (40줄)     →   prd-modes/kill.md (40줄)
```

라우터에는 **"어느 모드를 부를지" 표만**. 상세는 모드 파일이 가짐.

---

## 패턴 B: 인덱스 + 리프

CLAUDE.md 를 짧은 인덱스로 두고, 주제별로 쪼개.

```
CLAUDE.md (인덱스, 50줄)
  └ docs/policies/deploy.md      ← 필요할 때만 AI 가 읽음
  └ docs/policies/security.md
```

AI 는 인덱스만 항상 읽고, 리프는 관련 작업할 때만 읽어 → 토큰 절약.

---

## 패턴 C: 산문 → 표

조건부 설명을 표로 압축. 5줄짜리 자연어가 1줄짜리 표 행으로.

```markdown
<!-- 이전 (5줄) -->
jobdori 채널일 때는 clauders.ai 레퍼런스를 우선 참조하고,
'AI = 유능한 신입사원' 프레임을 유지해야 해.
bootpay 채널일 때는 브랜드 중립 원칙을 적용해서
'부트페이' 라는 단어를 직접 쓰지 말고
'결제대행사' 같은 일반 표현으로 바꿔야 해.

<!-- 이후 (3줄) -->
| 채널 | 레퍼런스 | 톤 |
| jobdori | clauders.ai | 유능한 신입사원 |
| bootpay | (없음) | 브랜드 중립, 부트페이 → 결제대행사 |
```

## 2. CLAUDE.md == AGENTS.md 통합

Claude Code 는 둘 다 읽지만 OpenAI Codex 같은 다른 도구는 AGENTS.md 만 읽어. 두 도구 같이 쓰면 둘 다 필요하지만 **내용은 한 곳에만**.

```bash
# CLAUDE.md 는 본체로 두고 AGENTS.md 는 심볼릭 링크
ln -sf CLAUDE.md AGENTS.md
```

또는 AGENTS.md 에 한 줄만:

```markdown
See CLAUDE.md.
```

---

## 3. ARCHIVED 분리

```bash
mkdir -p docs/archive
git mv docs/SERVICE-DIRECTION.md docs/archive/
```

`docs/README.md` 에 활성 문서 인덱스만 두면 AI 가 죽은 문서를 안 끌어와.

---

## 4. LLM 이 쓴 요약 삭제

`CLAUDE.md` 에 "Claude 가 작성한 프로젝트 요약" 같은 자동생성 블록이 있으면 삭제.

연구 결과: **LLM 자동생성 AGENTS.md 는 성공률 -3%, 사람이 쓴 건 +4%**. 자동생성은 손해.

판별:
- 줄마다 길이가 균일하게 비슷
- "comprehensive", "robust", "seamless" 같은 단어 반복
- 코드 보면 알 수 있는 사실 나열

→ 사람이 직접 쓴 "왜 이 결정을 했는지" 만 남기고 나머지 삭제.

---

## 5. 검증

청소 작업 후 다시 측정:

```bash
wc -l CLAUDE.md AGENTS.md
```

200줄 넘으면 다시 1번부터.

---

## AI 한테 시키는 법 (프롬프트 예시)

이 페이지의 작업은 사람이 결정 → AI 가 실행 패턴이야:

```
CLAUDE.md 가 470줄이야. 200줄 이하로 줄여줘.
- "Important Policies" 섹션은 .claude/policies/important.md 로 분리
- "Deploy Runbook" 섹션은 scripts/deploy.sh 와 docs/deploy.md 로 분리
- 산문으로 된 조건부 설명은 표로 바꿔
- 분리 후 원본 위치에는 한 줄 포인터만 남겨
```

→ "어디로 옮길지" 는 사람이 지정. AI 는 옮기는 일을 함.

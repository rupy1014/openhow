## 뭐가 들어있냐

다섯 블록이야.

### ① 비주얼 지시 — 화면 어디에 뭐가 있냐

"알아서 예쁘게"가 아니야. 위치를 못 박아.

```markdown
### 비주얼 지시사항
- **좌측:** 시장 규모(8조/온라인 5조) 인포그래픽
- **중앙:** 네이버, 카카오, 인스타그램 등 파편화된 광고 채널 로고 나열
- **우측:** '데이터 사일로'를 상징하는 단절된 기둥들
- **하단:** 연결 고리 아이콘 배치
```

좌/중/우/하단을 적으면 AI가 레이아웃을 안 헤매.
안 적으면 매번 세로로 쌓인 밋밋한 화면이 나와.

### ② 스크립트 — 단, "참고용"이라고 못 박아

슬라이드마다 실제로 말할 원고를 통째로 넣어. 그리고 문서 맨 위에 이 한 줄.

```text
스크립트 내용은 참고용으로만 봐주고,
내용들의 핵심을 참고해서 각 화면에 나눠서 적절하게 넣어줘.
```

이 한 줄이 진짜 중요해.
없으면 AI가 원고를 그대로 슬라이드에 때려넣어서 글자만 빽빽해져.

발표자료 최악의 사고가 "말할 내용을 슬라이드에 다 적는 것"이잖아.
그걸 프롬프트 한 줄로 막은 거야.

### ③ 전역 스타일 — 색은 hex로

```markdown
| Primary Color | #2FD096 (Docfriends Green) |
| Typography    | Pretendard Variable         |
| Slide Size    | Max 3840×2160 / Min 1280×720, 16:9 |
| Layout        | Full-height Section (100vh) |
```

"초록색 계열로" 하면 24장이 제각각 다른 초록이 나와.
`#2FD096` 하나 박으면 전부 같은 색이 나와.

회사 브랜드 컬러 hex는 반드시 찾아서 적어.

### ④ 인터랙션 — 용어로 지정

```text
페이지 전환 시 CSS Scroll Snap 으로 한 슬라이드씩 정확히 멈추게 해줘.
딱딱하게 끊기지 않도록 Cubic-bezier(0.645, 0.045, 0.355, 1) 을 적용해줘.
```

### ⑤ 에셋 규칙 — 순서까지 번호로

```markdown
정해진 순서: 1.네이버 2.카카오 3.당근 4.강남언니 5.구글 6.블라인드 7.키즈노트

디자인 팁: "32개사 연동"을 보여주려고 위 10개사를 전면 배치하고
나머지는 '+25 more' 로 은은하게 처리해서 전문성 강조.
```

로고 순서는 회사 사정이 걸린 문제잖아. AI는 그 맥락을 몰라. **번호로 못 박아.**

---

## 용어를 모르면 어떡하냐

`Cubic-bezier(0.645, 0.045, 0.355, 1)` 같은 거 몰라도 돼. 알 필요도 없어.

문제는 "부드럽게 넘어가게 해줘"라고 하면 결과를 확인할 방법이 없다는 거야.
마음에 안 들면 "좀 더 부드럽게"를 반복하게 되고, 그 루프는 안 끝나.

그래서 **요구사항 쓰기 전에 용어부터 받아내.**

```text
웹으로 발표 슬라이드를 만들려고 해.
스크롤할 때 한 화면씩 딱딱 멈추고, 요소들이 순서대로 나타나면 좋겠어.

이런 걸 웹에서 뭐라고 부르는지 용어로 정리해줘.
각 용어마다 어떤 느낌인지 한 줄 설명도 붙여줘.
아직 코드는 짜지 말고 용어만.
```

이런 게 돌아와.

```
Scroll Snap            스크롤하면 다음 섹션에 착 달라붙음
Scroll-triggered Anim  화면에 들어올 때 요소가 나타남
Stagger                여러 요소가 시차를 두고 순차 등장
Easing Function        움직임의 가속도
Parallax               배경과 오브젝트가 다른 속도로 움직임
```

이걸 그대로 요구사항에 붙여넣어.
실제로 `requirement.md` 의 인터랙션 섹션이 이 대화의 결과물이야.

용어를 외우는 게 아니라, **AI한테 받아서 요구사항에 되돌려 넣는 거야.**

**[👉 완성된 웹 슬라이드 열어보기](./kimes-deck-example.html)**

스크롤하면 한 장씩 착 붙고, 숫자가 0부터 올라가고, 로고가 중앙으로 모여.
KIMES 세미나에서 실제로 쓴 자료를 이 특강용으로 단일 HTML 한 파일로 다시 만든 거야.

파워포인트 안 열었어.

---

## 왜 PPT로 시키면 안 되냐

AI가 `.pptx`를 못 만드는 건 아니야. 문제는 **그다음**이야.

"3번 슬라이드 화살표 방향만 바꿔줘"라고 하면 AI는 파일을 통째로 다시 만들어.
네가 어제 손으로 맞춰둔 정렬, 폰트, 여백이 같이 날아가.

바이너리라서 그래.

```
.pptx  →  부분 수정 ✕   뭐가 바뀌었는지 확인 ✕   되돌리기 ✕
웹     →  부분 수정 ○   확인 ○                되돌리기 ○
```

웹은 슬라이드 한 장이 텍스트 파일 하나거든.

```
app/src/components/slides/
├── Slide01_Title.jsx
├── Slide09_DoctalkResults.jsx    ← 숫자 카드 페이지
├── Slide13_AdReviewProblem.jsx
└── ... 24개
```

"9번 슬라이드 숫자 카드를 4개에서 6개로 늘려줘" 하면 **그 파일 하나만** 열어서 고쳐.
나머지 23장은 손도 안 대.

---

## 뭐가 더 되냐

PPT에서 애니메이션 하나 넣으려면 메뉴를 몇 번 눌러야 하는지 생각해봐.
웹은 그냥 말로 시켜.

| 효과 | 실제로 들어간 곳 |
|---|---|
| 스크롤 스냅 | 스크롤 한 번에 다음 장으로 착 |
| 카운트업 | `25,000+` `4,500+` `160만+` 이 0부터 올라감 |
| 순차 등장 | 카드 6개가 0.06초 간격으로 하나씩 |
| 연결선 애니메이션 | 플랫폼 로고 7개 → 중앙 허브로 흐르는 곡선 42개 |
| 영상 임베드 | 슬라이드 안에서 실제 서비스 데모 재생 |

마지막 줄이 제일 커. **실제 제품 화면을 슬라이드 안에서 돌릴 수 있어.**

그리고 발표장에서 안 깨져. URL이니까 남의 노트북에서 열어도 폰트가 안 바뀌어.
발표 직전에 오타 고쳐서 푸시하면 2분 뒤에 반영돼.

---

## 근데 웹이 안 맞을 때도 있어

정직하게 말하면 이래.

| 이럴 땐 그냥 PPT | 이유 |
|---|---|
| "파일로 보내주세요" | URL이 아니라 첨부파일이 필요한 자리 |
| 인터넷 없는 발표장 | 로컬 실행을 따로 준비해야 함 |
| 남이 이어서 편집 | 받는 사람이 코드를 못 만짐 |
| 3장짜리 간단한 자료 | PPT가 더 빠름 |

세미나, 데모데이, IR처럼 **내가 직접 발표하고 / 내용이 계속 바뀌고 / 제품 화면을 보여줘야 하는** 자료에 제일 잘 맞아.

---

## 그래서 뭘 하면 되냐

만드는 순서는 이래. 뒤 문서들이 한 단계씩 다뤄.

```
1. requirement.md 쓰기        ← 결과물의 90%가 여기서 정해져
2. 회사 자료를 .md로 깔기      ← 내용과 숫자의 출처
3. 공통 뼈대 먼저 → 슬라이드 찍어내기
4. 브라우저로 보고 고치기 → 배포
```

디자인 감각이 좋아서 잘 나온 게 아니야.
**시작할 때 요구사항 문서 한 장을 제대로 썼기 때문**이야.

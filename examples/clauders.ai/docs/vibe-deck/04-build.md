**요구사항을 다 썼다고 "이대로 24장 만들어줘" 하면 안 돼.**

뒤로 갈수록 품질이 떨어지고, 앞에서 정한 스타일을 잊어버려.

순서는 이래.

```
1. 요구사항 + 자료 폴더를 보여주고 "먼저 읽고 구조를 제안해줘"  ← 아직 만들지 마
2. 슬라이드 목록만 합의
3. 공통 스타일 뼈대 만들기
4. 슬라이드 3~5장씩 끊어서
5. 브라우저로 보고 고치기
```

---

## 3번이 제일 중요해

KIMES 자료의 공통 뼈대는 다 합쳐서 150줄이 안 돼.

```
app/src/
├── App.jsx                    슬라이드 24장을 순서대로 나열 (69줄)
├── hooks/
│   ├── useScrollSnap.js       스크롤·키보드 네비게이션 (54줄)
│   └── useSlideAnimation.js   등장 애니메이션 공통 처리 (39줄)
├── components/common/
│   └── SlideLayout.jsx        슬라이드 한 장의 껍데기 (17줄)
└── styles/
    ├── index.scss             색·폰트 (34줄)
    └── slides.css             공통 스타일 (528줄)
```

`slides.css` 에 이런 클래스가 미리 정의돼 있어.

```css
.section-label    /* 상단 작은 영문 라벨 */
.section-title    /* 큰 제목 */
.stat-card        /* 숫자 카드 */
.compare-box      /* Before/After 비교 */
.process-step     /* 단계 표시 */
```

이게 있으면 새 슬라이드 만들 때 AI가 재사용해.
없으면 매번 새 스타일을 지어내서 24장이 제각각이 돼.

그래서 슬라이드보다 **먼저** 시켜.

```text
슬라이드를 만들기 전에, 24장 전체가 공유할 공통 스타일부터 만들어줘.

- 슬라이드 껍데기 (100vh, 스크롤 스냅, 안전 영역)
- 제목 / 부제 / 라벨
- 숫자 카드, 비교 박스, 단계 표시 같은 반복 요소
- 색과 폰트는 CSS 변수로

이거 먼저 만들고 나서 슬라이드 작업 시작하자.
```

## 화면 크기 대응은 한 줄이 핵심

발표장 프로젝터 해상도는 예측이 안 되잖아.

```css
html {
  /* 1440px 기준 16px → 화면 폭에 비례해서 커지고 작아짐 */
  font-size: clamp(14px, 1.111vw, 19px);
}
```

모든 치수를 `rem` 으로 쓰고, 기준 글자 크기 하나만 화면 폭에 묶는 거야.
4K에서도 1280px 노트북에서도 **레이아웃이 안 깨지고 비율만 바뀌어.**

그리고 한글 슬라이드엔 이 두 줄이 필수야.

```css
.slide { word-break: keep-all; }        /* 단어 중간에서 안 끊김 */
.section-title { text-wrap: balance; }  /* 제목 줄바꿈이 균형 있게 */
```

`keep-all` 이 없으면 "데이터 사일" 에서 끊기고 다음 줄에 "로" 가 내려가.
한글 발표자료에서 제일 흔한 사고야.

## 슬라이드 하나짜리 프롬프트는 이 정도 밀도

`requirement.md` 에 실제로 들어있던 거야.

```text
중앙에 닥프렌즈 로고를 배치하고 좌측에는 플랫폼 로고(네이버~키즈노트 순),
우측에는 EMR 로고(비트컴퓨터~다솜메디케어 순)를 배치해줘.

양쪽 로고들이 중앙으로 모여드는 Moving Line Animation 으로 연결성을 시각화해줘.

하단에는 "월 평균 14% 성장" 을 #2FD096 볼드 텍스트와 상승 화살표로 강조해줘.
```

**배치 / 애니메이션 / 강조 요소.** 세 개면 충분해.

## 한 장에 안 들어가면 쪼개라고 시켜

원래 요구사항의 슬라이드 섹터는 **7개**였어. 결과물은 **24장**이야.

만들다 보니 한 장에 안 들어가서 쪼갠 거야. 파일 이름에 흔적이 남아있어.

```
Slide02_MarketEnv  →  Slide02b_AdChannels
Slide08_Emr        →  Slide08b_UnifiedManagement
                   →  Slide08c_SlotSync
Slide14_AiReview   →  Slide14b_KmaPartnership
Slide16_PatientMsg →  Slide16b_AiConsultation
```

한 장에 욱여넣으면 글자가 작아져서 뒷자리에서 안 보여.

```text
8번 슬라이드에 내용이 너무 많아.
"EMR 연동" / "통합 관리" / "실시간 슬롯 동기화" 세 개로 쪼개서
각각 한 화면씩 쓰게 해줘. 파일은 8, 8b, 8c 로 나눠줘.
```

> 슬라이드가 빽빽하면 내용을 줄이는 게 아니라 **장수를 늘리는 게** 정답이야.
> 웹은 장수 늘리는 비용이 0이거든.

## 순서 바꾸기와 시안 남기기

`App.jsx` 는 그냥 나열이야.

```jsx
<Slide04_AdPainPoint />
<Slide10b_TrackingOverviewAlt />   ← 10번대가 여기 끼어 있음
<Slide05_DataSilo />
```

리허설하다가 "이 얘기를 앞으로 빼는 게 낫겠다" 해서 옮긴 흔적이야.
**"6번을 4번 뒤로 옮겨줘"** 한 마디면 끝나고, 잘못되면 되돌리기도 한 번에 돼.

그리고 KIMES 프로젝트엔 만들고 안 쓰는 슬라이드가 3개 남아있어.

```
Slide10_TrackingOverview.jsx    ← 10b 가 채택됨
Slide11_EmrTracking.jsx
Slide11b_BookingDataFlow.jsx
```

지운 게 아니라 남긴 거야. `App.jsx` 에서 한 줄 갈아끼우면 시안 A/B 비교가 돼.

```text
10번 슬라이드를 다른 레이아웃으로 하나 더 만들어줘.
기존 파일은 지우지 말고 Slide10b_... 로 새로 만들어서,
App.jsx 에서 새 버전을 쓰게 해줘.
```

## 고칠 땐 파일명이나 번호로 지목해

이게 웹으로 만드는 진짜 이유야.

```
❌ "숫자 부분이 좀 이상해"

✅ "9번 슬라이드(Slide09_DoctalkResults.jsx)에서
    '연동 전자차트사' 카드만 초록 배경으로 바꾸고 나머지는 회색으로 둬"
```

파일 하나만 열어서 고치니까 나머지 23장은 안 건드려.

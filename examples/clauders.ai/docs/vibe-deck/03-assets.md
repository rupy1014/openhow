**요구사항이 "어떻게 보일지"를 정한다면, 자료는 "무슨 내용이 들어갈지"를 정해.**

KIMES 프로젝트 폴더는 이렇게 생겼어.

```
2026-kimes-seminar/
├── requirement.md              ← 앞 문서에서 다룬 거
├── business docs/              ← 서비스 내용을 .md 로
│   ├── 닥프렌즈 비지니스 개요.md
│   ├── 닥톡예약 개요.md
│   ├── 닥톡광고 개요.md
│   ├── 닥톡AI 의료광고 자동심의 개요.md
│   └── 닥톡AI 환자메세지 개요.md
├── resources/reference image/
│   ├── Docfriends_Pitchdeck_..._png/   ← 기존 피치덱 27장을 페이지별 이미지로
│   ├── 닥톡AI 자동심의 PT_png/          ← 의협 발표자료 17장
│   ├── 닥톡예약 UI/                     ← 실제 서비스 화면 캡처
│   └── 파트너사 유틸리티/                ← 로고 파일
└── app/                        ← 결과물
```

---

## 왜 .md 로 먼저 바꾸냐

`business docs/` 는 전부 마크다운이야. PDF나 PPT 원본이 아니고.

AI가 PDF를 못 읽는 게 아니야. **토큰을 많이 먹는다**는 게 문제야.

24장을 만드는 내내 소개서 PDF를 통째로 다시 읽으면, 작업 기억을 거기 다 써버려서
정작 뒷장 슬라이드 품질이 떨어져.

그래서 한 번만 변환해둬.

```text
회사 소개서 PDF를 읽고, 발표자료 만들 때 참고할 수 있게
마크다운으로 정리해줘. `business docs/서비스개요.md` 로 저장해줘.

포함할 것: 해결하는 문제, 핵심 기능, 차별점, 숫자로 말할 수 있는 성과
```

---

## 숫자는 반드시 출처가 있어야 해

발표자료 최악의 사고가 **AI가 지어낸 숫자**야.
"월 평균 14% 성장" 이 근거 없이 박히면 발표장에서 터져.

[예시 덱](./kimes-deck-example.html) 8번 슬라이드에 나오는 숫자들 —
`25,000+` `4,500+` `32개` `14%` `34,000건` `160만+` —
전부 `business docs/` 와 `requirement.md` 에 이미 적혀 있던 값이야.
AI는 배치만 했어.

순서가 이래야 해.

```
1. 숫자를 내가 먼저 .md 에 적는다
2. "이 문서에 있는 숫자만 써라" 라고 지시한다
3. 완성된 슬라이드 숫자를 원본과 대조한다
```

3번 건너뛰지 마. 5분이면 돼.

---

## 이미지는 페이지별로 쪼개

기존 피치덱을 참고시키려고 PDF를 통째로 주는 것보다, 페이지별 이미지가 훨씬 나아.

```
resources/reference image/Docfriends_Pitchdeck_.._png/
├── ..._images-0.jpg
├── ..._images-1.jpg
└── ... 27장
```

이러면 이렇게 말할 수 있어.

```text
피치덱 12번 페이지의 도표 스타일로 만들어줘.
```

PDF 통째로 주면 이게 안 돼.

그리고 실제 서비스 UI 캡처는 따로 챙겨.
KIMES 자료는 닥톡예약 실제 화면을 슬라이드에 그대로 박았는데,
그림으로 설명하는 것보다 훨씬 설득력이 있어.

---

## 정리하면

| 원본 | 어떻게 | 왜 |
|---|---|---|
| 회사 소개서 PDF | `.md` 로 변환 | 토큰 절약, 반복 참조 |
| 기존 피치덱 | 페이지별 이미지로 쪼갬 | "12번 페이지처럼" 이 가능해짐 |
| 서비스 화면 | 스크린샷 그대로 | 실재감 |
| 로고 | 파일로 + 순서 명시 | 회사 사정이 걸린 문제 |
| 숫자 | 내가 먼저 `.md` 에 | 환각 방지 |

---

## 한 줄 정리

AI가 가볍게 반복해서 읽을 수 있는 형태로 자료를 먼저 깔아. 숫자는 내가 적고, AI는 배치만 하게.

**코드는 멀쩡한데 화면은 깨져 있는 경우가 계속 생겨. AI는 자기 결과물을 못 보거든.**

---

## 루프는 이거야

```bash
npm run dev
```

브라우저 띄워놓고 슬라이드를 훑어. 이상한 데 찾으면 스크린샷 찍어서 그대로 붙여넣어.

```text
[스크린샷 첨부]
12번 슬라이드 오른쪽 그래프가 화면 밖으로 나갔어. 안쪽으로 들여줘.
```

Claude Code 면 브라우저를 직접 띄워서 스크린샷 찍게 시킬 수도 있어.
근데 **최종 판단은 네 눈으로 해.**
자동 캡처는 "안 깨졌다"까지만 확인해주지 "발표장에서 잘 보인다"는 확인 못 해.

---

## 발표 전 체크리스트

| 확인 | 왜 |
|---|---|
| 창을 **1280×720** 으로 줄여서 전체 훑기 | 발표장 프로젝터가 이 해상도인 경우가 많음 |
| 텍스트가 화면 밖으로 안 나가는지 | 제일 흔한 사고 |
| 한글이 단어 중간에서 안 끊기는지 | `word-break: keep-all` |
| 어두운 슬라이드에서 글자가 읽히는지 | 프로젝터는 모니터보다 대비가 낮음 |
| 웹폰트가 뜨는지 | 안 뜨면 전체 인상이 무너짐 |
| 숫자가 원본 자료와 같은지 | [자료 깔기](./03-assets) 참고 |
| 영상이 자동 재생되는지 | `muted` 없으면 브라우저가 막음 |
| 방향키·스페이스로 넘어가는지 | 마우스 스크롤로 발표하면 손 떨림이 화면에 보임 |

### 리모컨은 따로 챙겨야 해

KIMES 자료의 `useScrollSnap.js` 는 방향키와 스페이스만 처리해.
근데 **발표용 리모컨은 보통 PageUp/PageDown 을 보내.**

```text
발표용 리모컨을 쓰려고 해.
PageDown/PageUp 키로도 슬라이드가 넘어가게 추가해줘.
```

[예시 덱](./kimes-deck-example.html)에는 이걸 넣어놨어. 리모컨으로 눌러봐.

## 배포는 한 번만 세팅하면 끝

```text
이 프로젝트를 GitHub Pages 로 배포하고 싶어.
main 브랜치에 푸시하면 자동으로 빌드해서 배포되게 워크플로우를 만들어줘.
```

`.github/workflows/deploy.yml` 파일 하나 생기고 끝이야.

### 여기서 꼭 걸려

GitHub Pages 는 `https://아이디.github.io/저장소이름/` 처럼 **저장소 이름이 경로에 붙어.**
이것 때문에 로컬에선 잘 보이던 이미지가 배포하면 전부 깨져.

KIMES 프로젝트는 두 군데에서 처리했어.

```js
// vite.config.js
base: '/2026-kimes-seminar/',
```

```jsx
<img src={`${import.meta.env.BASE_URL}images/hero-3d.png`} />
```

배포했는데 이미지가 안 보이면 십중팔구 이거야.

```text
배포된 페이지에서 이미지가 전부 안 나와.
GitHub Pages 하위 경로 문제 같은데, 이미지 경로를 전부 확인해줘.
```

## 남는 찌꺼기는 정직하게 인정하자

결과물이 잘 나왔다고 과정이 깔끔했던 건 아니야. KIMES 프로젝트에 실제로 남은 것들.

| 남은 것 | 상태 |
|---|---|
| `FlowChart.jsx` `LogoGrid.jsx` `AnimatedText.jsx` | 초반에 껍데기만 만들고 한 번도 안 씀 |
| Tailwind CSS | 설치는 됐는데 코드 어디에도 안 씀 |
| `@carbon/react` | 요구사항엔 "모든 UI를 여기서" 라고 적었는데 실제론 아이콘만 씀 |
| 슬라이드 3장 | 시안으로 만들고 미채택 |

여기서 배울 게 두 개야.

**하나, 디자인 시스템을 강제하지 마.**
슬라이드는 일반 웹사이트랑 달라서 매 장 레이아웃이 달라.
정해진 컴포넌트를 끼워맞추는 것보다 **색·폰트·간격만 통일**하고 나머지는 자유롭게 두는 게 잘 맞아.

**둘, 안 쓰는 건 가끔 물어봐.**

```text
지금 코드에서 실제로 안 쓰이는 파일이랑 패키지를 찾아줘.
지우지는 말고 목록만 보여줘.
```

발표자료는 한 번 쓰고 마는 경우가 많으니 급하면 그냥 둬도 큰일은 안 나.

## 자주 빠지는 함정 모음

| 함정 | 증상 | 해결 |
|---|---|---|
| "PPT 만들어줘"로 시작 | 매번 통째로 다시 만들어 수정이 안 쌓임 | 웹으로, 슬라이드 1장 = 파일 1개 |
| 요구사항 없이 바로 시킴 | 레이아웃 제각각, 색이 24가지 | `requirement.md` 먼저, hex 코드까지 |
| 원고를 그대로 화면에 넣음 | 글자만 빽빽 | "참고용, 핵심만 요약해서" 명시 |
| 자료를 PDF로만 줌 | 토큰 다 먹고 뒷장 품질 저하 | `.md` 전처리, 이미지는 페이지별로 |
| 숫자 검증 안 함 | 근거 없는 수치가 발표장에서 터짐 | 내가 먼저 적고, 완성 후 대조 |
| 24장 한 번에 시킴 | 뒷장으로 갈수록 대충 | 뼈대 먼저 → 3~5장씩 |
| 한 장에 다 욱여넣음 | 뒷자리에서 안 보임 | 내용 줄이지 말고 장수 늘리기 |
| 브라우저로 안 봄 | 코드는 멀쩡, 화면은 깨짐 | 스크린샷 붙여넣는 루프 |
| `word-break` 안 넣음 | 한글이 단어 중간에서 끊김 | `keep-all` |
| 글자 크기 px 고정 | 발표장 해상도에서 붕괴 | `rem` + `clamp()` |
| 배포 후 이미지 깨짐 | 로컬은 되는데 배포하면 안 보임 | `base` 경로 + `BASE_URL` |
| 리모컨 테스트 안 함 | 발표장에서 안 먹힘 | PageUp/PageDown 추가 |

## 오늘 바로 해볼 것

1. 다음에 할 발표를 하나 고른다.
2. 폴더 만들고 `requirement.md` 를 만든다.
3. AI한테 "웹 슬라이드 인터랙션 용어를 정리해줘"라고 물어서 답을 받아둔다.
4. 회사 브랜드 컬러 hex 와 폰트 이름을 찾아 적는다.
5. 발표 원고를 섹터별로 나눠 그대로 넣는다.
6. 섹터마다 좌/중/우/강조 수치를 한 줄씩 적는다.
7. "스크립트는 참고용, 핵심만 요약해서" 한 줄을 맨 위에 박는다.
8. 회사 자료를 `business docs/` 에 `.md` 로 정리시킨다.
9. 기존 발표자료 PDF는 페이지별 이미지로 뽑아 넣는다.
10. "먼저 읽고 슬라이드 목록을 제안해줘" — **아직 만들지 말라고 한다.**
11. 목록 합의되면 "공통 스타일 뼈대부터".
12. 3~5장씩 만들고 매번 브라우저로 확인한다.
13. 1280×720 으로 줄여 전체를 훑는다.
14. 모든 숫자를 원본과 대조한다.
15. 배포하고 이미지가 다 나오는지 확인한다.
16. 리모컨으로 실제로 넘겨본다.

## 한 줄 정리

좋은 발표자료는 AI가 잘 만들어서 나오는 게 아니라, 네가 요구사항을 잘 적어서 나오는 거야.

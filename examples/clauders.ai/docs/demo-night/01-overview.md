데모나잇은 클로더즈 **축제**야. 내가 무엇을 고민했고, 어떤 고객의 어떤 문제를 어떻게 풀었는지 사람들 앞에서 5분 동안 보여주는 무대야.

완성을 못 했어도 괜찮아. "이런 문제를 이렇게 풀고 싶었고, 여기까지 만들어봤다. 다음엔 이렇게 할 거다"까지만 말해도 충분해. 중요한 건 결과물의 완성도가 아니라, **사람들 앞에서 내 프로젝트를 5분 동안 스피치해보는 경험** 그 자체야.

## 클로더즈 전체 기수들이 참관하게 돼

같은 기수끼리만 돌려보고 끝나면 "AI 써서 뭐 만들었다"에서 멈춰. 데모나잇엔 클로더즈 전체 기수가 모여. 선배 기수가 후배의 프로젝트를 보고, 후배 기수가 선배의 발자취를 보는 자리야. 그 순간 "AI 써서 뭐 만들었다"가 **"클로더즈 동료들에게 선보였다"** 로 바뀌고, 그 경험이 이후 투자·고객 미팅·다음 무대까지 그대로 굴러가길 상상하고 있어.

## 데모데이처럼 발표해

- 관객: 클로더즈 전체 기수 (선·후배 모두)
- 포맷: 인당 5~8분 발표 + 질의응답, 전원 라이브 시연 필수

"여기까지 만들었고, 다음엔 이렇게 할 거다" 는 그 자체로 한 편의 피치야.

## 발표 진행

전체 흐름은 **모더레이터(운영진)** 가 잡아줘. 발표자는 신호만 받고 따라가면 돼.

- 인당 약 **5~8분 발표**
- 발표 직후 **질의응답**
- 발표자가 **다음 발표자를 지명**하고 마이크를 넘기면서 다음 무대로 진행

## 듣는 사람 매너

발표자한테 방해되지 않는 선에서 적극적으로 반응해줘. 동료의 무대도 같이 만들어주는 게 데모나잇 분위기야.

- **이모티콘 리액션** 으로 표현 — "나 잘 듣고 있어 / 어 공감해! / 와 멋지다!"
- 발표 중·후에 도움이 될 만한 내용은 **공유 문서 댓글** 에 달아서 발표자한테 공유
- 박수와 호응이 다음 발표자한테 에너지를 넘겨주는 장치야

## 발표자 요령

데모와 스토리 둘 다 챙겨야 5분이 살아.

### 화면 공유

- 구글 미트 하단 중앙 **'화면 공유'** 버튼(이모티콘 왼쪽)을 눌러 창 또는 전체화면으로 공유
- **배포한 앱·웹을 먼저** 보여주고, **발표 문서는 그다음**. 처음 듣는 사람은 결과물부터 봐야 맥락이 잡혀

### 데모를 매끄럽게 만드는 장치

- **'둘러보기' 또는 '샘플 데이터 채우기'** 버튼을 미리 만들어둬. 로그인 없이도 핵심 흐름이 한눈에 들어오면 시연이 훨씬 수월해져
- 민감한 실데이터 말고, 기능·흐름이 잘 드러나는 **샘플 데이터** 를 클로드코드한테 박아달라고 지시
- 시연이 멈춰도 당황하지 않게 **녹화본·스크린샷 백업** 한 벌 챙겨두기

### 시연이 멈췄을 때

5분 안에 시연이 멈추거나 AI가 응답을 안 해도 패닉 금지. 미리 정해둔 순서로 넘어가면 돼.

1. **10초 정도 기다려봐** — 네트워크·AI 응답 지연은 대부분 이 안에 풀려
2. 10초 넘어가면 **"잠깐, 미리 녹화한 영상으로 보여줄게"** 한 마디 하고 백업 영상으로 전환
3. 영상이 끝나면 복구 시도하지 말고 **바로 Ask 슬라이드로 점프**
4. Q&A 때 "끊긴 부분은 끝나고 개별로 보여드릴게" 라고 마무리

### 스토리텔링이 데모만큼 중요해

5분 안에 다음 세 줄만 깔리면 관객이 따라와.

- **누구를 위해** 만들었는지
- **왜** 만들었는지
- **Before vs After** — 만들기 전과 후, 프로세스가 어떻게 달라졌는지

## 5분 피치덱 8장 구성

데모나잇용 덱은 아래 8장으로 짜면 들어와. **I~VI는 필수**, **VII~VIII은 시간 남으면 옵션**이야. 오른쪽은 가상의 단골노트 앱 샘플.

| # | 슬라이드 | 들어갈 내용 | 샘플 (단골노트) |
| --- | --- | --- | --- |
| I | 프로젝트 이름 + One-liner | 뭐 하는 서비스인지 한 문장 | **단골노트** — "동네 카페·미용실 사장님이 단골 손님과 방문 기록을 가볍게 관리하는 노트 앱" |
| II | 화면 스크린샷 + 배포 URL | Vercel·Netlify 등 배포 링크 박아두기 | (배포 링크 첨부) |
| III | Audience | 누가 쓰는 서비스인가 | 동네 카페·미용실·공방 사장님 · POS 없이 가볍게 단골을 챙기고 싶은 1인 자영업자 |
| IV | Problem | 어떤 문제가 있었나 | 단골 얼굴·취향이 머릿속에만 있어 한두 달이면 잊힘 · 메모가 노트·카톡에 흩어짐 · 누가 진짜 단골인지 매출 기여도가 안 보임 |
| V | Solution | 무엇을 만들었나 | 손님 검색·등록 · 방문·취향 한 줄 메모 · 단골 랭킹 · 안부 인사 문구 자동 추천 |
| VI | 만든 사람 + 동기 | 개인 또는 팀 + 만든 배경 한 줄 | 개인 — 동네 카페 운영 경험에서 "단골이 잊히는 문제"를 풀려고 기획·개발 |
| VII (옵션) | 레퍼런스 | 참고한 사이트·API | 카카오 알림톡 API · Claude API |
| VIII (옵션) | What's Next | 앞으로 붙일 기능 | 카카오 알림톡 자동 발송 · 매출 기록 연동 · 방문 주기 알림 |

5분 안에서 시간은 대략 이렇게 흘러.

- **I~IV 슬라이드** (Problem까지) — 90초
- **V 슬라이드 + 라이브 시연** — 2분 30초
- **VI~VIII 슬라이드** (만든 사람 + Ask) — 60초

마지막엔 관객이 **한 문장으로** 내 프로젝트를 말할 수 있어야 5분이 살아.

- ❌ "AI 써서 뭐 만들었대"
- ⭕ "동네 카페 사장이 단골 잊지 않게 도와주는 노트 앱"

## 슬라이드 작성 규칙

데모나잇 덱은 화려함보다 **데모 시간을 살려주는 도구**야. 네 가지만 지키면 돼.

- **1장 1메시지** — 한 슬라이드에 말할 거는 하나
- **글자는 20단어 이하** — 5m 뒷줄에서도 읽힐 정도
- **폰트 32pt 이상** — 16:9 1920×1080 기준
- **스크린샷은 풀블리드** — 테두리·URL 바 보여도 괜찮아. 오히려 신뢰도 ↑

라이브 시연으로 넘어갈 땐 "**자, 지금은 실제 화면으로 보여줄게**" 한 문장 + 미리 풀스크린으로 띄워둔 브라우저로 **2초 안에** 전환. 전환이 뭉개지면 관객 주의가 떨어져.

## 왜 무대에 세우는가

- 혼자 만들고 끝나면 **"AI 써서 뭐 만들었다"** 에서 멈춰. 무대는 그걸 **"클로더즈 동료들에게 선보였다"** 로 바꿔
- 5분 안에 문제·솔루션·데모를 말하는 연습은 **이후 투자·고객 미팅에서 그대로 재사용** 돼
- 녹화된 피치는 **본인 포트폴리오 + 후배 기수가 참고할 클로더즈 아카이브** 로 남아

## 자주 헷갈리는 포인트

- **데모나잇을 그냥 발표회로 이해함** — 이 이벤트는 클로더즈 전체 기수 앞에서의 증명과 아카이브 자산화야
- **외부 관객용 마케팅 무대로 오해함** — 데모나잇 관객은 클로더즈 동료들이야. 외부 모객은 별도 활동
- **앱 없이 문서만 띄움** — 처음 듣는 사람은 결과물부터 봐야 이해돼. 앱 → 문서 순서를 지켜
- **로그인 화면에서 멈춤** — '둘러보기' / '샘플 데이터 채우기' 버튼을 미리 박아두면 시연이 끊기지 않아
- **시연 실패 대응 시나리오를 안 챙김** — 백업 영상 한 벌 + "10초 기다림 → 영상 → Ask 점프" 절차가 없으면 패닉으로 5분이 다 날아가
- **한 슬라이드에 메시지 여러 개** — 발표자도 관객도 못 따라와. 1장 1메시지만 지켜
- **완성된 것만 무대에 세우려 함** — 미완성도 "여기까지 + 다음 계획" 으로 5분이 충분히 채워져

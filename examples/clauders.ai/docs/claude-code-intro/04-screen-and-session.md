## 핵심 요약

이 문서의 핵심은 세 줄이야.

- **화면은 세 칸이다.** 왼쪽은 내 파일 목록, 가운데는 편집 영역, 아래는 터미널. 이거 하나만 알아도 화면이 안 무서워져.ㅁ
- **터미널은 개발자 전용이 아니다.** 우리가 할 일은 명령어를 외우는 게 아니라 질문을 던지는 거야.
- **터미널 창 하나가 세션 하나다.** 여러 개 열어서 나눠 쓸 수 있고, 껐던 작업도 이어갈 수 있어.

```text
화면은 파일 / 편집 / 터미널 세 칸이다.
터미널에서 claude를 실행하면 세션이 시작된다.
세션은 여러 개 열 수 있고, 나중에 다시 불러올 수도 있다.
```

## 1. IDE는 작업실이고, 화면은 세 칸이다

Claude Code를 깔 때 VS Code도 같이 깔았을 거야.

VS Code 같은 걸 IDE라고 불러. 통합 개발 환경이라는 뜻인데, 어렵게 생각할 것 없어.

```text
IDE = 개발에 필요한 도구가 다 모여 있는 작업실
```

작업실 안이 세 칸으로 나뉘어 있다고 보면 돼.

| 위치 | 뭐가 있나 | 언제 보나 |
| --- | --- | --- |
| 왼쪽 패널 | 내 파일과 폴더 목록 | 지금 이 프로젝트에 뭐가 있는지 볼 때 |
| 가운데 패널 | 파일을 열면 나오는 편집 영역 | 파일 내용을 직접 보거나 고칠 때 |
| 아래 패널 | 터미널 | Claude Code에게 일을 시킬 때 |

처음엔 가운데 편집 영역을 거의 안 쓰게 될 거야.

우리가 코드를 직접 타이핑할 일이 별로 없거든.

대신 왼쪽에서 "아 이런 파일이 생겼구나" 확인하고, 아래 터미널에서 대화하는 시간이 대부분이야.

도구에 따라 오른쪽에 별도의 AI 패널이 붙는 것도 있어. 그건 도구마다 다르니 지금은 신경 안 써도 돼.

프로젝트가 뭔지, 폴더를 어떻게 나누는지는 [첫 프로젝트 만들기](../getting-started/04-create-project)에서 이미 다뤘어.

## 2. 터미널은 생각보다 안 무섭다

터미널을 보고 겁먹는 사람이 정말 많아.

까만 화면에 글자만 있으니까 개발자들만 쓰는 물건처럼 보이거든.

```text
터미널 = 글로 컴퓨터에게 명령하는 곳
```

그게 전부야.

여기서 `claude`를 입력하면 Claude Code가 켜져.

그다음부터는 그냥 한국어로 말하면 돼.

```text
이 파일이 뭔지 설명해줘
이 폴더 구조 좀 정리해줘
방금 만든 화면에 로그인 버튼 추가해줘
```

명령어를 외울 필요가 없는 이유가 여기 있어.

**우리가 할 일의 거의 전부는 질문을 던지는 거야.**

실제로 필요한 명령은 AI가 알아서 실행해줘.

파일을 설명받고 싶으면 그 파일을 터미널 창으로 끌어다 놓고 이렇게만 말하면 돼.

```text
이 파일 설명해줘
```

물론 파일을 어떤 구조로 배치할지, 그 안에 뭘 넣을지 설계하는 건 사람 몫이야.

그건 뒤에서 계속 연습하게 될 거고, 지금은 "터미널은 대화창이다" 정도만 잡으면 충분해.

터미널로 쓸지 익스텐션 패널로 쓸지 고민된다면 [터미널 vs 익스텐션](../getting-started/05-terminal-vs-extension)을 보면 돼.

## 3. 터미널 창 하나가 세션 하나다

Claude Code는 터미널에서 돌아가니까, 터미널 창을 여러 개 열면 Claude Code도 여러 개 돌릴 수 있어.

이 창 하나하나를 세션이라고 불러.

```text
터미널 창 1개 = 세션 1개 = 대화 1개
```

세션끼리는 서로 대화 내용을 공유하지 않아.

A 창에서 나눈 얘기를 B 창은 몰라. 완전히 분리된 환경이야.

그래서 이렇게 나눠 쓸 수 있어.

| 창 | 하는 일 |
| --- | --- |
| A | 백엔드 작업 |
| B | 프론트엔드 작업 |
| C | 기획 문서 작업 |

완전히 독립된 작업이라면 이렇게 나누는 게 훨씬 편해.

다만 딱 하나 조심할 게 있어.

```text
서로 다른 세션이 같은 파일을 동시에 고치면 충돌한다.
```

요즘은 "다른 에이전트가 이 파일 만지고 있어요" 하고 알려주는 경우도 있긴 해.

그래도 **같은 파일을 동시에 수정하는 건 최대한 피하는 게 좋아.**

병렬로 돌릴 거면 아예 겹치지 않는 작업으로 나눠.

## 4. 껐던 작업을 이어가려면

작업하다 보면 창을 닫아야 할 때가 생겨.

실수로 닫을 수도 있고, 컴퓨터를 껐을 수도 있지.

이럴 때 쓸 수 있는 게 두 가지야.

```text
claude -c   가장 최근 세션을 이어서 연다
claude -r   과거 세션 목록을 보여주고 골라서 연다
```

`-r`을 쓰면 이 프로젝트에서 했던 세션들이 쭉 나와.

2주 전에 하던 작업도 살아 있으면 골라서 불러올 수 있어.

세션이 많아지면 헷갈리니까 이름을 붙여두는 것도 방법이야.

```text
/rename 로그인기능
```

여기까지가 기능 설명이고, 이제 중요한 얘기를 할게.

**사실 이어서 여는 것보다 새로 여는 게 나은 경우가 많아.**

왜냐면 세션을 불러오면 그때까지 쌓인 대화가 통째로 딸려오거든.

지저분해진 대화까지 그대로 이어받는 거야. 이게 왜 문제인지는 [다음 문서](./05-context-and-memory)에서 자세히 다룰게.

그래서 이런 방식을 더 추천해.

```text
1. 작업을 마칠 때 "지금까지 한 것, 남은 것"을 파일로 적어둔다
2. 다음에는 새 세션을 연다
3. 그 파일을 읽히고 이어서 시킨다
```

투두 문서 하나만 있으면 되고, 훨씬 깔끔하게 이어져.

## 5. Node.js랑 Git은 왜 깔았을까

설치할 때 Node.js랑 Git을 같이 깔았을 거야.

"이게 뭔데 깔라는 거지?" 싶었을 텐데, 딱 이 정도만 알면 돼.

| 이름 | 역할 | 비유 |
| --- | --- | --- |
| Node.js | Claude Code가 돌아가는 바탕 | 프로그램이 실행되게 해주는 받침대 |
| Git | 작업 상태를 저장하는 도구 | 게임의 세이브 포인트 |

Git을 조금만 더 설명하면 이래.

우리가 작업할 때마다 폴더를 통째로 압축해서 백업할 순 없잖아.

그 대신 "여기까지 됐다"는 지점을 저장해두는 게 Git이야.

그 저장한 걸 인터넷 공간에 올려두는 게 GitHub이고.

```text
Git = 내 컴퓨터에서 세이브 포인트를 찍는 것
GitHub = 그 세이브 포인트를 클라우드에 올려두는 곳
```

여기서 중요한 건 이거야.

```text
지금 단계에서 이보다 깊이 알 필요는 없다.
```

Node.js가 뭔지 몰라도 작업하는 데 전혀 지장 없어.

설치할 때 한 번 나타나는 이름 정도로 생각하면 돼.

Git은 나중에 서비스 만들기 주차에서 제대로 다루게 될 거야.

## 자주 헷갈리는 포인트

### 터미널 명령어를 외워야 해?

아니. 우리가 직접 칠 명령은 `claude` 하나 정도야. 나머지는 한국어로 말하면 AI가 알아서 실행해.

### 창을 여러 개 여는 게 항상 좋아?

아니. 서로 다른 작업일 때만 좋아. 같은 파일을 건드리는 작업이면 오히려 충돌 나서 손해야.

### 이전 세션을 불러왔는데 이상하게 답해

이어서 열면 예전 대화가 다 딸려와서 그래. 작업이 바뀌었으면 새 세션을 열고, 필요한 내용만 파일로 넘겨주는 게 나아.

### 왼쪽 파일 목록에 뭐가 잔뜩 생겼어

AI가 작업하면서 만든 파일들이야. 뭔지 모르겠으면 그 파일을 끌어다 놓고 "이 파일 뭐야?" 하고 물어보면 돼.

### VS Code 말고 다른 걸 써도 돼?

돼. 화면 구조는 대부분 비슷해. 왼쪽 파일, 가운데 편집, 아래 터미널이라는 뼈대는 도구가 달라져도 거의 같아.

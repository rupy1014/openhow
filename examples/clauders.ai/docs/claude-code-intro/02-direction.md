## 핵심 요약

**Claude 유료로 결제 했지? 여러분 PC에 박사급 인재가 생겼는데, 땡땡이 치고 놀고있으니까 놀지 못하도록 일을 잘 시켜보자. 근데 어떻게 해야 잘 부려먹었다고 소문이 날 수 있을까? 그 과정과 노하우를 공유할게.**

## 1. Claude Code는 내 PC에 앉은 박사급 인재다

Claude Code를 마법사처럼 생각하면 오히려 헷갈려. 버튼 하나 누르면 완성품이 알아서 나오는 존재가 아니야.

Claude Code는 내 폴더를 읽고, 파일을 만들고, 코드를 고치고, 명령을 실행하면서 실제 작업을 대신 해주는 파트너야.

입문 단계에서는 이렇게 이해하면 제일 편해.

> **내 PC 안에 상주하는 박사급 전담 인재**

이 인재는 능력이 이미 충분해.

- 문서 초안을 빠르게 만들어줘
- 폴더 안에 뭐가 있는지 설명해줘
- 간단한 HTML 페이지를 만들어줘. 앱도 개발하고 출시할 수 있어.
- 에러 메시지를 읽고 원인을 찾아줘. 서비스 개발이나 운영도 가능해.
- 긴 내용을 짧게 정리해줘. 이메일도 정리하고, 나만의 소설도 작성할 수 있어.
- 내가 만든 결과물을 더 보기 좋게 고쳐줘. 톤앤매너를 정해서 정돈할 수 있어.

근데 딱 하나 모르는 게 있어.

- 내가 뭘 중요하게 보는지 몰라
- 내 취향을 몰라
- 이 프로젝트가 왜 필요한지 몰라
- 내가 개발자인지 비개발자인지 몰라
- 어디까지 해도 되고, 어디부터는 하면 안 되는지 몰라

즉 **실력은 박사급인데 내 맥락은 제로**야. 그러니까 첫날부터 “알아서 다 해줘”라고 던지면 안 돼.

근데 잘 쓰는 법은 생각보다 단순해. 여러분한테는 이미 **도메인 지식**이 있잖아. 마케터든, 기획자든, 목공예를 하든 각자만의 산출물 방식이 있고, 회사에서 써온 템플릿 포맷과 왜 그렇게 써왔는지에 대한 이유, 그리고 실제 샘플 파일까지 — 이미 다 손에 쥐고 있어.

이걸 **AI가 알아들을 수 있게 세팅**만 해주면, 여러분이 원하는 그대로 결과물을 뽑아줄 거야. 결과물을 보고 세팅을 계속 개선해 나가면 돼.

## 2. 첫날엔 작은 일부터 이것저것 시켜보자

첫날부터 거창한 프로젝트를 통째로 맡길 필요는 없어. 작은 요청부터 이것저것 던져보면서 이 친구가 어디까지 해주는지, 어떤 식으로 답하는지 살펴보는 게 먼저야.

보통은 이렇게 가볍게 시작해.

> “혹시 이런 것도 할 줄 알아?”
>
> “이 자료 한번 정리해볼래?”
>
> “이 문장 좀 더 자연스럽게 바꿔줄 수 있어?”
>
> “이 폴더 보고 뭐가 있는지 설명해줄래?”

조금 감이 잡히면 한 발 더 들어가봐.

> “나는 이런 식으로 일해왔는데, 더 좋은 방법이 있을까?”
>
> “다른 회사나 다른 사람들은 이걸 어떻게 처리하지?”
>
> “네가 방금 제안한 건 내 상황이랑 안 맞아. 지금 내가 하는 프로젝트는 ○○이고, 그 중에서 내가 맡은 업무는 △△라서 이런 산출물을 내고 있었거든. 이 맥락으로 다시 제안해줘.”

앞의 네 줄은 "뭘 할 줄 아는지" 탐색하는 거라면, 뒤의 세 줄은 **내 맥락을 던져주면서 답을 내 것에 맞게 끌어오는 대화**야. 여기서부터 1번에서 얘기한 도메인 세팅이 쌓이기 시작한다.

이렇게 툭툭 던지다 보면 감이 온다.

> 아, “초보자용”이라고 말하면 설명이 쉬워지는구나.
>
> 아, “계획만”이라고 해야 바로 코드를 안 짜는구나.
>
> 아, “짧게”라고 해야 답이 줄어드는구나.
>
> 아, 마음에 안 드는 부분을 콕 집어 말하면 바로 고쳐주는구나.

처음엔 결과물보다 **감 잡기**가 목적이야.

## 3. 좋은 결과는 한 번에 안 나온다 — 주고받으면서 만든다

매번 마음에 드는 결과가 한 번에 나오는 건 아니야.

방향이 어긋나는 건 AI가 못해서라기보다, 보통은 **내가 원하는 맥락이 아직 밖으로 안 나왔기 때문**이야.

예를 들어 이렇게 시작했다고 해보자.

```text
자기소개 페이지 만들어줘.
```

이렇게 말하면 Claude가 바로 페이지를 만들 수도 있지만, 보통은 맥락을 잡으려고 먼저 물어볼 수 있어.

```text
누구를 소개하는 페이지인가요?
보는 사람은 누구인가요?
포트폴리오용인가요, 수업 발표용인가요, 개인 프로필용인가요?
꼭 넣고 싶은 내용이 있나요?
분위기는 전문적으로 갈까요, 친근하게 갈까요?
```

이 질문을 귀찮게 보면 안 돼.

Claude가 일을 미루는 게 아니라, **일을 제대로 하기 위해 필요한 맥락을 맞추는 과정**이야.

그래서 처음부터 이렇게 말하면 훨씬 자연스럽다.

```text
나를 소개하는 아주 간단한 웹페이지를 만들고 싶어.
목적은 클로더즈 수업에서 "내가 AI로 무엇을 만들고 싶은지" 보여주는 거야.
나는 코딩을 처음 배우는 비개발자고, 아직 넣을 내용이 완벽하게 정리되지는 않았어.

바로 만들기 전에 필요한 질문을 5개만 해줘.
내 답변을 바탕으로 첫 화면 구성부터 제안해줘.
```

그럼 Claude가 질문을 해줄 거야.

너는 완벽하게 답하려고 하지 말고, 지금 생각나는 만큼만 답하면 돼.

```text
1. 보는 사람은 같이 수업 듣는 사람들과 지인들이야.
2. 목적은 내가 어떤 사람이고, 앞으로 어떤 서비스를 만들고 싶은지 보여주는 거야.
3. 아직 경력이나 포트폴리오는 많지 않아. 대신 내가 관심 있는 문제를 보여주고 싶어.
4. 분위기는 너무 개발자 포트폴리오 같지 않고, 친근했으면 좋겠어.
5. 일단 한 화면짜리로 가볍게 만들고 싶어.
```

이제 이 답변을 기반으로 시키면 된다.

```text
좋아. 이 답변을 바탕으로 자기소개 페이지 첫 화면을 만들어줘.
섹션은 소개, 관심 있는 문제, 만들고 싶은 서비스, 연락 방법 정도면 돼.
디자인은 깔끔하되 너무 개발자 포트폴리오처럼 보이지 않게 해줘.

만든 뒤에는 어떤 파일이 어떤 역할을 하는지도 초보자 눈높이로 설명해줘.
```

결과가 너무 딱딱하게 나오면 바로 이어서 말하면 돼.

```text
좋아. 그런데 아직 너무 개발자 포트폴리오 같아.
비개발자가 처음 만든 소개 페이지처럼 더 쉽고 친근하게 바꿔줘.
문장도 조금 더 말하듯이 바꿔줘.
```

마음에 들게 나오면 보완을 시킨다.

```text
좋아. 이제 각 코드 옆에 초보자용 한글 주석을 달아줘.
내가 어떤 부분을 바꾸면 이름, 소개문, 색상이 바뀌는지도 알려줘.
```

감이 잡히면 다음 단계를 꺼낸다.

```text
이제 이 페이지를 실제로 배포하려면 다음에 뭘 해야 하는지 단계별로 알려줘.
```

처음엔 “해줘”로 시작해도 돼.

다만 한 번에 완벽한 프롬프트를 쓰려고 하기보다, **질문을 받고, 답하고, 결과를 보고, 다시 고치는 흐름**에 익숙해지는 게 훨씬 중요해.

## 4. 세 가지만 붙이면 결과가 좋아진다

앞에서는 던져보고 고쳐 받으면서 감을 잡았어. 여기에 세 가지만 붙이면 처음부터 결과의 정확도가 확 올라간다.

### 1) 업무 — 뭘 해줘?

```text
자기소개 페이지 초안을 만들어줘.
```

### 2) 상황 — 지금 어떤 상태야?

```text
나는 코딩을 처음 배우는 비개발자야.
이건 4주짜리 입문 수업 자료야.
```

### 3) 기준 — 어떤 식이면 좋아?

```text
최대한 쉽게 설명해줘.
외부 라이브러리는 쓰지 마.
일단 코드는 만들지 말고 계획만 알려줘.
```

한 줄로 정리하면 이거야.

> “이 업무 해줘. 지금 상황은 이렇고, 결과는 이런 기준이면 좋겠어.”

### 이렇게도 써먹는다 — 모르는 코드를 만났을 때

프로젝트가 굴러가다 보면 AI가 이것저것 만들어줬는데 내가 못 읽는 코드가 쌓일 때가 있어. 외부에서 누가 공개한 좋아 보이는 소스를 받아왔는데 무슨 말인지 하나도 모를 때도 있고.

이럴 땐 똑같이 3박자를 끼워넣는다.

```text
이 코드 설명해줘. (또는 파일, 또는 프로젝트)
나는 아무것도 모르는 초등학생이라고 생각하고,
알기 쉽게 쉬운 비유로 풀어줘.
```

업무는 “설명해줘”, 상황은 “아무것도 모르는 초등학생”, 기준은 “한 줄씩 쉬운 비유로”. 그러면 어른이 어린이한테 풀어주듯 톤이 바뀌어서 알아듣게 설명해준다. 같은 3박자인데 끼워넣는 내용만 바꾸면 받는 결과물의 결이 완전히 달라져.

여기까지 오면 “해줘”만 하던 때보다 원하는 결과에 훨씬 빨리 도달하게 돼.

## 5. 결국, 머릿속을 꺼내는 작업이다

여기서 하고 싶은 말은 "프롬프트 공식을 외우자"가 아니야.

업무, 상황, 기준을 붙이는 이유는 단순히 답변을 예쁘게 받으려는 게 아니야. 사실 더 중요한 건 **내 머릿속에만 있던 생각을 밖으로 꺼내는 것**이야.

처음에는 나도 내가 뭘 원하는지 잘 모를 때가 많아.

```text
자기소개 페이지를 만들고 싶다.
업무 자동화를 해보고 싶다.
내 서비스를 알려보고 싶다.
뭔가 만들고 싶은데 어디서부터 해야 할지 모르겠다.
```

이 정도로만 머릿속에 떠다니는 경우가 많거든.

그런데 Claude에게 던져보면 질문이 돌아와.

```text
누가 볼 건가요?
왜 필요한가요?
어떤 톤이면 좋나요?
어디까지 만들면 충분한가요?
결과물은 문서인가요, 화면인가요, 코드인가요?
```

이 질문에 답하다 보면 이상하게 내 생각이 조금씩 정리돼.

처음에는 그냥 "자기소개 페이지"였는데, 대화하다 보면 이렇게 바뀐다.

```text
나는 코딩을 처음 배우는 비개발자고,
클로더즈 수업에서 내가 어떤 문제에 관심 있는지 보여주고 싶고,
너무 개발자 포트폴리오처럼 보이기보다는
친근한 한 화면짜리 소개 페이지를 만들고 싶다.
```

이게 바로 머릿속에 있던 생각이 밖으로 나온 거야.

업무 자동화도 똑같아.

처음에는 이렇게 막연하게 시작할 수 있어.

```text
우리 회사에서 반복하는 일을 자동화하고 싶어.
```

그러면 Claude가 물어볼 거야.

```text
어떤 일을 반복하나요?
지금은 어떤 순서로 처리하나요?
입력 자료는 어디에 있나요?
최종 결과물은 어떤 형태인가요?
사람이 꼭 확인해야 하는 부분은 어디인가요?
```

이 질문에 답하다 보면 "자동화하고 싶다"가 점점 구체적인 작업으로 바뀐다.

```text
매주 금요일에 엑셀 파일을 받아서,
고객별 매출을 정리하고,
이상치만 따로 표시한 뒤,
팀장에게 보낼 요약 메일 초안을 만들고 싶다.
```

이렇게 밖으로 꺼내져야 Claude도 일을 할 수 있어.

그러니까 이 강의에서 "해줘" 하면서 감을 잡자는 건, 아무 생각 없이 AI에게 떠넘기자는 말이 아니야.

오히려 반대야.

내가 평소에 머릿속으로만 하던 판단, 취향, 기준, 업무 흐름을 Claude와 대화하면서 하나씩 꺼내보자는 거야.

그게 밖으로 나오면 그때부터 결과물이 붙어.

```text
문서로 정리해줘.
화면으로 만들어줘.
코드로 만들어줘.
실행 순서로 쪼개줘.
초보자도 이해하게 설명해줘.
```

이렇게 이어갈 수 있거든.

결국 Claude Code를 잘 쓴다는 건, 멋진 명령어를 많이 아는 게 아니라 **내 생각을 AI가 알아들을 수 있는 형태로 꺼내는 연습**이야.

처음엔 그냥 이것저것 시켜봐.

그리고 결과를 보면서 계속 말해봐.

```text
이건 내가 생각한 거랑 달라.
이 부분은 좋아.
여기는 더 쉽게 가자.
이건 우리 상황에는 안 맞아.
방금 대화를 바탕으로 다시 정리해줘.
```

이 과정을 반복하다 보면, AI가 뭘 할 수 있는지도 알게 되고, 내가 뭘 원하는지도 더 선명해진다.

그게 "해줘" 하면서 감을 잡아가는 진짜 이유야.

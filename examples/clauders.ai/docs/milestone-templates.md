# 주차별 마일스톤 인증 템플릿

## 핵심 요약

**기수제는 강의를 다 들었는지가 아니라, 그 주차의 결과물을 냈는지로 굴러가. 인증 템플릿이 있어야 피드백이 빨라지고 운영도 가벼워진다.**

한 번 템플릿을 맞춰두면 운영자도 덜 헷갈리고, 수강생도 "이 정도면 됐다"를 바로 판단할 수 있어. 그래서 이 문서는 형식 문서 같아 보여도 완주율을 받쳐주는 장치에 더 가까워.

## 왜 이 문서가 필요한가

같은 “배포 링크 제출”이라도 사람마다 내는 방식이 제각각이면

- 피드백이 느려지고
- 운영자가 뭘 봐야 할지 헷갈리고
- 수강생도 “이 정도면 됐나?”를 모르기 쉬워

그래서 주차별 인증은

> **작고, 동일한 포맷으로, 바로 비교 가능하게**

받는 게 핵심이야.

## 1. 시작하기 인증 템플릿

### 제출 목표
- 환경 세팅 완료
- 신규 프로젝트 폴더 생성 완료
- 첫 요청 실행 완료

### 제출 포맷

```md
# 시작하기 인증

- 이름/닉네임:
- 프로젝트 한 줄 이름:

## 1. 환경 세팅 스크린샷
- 첨부 1장

## 2. 신규 프로젝트 폴더 스크린샷
- 첨부 1장

## 3. 첫 요청 결과 스크린샷
- 첨부 1장 (`claude` 대화 + 생성 또는 수정된 파일)

## 4. 한 줄 상태
- 지금 어디까지 됐는지 한 줄
```

### 통과 기준
- Claude Code 실행 흔적이 보여
- 프로젝트 폴더가 실제로 있어
- 첫 요청을 한 흔적이 보여
- “설치는 했는데 폴더는 없음” 상태가 아니야

## 2. 초보 개념잡기 인증 템플릿

### 제출 목표
- `CLAUDE.md` 초안
- `docs/` 업무 문서 1개
- 원본 산출물 또는 전처리한 `.md` 자료 위치

### 제출 포맷

```md
# 초보 개념잡기 인증

- 이름/닉네임:
- 프로젝트명:

## 1. CLAUDE.md 초안
- 핵심 섹션 요약 또는 캡처

## 2. 업무 문서 1개
- 파일 위치: `docs/...`
- 어떤 회사 산출물을 바탕으로 만들었는지:

## 3. 원본/전처리 자료
- 원본 위치: `references/raw/...`
- 전처리 md 위치: `references/processed/...`
```

### 통과 기준
- `CLAUDE.md`에 프로젝트 맥락과 참고 문서 위치가 있다
- `docs/` 업무 문서에 판단 기준이나 작성 과정이 들어 있다
- PDF/PPT 원본을 그대로 쓰지 않고 필요한 내용이 `.md`로 전처리되어 있다

## 3. 서비스 만들기 인증 템플릿

### 제출 목표
- PRD 1장
- CLAUDE.md 증강본
- UI 또는 저장 중 1기능 작동

### 제출 포맷

```md
# 서비스 만들기 인증

- 이름/닉네임:
- 프로젝트명:

## 1. PRD 1장
- 한 줄 설명:
- 대상 사용자:
- 핵심 기능:
- 안 만들 것:
- 성공 기준:

## 2. CLAUDE.md 증강본
- 새로 추가한 규칙 3~5개

## 3. 1기능 작동 증빙
- 무엇이 작동하는지:
- 캡처 또는 짧은 영상:
```

### 통과 기준
- PRD에 Not이 비어 있지 않다
- 성공 기준이 관찰 가능해
- 작동 증빙이 말뿐이 아니라 실제 화면으로 확인돼

## 4. 본격 바이브 코딩 인증 템플릿

### 제출 목표
- 외부 연동 1개
- Git 히스토리
- 배포 링크

### 제출 포맷

```md
# 본격 바이브 코딩 인증

- 이름/닉네임:
- 프로젝트명:

## 1. 외부 연동 1개
- 어떤 연동인지:
- 어떻게 확인했는지:

## 2. Git 히스토리
- 대표 커밋 3개:
  -
  -
  -

## 3. 배포 링크
- URL:

## 4. 지금 가장 불안한 지점 1개
- (선택)
```

### 통과 기준
- 외부 연동이 실제 동작해
- Git 저장 리듬이 최소 2~3개 이상 보여
- 배포 링크가 열리고 핵심 화면이 깨지지 않는다

## 5. 데모나잇 인증 템플릿 (선택)

> 본편 주차는 아니고, 데모나잇 참여 수강생 대상. 자동화 입문 인증 템플릿(`/write 1화`)은 아직 미확정 — 향후 운영 단계에서 추가.

### 제출 목표
- 피드백 1건 반영
- 수정 배포
- 자동화 확장 아이디어 1건

### 제출 포맷

```md
# 데모나잇 인증

- 이름/닉네임:
- 프로젝트명:

## 1. 최종 배포 링크
- URL:

## 2. 피드백 1건 반영
- 받은 피드백:
- 어떻게 바꿨는지:
- Before/After:

## 3. 자동화 아이디어 1건
- 입력:
- 처리:
- 출력:
- 주기:
```

### 통과 기준
- Before/After가 실제로 비교 가능해
- 자동화 아이디어가 입력/처리/출력 구조를 가져
- “언젠가 자동화”가 아니라 구체 반복 업무와 연결돼

## 운영자 메모 — 빠른 체크 순서

각 제출물은 아래 순서로 보면 돼.

1. **진짜 결과물이 있나**
2. **링크/화면이 실제로 열리나**
3. **무엇을 만들었는지 한 문장으로 설명 가능한가**
4. **다음 단계로 넘겨도 되는가**

## 자주 헷갈리는 포인트

- 제출 포맷이 너무 길어져서 수강생이 미룸
- 운영자가 세부 기준 없이 감으로만 봄
- 스크린샷은 있는데 실제 링크/동작 확인이 없음

## 자주 헷갈리는 포인트

- **템플릿을 꼭 그대로 복붙해야 하나?** — 형식은 조금 달라도 되지만, 운영자가 바로 볼 수 있는 핵심 정보는 빠지면 안 돼.
- **잘 쓴 글이 더 중요한가?** — 아니야. 실제 링크, 스크린샷, 동작 흔적처럼 확인 가능한 증빙이 더 중요해.

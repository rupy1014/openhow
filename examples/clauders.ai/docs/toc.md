# 클로더즈 1기 주차 목차

처음 들어오면 "그래서 4주 동안 뭐가 어떻게 이어지지?" 싶지. 그럴 때 이 페이지 하나만 보면 돼.
순서는 **시작하기 → 초보 개념잡기 → 자동화 입문 → 서비스 만들기 (내 아이디어 MVP)**.
처음엔 많아 보여도 실제로는 앞 단계 결과물이 다음 단계 재료가 되는 흐름이야. 자동화 입문은 **새 개념을 쏟아붓는 자리가 아니라** 초보 개념잡기에서 만든 프로젝트 업무매뉴얼과 담당자 감각이 실제 레시피(`/write 1화`)로 어떻게 조립돼 돌아가는지 확인하는 블록이고, 그 뒤 **서비스 만들기**에서 **내 아이디어 한 사이클(아이디어 → PRD → 프론트/백엔드 → 디버깅 → 배포 → PMF)** 을 끝까지 굴리며 바이브 코딩 지식까지 같이 흡수한다.

## 핵심 요약

**이 페이지는 4주 커리큘럼을 외우라고 만든 게 아니라, 지금 내가 어느 구간에 있고 다음에 뭘 남겨야 하는지 한눈에 잡게 해주는 지도야.**

## 왜 목차도 따로 읽어야 하냐면

목차는 그냥 링크 모음처럼 보이기 쉬워. 그런데 클로더즈에서는 각 파트가 따로 노는 게 아니라 앞 단계 결과물이 다음 단계 재료가 되거든. 그래서 이 페이지는 순서를 외우는 용도보다, 지금 내가 어느 고리에서 움직이고 있는지 확인하는 지도 역할을 해.

## 전체 구조

표만 보고 지나가지 말고, 각 줄이 "이번 주에 뭘 남겨야 하는지"라고 생각하면서 보면 훨씬 잘 들어와.

| --- | --- | --- | --- |

| [초보 개념잡기](./claude-code-intro/01-model-choice) — AI 기초·감 잡기·일 잘 시키기·환경 이해 | AI 기초·작게 시켜보기·프로젝트 업무매뉴얼 만들기 + 화면/컨텍스트/검증 습관 | 비동기 6편 | 사전 준비 |

## 바이브 코딩 4단계 (공식 이름표)

이 라벨을 붙여두는 이유는 멋있어 보여서가 아니야. 막혔을 때 "내가 지금 탐색에서 막힌 건지, 구현에서 막힌 건지" 빨리 구분하려고 붙이는 거야.

Claude Code 101의 **Explore → Plan → Code → Commit** 을 잡돌식 한국어로 박은 거야. 매 주차·매 세션이 이 4단계 중 어디에 해당하는지 라벨로 붙여.

| 단계 | 한국어 | 클로더즈 주차 |
| --- | --- | --- |
| Explore | 탐색 | 자동화 입문 확인 + 서비스 만들기 전반 (아이디어·기획·기술 선택) |
| Plan | 기획 | 서비스 만들기 전반 (PRD·구조·레퍼런스) |
| Code | 구현 | 서비스 만들기 후반 (Git·프론트엔드·백엔드·디버깅·배포) |
| Commit | 저장·배포 | 서비스 만들기 후반 + 데모나잇 (피드백·PMF) |

수강생이 막혔을 때 "지금 내가 어느 단계에서 꼬였는지" 자가 진단이 가능해진다.

## 시작하기 — 환경 셋업

> 비동기 4강. 설치·VS Code·Claude Code 개념·신규 프로젝트 셋업·"해줘" 한 번까지. **초보 개념잡기 라이브 시작 전 손이 한 번 움직여본 상태**가 목표.

- **1강.** Claude Code 설치 + VS Code 관제탑 (원 `part-01/01-chapter` · `02-chapter` 기반) — AI 코딩 도구 비교(구 부록 C) 내용 통합
- **2강.** Claude Code (왜 CLI 써야 하는지) — **신규 작성** (vibe-codex-book Part 1 차용 후보)
- **3강.** 신규 프로젝트 생성 — 작업 폴더·`claude` 첫 실행·Git init까지
- **4강.** "해줘"라고 하기 — 작은 요청·계획 먼저·참고자료 주기·첫 파일 생성/수정 경험

**인증물**: 환경 세팅 스크린샷 + 신규 프로젝트 폴더 스크린샷 + 첫 요청 결과 스크린샷
**완주 지표**: 90% 이상 제출 (초보 개념잡기 진입 게이트)

## 초보 개념잡기 — AI 기초·감 잡기·일 잘 시키기·환경 이해

> 초보 개념잡기는 길게 끌고 가지 않는다. AI가 어떤 도구인지 감을 잡고, 작은 요청을 해보고, 내 일을 설명하기 위한 프로젝트 업무매뉴얼을 만드는 데 집중한다. 브리프·PRD·배포는 뒤 파트에서 실제 작업으로 다룬다.
>
> 1~3강이 **일을 시키는 감각**이라면, 4~6강은 **그 일이 돌아가는 환경**이다. 화면이 왜 세 칸인지, AI가 왜 갑자기 멍청해지는지, 검증은 왜 다른 창에서 해야 하는지를 잡는다. 6기 특강(모네) 내용을 문서로 옮긴 블록이라, 1~3강만 봐도 진도는 나가지만 여기까지 보면 막히는 지점이 확 줄어든다.

- **1강 AI 기초.** 회사/제품/모델, 등급, 기본 용어를 잡는다.
- **2강 감 잡기.** 작은 요청을 던지고 결과를 보며 다시 시키는 감각을 익힌다.
- **3강 일 잘 시키기.** 회사 산출물을 `.md`로 전처리하고, 대화로 업무매뉴얼을 뽑아 프로젝트에 남긴다.
- **4강 화면 읽는 법.** IDE 세 칸 구조, 터미널, 세션 여러 개 쓰기, 껐던 작업 이어가기.
- **5강 AI는 기억하지 않는다.** 컨텍스트가 매번 다시 읽히는 원리에서 오염·컴팩트·메모리·토큰을 한 줄로 잇는다.
- **6강 결과 끌어올리기.** 역질문, Plan Mode, 다른 세션에서 검증, 구조화된 입력.

**인증물**: `CLAUDE.md` 초안 + `docs/` 업무 문서 1개
**완주 지표**: 90% 이상 제출

## 자동화 입문 — 초보 개념잡기 레시피 확인 + `/write 1화`

> 새 개념을 쏟아붓는 자리가 아니라, **초보 개념잡기에서 만든 프로젝트 업무매뉴얼과 담당자 감각이 실제 working system에서 어떻게 한 덩어리로 조립돼 돌아가는지** 눈으로 확인하는 블록이야. 자기 프로젝트 이전 단계라 부담 없이 레시피 한 번 돌려본다.

- **1강 4가지 기능.** commands / agents / skills / hooks — Claude Code 내 맞춤 장치 4개가 초보 개념잡기 개념(3강 업무매뉴얼 / 2강 일 시키기 / 프로젝트 문서)을 어떻게 포장해두는지 매핑
- **2강 작업 맡기기.** 블로그 연재용 `/write` 명령과 담당자 워크플로우 — CLAUDE.md·tone-and-manner 파일이 실제로 어떻게 읽히고, 마스터 에이전트가 서브 에이전트를 순서대로 부르는지 확인
- **3강 사례 모음.** `/write` 외의 응용 예시(뉴스봇·자동화 패턴)로 확장 감각 맛보기
- **4강 숙제.** 자기 주제로 연재 폴더 세팅 + `/write 1화` 직접 실행까지 손으로 해보기
- **바이브 4단계.** 사전 준비 + Explore. 내 프로젝트를 만드는 게 아니라 레시피 동작을 확인하는 단계.

**인증물**: `/write 1화` 실행 스크린샷 + `drafts/1화.md` 결과물
**완주 지표**: 70% 이상 제출 (서비스 만들기 진입 권장 게이트)

> 본격 자동화 운영(Part 5 / OpenClaw) 은 클로더즈 범위 밖. 수료 후 자료로 링크 제공.

## 서비스 만들기 — 내 아이디어 한 사이클로 MVP 배포까지

> 자동화 입문까지 손에 익었으면, 이번엔 **본인 아이디어**를 하나의 흐름으로 아이디어부터 PMF 까지 끝까지 굴린다. 본인 아이디어가 따로 있어도 같은 흐름에 본인 아이디어를 넣으면 된다. 전반은 방향 잡기, 후반은 코드·배포 실전이라고 보면 돼.
>
> 본격 바이브 코딩(API·디버깅·배포·인증) 도 별도 주차가 아니라 이 안에 흡수돼 있다. 기존 `vibe-coding/` 강의 폴더는 이 챕터들로 합쳐졌고 원본은 `docs_backlog/vibe-coding/` 에 백업돼 있다.

### 전반 (Explore + Plan) — 1~5강

- **1강 [전체 흐름](./build-service/00-overview).** 아이디어 → PMF 한 장 지도.
- **2강 [아이디어](./build-service/01-idea).** 고객·문제·가설 3줄로 아이디어 좁히기.
- **3강 [바이브 기획](./build-service/02-lean-plan).** PRD·사용자 흐름·IA·와이어프레임·MVP 범위 감 잡기.
- **4강 [PRD](./build-service/03-prd).** AI와 대화하고 레퍼런스를 비교해 prd.md 정리.
- **5강 [기술 선택과 구조 잡기](./build-service/04-tech).** 프론트 중심 MVP부터 서버·DB·API 기본 구조까지.
### 후반 (Code + Commit) — 6~13강

- **6강 [프론트엔드와 백엔드 이해](./build-service/05-build-frontend).** 사용자가 보는 화면과 화면 뒤 API·저장·비밀값 흐름 이해하기.
- **7강 [Git](./build-service/06-git).** 만든 기능을 저장하고, 망가졌을 때 되돌리기.
- **8강 [고치는 법](./build-service/07-fix).** 에러 3 요소(WHAT/WHY/WHERE) + AI 디버깅 3 박자 + 3 회 룰.
- **9강 [배포](./build-service/08-deploy).** Vercel + 환경변수 + GitHub 연결로 URL 확보.
- **10강 [피드백](./build-service/09-feedback).** 5 명 정성 인터뷰 + 사용 로그 5 지표(보너스).
- **11강 [PMF 찾기](./build-service/10-pmf).** 고객 피드백으로 내 제품에 맞는 시장 찾기.
- **12강 [모객](./build-service/11-distribution).** 고객이 모여 있는 채널에서 모르는 사람 데려오기.
- **13강 [첫 결제와 PG 연동](./build-service/12-pg-bootpay).** 가격 정해 링크로 받고, 팔리면 부트페이로 PG 붙이기.

**인증물**: PRD 1장 + 본인 프로젝트 MVP 배포 링크 + Git 히스토리 + 5명 피드백 메모 (모르는 사람 2명 포함) + 만드는 과정 공개 포스트 1개 + 첫 판매 제안 1건
**완주 지표**: PRD 게이트 70% + 후반 끝 50~60%

# 평가 기준표

## 핵심 요약

**평가 기준이 같아야 피드백 속도가 빨라져. 이 문서의 목적은 줄 세우기가 아니라, 다음 단계로 넘길 수 있는지 빠르게 판단하는 거야.**

이 기준표는 혼내려고 만든 게 아니야. 지금 어디까지 왔는지 빨리 같이 보고, 다음 단계에서 뭐 하나만 더 보완하면 되는지 잡아주려고 만든 표라고 보면 돼.

## 왜 평가 기준부터 선명해야 하냐면

기준이 없으면 운영자는 피드백이 들쭉날쭉해지고, 수강생은 어디까지 하면 통과인지 계속 불안해져. 그래서 이 문서는 차갑게 점수 매기려는 표가 아니라, 다음 단계로 넘길 수 있는 공통 판단 언어를 먼저 맞추는 문서라고 보면 돼.

## 평가 원칙

### 1. 감점표보다 통과표

우리는 “틀린 걸 잡는 평가”보다

> **다음 단계로 넘어가도 되는가**

를 보는 평가를 해.

### 2. 결과물 우선

- 들은 강의 수보다
- 실제 산출물과 동작 여부를 먼저 봐

### 3. 숫자와 행동 신호를 선호

- “좋아 보여”보다
- “3분 안에 첫 메시지 가능” 같은 기준이 더 세다

## 공통 통과 기준

아래 4개 중 3개 이상이면 기본 통과로 봐.

| 항목 | 질문 |
| --- | --- |
| 방향 선명도 | 누구를 위한 무엇인지 한 문장으로 말할 수 있나 |
| 범위 통제 | 안 만들 것이 분명한가 |
| 동작 증빙 | 실제로 눌러보거나 열어볼 수 있나 |
| 다음 단계 연결성 | 다음 주차 입력물로 바로 쓸 수 있나 |

## 단계별 기준

### 1. 시작하기

**통과 기준**
- 환경 세팅 흔적이 있어
- 신규 프로젝트 폴더가 있어
- 다음 파트로 진입 가능한 최소 상태다

**보류 기준**
- 설치만 했다고 말하지만 프로젝트 폴더가 없음
- 스크린샷이 모호해서 실제 상태 확인이 안 됨

### 2. 초보 개념잡기

**통과 기준**
- 주제 브리프가 1~2문장으로 적혀 있어
- CLAUDE.md 초안이 있어
- 첫 페이지 링크가 열려
- AI로 해본 3가지가 구체 행동으로 적혀 있어

**보류 기준**
- 브리프가 너무 추상적임
- 링크는 있는데 실제 페이지가 안 열림
- CLAUDE.md가 사실상 비어 있음

### 3. 자동화 입문

**통과 기준**
- `/write 1화` 실행 스크린샷이 있어
- `drafts/1화.md` 결과물이 실제로 나와 있어
- CLAUDE.md·tone-and-manner 파일을 본인 주제에 맞게 고친 흔적이 보여

**보류 기준**
- 세팅 프롬프트만 붙여넣고 멈춤
- `/write` 실행은 했지만 본인 주제가 아니라 예시 그대로
- 담당자 agent 파일이 비어 있음

### 4. 서비스 만들기

**통과 기준**
- PRD 1장이 있어
- Not이 비어 있지 않다
- 성공 기준이 관찰 가능해
- UI 또는 저장 중 1기능이 실제로 작동해

**보류 기준**
- PRD가 기능 나열만 있고 Why가 없음
- 안 만들 것이 없음
- 작동 증빙이 텍스트뿐임

### 5. 본격 바이브 코딩

**통과 기준**
- 외부 연동 1개가 실제로 동작해
- Git 저장 리듬이 보여
- 배포 링크가 열리고 핵심 기능이 깨지지 않는다

**보류 기준**
- 외부 연동 설명만 있고 실제 증빙이 없음
- 커밋이 1개뿐이거나 의미 단위가 안 보임
- 배포 링크가 죽어 있음

### 6. 데모나잇 (선택)

**통과 기준**
- 피드백 1건을 실제 반영했다
- 수정 배포 링크가 있어
- 자동화 확장 아이디어가 입력/처리/출력 구조로 적혀 있어

**보류 기준**
- 피드백은 받았지만 반영 증빙이 없음
- Before/After가 비교 안 됨
- 자동화 아이디어가 너무 추상적임

## 빠른 점수표

운영 편의를 위해 100점 만점보다 4항목 체크가 더 중요하지만,
점수로 봐야 할 때는 아래처럼 단순화해.

| 항목 | 배점 |
| --- | ---: |
| 방향 선명도 | 25 |
| 범위 통제 | 25 |
| 동작/증빙 | 30 |
| 다음 단계 연결성 | 20 |

### 해석
- **85~100**: 바로 다음 단계 진행
- **70~84**: 진행 가능, 단 보완 1~2개 코멘트
- **50~69**: 보완 후 재제출 권장
- **49이하**: 범위 재설정부터 다시

## 자주 감점되는 패턴

- 숫자 기준 없는 문장만 있음
- “될 것 같아” 수준이지 실제 증빙이 없음
- 안 만들 것이 비어 있음
- 범위가 갑자기 커져 있음
- 피드백 반영보다 새 기능 추가에 집착함

## 운영자 한 줄 코멘트 템플릿

### 통과
> 지금 단계 기준으로는 충분히 통과야. 다음 단계에서는 [한 가지]만 더 선명하게 잡으면 돼.

### 조건부 통과
> 핵심은 맞는데, 다음 단계로 가기 전에 [한 가지]만 보완하면 훨씬 덜 흔들려.

### 보류
> 지금 문제는 실력보다 범위/증빙이야. [한 가지]를 줄이거나 실제 동작 증빙부터 다시 잡아줘.

## 자주 헷갈리는 포인트

- **보류면 실패라는 뜻인가?** — 아니야. 지금 보완할 한 가지가 선명해졌다는 뜻에 더 가까워.
- **모든 항목이 완벽해야 통과하나?** — 아니야. 다음 단계로 안전하게 넘어갈 수 있는지가 더 중요해.

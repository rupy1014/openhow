> "할일 앱 만들긴 했는데... 이걸 진짜 서비스로 바꾸려면 뭘 더 해야 돼?"

지금까지 5개 프로젝트를 만들었어.
할일 앱, AI 챗봇, AI 분석 서비스, 슬랙 봇, 데이터 대시보드.

다 "돌아가긴" 해. 근데 "서비스"는 아니야.
진짜 서비스가 되려면 6가지가 더 필요해.

1. 로그인 (누가 쓰는지)
2. 결제 (돈을 받을 수 있는지)
3. 멀티유저 (여러 명이 동시에 쓸 수 있는지)
4. 성능 (느리지 않은지)
5. 모니터링 (에러가 나면 내가 아는지)
6. 보안 (뚫리지 않는지)

하나씩 보자.

---

## 1. 로그인 붙이기

지금 만든 앱은 아무나 들어와서 아무 데이터나 볼 수 있어.
"이 데이터는 나만 볼 수 있어야 해" 라는 순간이 오면, 로그인이 필요해.

### 두 가지 선택지

| 방식 | 뭐냐 | 언제 쓰냐 |
|------|------|-----------|
| **NextAuth.js** | Next.js 전용 인증 라이브러리 | Next.js 프로젝트일 때 |
| **Supabase Auth** | Supabase 내장 인증 | Supabase를 DB로 쓰고 있을 때 |

둘 다 구글/깃허브 소셜 로그인을 지원해.
이메일+비밀번호 방식도 되고.

### AI한테 이렇게 시켜

```
"NextAuth.js로 구글 로그인 추가해줘.
로그인하면 세션에 userId 저장하고,
로그인 안 했으면 /login 페이지로 리다이렉트해."
```

Supabase를 쓰고 있다면:

```
"Supabase Auth로 구글 소셜 로그인 붙여줘.
로그인 성공하면 /dashboard로 이동하게 해줘.
supabase.auth.getUser()로 현재 유저 가져오는 훅도 만들어줘."
```

### 핵심 포인트

- **소셜 로그인부터 시작해.** 이메일+비밀번호는 비밀번호 찾기, 이메일 인증 등 신경 쓸 게 많아.
- 소셜 로그인은 구글/깃허브 개발자 콘솔에서 클라이언트 ID, 시크릿을 발급받아야 해.
- AI한테 "구글 클라우드 콘솔에서 OAuth 클라이언트 만드는 순서 알려줘"라고 하면 돼.

## 2. 결제 연동하기

"이 기능은 유료로 해야지." 그 순간이 오면 결제가 필요해.

### 두 가지 선택지

| 서비스 | 특징 | 수수료 |
|--------|------|--------|
| **Stripe** | 글로벌 표준. 문서가 좋아. | 3.4% + 400원 |
| **토스페이먼츠** | 한국 결제에 최적화. 카드/계좌이체/간편결제. | 3.3% |

해외 사용자를 상대한다면 Stripe.
한국 사용자만이면 토스페이먼츠.

### AI한테 이렇게 시켜

```
"Stripe Checkout으로 월 9,900원 구독 결제 페이지 만들어줘.
결제 성공하면 users 테이블에 plan: 'pro' 저장하고,
pro 유저만 접근 가능한 /pro 페이지 만들어줘."
```

### 핵심 포인트

- **Stripe Checkout**을 써. Stripe이 결제 페이지를 호스팅해주니까 직접 카드번호 입력 폼을 만들 필요 없어.
- 테스트 모드가 있어서 실제 결제 없이 개발할 수 있어. 테스트 카드번호: `4242 4242 4242 4242`.
- 구독(월결제)이 필요하면 Stripe Billing을 같이 써.
- 토스페이먼츠도 테스트 키가 있어. 개발 중엔 항상 테스트 키 사용.

## 3. 멀티유저 지원

지금 할일 앱의 DB를 봐.

```sql
-- 지금: 모든 할일이 한 테이블에
CREATE TABLE todos (
  id INTEGER PRIMARY KEY,
  title TEXT,
  done BOOLEAN
);
```

누가 만든 할일인지 구분이 안 돼.
100명이 쓰면 100명의 할일이 섞여.

```sql
-- 고도화: userId 컬럼 추가
CREATE TABLE todos (
  id INTEGER PRIMARY KEY,
  title TEXT,
  done BOOLEAN,
  user_id TEXT NOT NULL  -- 누구 거냐
);
```

이 한 줄이면 "내 할일만 보기"가 가능해져.

### AI한테 이렇게 시켜

```
"todos 테이블에 user_id 컬럼 추가해줘.
할일 생성할 때 로그인한 유저의 ID를 자동으로 넣고,
조회할 때는 현재 로그인한 유저의 할일만 가져오게 해줘."
```

### 권한 관리가 필요할 때

"관리자만 삭제할 수 있어야 해" 같은 요구가 생기면:

```
"users 테이블에 role 컬럼 추가해줘. 'admin'이랑 'user' 두 가지.
/admin 페이지는 role이 'admin'인 유저만 접근 가능하게 해줘.
미들웨어에서 체크하게 해줘."
```

### 핵심 포인트

- **모든 데이터 테이블에 `user_id`를 넣는 게 기본이야.**
- API에서 데이터를 가져올 때 `WHERE user_id = 현재유저` 조건을 빠뜨리면 다른 사람 데이터가 보여. 보안 사고야.
- 이건 AI가 실수할 수 있는 부분이야. 반드시 확인해.

## 4. 성능 최적화

유저가 10명일 때는 괜찮아도, 100명이 되면 느려지기 시작해.

### 캐싱

같은 데이터를 매번 DB에서 가져오면 느려.
자주 바뀌지 않는 데이터는 캐시에 저장해두고 빠르게 꺼내 써.

```
"API 응답에 Cache-Control 헤더 추가해줘.
자주 안 바뀌는 목록 API는 5분 캐시,
유저별 데이터는 캐시하지 마."
```

### 이미지 최적화

이미지가 크면 페이지 로딩이 느려져.
Next.js를 쓰고 있다면 `next/image`를 쓰면 자동 최적화돼.

```
"모든 <img> 태그를 next/image의 Image 컴포넌트로 바꿔줘.
width, height 명시하고, lazy loading 적용해줘."
```

### 번들 사이즈

설치한 라이브러리가 많으면 웹사이트 자체가 무거워져.

```
"현재 프로젝트의 번들 사이즈 분석해줘.
@next/bundle-analyzer 설치하고 실행해서
어떤 라이브러리가 제일 큰지 알려줘."
```

### 핵심 포인트

- **성능은 "느려진 후"에 최적화해도 돼.** 미리 걱정하지 마.
- 느려졌다고 느끼면 그때 AI한테 "이 페이지가 느린데 원인 분석해줘"라고 하면 돼.
- 가장 흔한 원인: 이미지 크기, 불필요한 API 호출, 무거운 라이브러리.

## 5. 모니터링

배포하고 나면 에러가 언제 터지는지 모르잖아.
내가 직접 확인하기 전까지는 유저가 먼저 발견해.

### 에러 트래킹: Sentry

에러가 터지면 자동으로 알림을 보내주는 서비스야.

```
"Sentry 설치하고 초기 설정해줘.
Next.js 프로젝트에 맞게 sentry.client.config.ts,
sentry.server.config.ts 만들어줘.
에러 발생 시 Slack 웹훅으로 알림도 보내줘."
```

### 로그 수집

`console.log`를 남겨도 Vercel 대시보드에서 볼 수 있어.
근데 로그가 많아지면 관리가 안 돼.

간단한 방법:

```
"중요한 API 엔드포인트에 로깅 미들웨어 추가해줘.
요청 URL, 메서드, 응답 시간, 상태 코드를 남기게 해줘.
에러일 때는 요청 body도 남겨줘."
```

### 핵심 포인트

- **Sentry 무료 플랜이면 개인 프로젝트엔 충분해.** 월 5,000건 에러 수집 가능.
- Vercel에 배포했으면 Vercel Analytics도 무료로 쓸 수 있어. 페이지별 로딩 속도를 보여줘.
- 모니터링은 "보험"이야. 안 터질 수도 있지만, 터졌을 때 바로 알 수 있어.

## 6. 보안 기본기

해킹당하면 데이터가 날아가.
기본만 지켜도 대부분의 공격을 막을 수 있어.

### 환경변수 관리

API 키, DB 비밀번호 같은 건 코드에 직접 쓰면 안 돼.

```
"모든 하드코딩된 API 키를 .env 파일로 옮겨줘.
.env는 .gitignore에 추가하고,
코드에서는 process.env.API_KEY 형태로 참조하게 바꿔줘."
```

### SQL 인젝션 방지

유저 입력값을 그대로 SQL에 넣으면 위험해.

```
-- 위험한 코드
SELECT * FROM users WHERE name = '${userInput}';

-- 안전한 코드 (파라미터 바인딩)
SELECT * FROM users WHERE name = ?;
```

AI가 만든 코드가 파라미터 바인딩을 쓰고 있는지 확인해.
안 쓰고 있으면:

```
"이 SQL 쿼리를 파라미터 바인딩 방식으로 바꿔줘.
유저 입력값을 직접 문자열에 넣지 말고."
```

### HTTPS

Vercel, Cloudflare Pages로 배포하면 HTTPS는 자동이야.
직접 서버를 운영하는 경우만 신경 쓰면 돼.

### 핵심 포인트

- **`.env` 파일은 절대 git에 올리지 마.** `.gitignore`에 반드시 추가.
- AI가 만든 코드도 보안 실수가 있을 수 있어. "이 코드에 보안 취약점 있는지 검토해줘"라고 한 번 물어봐.
- 완벽한 보안은 없어. 근데 위 3가지(환경변수, SQL 인젝션, HTTPS)만 지켜도 90%는 막아.

## 고도화 순서

전부 다 한 번에 할 필요 없어.
상황에 따라 우선순위가 달라.

| 상황 | 먼저 해야 할 것 |
|------|----------------|
| "나만 쓸 건데" | 모니터링 → 보안 → 끝 |
| "친구 몇 명이랑 쓸 건데" | 로그인 → 멀티유저 → 모니터링 |
| "불특정 다수에게 오픈할 건데" | 로그인 → 보안 → 멀티유저 → 성능 → 모니터링 |
| "돈 받을 건데" | 로그인 → 결제 → 보안 → 멀티유저 → 모니터링 → 성능 |

핵심은 **로그인이 거의 항상 1순위**라는 거야.
누가 쓰는지 모르면 나머지를 붙일 수가 없어.

## AI한테 고도화 시키는 팁

### 한 번에 하나씩

```
❌ "로그인이랑 결제랑 권한 관리 다 추가해줘"
✅ "먼저 NextAuth로 구글 로그인만 추가해줘"
```

한 번에 여러 개 시키면 충돌이 나거나 코드가 꼬여.
하나 붙이고, 테스트하고, 다음 거 붙여.

### 기존 코드 설명하기

```
"지금 프로젝트 구조를 먼저 파악해줘.
그다음에 기존 코드를 최대한 건드리지 않고
로그인 기능을 추가하는 방법을 알려줘."
```

AI가 기존 코드를 이해하지 못하면 처음부터 다시 만들려고 해.
"기존 코드 유지"를 강조해야 해.

### 테스트 먼저 요청

```
"이 기능 추가하기 전에 테스트 코드부터 만들어줘.
로그인 성공, 실패, 세션 만료 케이스를 커버해줘."
```

고도화는 기존 기능을 망가뜨리기 쉬워.
테스트가 있으면 "기존에 되던 게 안 되는" 상황을 막을 수 있어.

## 한 줄 정리

프로젝트를 "서비스"로 만드는 건 결국 **로그인 → 멀티유저 → 결제 → 성능 → 모니터링** 순서야. 한 번에 하나씩, AI한테 시키면 돼.

> "코딩 안 배워도 된다면서? 그런데 뭔가 알아야 한다고?"

맞아. 헷갈리지.
"코드 몰라도 된다"면서 "뭔가는 알아야 한다"니.

**사실 이게 바이브 코딩의 핵심이야.**

코드 **문법**은 몰라도 돼.
근데 **개념**은 알아야 해.

그 차이를 명확하게 정리해줄게.

```
📚 이 글을 읽고 나면

✅ 바이브 코딩이 뭔지 설명할 수 있어
✅ 코드 문법과 개발 개념의 차이를 구분할 수 있어
✅ 문법 몰라도 개념은 알아야 한다는 걸 이해해
```

## 전통적인 코딩 vs 바이브 코딩

먼저 큰 그림부터 볼게.

```
┌───────────────────────────────────────────────────────────────────────┐
│                     프로그램을 만드는 두 가지 방법                        │
├─────────────────────────────┬─────────────────────────────────────────┤
│       전통적인 코딩          │           바이브 코딩                    │
├─────────────────────────────┼─────────────────────────────────────────┤
│  사람이 직접 코드를 짠다      │   AI가 코드를 짜고, 사람이 방향을 잡는다   │
│  문법, 규칙을 외워야 한다     │   의도와 결과를 명확하게 지시한다         │
│  오류 하나에 몇 시간 고민     │   AI한테 물어보면 바로 해결책 제시        │
│  혼자 모든 걸 알아야 한다     │   AI와 대화하면서 같이 만든다            │
└─────────────────────────────┴─────────────────────────────────────────┘
```

전통적 코딩 vs 바이브 코딩: 직접 쌓는 것과 지휘하는 것의 차이
![전통적 코딩 vs 바이브 코딩: 직접 쌓는 것과 지휘하는 것의 차이](./images/traditional_vs_vibe_coding.png)

**잠깐, "바이브"면 대충 느낌만 전달하면 되는 거 아니야?**

아니야. 여기서 오해하면 안 돼.

```
⚠️ 바이브 코딩 ≠ 대충 말하기

"바이브"라는 단어 때문에 헷갈릴 수 있어.
"느낌만 전달하면 AI가 알아서 해주겠지?" → 이게 안 돼서 다들 막히는 거야.

바이브 코딩의 진짜 의미:
- 코드 문법은 몰라도 됨
- 대신 "뭘 만들지, 왜 만들지, 어떻게 동작해야 하는지"는 명확히 알아야 함
- AI한테 기술적인 지침을 정확하게 내려야 함
```

**바이브 코딩 학습**은 달라. 문법은 AI가 처리해. 너는 **"뭘 만들지"와 "이게 맞는지"**만 판단하면 돼.

"AI가 알아서 해주면 되는 거 아니야?"

아니야. 두 가지 이유가 있어.

## 바이브 코딩으로 뭘 만들 수 있냐?

실제로 개발 경험 없는 사람들이 바이브 코딩으로 만든 것들이야.

```
┌───────────────────────────────────────────────────────────────────────┐
│                 비개발자들이 만든 실제 사례                               │
├───────────────────────────────────────────────────────────────────────┤
│  💼 업무 자동화 — 뉴스 요약 슬랙 봇, 엑셀 자동 합치기, 이메일 분류     │
│  🌐 웹사이트 — 포트폴리오, 스터디 모임 관리, 소규모 쇼핑몰              │
│  📱 간단한 앱 — 습관 트래커, 가계부, 운동 기록                          │
│  📊 데이터 분석 — 매출 시각화 대시보드, 설문 자동 분석                   │
└───────────────────────────────────────────────────────────────────────┘
```

**이 사람들이 코딩을 배웠을까?**
아니야. **AI와 대화하는 법**을 배웠어.

```
⚠️ 바이브 코딩의 한계

모든 걸 바이브 코딩으로 만들 수 있는 건 아니야.

❌ 어려운 것: 수백만 명 대규모 서비스, 은행/병원 보안 시스템, 게임 엔진
✅ 잘 되는 것: 개인/소규모 도구, MVP, 자동화, 웹사이트, 데이터 분석

근데 대부분의 사람들에게는 "잘 되는 것들"이면 충분해.
```

## 비유하자면

```
💡 자동차를 직접 만들 줄 몰라도 운전은 할 수 있어.

근데 운전하려면 적어도 이건 알아야 해:
- 엑셀이 뭐고 브레이크가 뭔지
- 신호등이 뭘 의미하는지
- 어디로 가고 싶은지

바이브 코딩도 마찬가지야.
AI가 차를 만들어주지만, 운전은 네가 해.
```

![바이브 코딩 운전 비유: 엔진을 몰라도 운전은 할 수 있어요](./images/vibe_coding_driving_analogy.png)

그리고 재밌는 게 하나 있어.

바이브 코딩을 하다 보면 코드를 **짤 줄은 몰라도, 볼 줄은 알게 돼.**
처음엔 "뭔가 막 만드네..." 수준이지만,
몇 번 하다 보면 "아, 지금 로그인 부분 고치고 있구나" 가 보여.

## 한 줄 정리

```
✅ 바이브 코딩 = 코드 문법 대신 개념으로 AI를 지휘하는 것
✅ 몰라도 되는 것: 코드 문법, 프레임워크 사용법
✅ 알아야 하는 것: 프로그램 종류, 구조, 데이터 흐름, 아키텍처 개념
✅ 왜? 제대로 지시하려면 + AI가 뭘 하는지 판단하려면

다음 편에서는 이 개념들을 "어떤 수준까지" 알아야 하는지 구체적으로 보여줄게.
```

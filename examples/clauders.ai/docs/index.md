# 클로더즈 — 네 프로젝트를 4주 안에 완주하게 만드는 기수제

> **클로더즈는 "바이브 코딩을 배우는" 강의가 아니라, "네가 만들고 싶은 프로젝트를 4주 안에 끝까지 밀어주는" 기수제다.**
> 프레임워크는 공통(바이브 코딩 4단계 = Explore → Plan → Code → Commit), 프로젝트는 각자 달라.
> 4주 끝에 나오는 건 수료증이 아니라 **배포 링크 + 써본 사람의 피드백**이야.

## 핵심 요약

**한 줄로 말하면 이거야. 4주 동안 시작하기 → 초보 개념잡기 → 자동화 입문(확인차) → 서비스 만들기(내 아이디어 MVP) → 데모나잇 순서로 가고, 목표는 "배포까지 끝낸 MVP 1개 + 무대에서 증명"을 손에 남기는 거야.**

처음 들어왔을 때 "그래서 여기서 결국 뭘 남기게 되는데?" 싶으면 이 페이지부터 보면 돼. 큰 그림을 여기서 먼저 잡아두면 뒤 문서들이 훨씬 덜 복잡하게 읽혀.

## 왜 이 페이지를 먼저 보면 좋냐면

세부 강의부터 바로 들어가면 지금 내가 뭘 남겨야 하는지, 어디까지 가야 하는지를 놓치기 쉬워. 이 페이지는 모든 내용을 다 설명하려는 게 아니라, 4주 전체 그림과 완주 기준을 먼저 잡아주려는 허브라고 생각하면 돼.

## 누구에게 맞는 기수인가

- **비개발자·1인 창업자**인데 만들고 싶은 웹 서비스·툴·자동화가 **있는** 사람
- 유튜브·책으로 **혼자 굴러봤는데 완주를 못 해본** 사람
- Claude Code를 **CLI로** 쓰는 걸 배울 각오가 된 사람
- 4주 동안 **주 1회 라이브 + 주 5~8시간 개인 실행**을 낼 수 있는 사람

반대로 이런 기대라면 이 기수랑 잘 안 맞아.

- 이미 개발자거나 다른 프레임워크로 풀스택 구축이 가능한 사람 (→ 배울 게 적다)
- 네이티브 앱·결제·금융 도메인·실시간 다사용자 서비스를 4주 안에 만들고 싶은 사람 (→ 범위 초과)
- "개념만 강의로 듣고 싶다"는 사람 (→ 기수제는 실행 중심)

## 4주 흐름

처음엔 단계가 많아 보여도 실제로는 단순해. 앞 단계에서 만든 결과물이 그대로 다음 단계 재료가 되는 구조라, 한 번만 흐름을 잡아두면 어디쯤 왔는지 덜 헷갈려.

| 시점 | 주제 | 세션 | 바이브 4단계 | 인증물 |
| --- | --- | --- | --- | --- |
| **시작하기** | 설치·VS Code·Claude Code 개념·신규 프로젝트 셋업·"해줘" 한 번 | 비동기 4강 | 사전 준비 | 환경 스크린샷 + 신규 프로젝트 폴더 + 첫 요청 결과 |
| **초보 개념잡기** | AI 기초·감 잡기·일 잘 시키기·프로젝트 업무매뉴얼 만들기 + 화면/컨텍스트/검증 습관 | 비동기 6편 | 사전 준비 | `CLAUDE.md` 초안 + `docs/` 업무 문서 1개 |
| **자동화 입문** | 초보 개념잡기 확인차 — commands/agents/skills/hooks 4장치로 개념이 레시피에 어떻게 조립되는지 체험 + `/write 1화` 연재 세팅 | 비동기 5강 + 개인 실행 | 사전 준비 + Explore | `/write` 실행 스크린샷 + `drafts/1화.md` |
| **서비스 만들기 (내 아이디어 MVP)** | 린스타트업·아이디어·PRD·기술·구조·레퍼런스·Git·프론트/백엔드·디버깅·배포·피드백·PMF·모객·결제·PG 연동 — 내 아이디어 한 사이클로 MVP 배포까지 완성 | 라이브 2회 + 개인 실행 | Plan + Code + Commit | PRD 1장 → 본인 프로젝트 MVP 배포 링크 + Git 히스토리 + 공개 포스트 1개 + 첫 판매 제안 1건 |

> 자동화 입문은 **새 개념을 쏟아붓는 자리가 아니라 초보 개념잡기에서 깐 개념을 레시피로 확인하는 블록**이야. 본격 자동화 운영(Part 5 / OpenClaw 등)은 클로더즈 범위 밖으로, 수료 후 자료·인강으로 연결 예정.

## 이 기수가 주는 변화

| 구간 | 출발 상태 | 도착 상태 |
| --- | --- | --- |
| 시작하기 | "AI 써보고는 싶은데 뭐부터?" | 환경 세팅 완료 + 신규 프로젝트 폴더 + Claude Code 첫 실행 |
| 초보 개념잡기 | "Claude에게 뭘 어떻게 맡겨야 할지 감이 없음" | AI 기초 감각 + 일 시키는 법 + 프로젝트 업무매뉴얼 초안 + 화면·컨텍스트·검증 이해 |
| 자동화 입문 | "배운 개념이 실제 레시피에선 어떻게 조립돼 돌아가는지 못 봄" | commands/agents/skills/hooks 4장치가 프로젝트 업무매뉴얼과 담당자 흐름을 어떻게 묶는지 이해 + `/write 1화` 직접 돌려본 경험 |
| 서비스 만들기 | "PRD? 외부 연동·인증·디버깅·배포를 어디서 끊어야 할지 모름" | 린스타트업 맥락 + 내 아이디어 MVP 흐름 (PRD 1장 → 프론트/백엔드 → 디버깅 → 배포) + Git 히스토리 + 배포 링크 + PMF 사이클 + 모객·첫 판매 제안 경험 |

## 구버전 원고

4주 기수제로 재구성하기 전의 원 20장(Part 1~5) 원고는 `docs_backlog/` 아래에 그대로 남아 있어. 각 주차 자료의 "참고 원고" 섹션이 어느 장을 끌어오는지 명시해.

## 자주 헷갈리는 포인트

- **여기서 세부 방법까지 다 알아야 하나?** — 아니야. 큰 그림과 완주 기준만 잡으면 충분해.
- **어디부터 읽으면 되나?** — 이 페이지로 전체 흐름만 잡고, 실제 실행은 `시작하기`부터 들어가면 돼.

## 남은 설계 과제

- 프로젝트 범위 제약 문서의 예시 프로젝트 20개까지 확장
- 주차별 마일스톤 인증 템플릿 실제 운영본 확정
- 평가 기준표에 수강생 예시 3건 시뮬레이션 추가
- 4가지 운영 자산 초안 (시작하기 자료 세트·초보 개념잡기 업무매뉴얼 템플릿·자동화 입문 `/write 1화` 세팅 스크립트·서비스 만들기 내 아이디어 MVP 흐름 자료)
- 피어 리뷰 페어링 규칙 + 공개 배포 데이 운영 스크립트
- 시작하기 2강 "Claude Code (왜 CLI 써야 하는지)" 신규 섹션
- 초보 개념잡기 라이브 9강 프롬프트 카드 4~5종 상세 스크립트

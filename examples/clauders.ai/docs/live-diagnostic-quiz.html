클로더즈 라이브 시작용

10문항 진단 퀴즈

시험이 아니라, 오늘 수업에서 어디를 더 다뤄야 하는지 확인하는 진단 퀴즈입니다.

진행 방법: 먼저 수강생에게 채팅으로 답만 받습니다. 예: B / C / A. 충분히 답을 받은 뒤 각 문항의 정답 보기를 눌러 해설을 보여주세요.
1

Claude Code에게 일을 시킬 때 가장 먼저 줘야 하는 것은?

  1. “예쁘게 만들어줘” 같은 큰 요청
  2. 프로젝트가 뭔지, 누구를 위한 건지, 결과 기준이 뭔지
  3. 최신 AI 모델 이름
  4. 코드 파일 전체를 복사한 긴 프롬프트

정답: B

진단: B를 고른 사람은 CLAUDE.md, PRD, 업무문서로 넘어갈 준비가 되어 있습니다. A/D가 많으면 “맥락과 기준을 먼저 준다”는 부분을 다시 짚어야 합니다.

2

4주 안에 만들기 가장 위험한 프로젝트는?

  1. 운동 기록을 입력하면 주간 리포트를 보여주는 페이지
  2. 회의록을 붙여넣으면 액션아이템 3개를 뽑아주는 도구
  3. 로그인, 결제, 커뮤니티, 채팅, 관리자까지 있는 종합 플랫폼
  4. 블로그 글 초안을 자동으로 만들어주는 워크플로우

정답: C

진단: C를 고르지 못한 사람이 많으면 범위 조절 감각이 약한 상태입니다. “이번 주에는 기능을 줄이는 게 실력”이라는 메시지로 연결하세요.

3

에러가 났을 때 Claude에게 가장 잘 물어보는 방식은?

  1. 안 돼요. 고쳐줘.
  2. 왜 이러지?
  3. 아래 에러 메시지와 내가 한 행동을 보고, 원인 후보 3개와 먼저 확인할 것 1개를 알려줘.
  4. 처음부터 다시 만들어줘.

정답: C

진단: A/B가 많으면 에러 전달 재료가 부족한 상태입니다. D가 많으면 작은 복구보다 리셋에 의존하는 경향이 있습니다.

4

PRD에서 반드시 있어야 하는 항목은?

  1. 멋진 서비스 이름
  2. 안 만들 것
  3. 사용할 아이콘 목록
  4. 언젠가 붙일 모든 기능

정답: B

진단: “안 만들 것”이 있어야 4주 안에 끝낼 수 있습니다. 이걸 못 고르면 아이디어보다 범위 통제가 먼저입니다.

5

AI 응답을 기다리는 동안 가장 먼저 확인하면 좋은 것은?

  1. 응답이 완벽한지 기다리기만 한다
  2. 내가 기대한 결과가 무엇인지 한 줄로 적어둔다
  3. 다른 기능을 새로 부탁한다
  4. 브라우저를 닫고 다음 강의로 넘어간다

정답: B

진단: AI 응답을 기다리는 시간에는 “내가 원한 결과”를 먼저 정리해야 합니다. 그래야 나온 결과가 맞는지 바로 판단할 수 있습니다.

6

Claude Code의 /write 같은 한 줄 명령어는 어떤 장치에 가까울까요?

  1. command
  2. agent
  3. hook
  4. database

정답: A

진단: command는 자주 쓰는 업무 흐름을 한 줄로 부르는 단축키입니다. 여기서 agents, skills, hooks와의 차이를 짧게 이어 설명하면 좋습니다.

7

처음 MVP를 만들 때 가장 좋은 성공 기준은?

  1. 사용자가 멋있다고 느낀다
  2. 언젠가 돈이 될 것 같다
  3. 처음 온 사용자가 3분 안에 핵심 행동 1개를 끝낸다
  4. 기능이 많아 보인다

정답: C

진단: 좋은 성공 기준은 관찰 가능해야 합니다. “좋다/멋있다”보다 “몇 분 안에 무엇을 한다”가 강합니다.

8

Git을 배우는 가장 큰 이유는?

  1. 개발자처럼 보이려고
  2. 기능이 끝날 때마다 안전하게 세이브하려고
  3. 코드를 더 어렵게 만들려고
  4. 배포를 무조건 자동으로 하려고

정답: B

진단: Git은 초보자에게 “세이브 시스템”입니다. 이 감각이 잡히면 망가질까 봐 손을 못 대는 불안이 줄어듭니다.

9

Claude가 답을 줬는데 결과가 애매할 때 가장 좋은 다음 요청은?

  1. 좋아. 이제 기능을 5개 더 추가해줘.
  2. 이 결과가 내 목표에 맞는지 기준 3개로 점검해줘.
  3. 처음부터 전부 다시 만들어줘.
  4. 왜 이렇게 못 해?

정답: B

진단: 결과가 애매하면 새 기능을 추가하기보다 기준으로 점검해야 합니다. 그래야 다음 요청이 작고 정확해집니다.

10

데모나잇 전에 가장 먼저 준비해야 할 것은?

  1. 완벽한 발표 자료 30장
  2. 배포 링크, 1분 데모 흐름, 피드백 받을 질문 1개
  3. 모든 기능 완성
  4. 새로운 아이디어 추가

정답: B

진단: 데모나잇은 완벽한 제품 발표가 아니라 “작동하는 결과물을 사람 앞에서 검증하는 자리”입니다.

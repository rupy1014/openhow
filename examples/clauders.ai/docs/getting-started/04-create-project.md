## 핵심 요약

프로젝트는 거창한 무언가가 아니라, **Claude Code가 읽을 파일과 규칙이 함께 들어 있는 폴더 하나를 제대로 만드는 것**으로 시작해.

지금은 프로젝트를 크게 상상하기보다 "AI가 일할 작업 구역을 제대로 만든다"는 느낌으로 접근하면 돼.

## 프로젝트는 그냥 "큰 폴더"야

여기서 말하는 프로젝트는 거창한 서비스나 앱 이름이 아니야.  
그냥 **관련 파일들을 한곳에 모아둔 큰 폴더**라고 생각하면 돼.

예를 들면 이런 거야.

- 유튜브 대본 작업용 폴더 하나
- 이력서 수정용 폴더 하나
- 첫 연습용 폴더 하나

즉 이 강의에서 말하는 프로젝트는 “앱을 하나 만든다”보다 먼저, **Claude가 일할 작업 구역을 하나 만든다**에 가까워.

예를 들어 위의 `첫 연습용 폴더`를 실제로 만들면 대충 이런 구성이야.

```text
my-first-vibe/
├── CLAUDE.md
├── README.md
└── prd.md
```

이런 식으로 작업 파일을 한곳에 묶어두면, 그 폴더 하나가 바로 프로젝트가 돼.

## 프로젝트는 여러 개 만들어도 되나

물론이야. 오히려 **주제가 다르면 폴더도 나누는 게 맞아.**

예를 들어 이렇게 운영하면 돼.

```text
~/projects/
├── my-first-vibe/
│   ├── CLAUDE.md
│   ├── README.md
│   └── prd.md
├── youtube-script-lab/
│   ├── CLAUDE.md
│   ├── ideas.md
│   └── scripts/
└── resume-helper/
    ├── CLAUDE.md
    ├── drafts/
    └── assets/
```

- `my-first-vibe` → 첫 연습용
- `youtube-script-lab` → 유튜브 기획/원고용
- `resume-helper` → 이력서 수정용

이렇게 나누면 좋은 이유는 단순해.

- 폴더마다 목적이 선명해지고
- `CLAUDE.md` 규칙도 따로 붙일 수 있고
- 파일이 섞이지 않고
- 나중에 다시 열어도 맥락이 덜 헷갈려

즉 **프로젝트 여러 개를 만드는 건 이상한 게 아니라 정상적인 방식**이야.

## 프로젝트 안은 어떻게 구성되나

처음엔 아래처럼 아주 단순해도 충분해.

```text
my-first-vibe/
├── CLAUDE.md
├── README.md
└── prd.md
```

- `CLAUDE.md` → Claude에게 주는 규칙
- `README.md` → 이 폴더가 뭔지 설명
- `prd.md` → 이 프로젝트에서 만들고 싶은 결과와 방향 정리

여기서 `prd.md`는 Product Requirements Document의 줄임말이라고 어렵게 생각할 필요는 없어.  
초보자 기준으로는 그냥 **"내가 뭘 만들고 싶은지 적어두는 메모 파일"**이라고 이해하면 충분해.

그리고 이 파일들을 처음부터 네가 다 손으로 만들 필요도 없어.

- 폴더만 하나 열고
- Claude Code를 실행한 다음
- "README.md 만들어줘"
- "prd.md 초안 만들어줘"
- "CLAUDE.md도 같이 작성해줘"

이렇게 대화하면서 하나씩 만들어가면 돼.  
즉 프로젝트는 **내가 완성해서 들고 오는 것**보다, **Claude와 대화하면서 같이 채워가는 작업 폴더**에 더 가깝다.

조금 익숙해지면 이렇게 늘어나도 돼.

```text
youtube-script-lab/
├── CLAUDE.md
├── README.md
├── ideas.md
├── scripts/
└── assets/
```

중요한 건 폴더 개수가 아니라 **무슨 작업을 하는 폴더인지 내가 바로 설명할 수 있느냐**야.

---

## `.md`는 뭐냐

`.md`는 마크다운(Markdown) 파일이야. 어려운 형식이 아니라 **그냥 텍스트 파일**에 가까워.

- `#` → 제목
- `-` → 목록
- `**글자**` → 굵게

이 정도만 알아도 충분해. 여기서 중요한 건 **AI는 raw 텍스트 기반 포맷을 다루기 편하다**는 점이야.

예를 들면 이런 파일들:

- `.txt` → 그냥 텍스트
- `.md` → 구조가 조금 있는 텍스트
- `.csv` → 표 데이터를 글자로 저장한 텍스트
- `.json` → 구조화된 데이터를 글자로 저장한 텍스트

이런 파일은 내용이 글자로 바로 들어 있어서 AI가 읽고 정리하기 편한 편이야.

반대로 `ppt`, `pptx` 같은 파일은 사람이 보기엔 편하지만, AI 입장에서는 바로 읽기 좋은 텍스트 기반 포맷은 아니야.  
읽을 수 있는 경우도 있지만, 보통 **텍스트 파일만큼 안정적이고 깔끔하게 다루기 어렵다**고 이해하면 돼.

그래서 `.md`를 많이 쓰는 거야.

- 사람도 읽기 쉽고
- AI도 읽기 쉽고
- 제목, 목록, 강조 정도의 구조도 넣을 수 있어

즉 `.md`는 **사람과 AI가 둘 다 보기 좋은 문서 포맷**이라서 프로젝트 설명, 작업 규칙, 초안, 할 일 목록에 자주 쓰여.

---

## 웹 AI와 뭐가 다르냐

웹에서 쓰는 Claude.ai나 Claude 앱도 설정 기능과 연결 기능이 있어. 하지만 입문자가 자주 놓치는 차이가 있어.

| 방식 | 설정이 붙는 곳 | 작업 파일과의 거리 |
| --- | --- | --- |
| 웹/앱 AI | 계정·앱·프로젝트 화면 안 | 설정과 파일이 분리되기 쉬움 |
| Claude Code | 폴더 안 `CLAUDE.md` | 설정과 파일이 같은 자리에 있음 |

이 차이가 생각보다 크다.

- 웹 AI는 대화를 새로 열면 다시 설명해야 할 때가 많다
- Claude Code는 폴더를 다시 열면 **설정도 같이 따라온다**
- 블로그 폴더엔 블로그 규칙, 업무 폴더엔 업무 규칙을 붙여둘 수 있어

즉 **프로젝트 = 폴더 + 파일 + 규칙**으로 묶인다는 점이 Claude Code 방식의 강점이야.

---

## Claude Code의 global / project 감각은 이렇게 보면 돼

처음엔 헷갈릴 수 있는데, Claude Code는 크게 **두 층**으로 생각하면 편해.

| 층 | 대표 위치 | 뜻 |
| --- | --- | --- |
| 전역(User / Global) | `~/.claude/CLAUDE.md`, `~/.claude/settings.json` | 내 모든 프로젝트에 공통으로 적용 |
| 프로젝트(Project) | `프로젝트폴더/CLAUDE.md`, `.claude/settings.json` | 이 프로젝트를 같이 쓰는 사람에게 공통 적용 |

아주 쉽게 풀면:

- **Global** = 어디서나 가져가는 내 기본 습관
- **Project** = 이 폴더에서 같이 지키는 팀 규칙

예를 들면 이런 식이야.

- **Global**: “항상 한국어로 답해”, “설명은 짧게”
- **Project**: “이 프로젝트는 비개발자 대상”, “유튜브 톤으로 써”

입문 단계에서는 이 두 개만 이해해도 충분해.

- `~/.claude/CLAUDE.md` = 내가 어디서나 반복하고 싶은 공통 규칙
- `프로젝트폴더/CLAUDE.md` = 이 폴더에서만 쓸 규칙

Claude Code 공식 문서 기준으로는 설정 파일도 비슷한 층으로 나뉘어.

- `~/.claude/settings.json` = 전역 설정
- `.claude/settings.json` = 프로젝트 공용 설정

겹치면 보통 **더 가까운 설정이 더 직접적으로 영향을 준다**고 이해하면 편해.  
다만 `CLAUDE.md` 계열과 settings 파일은 정확한 적용 방식이 조금 다를 수 있으니, 입문 단계에서는 **Global은 공통 규칙, Project는 폴더 규칙** 정도로 이해하면 충분해.

처음엔 설정 JSON까지 건드릴 필요는 없어. **입문자는 `CLAUDE.md`만 잘 써도 충분히 시작할 수 있어.**

하위 폴더에도 `CLAUDE.md`를 둘 수 있어. 예를 들어 `posts/CLAUDE.md`를 두면 그 폴더 안 작업에만 더 구체적인 규칙을 붙일 수 있어.

## Claude Code가 열리면 뭘 먼저 읽나

Claude Code는 빈 상태에서 시작하는 게 아니야. 프로젝트 폴더에서 실행되면 **정해진 순서대로 파일을 스캔해서 규칙을 쌓아 올려.** 이 순서를 알면 `CLAUDE.md`를 어디에 둬야 할지가 한 번에 정리돼.

| 순서 | 위치 | 역할 |
| --- | --- | --- |
| 1 | `~/.claude/CLAUDE.md` | 내 모든 프로젝트 공통 규칙 |
| 2 | `~/.claude/settings.json` | 전역 설정 (모델, 권한 등) |
| 3 | `프로젝트폴더/CLAUDE.md` | 이 프로젝트 규칙 |
| 4 | `프로젝트폴더/.claude/settings.json` | 프로젝트 공용 설정 |
| 5 | `하위폴더/CLAUDE.md` | 그 폴더 안에서 작업할 때 추가로 읽는 규칙 |

핵심은 **전역 → 프로젝트 → 하위 폴더** 순이고, 규칙이 겹치면 보통 **더 가까운 규칙이 더 직접적으로 적용**돼.

그래서 `CLAUDE.md`는 놓는 위치가 곧 적용 범위야.

- 어디서나 지키고 싶은 말 → `~/.claude/CLAUDE.md`
- 이 프로젝트에서만 지킬 말 → `프로젝트폴더/CLAUDE.md`
- 특정 폴더(예: `posts/`)에서만 지킬 말 → `그 폴더/CLAUDE.md`

Claude Code는 매번 이 순서대로 파일을 훑고 작업을 시작해. 즉 `CLAUDE.md` 하나만 잘 놔둬도 **대화를 새로 시작할 때마다 같은 규칙이 자동으로 따라온다.**

## `CLAUDE.md`는 왜 같이 만들어야 하나

`CLAUDE.md`는 매번 같은 말을 반복하지 않게 해주는 **프로젝트 규칙 파일**이야.

새 신입사원에게 매일

> "우리 팀은 한국어로 문서 써."
> "외부 라이브러리는 함부로 추가하지 마."
> "작업 끝나면 바꾼 파일부터 알려줘."

이걸 반복하느니, **학생 수칙 한 장**을 주는 게 훨씬 빠르지. `CLAUDE.md`가 딱 그 역할을 해.

- 폴더를 다시 열어도 규칙이 그대로 따라와
- 프로젝트마다 다른 작업 스타일을 붙일 수 있어
- 나중에 프롬프트를 짧게 써도 맥락이 유지돼

즉 프로젝트 만들기와 `CLAUDE.md` 작성은 따로가 아니라 **한 세트**라고 보는 게 맞아.

## 직접 만들어보자

:::steps

### 1) 바탕화면에 폴더 만들고 VS Code로 열기

어렵게 생각할 것 없어. 이렇게만 하면 돼.

1. **바탕화면에 폴더 하나** 만들기 (예: `my-first-vibe`)
2. **VS Code 실행**
3. 상단 메뉴에서 `File → Open...` (Mac은 `File → Open Folder...`) 눌러서 방금 만든 폴더 선택

그러면 VS Code가 그 폴더를 프로젝트로 열어.

- 폴더 이름은 짧고 영문 기반으로. 공백, 한글, 특수문자는 처음엔 피하는 편이 덜 헷갈린다
- 예시: `my-first-vibe`, `youtube-script-lab`, `resume-helper`

폴더가 열리면 VS Code 화면에서 이 세 군데만 보면 돼.

| 위치 | 이름 | 역할 |
| --- | --- | --- |
| 왼쪽 | 파일 탐색기 | 폴더 안 파일 목록 |
| 가운데 | 에디터 | 파일 내용을 읽고 수정 |
| 아래 | 터미널 | `claude`, `git` 같은 명령 실행 |

### 2) 터미널 열기

- `Ctrl + \``
- 또는 `Terminal → New Terminal`

화면 아래쪽에 터미널이 뜨면 준비 끝이야.

### 3) Claude Code 실행하기

```bash
claude
```

또는 이 코스 흐름대로 더 빠르게 갈 거면:

```bash
dsclaude
```

`>` 입력 줄이 보이면 Claude Code가 지금 이 폴더를 프로젝트로 잡은 거야.

### 4) `CLAUDE.md` 만들어보기

처음엔 "아, 대충 이런 구조구나" 감만 잡으면 돼.  
직접 한 번 만들어보되, 아직 길게 쓸 필요는 없어. 처음엔 **4섹션만** 있으면 충분해.

```markdown
# 내 첫 프로젝트 규칙

## 기술 스택
- HTML + CSS만 사용

## 디자인
- 다크 배경, 밝은 글자

## 금지 사항
- 외부 라이브러리 추가하지 마

## 작업 방식
- 설명은 한글로
- 수정한 파일을 먼저 알려줘
```

핵심은 “예쁘게 해줘” 같은 추상어보다 **도구 / 색상 / 금지 / 작업 방식**을 짧게라도 적어두는 거야.

그런데 나중엔 이걸 꼭 손으로 다 입력할 필요는 없어.

Claude에게 이렇게 말해도 돼.

```text
CLAUDE.md 파일 만들어줘. 내용은 "초보자도 이해할 수 있게 한국어로 설명해. 서론 없이 바로 핵심부터 말해."
```

또는 Claude Code 안에서 `/init`을 실행하면 시작용 `CLAUDE.md`를 자동으로 만들어주기도 해.  
공식 문서 기준으로 `/init`은 현재 프로젝트를 보고 초안 파일을 만들어주고, 이미 파일이 있으면 개선 방향을 제안해.

즉 처음엔 **직접 한 번 써보면서 구조를 이해하고**, 나중엔 **Claude에게 만들어달라고 하거나 `/init`으로 시작해도 된다**고 보면 돼.

Claude Code 공식 가이드도 `CLAUDE.md`는 **짧고 사람 읽기 쉽게 유지하라**고 권장해.  
즉 `CLAUDE.md`는 "무조건 길게 적는 문서"가 아니라, **Claude가 매번 알면 좋은 공통 규칙만 적는 메모**에 가까워.

그러면 왼쪽 파일 탐색기에 `CLAUDE.md`가 생기고, 이 파일이 바로 이 폴더의 프로젝트 규칙이야.

### 5) Git도 같이 시작하기

프로젝트를 만든 김에 로컬 저장소도 바로 잡아두면 다음 단계가 편하다.

```bash
git init
```

지금은 GitHub 연결까지 갈 필요 없어. **로컬에서 이 폴더를 버전 관리할 준비만 끝내면 충분해.**

:::

## 자주 헷갈리는 포인트

- **여러 주제를 한 폴더에 몰아넣어** → 프로젝트 목적이 다르면 폴더를 나누는 게 낫다
- **폴더 이름을 너무 복잡하게 짓는다** → 처음엔 짧은 영문 이름이 제일 덜 막힌다
- **`CLAUDE.md`를 거창하게 쓰려 해** → 한두 줄 규칙만 있어도 시작은 충분해
- **`CLAUDE.md`를 추상적으로 쓴다** → "예쁘게"보다 색상, 금지 항목, 파일 범위를 적는 게 낫다
- **프로젝트 이름부터 완벽해야 한다고 생각해** → 지금은 손이 한 번 움직이는 경험이 더 중요해
- **GitHub 연결까지 한 번에 끝내려 해** → 지금은 `git init`까지만 해도 진도가 맞다

## 바로 실행할 다음 단계

1. `my-first-vibe` 같은 새 폴더를 하나 만들어
2. VS Code로 열고 터미널에서 `claude`나 `dsclaude`를 실행해
3. `CLAUDE.md`에 기술 스택 / 금지 사항 / 작업 방식 1~2줄씩 먼저 적어
4. `git init`으로 로컬 저장소까지 켜

이 네 가지만 끝나면 다음 실습 강의부터는 "설명 듣기"가 아니라 **진짜 작업 시작 상태**가 돼.

**같은 뉴스도 카톡으로 보내는 거랑 웹에 올리는 건 달라.**

카톡은 500자 안에 끝나야 해. 웹사이트는 이미지랑 태그까지 붙여야 해. Threads는 280자에 해시태그가 필요해.

리뷰가 만들어졌으면, 보내려는 곳에 맞게 포맷을 바꿔야 해.

---

## 채널마다 뭐가 다르냐

| 채널 | 포맷 | 길이 | 특이사항 |
|------|------|------|---------|
| 카카오톡 | 순수 텍스트 | ~500자 | 링크는 맨 끝에 하나만 |
| Threads | 짧은 포스트 | ~280자 | 해시태그, 쓰레드로 이어쓰기 |
| 웹사이트 | 마크다운 | 제한 없음 | 이미지, 카테고리, 태그 필요 |
| Slack | 블록 메시지 | ~1000자 | 구조화된 레이아웃, 버튼 가능 |
| 이메일 뉴스레터 | HTML | ~2000자 | 제목이 핵심 (열어야 읽으니까) |

같은 기사를 카톡용으로 바꾸면:

```
[AI 브리핑] Claude Code 멀티에이전트 지원

여러 AI 에이전트가 동시에 일하는 기능이 추가됐어.
코드 리뷰, 테스트, 문서화를 각각 다른 에이전트가 맡아.
바이브코딩할 때 /workflow 한 번이면 3개가 동시에 돌아가.

👉 https://example.com/article
```

Threads용으로 바꾸면:

```
Claude Code에 멀티에이전트가 왔다.
코드 리뷰 + 테스트 + 문서화를 AI 3명이 동시에.

바이브코딩 생산성 체감 2배 이상. 🧵 아래에 설치법 👇

#AI코딩 #ClaudeCode #바이브코딩 #멀티에이전트 #자동화
```

포맷만 다르지, 원본 리뷰는 같아.

## 퇴고는 왜 따로 있냐

AI가 쓴 초고에는 문제가 있어:

- **번역투**: "~하는 것이 중요합니다" → "~해야 해"
- **마케팅 문구**: "혁신적인", "획기적인" → 삭제
- **과장**: 검증 안 된 숫자, 원문에 없는 정보 추가

그래서 **초고 쓰는 AI와 교정하는 AI가 달라**. 기자가 기사를 쓰고, 데스크가 교정하는 것처럼.

프로젝트에 `.agent/skills/refine_content/SKILL.md`가 있어. 퇴고 규칙이 적혀 있어:

```
톤앤매너:
  [x] 번역투 제거
  [x] 반말체 일관성 ("~했어", "~인 거야")
  [x] 마케팅 문구 제거

사실 확인:
  [x] 검증 안 된 주장 제거
  [x] 원문에 없는 정보 추가 안 했는지
  [x] 숫자/날짜가 정확한지
```

리뷰어 유형별로 규칙도 달라. `product_reviewer`가 쓴 글에서 "Claude로 클론 코딩해봐"가 나오면? 퇴고 단계에서 잘려나가.

---

## 어떻게 돌리냐

`/workflow`를 쓰면 퇴고까지 자동이야. 따로 돌리고 싶으면:

**Step 1.** 퇴고 실행

```
> content-workflow/ 폴더의 리뷰들을 퇴고해줘.
> 번역투 제거하고, 톤을 맞춰줘.
```

**Step 2.** 채널용 포맷 변환

```
> content-workflow/ 리뷰들을 카카오톡용 500자 요약으로 변환해줘.
> 링크는 맨 끝에 하나만 넣어줘.
```

톤 자체를 바꾸고 싶으면:

```
> 리뷰어들의 톤을 존댓말로 바꿔줘. "~했습니다", "~인데요" 스타일로.
```

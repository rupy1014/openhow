## 핵심 요약

**배포는 내 컴퓨터에서만 보이던 서비스를 인터넷 주소로 열어주는 일이야. `localhost:3000`은 나만 볼 수 있지만, 배포하면 고객에게 보낼 수 있는 URL이 생겨. 처음에는 Vercel을 추천해. Next.js와 잘 맞고, GitHub 연결도 쉽고, Claude에게 “Vercel CLI로 배포해줘”라고 하면 로그인 인증을 거친 뒤 배포까지 대부분 진행할 수 있어. 가격은 무료로 시작할 수 있지만, 서비스가 커지면 유료나 사용량 과금이 생길 수 있으니 표를 보고 감만 잡아두면 돼.**

서비스를 만들었다고 끝난 게 아니야.

내 컴퓨터에서만 돌아가면 고객은 볼 수 없어.

```text
내 컴퓨터: http://localhost:3000
고객: 접속 못 함
```

배포를 하면 이런 주소가 생겨.

```text
https://my-service.vercel.app
```

이 링크를 보내야 고객이 직접 눌러보고 피드백을 줄 수 있어.

그래서 배포는 개발의 마지막 장식이 아니라, **고객 검증을 시작하는 문**이야.

## 1. 배포가 뭐야?

배포는 내 서비스를 인터넷에서 접속할 수 있게 올리는 일이야.

쉽게 말하면 이거야.

```text
내 컴퓨터에서만 보이는 상태
→ 인터넷 주소로 누구나 열어볼 수 있는 상태
```

예를 들어.

```text
배포 전: 나만 확인 가능
배포 후: 고객 5명에게 링크 전달 가능
```

고객에게 이렇게 말할 수 있어야 해.

```text
이 링크 한번 눌러보고 써봐.
어디서 막히는지 알려줘.
```

이게 가능해지는 순간부터 진짜 피드백을 받을 수 있어.

## 2. 어디에 배포할까?

배포 서비스는 여러 개가 있어.

처음에는 전부 알 필요 없어.

비개발자 MVP 기준으로 보면 이 정도만 비교하면 돼.

> 가격은 2026년 4월 기준 공개 가격을 바탕으로 정리한 거야. 요금제는 자주 바뀌니까 실제 결제 전에는 공식 pricing 페이지를 다시 확인해야 해.

| 서비스 | 처음 가격 감각 | CLI 잘 되나? | 잘 맞는 경우 | 초보자 판단 |
| --- | --- | --- | --- | --- |
| Vercel | Hobby 무료, Pro는 월 $20부터 + 사용량 | 매우 좋음. `vercel` 명령으로 배포 가능 | Next.js, React 웹앱, 빠른 MVP | 제일 추천 |
| Netlify | Free 무료, Personal 월 $9, Pro 월 $20 수준 | 좋음. `netlify deploy` 가능 | 정적 사이트, 프론트 중심 웹앱 | 쉬움 |
| Cloudflare Pages | 정적 배포는 무료로 시작, Functions는 Workers 요금과 연결. Workers Paid는 월 $5부터 | 가능. `wrangler` 사용 | 정적 사이트, Cloudflare를 이미 쓰는 경우 | 조금 어려움 |
| Railway | Hobby 월 $5, 포함 사용량 $5. 사용량 넘으면 추가 과금 | 좋음 | 서버, DB, 백엔드 프로세스 | 웹 프론트 첫 배포용은 아님 |
| Render | 무료 컴퓨트 플랜 있음. 유료는 서비스별 과금 | 가능 | 서버, API, 백엔드 배포 | 백엔드가 커질 때 검토 |
| AWS/GCP | 무료 체험/프리티어가 있지만 이후 사용량 과금 | 가능하지만 복잡 | 회사/대규모 인프라 | 처음 MVP에는 비추천 |

처음 MVP라면 결론은 단순해.

```text
Next.js / React 웹앱 → Vercel
정적 페이지 중심 → Netlify 또는 Cloudflare Pages
서버·DB 프로세스가 따로 필요 → Railway / Render 검토
처음부터 AWS/GCP → 웬만하면 피하기
```

이 문서에서는 Vercel을 기준으로 설명할게.

이유는 단순해.

```text
GitHub 연결이 쉽다
Next.js와 잘 맞다
무료로 시작 가능하다
환경변수 설정이 비교적 쉽다
CLI 배포가 Claude와 잘 맞는다
```

## 3. 대시보드로 배포하는 방법

가장 기본은 GitHub에 올리고 Vercel에서 가져오는 방식이야.

### Step 1. GitHub에 코드 올리기

아직 GitHub에 안 올렸으면 Claude에게 시켜.

```text
이 프로젝트를 GitHub에 올려줘.
처음이라서 단계별로 설명하면서 진행해줘.
리포지토리 이름은 my-mvp-service로 해줘.
```

이미 올렸으면 이 단계는 건너뛰어.

### Step 2. Vercel 가입

[Vercel](https://vercel.com)에 들어가서 GitHub 계정으로 로그인해.

처음에는 별도 복잡한 설정 없이 GitHub로 연결하면 돼.

### Step 3. 프로젝트 가져오기

Vercel 대시보드에서 보통 이런 흐름으로 진행해.

```text
Add New
→ Project
→ GitHub 리포지토리 선택
→ Deploy
```

대부분은 Vercel이 프레임워크를 알아서 감지해.

Next.js 프로젝트라면 빌드 명령이나 출력 폴더도 보통 자동으로 잡아줘.

### Step 4. URL 확인

배포가 끝나면 이런 주소가 생겨.

```text
https://my-mvp-service.vercel.app
```

이 주소를 열어서 핵심 기능을 직접 눌러봐.

```text
첫 화면이 뜨나?
버튼이 눌리나?
입력하고 결과가 나오나?
모바일에서도 볼 수 있나?
```

여기까지 되면 고객에게 보낼 준비가 된 거야.

## 4. Claude에게 Vercel CLI로 배포시키는 연출

대시보드로 해도 되지만, AI와 같이 개발할 때는 CLI 배포가 편할 때가 많아.

CLI는 터미널에서 명령어로 배포하는 방식이야.

Vercel은 CLI가 잘 되어 있어서 Claude에게 이렇게 말할 수 있어.

```text
Vercel CLI로 이 프로젝트를 배포해줘.
내가 처음이라서 필요한 인증 절차가 나오면 안내해줘.
로그인이 끝나면 배포를 진행하고,
마지막에 나온 URL을 알려줘.
```

그러면 보통 이런 흐름이 돼.

```text
1. Claude가 Vercel CLI 설치 여부를 확인
2. 필요하면 Vercel CLI 설치
3. `vercel` 명령 실행
4. 브라우저 로그인 또는 인증 코드 입력 안내
5. 프로젝트 연결 질문에 답변
6. 배포 진행
7. 배포 URL 출력
```

처음 인증은 사람이 해줘야 할 수 있어.

예를 들어 브라우저가 열리고 Vercel 로그인을 요구할 수 있어.

그건 정상적인 과정이야.

인증이 끝나면 Claude가 이어서 배포를 진행할 수 있어.

실전 프롬프트는 이렇게 쓰면 돼.

```text
Vercel CLI로 배포해줘.
단계마다 지금 무엇을 하는지 설명해줘.
인증이 필요하면 내가 해야 할 행동만 알려줘.
배포가 끝나면 URL을 열어보고,
고객이 테스트해야 할 핵심 동작 체크리스트도 만들어줘.
```

운영 배포까지 바로 하고 싶으면 이렇게 말할 수 있어.

```text
Vercel CLI로 production 배포까지 해줘.
가능하면 `vercel --prod`를 사용해줘.
환경변수가 빠져 있으면 먼저 확인하고 멈춰줘.
```

처음에는 `--prod`가 뭔지 몰라도 돼.

대충 이렇게 이해하면 돼.

```text
preview 배포 = 테스트용 주소
production 배포 = 고객에게 보여줄 대표 주소
```

## 5. 환경변수는 배포 서비스에도 넣어야 해

로컬에서 `.env.local`에 API 키를 넣었다고 끝이 아니야.

배포된 서비스는 내 컴퓨터가 아니라 Vercel 서버에서 돌아가.

그래서 Vercel에도 환경변수를 넣어야 해.

예를 들어 이런 값들이 있을 수 있어.

```text
OPENROUTER_API_KEY
OPENAI_API_KEY
DATABASE_URL
SUPABASE_URL
SUPABASE_ANON_KEY
```

Vercel 대시보드에서는 보통 이렇게 들어가.

```text
프로젝트
→ Settings
→ Environment Variables
→ 이름과 값 추가
→ Save
→ Redeploy
```

Claude에게는 이렇게 말하면 돼.

```text
이 프로젝트에서 필요한 환경변수를 찾아줘.
로컬 .env.local에 있는 값 중
Vercel에 등록해야 하는 값을 목록으로 정리해줘.

단, API 키 값 자체는 채팅에 출력하지 말고,
이름만 알려줘.
```

중요한 건 이거야.

```text
API 키를 코드에 직접 적으면 안 된다.
GitHub에 올리면 노출될 수 있다.
배포 서비스의 Environment Variables에 넣어야 한다.
```

## 6. 배포 전에 가격을 한 번 확인해

처음 MVP는 대부분 무료 범위에서 시작할 수 있어.

하지만 “무료”라고 해서 영원히 아무 비용도 안 든다는 뜻은 아니야.

특히 이런 경우에는 비용이 생길 수 있어.

```text
방문자가 많아진다
이미지나 파일을 많이 제공한다
서버 함수가 많이 호출된다
AI API를 많이 호출한다
DB 저장량이 늘어난다
팀원 계정을 추가한다
```

그래서 배포 전에 Claude에게 이렇게 물어봐.

```text
이 프로젝트를 Vercel에 배포하려고 해.
현재 기능 기준으로 비용이 생길 수 있는 부분을 정리해줘.
Vercel 비용, DB 비용, AI API 비용을 나눠서 알려줘.
처음 고객 5명 테스트에서는 무료 범위로 충분할지도 판단해줘.
```

그리고 실제 결제 전에는 공식 pricing 페이지를 확인해.

```text
Vercel 공식 pricing 페이지를 기준으로
현재 Hobby와 Pro 차이를 요약해줘.
내 프로젝트가 당장 유료가 필요한지도 판단해줘.
```

초기에는 대개 이렇게 가면 돼.

```text
고객 5명 테스트 → 무료 플랜으로 시작
반응이 생김 → 사용량 확인
실사용자가 늘어남 → 유료 플랜 검토
```

## 7. 배포 후에 고치고 싶으면?

GitHub와 Vercel을 연결해두면 흐름이 단순해.

```text
코드 수정
→ commit
→ push
→ Vercel이 자동으로 다시 배포
```

Claude에게는 이렇게 말하면 돼.

```text
[수정 내용] 고쳐줘.
브라우저에서 확인할 수 있게 실행해보고,
문제 없으면 commit하고 push해줘.
Vercel 배포가 완료되면 URL에서 확인할 체크리스트도 알려줘.
```

push하면 보통 잠시 뒤 새 버전이 올라가.

배포가 실패하면 Vercel 로그를 복사해서 Claude에게 주면 돼.

```text
Vercel 배포가 실패했어.
아래 build log를 보고 원인을 설명해줘.
최소 수정으로 고쳐줘.
[로그 붙여넣기]
```

## 8. 커스텀 도메인은 나중에 해도 돼

처음에는 Vercel이 주는 기본 주소로 충분해.

```text
https://my-mvp-service.vercel.app
```

나중에 진짜 서비스처럼 보이고 싶으면 내 도메인을 연결하면 돼.

```text
https://myservice.com
https://app.myservice.com
```

Vercel에서는 보통 이렇게 해.

```text
프로젝트
→ Settings
→ Domains
→ 내 도메인 입력
→ 안내된 DNS 설정 적용
```

처음부터 도메인까지 붙이려고 오래 붙잡히지 마.

고객 5명에게 보여주는 MVP라면 기본 URL로도 충분해.

## 자주 헷갈리는 포인트

### Vercel이 꼭 정답이야?

아니야. 다만 Next.js나 React 기반 MVP를 처음 배포할 때 가장 편한 선택지 중 하나야. Claude와 CLI로 진행하기도 좋아서 초보자에게 추천하기 쉽다.

### 무료로 계속 쓸 수 있어?

처음 테스트는 무료로 가능한 경우가 많아. 하지만 방문자, 서버 함수, 이미지, DB, AI API 사용량이 늘면 비용이 생길 수 있어. “무료 시작”과 “영원히 무료”는 달라.

### Vercel CLI가 뭐야?

터미널에서 Vercel에 배포하는 도구야. Claude에게 “Vercel CLI로 배포해줘”라고 하면 설치, 로그인 안내, 배포 명령 실행을 대부분 도와줄 수 있어.

### 인증은 Claude가 다 해줘?

로그인 자체는 사람이 해야 할 수 있어. 브라우저가 열리거나 인증 코드 입력이 필요할 수 있어. 인증만 끝나면 Claude가 이어서 배포를 진행할 수 있어.

### 환경변수를 안 넣으면 어떻게 돼?

로컬에서는 되는데 배포 후에는 안 될 수 있어. API 키나 DB 주소가 배포 서버에 없기 때문이야. 배포 실패나 기능 오류가 나면 환경변수를 먼저 확인해.

### 배포가 실패하면?

Vercel의 build log를 통째로 복사해서 Claude에게 줘. “이 로그를 보고 원인을 설명하고 최소 수정으로 고쳐줘”라고 말하면 돼.

### 가격이 무서워

처음에는 무료 플랜으로 시작하고, 결제 카드 등록이나 유료 업그레이드가 필요한 순간에는 Claude에게 “이 기능 때문에 비용이 생기는지 먼저 판단해줘”라고 물어봐.

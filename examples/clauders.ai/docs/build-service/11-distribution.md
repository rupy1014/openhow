## 핵심 요약

**만드는 건 쉬워졌어. 이제 승부는 모객이야. 근데 한 방 바이럴이 아니라, 살 사람을 먼저 그리고 꾸준히 모으는 사람이 이겨.**

10장에서 물었지.

“이 고객이 이미 모여 있는 채널은 어디인가?”

이번 장은 그 질문에 답하는 장이야.

배포 URL이 생겼다면 이제 사람을 데려와야 해.

친구 5명 피드백에서 끝나면 안 돼.

모르는 사람이 와야 진짜 시장 반응이 보여.

근데 여기서 조심해야 할 게 있어.

모객을 “홍보”로 이해하면 바로 막혀.

```text
저 이거 만들었어요.
써주세요.
피드백 주세요.
```

이 말은 상대에게 일만 시키는 말이야.

상대가 얻는 게 없어.

모객은 링크 뿌리기가 아니야.

**고객이 이미 모여 있는 곳에서 유용한 사람이 되는 일**이야.

## 인디해커들은 어떻게 벌었어?

혼자 서비스를 만들어 파는 사람을 해외에서는 “인디해커”라고 불러.

네덜란드의 피터 레벨스가 대표적이야.

직원 없이 혼자 만든 서비스 몇 개로 월 1억이 넘는 수익을 낸다고 알려졌어.

근데 그 사람이 코드를 제일 잘 짜서 그렇게 된 게 아니야.

만드는 과정을 매일 공개했어.

숫자도, 실패도, 매출도 숨기지 않고 트위터에 올렸어.

그래서 제품이 나오기 전부터 이미 보는 사람이 있었어.

핵심은 이거야.

**제품을 다 만들고 사람을 찾은 게 아니라, 사람을 먼저 모아두고 제품을 냈어.**

이걸 “오디언스 퍼스트”라고 해.

순서가 반대인 사람은 좋은 걸 만들어 놓고도 안 팔려.

예를 들어 이런 차이가 나와.

| 사람 | 준비 | 출시 첫 반응 |
| --- | --- | --- |
| A | 팔로워 1.2만 + 뉴스레터 4,200명을 6개월 쌓음 | 거친 제품인데 첫 주 830명 |
| B | 3주 동안 혼자 잘 만듦 | 잘 만든 제품인데 47명 |

이 차이는 제품 완성도만으로 안 나와.

**살 사람을 먼저 모은 사람이 이겨.**

유료 모임이든 뉴스레터든 작은 도구든 똑같아.

콘텐츠만 좋으면 사람이 모일 것 같지만, 실제로는 신뢰와 관계가 먼저야.

살 사람부터 모아두면 파는 건 쉬워.

순서가 반대면 좋은 걸 만들어 놓고도 안 팔려.

단, 지금 당장 6개월을 쓸 수는 없지.

그래서 작게, 하지만 꾸준히 시작해야 해.

큰 채널을 만들려고 하지 말고, 오늘 하나 올려.

## 모객엔 정답 채널이 없어

“어디에 올려야 터져요?”

이 질문엔 정답이 없어.

스레드도 좋고, 유튜브도 좋고, 커뮤니티도 좋아.

나만의 채널을 키우는 것도 좋고, 한 번 바이럴이 나는 것도 좋아.

뭐든 사람이 오면 다 좋은 거야.

진짜 중요한 건 채널 종류가 아니야.

**내가 그걸 지속할 수 있느냐**야.

이번 주엔 스레드, 다음 주엔 블로그, 그다음 주엔 유튜브로 옮겨 다니면 아무것도 안 쌓여.

한 번 터지고 멈추는 채널보다, 6주 동안 굴러가는 채널이 결국 더 멀리 가.

인디해커가 이긴 이유도 “한 방”이 아니라 “계속 했다”야.

그러니까 채널을 고를 때 제일 먼저 물어야 할 건 이거야.

“나 이거 6주 동안 계속할 수 있어?”

## 한국에서는 어디로 가야 해?

채널은 많아.

근데 아무 데나 올리면 스팸처럼 보여.

고객이 있는 곳을 골라야 해.

| 채널 | 누가 모여 있어 | 뭘 올려 | 주의할 것 |
| --- | --- | --- | --- |
| 스레드/X | 메이커, 1인 창업자, IT 관심층 | 만드는 과정, 배운 점, 숫자, 실패 기록 | 제품 자랑만 하면 지나쳐 |
| 디스콰이엇 | IT 메이커, 초기 사용자, 제품 좋아하는 사람 | 프로덕트 등록, 제작 배경, 배운 점 | 댓글 피드백에 방어적으로 굴지 마 |
| 카카오 오픈채팅 | 주제별 잠재 고객, 실무자, 취미 그룹 | 문제 해결 팁, 질문 답변, 짧은 사용 사례 | 입장하자마자 홍보하면 강퇴될 수 있어 |
| 네이버 카페/블로그 | 생활, 취미, 자영업, 지역 고객 | 문제 해결 글, 후기, 사용 전후 비교 | 카페 규칙 먼저 읽어 |
| 유튜브/숏폼 | 검색하는 사람, 얼굴과 목소리로 신뢰 보는 사람 | 문제 상황, 해결 과정, 짧은 데모 | 긴 설명보다 첫 5초가 중요해 |
| 크몽 같은 마켓플레이스 | 구매 의사가 있는 고객, 외주 찾는 사람 | 작은 상품, 템플릿, 자동화 세팅 | 플랫폼 수수료와 규칙을 봐 |

마켓플레이스는 조금 달라.

유통이 안에 들어 있어.

그래서 모객 없이 첫 판매가 나올 수도 있어.

대신 내 제품을 “상품”처럼 포장해야 해.

그냥 URL 하나 올리는 것과 달라.

## 채널은 어떻게 골라?

채널 선택은 감으로 하면 흔들려.

아래 기준으로 골라.

| 기준 | 물어볼 질문 | 좋은 신호 |
| --- | --- | --- |
| 고객 근접도 | 내 고객이 진짜 있어? | 댓글과 질문에 내 고객의 말이 보여 |
| 실행 가능성 | 내가 꾸준히 할 수 있어? | 6주 동안 주 2회는 올릴 수 있어 |
| 피드백 속도 | 반응이 빨리 와? | 댓글, DM, 조회수, 클릭이 하루 안에 보여 |
| 복리성 | 쌓이는 채널이야, 휘발되는 채널이야? | 검색되거나 프로필에 기록이 남아 |
| 유지 비용 | 6주 버틸 수 있어? | 글 하나 쓰는 데 에너지가 너무 크지 않아 |

여기서 제일 중요한 두 칸은 **실행 가능성**과 **유지 비용**이야.

지속가능성을 보는 칸이거든.

아무리 고객이 많은 채널이어도, 내가 한 주 만에 지치면 의미가 없어.

결론은 간단해.

**2개만 골라서 6주 커밋해.**

하나는 빠른 반응 채널이면 좋아.

예를 들면 스레드/X, 디스콰이엇, 오픈채팅이야.

하나는 쌓이는 채널이면 좋아.

예를 들면 블로그, 유튜브, 마켓플레이스야.

하지만 처음부터 완벽한 조합을 고르려고 하지 마.

고민이 길어지면 고객 근접도를 제일 먼저 봐.

내 고객이 없는 곳에서 열심히 해도 반응은 안 와.

채널은 씨앗 같아.

땅을 매주 갈아엎으면 뿌리가 못 내려.

## 어떻게 지속가능하게 해?

지속의 핵심은 두 개야.

**하나, 매일 작게 공개 기록을 남겨.**

처음부터 잘 쓰려고 하면 못 올려.

처음부터 알고리즘을 이기려고 하면 시작도 못 해.

처음 목표는 바이럴이 아니야.

**매일 하나씩 공개 기록을 남기는 것**이야.

이걸 빌드인퍼블릭이라고 해.

만드는 과정을 숨기지 않고 밖에 보여주는 거야.

7일만 해도 재료가 쌓여.

```text
1일차: 내가 보고 있는 고객 문제
2일차: 오늘 만든 화면 하나
3일차: 고객에게 들은 말 하나
4일차: 막힌 점 하나
5일차: 고친 점 하나
6일차: 숫자 하나
7일차: 배포 URL + 작은 피드백 요청
```

글 하나가 길 필요 없어.

세 문장이면 돼.

```text
오늘 1인샵 사장님 인터뷰에서 예약 문의를 놓치는 이유를 물어봤어.
캘린더가 없어서가 아니라, 카톡/인스타/문자가 섞여서 마지막 답변 상태를 잊는 게 문제였어.
그래서 첫 화면을 캘린더가 아니라 "답변 안 한 문의" 중심으로 바꿔보고 있어.
```

**둘, 10번 유용하고 1번 알려.**

다짜고짜 이렇게 말하면 무시당해.

```text
저 이거 만들었어요.
써주세요.
```

그 말은 상대에게 일만 시키는 말이거든.

먼저 유용한 사람이 돼야 해.

질문에 답해.

내가 겪은 문제를 공유해.

숫자를 숨기지 말고 보여줘.

예를 들면 이런 글이 더 좋아.

```text
자영업 예약 문의 정리 도구를 만들면서 알게 된 게 있어.

사장님들은 기능보다 "손님 메시지를 놓치지 않는가"를 먼저 봐.
그래서 첫 화면에서 오늘 놓친 문의 수를 바로 보이게 바꿨어.

비슷한 문제 겪는 사람 있으면 1분만 써보고 어디가 헷갈리는지 말해줘.
```

이건 홍보지만 정보도 있어.

상대가 읽고 배울 게 있어.

그래서 덜 밀려나.

비율로 잡으면 이래.

| 비율 | 내용 | 예시 |
| --- | --- | --- |
| 40% | 만들며 배운 것 | 고객이 첫 화면에서 막힌 이유 |
| 30% | 실험과 숫자 | 제목 바꾸니 클릭이 2배 된 이야기 |
| 20% | 제품 이야기 | 오늘 고친 기능, 데모, 사용 흐름 |
| 10% | 부탁 | 써봐, 피드백 줘, 공유해줘 |

핵심은 이거야.

**제품을 팔기 전에, 배우는 과정을 보여줘.**

제품 자랑은 닫힌 문이야.

과정 공유는 열린 문이야.

## 바이럴은 노리는 게 아니라 따라오는 거야

“한 번 빵 터지면 좋잖아.”

맞아. 바이럴은 좋아.

근데 바이럴을 목표로 잡으면 대부분 망해.

터뜨리려고 쓴 글은 티가 나거든.

바이럴은 꾸준히 쌓다가 그중 하나가 우연히 터지는 거야.

매일 올린 50개 중 1개가 터지는 거지, 1개를 노려서 터지는 게 아니야.

그러니까 한 방을 노리지 말고, 터질 후보를 많이 만들어.

꾸준함이 바이럴의 재료야.

그리고 한 번 터져도 거기서 끝나면 의미 없어.

터졌을 때 “내가 누구이고 뭘 만드는지”가 보이게 프로필과 기록을 미리 깔아둬.

그래야 한 번의 바이럴이 오디언스로 남아.

## 채널별 디테일은 딥다이브에서

스레드/X, 디스콰이엇, 오픈채팅, 네이버 카페, 블로그, 유튜브, 숏폼, 마켓플레이스.

각 채널은 문법이 달라.

유튜브 하나만 해도 제목, 첫 5초, 썸네일, 고정 댓글, 쇼츠와 긴 영상 차이까지 따로 배울 게 많아.

이 장에서 그걸 다 다루면 오히려 산만해져.

여기서는 원칙만 잡을게.

**각 채널의 디테일은 딥다이브하면서 경험담 위주로 나누자.**

직접 해본 것, 실패한 것, 반응이 왔던 문장, 아무 반응 없었던 글, 댓글에서 배운 것을 가져오면 돼.

그런 경험담이 진짜 자료야.

```text
어디에 올렸는지
어떤 문장으로 올렸는지
조회수, 댓글, 클릭, DM이 어땠는지
어떤 말에 반응이 왔는지
어떤 글은 완전히 묻혔는지
다음에는 뭘 바꿔볼 건지
```

우리는 채널 공략법을 외우려는 게 아니야.

**우리 고객이 어떤 말에 반응하는지 배우려는 거야.**

## 오늘 뭘 해야 해?

숙제는 3개야.

### 1. 채널 2개 골라

아래 표를 채워.

점수는 1점부터 5점까지면 돼.

| 후보 채널 | 고객 근접도 | 실행 가능성 | 피드백 속도 | 복리성 | 유지 비용 | 선택 |
| --- | --- | --- | --- | --- | --- | --- |
| 스레드/X |  |  |  |  |  |  |
| 디스콰이엇 |  |  |  |  |  |  |
| 카카오 오픈채팅 |  |  |  |  |  |  |
| 네이버 카페/블로그 |  |  |  |  |  |  |
| 유튜브/숏폼 |  |  |  |  |  |  |
| 마켓플레이스 |  |  |  |  |  |  |

점수가 제일 높은 2개를 골라.

고민이 길어지면 고객 근접도와 실행 가능성을 먼저 봐.

### 2. 공개 기록을 7일 동안 매일 올려

첫 글은 멋질 필요 없어.

짧아도 돼.

이 구조로 써.

```text
내가 누구 문제를 보고 있는지
오늘 뭘 만들었는지
만들면서 뭘 배웠는지
지금 어떤 피드백이 필요한지
배포 URL 또는 다음 액션
```

제품 설명보다 배운 점을 먼저 써.

그래야 광고처럼 덜 보여.

핵심은 “오늘도 밖에 내놨다”는 기록을 만드는 거야.

### 3. 모르는 사람 2명에게 피드백 받아

선택한 채널에 배포 URL을 공유해.

목표는 가입자 100명이 아니야.

**모르는 사람 2명 피드백**이야.

이 2명은 [피드백과 검증](./09-feedback)의 5명에 합류시켜.

친구 5명보다 모르는 사람 2명이 더 차가울 수 있어.

그게 좋아.

차가운 반응이 시장에 더 가까워.

## 자주 헷갈리는 포인트

### 팔로워 0인데 의미 있어?

의미 있어.

내 계정 팔로워가 없어도 채널에는 사람이 있어.

그게 남의 오디언스를 빌리는 거야.

디스콰이엇에 올리면 디스콰이엇 사람들이 봐.

오픈채팅에서 답변하면 그 방 사람들이 봐.

네이버 카페에 유용한 글을 쓰면 검색으로도 들어와.

팔로워 0은 시작점이지 벽이 아니야.

### 한 방 바이럴만 노리면 안 돼?

위험해.

바이럴은 결과지 전략이 아니야.

한 방만 노리면 안 터졌을 때 멈추게 돼.

매일 꾸준히 쌓는 사람이 결국 더 많이 터지고, 터진 뒤에도 남아.

### 광고 돌리면 안 돼?

지금은 범위 밖이야.

유료 광고는 PMF 뒤가 좋아.

아직 고객군, 메시지, 첫 경험이 흔들리면 광고비로 헷갈림만 커져.

광고는 물을 붓는 일이야.

바닥에 구멍이 있으면 더 빨리 샐 뿐이야.

먼저 모르는 사람 2명에게 직접 반응을 받아.

### 글재주가 없는데?

괜찮아.

Claude한테 초안을 시키면 돼.

이렇게 던져.

```text
내가 만든 서비스는 [서비스 설명]이야.
고객은 [고객군]이고, 해결하려는 문제는 [문제]야.
오늘 만든 건 [오늘 만든 것]이고, 배운 건 [배운 점]이야.

스레드에 올릴 빌드인퍼블릭 글 초안을 써줘.
조건은 이거야.
- 제품 자랑보다 배운 점을 먼저 써
- 마지막에 배포 URL과 피드백 부탁을 짧게 넣어
- 광고처럼 보이지 않게 써
- 문장은 짧게 써
```

초안은 그대로 올리지 마.

너 말투로 줄이고 고쳐.

AI가 쓴 티가 나면 신뢰가 떨어져.

### 매일 올리면 너무 홍보 같지 않아?

제품 자랑만 매일 하면 홍보 같아.

배운 점을 매일 올리면 기록이 돼.

차이는 여기야.

```text
홍보: 우리 서비스 이런 기능 있어요.
기록: 오늘 고객이 여기서 막혀서 이 기능을 줄였어요.
```

사람들은 완성품 광고보다 시행착오 기록에 더 쉽게 반응해.

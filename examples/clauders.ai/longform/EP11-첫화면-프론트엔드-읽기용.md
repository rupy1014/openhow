## 1. 시작 — 종이까지는 왔는데, 화면은요?

지난 영상에서 우리, 꽤 멀리 왔어요. //

머릿속에만 있던 아이디어를, "누가, 무슨 문제를, 어떻게" 풀지로 정리했죠. 그걸 한 장짜리 기획서, PRD로 만들었고요. //

그러니까 지금 우리 손에는 '계획'이 있어요. 종이 한 장은 있는 거예요. //

그런데 막상 여기서 다들 멈칫하세요. "좋아, 계획은 나왔는데… 이걸 화면으로는 대체 어떻게 만들지?" //

여기서 '코딩'이라는 단어가 떠오르면서 갑자기 작아지죠. "나 코드 한 줄도 못 짜는데."

오늘은 그 벽을 같이 넘어볼 거예요. 진짜 눈에 보이는 '첫 화면' 하나를 띄우는 것까지. 천천히 갈게요.

---

## 2. 먼저 안심부터 — 첫 화면 딱 하나만

본론 들어가기 전에, 늘 하던 거 한 번만 하고 갈게요. //

코딩 몰라도 돼요. 진짜로요. 오늘 우리가 직접 코드를 칠 일은 없어요. //

코드는 AI가 써요. 우리가 할 일은 "이런 걸 만들어줘" 하고 말로 부탁하고, 나온 화면을 눈으로 확인하는 거예요. //

그리고 하나 더. 오늘 거창한 거 안 만들어요. 로그인도, 결제도, 데이터 저장도 다 빼요. //

"그걸 빼면 뭐가 남아요?" 싶죠? 화면 한 장이 남아요. 그게 오늘의 목표예요. //

작아 보여도 괜찮아요. 내 머릿속 계획이 처음으로 눈앞에 '띡' 하고 뜨는 순간, 그게 생각보다 크거든요. 거기서부터 시작이에요.

---

## 3. 서비스는 식당이랑 똑같아요

자, 그럼 '화면을 만든다'는 게 뭔지부터 감을 잡아볼게요. 식당으로 비유하면 한 번에 이해돼요. //

식당에 가면 크게 두 공간이 있죠. 손님이 앉는 '홀'이랑, 음식을 만드는 '주방'. //

서비스도 똑같아요. //

**손님이 보고 만지는 홀**, 이게 '프론트엔드'예요. 화면이라고 보면 돼요. 메뉴판, 자리, 주문 벨. 손님 눈에 보이는 건 다 여기예요. //

**뒤에서 처리하는 주방**, 이게 '백엔드'예요. 주문을 받아서 음식을 만들고, 비밀 레시피를 지키고, 재료를 창고에서 꺼내오는 곳. 손님 눈엔 안 보이죠. //

프론트엔드, 백엔드. 영어라서 어렵게 들리지만 풀어보면 이게 다예요. //

'프론트(front)'는 앞쪽, 손님이 보는 앞. '백(back)'은 뒤쪽, 주방. 그렇게만 기억해도 충분해요. //

손님은요, 주방이 어떻게 돌아가는지 몰라도 밥 잘 먹어요. 메뉴판 보고, 주문하고, 음식 나오는 것만 보면 되거든요. 우리 서비스도 똑같아요. 사용자는 화면만 봐요.

---

## 4. 그래서 오늘은 '홀'만 차립니다

여기서 오늘의 핵심이 나와요. //

식당을 처음 차린다고 해서, 첫날부터 주방을 풀 세팅할 필요는 없어요. //

먼저 손님이 들어와서 "오, 여기 괜찮은데?" 하고 느낄 '홀' 분위기부터 만들어보는 거예요. 테이블 놓고, 메뉴판 한 장 붙이고. //

우리도 똑같이 가요. 오늘은 주방(백엔드) 없이, 손님석(프론트엔드)만 차릴 거예요. //

"주방 없이 식당이 돼요?" 싶죠. 이런 경우엔 충분히 돼요. //

자기소개 페이지, 소개용 한 장짜리 페이지, 메뉴를 보여주는 화면. 이런 '보여주기'가 목적인 화면은 주방이 없어도 멀쩡히 돌아가요. //

왜 이렇게 하냐면요. 우리 목적이 아직 '완성된 식당 운영'이 아니라 '반응 확인'이거든요. //

"이 화면, 사람들이 이해할까? 써보고 싶어 할까?" 이걸 보는 게 먼저예요. 그건 홀만 있어도 물어볼 수 있어요. //

그러니까 화면만 먼저 만드는 건, 대충 만드는 게 아니에요. 지금 단계에 딱 맞는, 제일 똑똑한 시작이에요.

## 5. '상태'라는 말, 겁먹지 마세요

화면 얘기를 하다 보면 '상태'라는 단어가 꼭 나와요. 영어로는 'state'고요. //

이거 어렵게 들리는데, 풀어보면 진짜 별거 아니에요. //

**상태는 '지금 화면이 기억하고 있는 값'이에요.** 이 한 줄이면 끝나요. //

예를 들어볼게요. 검색창에 글자를 한 자 한 자 치잖아요? 그때 화면이 "지금 여기 이 글자가 적혀 있어"라고 기억하고 있죠. 그 기억하는 값이 상태예요. //

버튼을 눌렀더니 "처리 중…" 하고 빙글빙글 도는 표시 본 적 있죠? 그것도 상태예요. "지금은 처리 중인 상태야"라고 화면이 기억하는 거죠. //

장바구니에 담은 물건 개수, 켜고 끈 다크모드, 지금 보고 있는 탭. 전부 화면이 기억하는 값, 그러니까 상태예요. //

왜 이걸 알려드리냐면요. 이따 우리가 만들 화면에서, 버튼을 누르면 인사말이 '띡' 하고 뜰 거예요. //

그게 바로 상태가 바뀌는 순간이에요. "인사를 보여줄까, 말까"를 화면이 기억하고 있다가, 버튼을 누르면 "이제 보여줘!"로 바뀌는 거죠. //

그러니까 상태라는 말이 나와도 이제 안 무섭죠? "아, 지금 화면이 뭘 기억하고 있구나." 그 정도면 충분해요.

## 6. '진짜'가 아니어도 배울 수 있어요 (목업)

하나만 더 짚고 갈게요. 이거 알면 진짜 마음이 편해져요. //

많은 분이 이렇게 생각하세요. "내 서비스에 AI가 들어가야 하는데, 그럼 처음부터 그 AI 기능을 다 붙여야 하는 거 아냐?" //

아니에요. 처음엔 '가짜 결과'를 보여줘도 돼요. 이걸 '목업'이라고 해요. //

목업은 쉽게 말하면 '견본'이에요. 가구점 가면 진열용 소파 있죠. 진짜로 파는 건 아닌데, 앉아보고 "오 이거 좋다" 느끼게 해주는 거. 그게 목업이에요. //

예를 들어볼게요. '상품 설명을 AI가 써주는 서비스'를 만든다고 해봐요. //

진짜로 AI를 연결하려면 손이 많이 가요. 근데 처음엔 이렇게 해도 돼요. 상품명을 입력하면, 미리 만들어둔 그럴듯한 예시 설명 하나를 딱 보여주는 거예요. //

그리고 사람들한테 물어보는 거죠. "이 정도 결과가 나오면, 너 이거 써볼 것 같아?" //

만약 "음, 이건 별로 필요 없는데?" 하면요? 진짜 AI를 안 붙여도 돼요. 시간 엄청 아낀 거예요. //

반대로 "오, 이거 좋은데? 진짜 되는 거야?" 하면, 그때 주방(백엔드)이랑 AI를 붙이면 돼요. //

한 가지 약속만 지켜요. 사람을 속이면 안 돼요. "이거 다 완성된 거야"라고 거짓말하는 게 아니라, "이런 결과가 나오면 쓸 것 같은지 보고 싶어"라고 솔직하게 물어보는 거예요. 그러면 충분히 의미 있어요.

## 7. 킬러 장면 — "자기소개 페이지 만들어줘"

자, 이제 말로만 하지 말고 진짜 화면 하나 만들어볼게요. 오늘의 하이라이트예요. //

우리가 만들 건 '자기소개 페이지'예요. 딱 화면 한 장. 주방 필요 없고, 저장도 필요 없어요. 프론트만으로 되는 거죠. //

AI한테 이렇게 부탁해볼게요. 어렵게 말 안 해도 돼요. 그냥 우리말로 부탁하면 돼요. //

```text
내 자기소개 페이지를 하나 만들어줘.

이름, 한 줄 소개, 좋아하는 것 세 개를 보여주고,
"인사하기" 버튼이 하나 있으면 좋겠어.
그 버튼을 누르면 화면에 "반가워요!" 인사가 떠.

나는 코드를 잘 몰라.
한 번에 다 만들지 말고,
브라우저에서 화면이 보이는 순간 멈춰서 설명해줘.
```

이렇게 부탁하면요. AI가 코드를 쓰기 시작해요. 파일을 몇 개 만들고요. //

그리고 한 5분쯤 지나면, 화면에 진짜로 떠요. 내 이름, 한 줄 소개, 좋아하는 것 세 개, 그리고 '인사하기' 버튼까지. //

버튼을 눌러볼까요? '반가워요!' 하고 인사가 화면에 딱 나타나요. //

아까 배운 거 기억나세요? 그 인사가 뜨고 안 뜨고를 화면이 기억하는 거, 그게 상태예요. 방금 우리가 상태가 바뀌는 걸 직접 본 거예요. //

처음 이걸 보면요, 진짜 좀 신기해요. 내가 코드는 한 줄도 안 쳤는데, 머릿속에 있던 화면이 눈앞에 떠 있으니까요. //

부탁할 때 작은 요령 하나만 알려드릴게요. "한 번에 다 만들지 말고, 화면 보이면 멈춰서 설명해줘." 이 한마디를 꼭 넣으세요. //

이게 왜 중요하냐면, AI가 혼자 너무 멀리 가버리면 우리가 따라가기 힘들거든요. 한 입씩, 확인하면서 가는 거예요.

## 8. AI가 만든 소스, 바로 넘기지 마세요

화면이 떴어요. 신나죠. 그럼 바로 다음 기능 만들고 싶어져요. //

여기서 딱 한 박자만 쉬어가요. 이게 오늘 영상에서 제일 중요한 습관이에요. //

화면이 잘 떴으면, 다음으로 넘어가기 전에 AI한테 "방금 뭘 만든 건지 설명해줘"라고 부탁하세요. //

코드를 외우라는 게 아니에요. 절대 아니에요. 그냥 "이 파일은 무슨 역할이구나" 정도 감만 잡으면 돼요. //

이렇게 부탁하면 좋아요.

```text
방금 만든 걸 초보자 기준으로 설명해줘.

1. 사용자가 처음 보는 화면이 어느 파일인지
2. 버튼이나 입력창 같은 조각이 어디 있는지
3. 화면이 기억하는 값(상태)이 뭔지
4. 인사하기 버튼을 누르면 무슨 일이 일어나는지

각 파일이 "한 줄로 무슨 일을 하는지"만 알려줘.
```

이렇게 물으면 AI가 친절하게 풀어줘요. "이 파일은 화면 전체고요, 이 부분은 버튼이고요, 이 값이 인사를 보여줄지 기억하는 상태예요." //

이걸 한 번 듣고 나면요, 나중에 "버튼 색깔만 바꾸고 싶어" 할 때 어디를 건드려야 하는지 감이 와요. //

비유하자면, 새 집에 이사 왔을 때 방이 어디 어디 있는지 한 바퀴 둘러보는 거랑 같아요. 벽돌 쌓는 법을 배우는 게 아니라, 그냥 집 구조를 파악하는 거예요. //

이 습관 하나가, 앞으로 AI랑 일할 때 우리를 '구경꾼'이 아니라 '주인'으로 만들어줘요.

## 9. 화면은 직접 눌러서 확인해요

코드는 AI가 만들어줘요. 그런데 '잘 됐는지' 확인하는 건 우리 몫이에요. 이것도 어렵지 않아요. //

그냥 직접 눌러보면 돼요. 손님처럼요. //

순서는 이래요. //

먼저, 화면을 처음 봤을 때 "여기서 뭘 하면 되는지" 한눈에 보이나요? 내 이름이랑 소개가 제대로 떠 있나요? //

그다음, '인사하기' 버튼을 눌러봐요. 인사말이 잘 뜨나요? //

한 번 더 눌러보고, 이상하게 동작하지는 않나 봐요. //

이게 다예요. 개발자처럼 검사하는 게 아니라, 그냥 손님 입장에서 "이거 잘 되네?" 확인하는 거예요. //

만약 버튼을 눌렀는데 아무 일도 안 일어나면요? 당황하지 말고 AI한테 그대로 말하면 돼요.

```text
인사하기 버튼을 눌렀는데 아무 반응이 없어.
초보자 기준으로, 뭘 확인해야 하는지 순서대로 알려줘.
```

이렇게요. 뭔가 안 될 때 어떻게 풀어가는지는, 사실 그 자체로 큰 주제라 다음다음 영상에서 제대로 다룰 거예요. 오늘은 "안 되면 그대로 AI한테 말하면 된다" 정도만 기억해두세요.

## 10. 오늘은 여기까지 — 경계선 긋기

자, 화면 한 장 떴어요. 버튼도 눌러봤어요. 오늘 목표 달성이에요. //

여기서 욕심이 슬슬 나기 시작해요. "이제 저장 기능 붙일까? 진짜 AI 연결할까? 인터넷에 올려서 친구한테 보낼까?" //

그 마음 너무 좋아요. 근데 오늘은 딱 여기서 멈춰요. 이유가 있어요. //

한 번에 다 하려고 하면, 어디서 꼬였는지 못 찾고 길을 잃거든요. 그래서 한 칸씩 갈 거예요. //

정리해드릴게요. 오늘 안 한 것들은 사라진 게 아니라, 각자 자기 영상이 따로 있어요. //

만든 걸 안전하게 저장하고, 망쳐도 되돌리는 법. 이건 바로 다음 영상에서요. //

화면에 빨간 에러가 떴을 때 푸는 법. 그건 그다음 영상에서요. //

내가 만든 걸 진짜 인터넷 주소로 만들어서 친구한테 카톡으로 보내는 거. 그건 좀 더 뒤 영상에서 제대로 다뤄요. //

그러니까 지금은요, 화면 한 장 띄운 걸로 충분히 잘하신 거예요. 진짜로요. 거기까지가 오늘의 한 칸이에요.

## 11. 마무리 + 다음 영상

오늘 거 짧게 정리할게요. //

서비스는 식당이랑 같아요. 손님이 보는 홀이 프론트엔드, 뒤에서 처리하는 주방이 백엔드. //

처음엔 홀, 그러니까 화면만 차려도 돼요. 그걸로 사람들 반응을 충분히 볼 수 있거든요. //

'상태'는 지금 화면이 기억하는 값이에요. 버튼 누르면 인사가 뜨는 거, 그게 상태가 바뀌는 거죠. //

진짜 기능이 없어도, 가짜 견본(목업)으로 먼저 반응을 볼 수 있어요. //

그리고 AI가 화면을 만들어주면, 바로 넘어가지 말고 "이게 뭐 하는 건지" 한 번 설명을 들어요. //

오늘 숙제는 딱 하나예요. AI한테 "내 자기소개 페이지 하나 만들어줘"라고 부탁해보세요. 화면 한 장 떠보는 거, 그 경험이 진짜 시작이에요. //

그런데 막상 만들다 보면 이런 걱정이 들어요. "이거 만지다가 잘 되던 화면이 망가지면 어떡하지?" //

다음 영상이 바로 그 얘기예요. 제목은 "망쳐도 괜찮아요, Git으로 되돌리기." 게임에서 세이브하고 불러오기 하듯이, 만든 걸 안전하게 저장하고 언제든 되돌리는 법을 같이 해볼게요. //

이거 알고 나면, 마음 놓고 이것저것 건드려볼 수 있어요. 그게 진짜 재밌어지는 지점이거든요. //

코드 한 줄 안 쳤는데 내 화면이 눈앞에 떠 있는 거, 그 기분 오늘 꼭 한 번 느껴보세요. 그거면 오늘은 충분해요. 다음 영상에서 만나요.

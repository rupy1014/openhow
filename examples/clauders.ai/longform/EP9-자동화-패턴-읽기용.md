# [EP9] 읽기용 대본 — 이런 것도 자동화돼요 (패턴 + 내 일에 적용하기)

> EP8(`/write` 한 줄로 블로그 글 완성) 받아서 → "그럼 이런 것도 돼요"의 범위를 넓히는 편. 자동화 5패턴을 비유로 + "원리는 하나(입력→처리→확인)" + "내 귀찮은 일 1건 자동화" 숙제. 카메라 보고 처음부터 끝까지 읽는 완성 대본. 약 10~12분.
> 톤: 친절·쉬움·완전 초보 배려. "몰라도 돼요, 천천히." 겁주기·하이프·과장 금지. 비유로 풀어주기.
> docs 근거: automation/03-patterns, automation/04-homework.
> `//` = 살짝 쉬는 지점 (EP1보다 드물게).

---

## 1. 시작 — "그건 블로그라서 된 거 아니에요?"

지난 영상 보신 분들, 좀 신기하지 않으셨어요? //

`/write 1화` 한 줄 쳤더니, 2~3분 뒤에 블로그 글 초안이 딱 완성돼서 나왔잖아요. //

근데 그거 보고 이런 생각, 한 번쯤 드셨을 것 같아요. "에이, 그건 블로그 글이니까 된 거 아니에요? 내 일은 그렇게 딱 떨어지는 게 아닌데." //

오늘은 그 얘기를 할 거예요. "그럼 내 일은 자동화가 되나, 안 되나." //

결론부터 말씀드리면요. 모양은 다 달라 보여도, 자동화가 굴러가는 방식은 몇 가지로 정리가 돼요. 그게 오늘 보여드릴 다섯 가지 패턴이에요.

---

## 2. 먼저 안심부터 — 외우는 거 아니에요

패턴 다섯 개라고 하니까 벌써 좀 부담되시죠? //

미리 말씀드릴게요. 이거 외우는 거 아니에요. 진짜로요. //

오늘 다섯 개를 쭉 보고 나면, 마지막에 제가 이렇게 말할 거예요. "사실 이거 전부 똑같은 원리예요." //

그러니까 지금은 그냥 "아, 이런 식으로 나뉘는구나" 정도만 편하게 들어주세요. 이름 못 외워도 괜찮아요, 천천히 가요. //

대신 보시는 동안 딱 하나만 같이 해주세요. 매일, 매주 반복하는 내 일 하나를 머릿속에 띄워놓는 거예요. 회의록 정리든, 똑같은 메일 답장이든, 주간 보고든요. 그걸 들고 다섯 개를 보면, "어, 내 건 이거랑 비슷한데?" 하는 순간이 와요.

---

## 3. 자동화가 뭐였는지부터 (짧게 복습)

본격적으로 가기 전에, 한 줄만 복습할게요. //

앞에서 자동화를 이렇게 설명드렸어요. **자동화는 일하는 흐름을 미리 한 번 정해두는 거예요.** //

그래서 다음부터는 명령어 한 줄만 치면, 그 흐름이 알아서 쭉 돌아가는 거고요. //

그리고 그 흐름 안에는 '담당자'들이 있어요. 이게 어려운 말로는 에이전트인데, 그냥 **각자 맡은 일을 하는 직원 한 명**이라고 생각하시면 돼요. 글 쓰는 담당자, 검수하는 담당자, 이런 식으로요. //

오늘 다섯 패턴은요. 이 담당자들을 **어떤 순서로 움직이게 할 거냐**, 그 짜는 방법이에요. 그것만 알고 들어가시면 돼요.

---

## 4. 패턴 하나 — 체인 (순서대로 가는 일)

첫 번째는 '체인'이에요. 사슬처럼 줄줄이 이어진다고 해서 체인이고요. //

**앞 단계가 끝나야 다음 단계를 할 수 있는 일.** 이게 체인이에요. //

제일 쉬운 비유는 김밥이에요. 밥을 먼저 깔고, 그 위에 재료를 올리고, 둘둘 말고, 마지막에 썰죠. 순서를 바꿀 수가 없어요. 재료부터 올리고 밥을 깔 순 없잖아요. //

일도 이렇게 생긴 게 많아요. 예를 들어 자기소개서를 쓴다고 해볼게요. 먼저 담당자 한 명이 내 경력을 쭉 정리하고요. 그걸 받아서 다음 담당자가 이야기로 풀어 쓰고요. 그다음 담당자가 문장을 다듬고요. 마지막 담당자가 그 회사에 맞는지 검수해요. //

앞사람 결과물을 뒷사람이 받아서 이어가는 거예요. 지난 영상의 블로그 글도 사실 이 체인이었어요. 회차 맥락 잡고, 초안 쓰고, 퇴고하고, 검수하고. 그 순서로 한 줄에 쭉 돈 거예요.

---

## 5. 패턴 둘 — 분류 (보고 나눠 보내는 일)

두 번째는 '분류'예요. //

들어온 내용을 먼저 보고, **어디로 보낼지 정하는 일.** //

병원 접수처를 생각하시면 딱 맞아요. 가면 먼저 물어보잖아요. "어디가 불편하세요?" 그러고 내과로 보낼지, 정형외과로 보낼지 정해주죠. //

일에서도 똑같아요. 고객 메일이 하루에 수십 통씩 온다고 해볼게요. 이게 결제 문의인지, 환불 문의인지, 계정 문의인지 먼저 슥 보고요. 결제면 결제 담당자한테, 환불이면 환불 담당자한테 넘기는 거예요. //

여기서 한 가지만요. 분류를 시키려면 **나누는 기준**을 미리 적어둬야 해요. "이런 내용이면 환불로 보낸다" 하고요. 그 기준을 문서로 한 번 정리해두면, 담당자가 그걸 읽고 알아서 나눠줘요. //

고객 문의 말고도요. 지원서 1차 분류, 버그 신고 종류 나누기, 아이디어 카테고리 정리. 이런 게 다 분류예요.

---

## 6. 패턴 셋 — 동시처리 (한꺼번에 해도 되는 일)

세 번째는 '동시처리'예요. //

**서로 기다릴 필요가 없는 일은, 한꺼번에 시키는 거예요.** //

이사할 때를 생각해보세요. 혼자 안방 싸고, 다 싸면 주방 싸고, 그다음 거실 싸면 하루 종일 걸리죠. 근데 세 명이서 각자 방 하나씩 동시에 싸면 금방 끝나잖아요. //

일도 그래요. 경쟁사 세 곳을 조사한다고 해볼게요. A 회사 조사가 끝나야 B 회사를 볼 수 있는 게 아니죠. 서로 상관이 없어요. 그럼 담당자 셋한테 동시에 시키면 돼요. //

대신 동시처리에는 한 가지가 꼭 따라와요. **마지막에 합치는 담당자 한 명이 필요해요.** 셋이 따로 조사해 왔으니까, 누군가 그걸 한자리에 모아서 정리해줘야 하거든요. //

여러 제목 후보 뽑기, 광고 문구 여러 개 만들기. 이런 "여러 개를 한 번에" 같은 일이 동시처리랑 잘 맞아요.

---

## 7. 패턴 넷 — 지휘자 (상황 보고 부르는 일)

네 번째는 '지휘자'예요. //

앞의 세 개는 순서가 거의 정해져 있었죠. 근데 일이라는 게 항상 그렇진 않잖아요. 해보다가 "어, 이건 좀 봐야겠는데?" 하는 경우가 생기죠. //

그럴 때 쓰는 게 지휘자예요. **미리 정한 순서대로만 안 가고, 결과를 보면서 그때그때 필요한 담당자를 부르는 거예요.** //

응급실 의사를 떠올리시면 돼요. 환자가 오면 일단 보고요. 뼈가 문제 같으면 엑스레이를 찍게 하고, 별일 아니면 굳이 큰 검사 안 하죠. 상황을 보고 필요한 것만 부르는 거예요. //

일로 보면요. 사업 기획서를 검토한다고 할 때, 법적으로 걸릴 게 전혀 없는 내용이면 법무 담당자를 굳이 안 불러도 되잖아요. 반대로 위험해 보이는 부분이 있으면, 그쪽을 깊게 보는 담당자를 더 부르고요. //

이건 좀 더 손이 가는 방식이에요. 그러니까 처음부터 이걸로 시작 안 하셔도 돼요. 일단 체인처럼 단순하게 만들어보고, 갈림길이 자꾸 생긴다 싶을 때 지휘자를 얹으면 돼요.

---

## 8. 패턴 다섯 — 반복개선 (될 때까지, 단 멈출 조건)

마지막 다섯 번째는 '반복개선'이에요. //

**초안을 만들고, 점수를 매겨보고, 기준에 못 미치면 다시 고치는 거예요.** 될 때까지 돌리는 거죠. //

우리가 글 쓸 때 하는 거랑 똑같아요. 초고 쓰고, 읽어보고, "이건 좀 밋밋한데" 싶으면 다시 고치잖아요. 그걸 담당자 둘이서 하게 만드는 거예요. 한 명은 쓰고, 한 명은 평가하고. 통과 못 하면 다시 쓰고요. //

예를 들어 광고 문구를 만든다고 해볼게요. 1회차를 썼는데 평가에서 "너무 평범함"이 나오면, 다시 써요. 2회차는 "혜택이 약함"이 나오면, 또 고쳐요. 3회차에서 기준을 통과하면, 그제야 저장하고 끝내는 거예요. //

자, 여기가 오늘 제일 중요한 부분이에요. 잘 들어주세요. //

**반복개선에는 멈추는 조건을 꼭 정해줘야 해요.** //

안 그러면 어떻게 될까요? 평가가 계속 "조금 아쉬운데?" 하면서, 고치고 또 고치고, 끝없이 돌 수 있어요. 시간도 버리고요. //

그래서 미리 정해두는 거예요. "80점 넘으면 통과", 그리고 "아무리 안 돼도 3번까지만 돌린다." 이렇게 멈출 선을 그어주면, 무한정 도는 일이 없어요. //

겁먹으실 건 아니에요. 그냥 "몇 점 넘으면 끝, 몇 번까지만" 한 줄 적어두면 되는 거예요. 그 한 줄이 안전장치예요.

## 9. 사실은요, 원리가 하나예요

자, 다섯 개 다 봤어요. 이제 약속드린 거 말씀드릴게요. //

이 다섯 개, 따로따로 외우실 필요 없어요. 뼈대가 전부 똑같거든요. //

뭐냐면요. 어떤 자동화든 결국 세 가지만 정하는 거예요. //

**하나, 입력 — 뭘 줄 거냐.** 어떤 자료를 보고 일하게 할지요. //

**둘, 처리 — 누가 어떤 순서로 할 거냐.** 담당자를 어떻게 움직일지요. //

**셋, 확인 — 어떤 기준으로 됐다고 볼 거냐.** 결과가 괜찮은지 뭘로 판단할지요. //

입력, 처리, 확인. 이 세 개예요. 다섯 패턴은 이 중에 '처리'를 어떻게 짜느냐가 다를 뿐이에요. //

순서대로 가면 체인, 보고 나눠 보내면 분류, 한꺼번에 하면 동시처리, 상황 보고 부르면 지휘자, 될 때까지 돌리면 반복개선. 뼈대는 같고 모양만 다른 거예요. //

그리고 실제 일에서는 이걸 섞어 써요. 예를 들면요. 앞에선 자료를 동시처리로 한 번에 모으고, 가운데선 체인으로 순서대로 정리하고, 끝에선 반복개선으로 기준 통과시키고. 이렇게요. //

그러니까 진짜로 잡으셔야 할 감은 이름이 아니에요. **"내 일 중에 어디가 순서 있는 일이고, 어디가 나누는 일이고, 어디가 다시 돌려야 하는 일인지"** 그걸 보는 눈이에요. 그건 그 일을 매일 하는 본인이 제일 잘 알아요.

## 10. 오늘 숙제 — 네 귀찮은 일, 딱 하나

자, 그럼 오늘 숙제예요. 이게 사실 오늘의 진짜 본론이에요. //

거창한 거 하지 마세요. 회사를 통째로 자동화한다, 이런 거 말고요. **내가 자주 반복하는 귀찮은 일, 딱 하나만 골라보세요.** //

고르는 기준은 간단해요. 첫째, 내가 실제로 자주 하는 일이고. 둘째, 예전에 만든 결과물 샘플이 하나라도 있고. 셋째, 잘 나온 건지 별로인 건지 내가 판단할 수 있는 일. //

주간 보고, 회의록 정리, 고객 메일 답장 초안, 유튜브 대본 초안. 이런 거 다 좋아요. //

골랐으면, 진짜 작게 세팅해보는 거예요. 순서대로 말씀드릴게요. //

**하나, 샘플을 넣어둬요.** 예전에 잘 썼던 결과물 하나를 프로젝트에 넣어두세요. AI가 "아, 이런 모양으로 만들면 되는구나" 참고할 수 있게요. //

**둘, 기준을 글로 적어요.** 이게 제일 중요해요. 이 일이 뭔지, 누가 보는 건지, 잘 된 결과물은 어떤 모양인지. 머릿속에만 있던 걸 밖으로 꺼내서 적는 거예요. 신입사원한테 인수인계한다 생각하시면 돼요. 그 사람이 이 글만 보고 첫 초안을 만들 수 있을 정도면 충분해요. //

**셋, 담당자 둘이랑 명령어 하나만 만들어요.** 초안 쓰는 담당자 하나, 검수하는 담당자 하나. 그리고 그 둘을 부르는 명령어 한 줄. 처음엔 이거면 돼요. //

**넷, 딱 한 번 돌리고, 결과를 읽어요.** //

여기서 하나만 미리 안심시켜드릴게요. **첫 결과가 별로인 건 정상이에요.** 그게 실패가 아니에요. //

오히려 그 별로인 결과를 읽고, "아, 숫자를 너무 단정적으로 말했네", "보고용치곤 문장이 길었네" 하고 찾아내는 게 핵심이에요. 그걸 아까 적어둔 기준 문서에 한 줄 더 추가하는 거죠. "원인은 단정하지 말고 '확인이 필요하다'로 쓴다" 이렇게요. //

그러고 다음에 다시 돌리면, 내 일에 점점 맞게 나와요. //

**한 번 돌리고, 읽고, 기준 한 줄 고쳤다.** 여기까지 하셨으면 오늘 숙제는 성공이에요. 그게 자동화의 전부예요.

## 11. 마무리 + 다음 영상

오늘 거 정리할게요. //

자동화 패턴은 다섯 개예요. 순서대로 가는 체인, 보고 나누는 분류, 한꺼번에 하는 동시처리, 상황 보고 부르는 지휘자, 될 때까지 돌리는 반복개선. //

근데 외우진 마세요. 원리는 하나예요. 뭘 줄지, 누가 어떤 순서로 할지, 어떤 기준으로 됐다고 볼지. 입력, 처리, 확인. //

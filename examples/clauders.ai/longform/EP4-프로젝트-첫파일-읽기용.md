# [EP4] 읽기용 대본 — "프로젝트"가 뭐예요? + AI한테 첫 일 시키기 (첫 파일 만들기)

> 단계 1(시작하기)의 두 번째 영상. EP3에서 설치한 검은 창을 가지고, 이번엔 AI가 일할 '작업실'을 차리고 첫 일을 시켜본다. 약 10~12분.
> 톤: 친절·쉬움·완전 초보 배려. "몰라도 돼요, 천천히." 겁주기·하이프·과장 금지. 비유로 풀어주기.
> docs 근거: getting-started/04-create-project.
> `//` = 살짝 쉬는 지점. 드물게만 표시. 그 외엔 자연스럽게 이어서.

---

## 1. 시작 — 설치는 했는데, 이제 뭐 하죠?

지난 영상에서 우리, 같이 설치까지 했어요. //

검은 창 띄우고, `claude` 한 줄 쳐서, 세션 시작되는 그 순간까지요. 거기까지 오신 것만 해도 진짜 큰 거예요.

그런데 막상 창을 띄워놓고 보면, 이런 생각이 들죠. "그래서… 여기서 뭘 어떻게 하라는 거지?"

맞아요. 저도 처음에 딱 거기서 멈췄어요. //

그래서 오늘은요. 그 멈춘 자리에서 딱 한 발짝 더 나가볼 거예요. AI한테 진짜 일을 하나 시켜서, 내 눈앞에 결과물 하나를 만들어내는 거예요.

오늘 나오는 단어들, "프로젝트", "폴더", "파일" 같은 거요. 어려워 보여도 다 일상적인 말로 풀어드릴게요. 모르는 게 나와도 괜찮아요. 천천히 같이 가요.

---

## 2. '프로젝트'가 뭐냐면요

AI를 좀 쓰려고 하면, 자꾸 "프로젝트"라는 말이 나와요. //

이 단어 때문에 처음에 다들 한 번 움찔하세요. "프로젝트? 뭔가 대단한 걸 기획해야 하나?" 싶거든요.

전혀 아니에요. 여기서 말하는 프로젝트는요. **그냥 폴더 하나예요.**

컴퓨터에 바탕화면 있죠? 거기에 폴더 하나 새로 만들잖아요. 그 폴더 하나가 바로 프로젝트예요. 진짜 그게 다예요.

좀 더 느낌 오게 비유를 하나 들게요. //

프로젝트는 **AI가 일할 작업실**이에요. //

이렇게 생각해보세요. 새로 온 직원한테 "여기가 네 책상이야" 하고 자리를 하나 딱 정해주잖아요. 그 책상이 작업실이에요. 그 사람은 거기 앉아서 일하는 거고요.

폴더 하나 만드는 게, AI한테 "여기가 네 작업실이야" 하고 책상을 하나 내주는 거랑 똑같아요.

그래서 폴더가 곧 작업실이고, 작업실이 곧 프로젝트예요. 셋 다 같은 말이에요.

그 작업실 안에 뭐가 들어가냐면요. 같이 작업할 파일들이 들어가요. //

예를 들어 유튜브 대본을 쓰는 작업실이면, 그 안에 대본 파일들이 모여요. 이력서를 고치는 작업실이면, 그 안에 이력서 파일이 들어가고요.

이렇게 **관련 있는 파일들을 한 폴더에 모아둔 것**. 그게 프로젝트예요. 거창한 거 하나도 없죠?

---

## 3. 그럼 작업실부터 같이 차려볼게요

자, 말로만 들으면 헷갈리니까 직접 하나 차려봐요. //

거창하게 안 할 거예요. 진짜 빈 작업실 하나만 만들 거예요. 순서대로 천천히 따라오시면 돼요.

**첫째, 바탕화면에 폴더 하나 만들어요.** //

새 폴더 만들고, 이름을 붙여요. 저는 `my-first-vibe`라고 할게요. "내 첫 작업실" 정도 뜻이에요.

이름 지을 때 팁 하나. 처음엔 **영어로 짧게** 짓는 게 편해요. 한글이나 띄어쓰기, 특수문자는 가끔 컴퓨터가 헷갈려 하거든요. 그냥 `my-first-vibe`처럼 영어에 가운데 줄표 정도면 충분해요.

**둘째, 이 폴더를 'VS Code'로 열어요.** //

VS Code는요. 우리가 지난 영상에서 깔았던, 글이랑 파일을 다루는 작업 프로그램이에요. 한글이나 메모장 같은 건데, AI랑 같이 쓰기 좋은 거라고 보시면 돼요.

VS Code를 켜고, 위쪽 메뉴에서 "파일 열기" 비슷한 걸 눌러서, 방금 만든 폴더를 골라주세요. 그러면 VS Code가 그 폴더를 작업실로 딱 열어줘요.

화면에서 딱 세 군데만 봐주세요. //

**왼쪽**은 파일 목록이에요. 이 작업실 안에 뭐가 들어 있는지 보여줘요. 지금은 텅 비어 있겠죠. 방금 만든 빈 폴더니까요.

**가운데**는 파일 내용을 보는 곳이고요. **아래쪽**엔 우리가 명령을 치는 검은 줄, 터미널이 있어요. 지난 영상에서 봤던 그 검은 창이에요.

**셋째, 그 터미널에서 AI를 깨워요.** //

아래 터미널을 누르고, `claude`라고 친 다음 엔터를 눌러요. (지난 영상에서 더 빠른 방법 알려드렸으면 그걸로 하셔도 돼요.)

그러면 입력 줄이 하나 뜰 거예요. 화살표처럼 생긴 `>` 표시요. //

이게 떴다는 건요. AI가 지금 **이 폴더를 자기 작업실로 잡고**, "자, 뭐 시킬까요?" 하고 기다리는 상태예요.

여기까지 오셨으면, 작업실 다 차린 거예요. 이제 진짜 재밌는 거 할 차례예요.

---

## 4. 드디어, 빈 작업실에 첫 일 시키기

지금 우리 작업실, 텅 비어 있죠. 왼쪽 파일 목록에 아무것도 없어요. //

여기서 AI한테 첫 일을 시켜볼 거예요. 거창한 거 아니에요. 딱 한 줄이면 돼요.

터미널에 이렇게 쳐보세요.

```text
README 파일 하나 만들어줘. 이 폴더가 뭐 하는 곳인지 짧게 적어줘.
```

그리고 엔터. //

이게 끝이에요. 진짜로요. 영어도 코딩도 하나도 없죠. 그냥 사람한테 말하듯이 한국어로 부탁한 거예요.

이제 잠깐만 기다려보세요. //

AI가 뭐라고 주르륵 설명을 하더니, 잠시 뒤에… **왼쪽 파일 목록에 파일이 하나 톡 생겨요.** `README.md`라는 파일이요.

방금까지 텅 비어 있던 그 빈 방에, 처음으로 물건 하나가 딱 놓인 거예요. //

이 순간이요. 별거 아닌 것 같아도, 처음 보면 다들 "어? 진짜 생겼네?" 하세요. 제가 가르쳐본 분들 거의 다 이 장면에서 한 번 웃으셨어요.

그 파일을 한 번 눌러보세요. 가운데 화면에 내용이 뜰 거예요. 이 폴더가 뭐 하는 곳인지, AI가 알아서 적어둔 글이요.

내가 직접 한 글자도 안 쳤는데, 부탁 한 줄로 멀쩡한 파일 하나가 생긴 거예요. //

이게 바로 EP1에서 제가 말씀드린 그 "어? 이게 되네?" 순간이에요. 오늘 이거 하나만 직접 해보셔도, 이 영상 본 값은 다 한 거예요.

---

## 5. 방금 생긴 그 파일, 뭐냐면요

자, 신기한 김에 그 파일이 정확히 뭔지도 잠깐 짚고 갈게요. //

이름이 `README.md`였죠. 두 부분으로 나눠서 볼게요.

먼저 **README**. 영어로 "리드 미", 그러니까 "나 좀 읽어줘"라는 뜻이에요.

이름 그대로예요. 이 폴더를 처음 열어본 사람이, "여기 뭐 하는 데지?" 싶을 때 제일 먼저 읽으라고 두는 **안내문**이에요. 가게 입구에 붙은 "영업시간 안내" 같은 거라고 보시면 돼요.

그 다음 뒤에 붙은 **.md**. 이게 좀 낯설죠. //

`.md`는 마크다운이라는 형식인데요. 어렵게 생각 안 하셔도 돼요. **그냥 글자만 담긴 텍스트 파일**이라고 보면 돼요. 메모장에 쓰는 글처럼요.

다만 제목이나 목록 정도는 살짝 꾸밀 수 있게 만든 거예요. 사람도 보기 편하고, AI도 읽기 편한 포맷이라서, AI랑 일할 땐 이 `.md`를 많이 써요.

그래서 앞으로 AI랑 작업하다 보면 `.md`로 끝나는 파일이 자주 보일 거예요. 그때마다 "아, 그냥 글자 적어둔 파일이구나" 하시면 돼요. //

이 정도만 알아도 충분해요. 더 깊은 건 나중에 필요할 때 자연스럽게 알게 되니까, 지금은 넘어가도 괜찮아요.

여기서 제일 중요한 건 따로 있어요. //

파일을 내가 손으로 다 만들어 들고 오는 게 아니라는 거예요. **빈 폴더 하나 열어두고, AI랑 대화하면서 하나씩 채워가는 거예요.**

"README 만들어줘", "할 일 목록 파일도 하나 만들어줘", 이렇게 부탁하면서요. 작업실은 그렇게 같이 채워가는 곳이에요.

---

## 6. 작업실에 '신입 수칙' 한 장 붙이기 (맛보기)

자, 여기서 하나만 더 맛만 보고 갈게요. //

AI랑 일을 시키다 보면 이런 게 좀 귀찮아져요. 똑같은 부탁을 매번 다시 해야 하거든요.

"한국어로 설명해줘", "어려운 말 말고 쉽게 써줘", 이런 거요. 새 대화를 열 때마다 또 말하고, 또 말하고. //

이게 꼭, 새 직원 올 때마다 매일 아침에 "우리는 한국어로 써요, 이건 이렇게 해요" 하고 똑같은 말 반복하는 거랑 같아요. 사람도 지치고 직원도 헷갈리죠.

그래서 작업실에 종이 한 장을 붙여두는 거예요. **"우리 작업실은 이렇게 일해요"** 하는 신입사원 수칙 같은 거요.

이 수칙 파일 이름이 바로 `CLAUDE.md`예요. //

이름은 어렵게 생겼지만, 하는 일은 단순해요. 작업실 벽에 붙여둔 규칙 메모예요. 예를 들면 이런 걸 적어두는 거예요.

```text
- 설명은 항상 한국어로 해줘
- 어려운 용어 말고 쉽게 풀어서 써줘
- 작업 끝나면 어떤 파일을 바꿨는지 먼저 알려줘
```

이렇게 한 번 붙여두면요. 다음에 작업실을 다시 열어도, AI가 이 수칙을 알아서 읽고 그 규칙대로 일해요. 매번 다시 설명 안 해도 돼요. //

이것도 직접 손으로 안 적어도 돼요. AI한테 "이런 규칙으로 `CLAUDE.md` 만들어줘" 하면 그대로 만들어줘요.

근데 오늘은 여기까지만요. **이건 진짜 맛보기예요.** //

이 수칙을 어떻게 잘 적어야 AI가 일을 똑 부러지게 하는지, 그 진짜 요령은요. 좀 뒤에 나오는 EP6에서 제대로 다룰 거예요.

지금은 딱 하나만 기억하세요. "아, 작업실마다 규칙 한 장을 붙여둘 수 있구나." 그거면 충분해요.

---

## 7. 작업실은 여러 개 차려도 괜찮아요

마지막으로 자주 받는 질문 하나만 풀고 갈게요. //

"작업실, 그러니까 폴더를 여러 개 만들어도 돼요?"

네, 오히려 그게 더 좋아요. //

주제가 다르면 폴더를 나누는 게 맞아요. 유튜브 대본은 대본 작업실에, 이력서는 이력서 작업실에. 이렇게 따로 두는 거죠.

이게 왜 좋냐면요. 작업실마다 목적이 선명해지고, 파일이 안 섞이고, 아까 그 '신입 수칙'도 작업실마다 다르게 붙일 수 있어요. 대본 작업실엔 대본 규칙, 이력서 작업실엔 이력서 규칙으로요.

그러니까 폴더 여러 개 만드는 거, 이상한 거 아니에요. 아주 정상적인 방식이에요. //

그리고 초보분들이 자주 걸리는 거 두 개만 미리 안심시켜 드릴게요.

하나, **이름 완벽하게 안 지어도 돼요.** 나중에 바꾸면 돼요. 지금은 그럴듯한 이름보다, 손이 한 번 움직여본 경험이 훨씬 중요해요.

둘, **`CLAUDE.md` 거창하게 안 써도 돼요.** 한두 줄만 적어도 충분히 시작돼요. 길게 쓰려다 시작도 못 하는 게 제일 아까워요.

---

## 8. 마무리 + 다음 영상

자, 오늘 거 정리할게요. //

프로젝트는 거창한 게 아니라, AI가 일할 **작업실, 그러니까 폴더 하나**예요. //

작업실을 차리는 건, 폴더 만들고, VS Code로 열고, `claude`로 AI를 깨우면 끝이고요. //

거기서 "README 만들어줘" 한 줄이면, 빈 작업실에 첫 파일이 톡 생겨요. 그게 오늘의 첫 손맛이에요. //

그리고 작업실 벽엔 `CLAUDE.md`라는 신입 수칙 한 장을 붙여둘 수 있다. 이건 맛만 봤죠. //

오늘 영상 끄시기 전에, 딱 하나만 해보세요. 빈 폴더 하나 만들고, AI한테 "README 만들어줘" 한 번 시켜보기. 그 파일 톡 생기는 거 직접 보시면, 다음이 훨씬 쉬워져요.

다음 영상에서는요. 우리가 오늘 자꾸 "신입사원"에 빗댔잖아요. //

그 비유를 제대로 파볼 거예요. "AI는 똑똑한 신입사원이다." 머리는 진짜 좋은데 우리 사정은 하나도 모르는 신입. 그런 친구한테 일을 어떻게 던져야 잘 받아오는지, 그 감을 잡는 시간이에요.

이 순서대로만 천천히 따라오시면 돼요. 제가 계속 옆에서 같이 갈게요. //

빈 폴더에 첫 파일이 톡 생기는 그 손맛, 오늘 꼭 한 번 느껴보세요. 그 재미가 한 번 붙으면, 다음 이야기는 훨씬 쉬워져요.

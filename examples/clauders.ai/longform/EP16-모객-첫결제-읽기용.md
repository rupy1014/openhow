# [EP16] 읽기용 대본 — (심화) 만든 거 알리고 첫 1,000원 받기 (모객·결제)

> 입문 사다리 끝의 보너스 영상. "여기까지 안 와도 괜찮아요, 궁금한 사람만." 카메라 보고 처음부터 끝까지 읽는 완성 대본. 약 12~15분.
> 톤: 부담 빼기·완전 초보 배려·용어 풀기·"몰라도 돼요 천천히". 겁주기·하이프·과장 금지.
> docs 근거: build-service/11-distribution(모객), 12-pg-bootpay(첫 결제·PG).
> 연속성: EP15(피드백·PMF) 받고 시작 → 마지막에 EP17(데모나잇 + 챌린지) 예고.
> `//` = 살짝 쉬는 지점. 드물게.

## 1. 시작 — 여기까지 온 것만으로 대단해요

지난 영상에서 우리, 만든 걸 다섯 명한테 보여주고 피드백을 받았어요. 친구 말고 모르는 사람한테도요. //

"어때?" 말고 "또 쓸 것 같아?"를 물었고, 그 사람이 다시 돌아오는지를 보면서 'PMF'라는 감, 그러니까 "이게 진짜 필요한 물건인가" 하는 감을 잡아봤죠. //

오늘은 그다음 이야기예요. 만든 걸 더 많은 사람한테 알리고, 어쩌면 첫 1,000원을 받아보는 거. //

근데 먼저, 솔직하게 말씀드릴게요. 오늘 영상은 보너스예요. 여기까지 안 와도 괜찮아요. 진짜로요. //

AI로 내 걸 만들어서 진짜 인터넷 주소로 띄워봤다, 그것만으로도 이미 충분히 대단한 거예요. //

돈 받는 거, 사람 모으는 거, 이건 '하고 싶은 사람만' 하는 거예요. 궁금한 분만 편하게 따라오세요. 오늘도 어렵게 안 갈게요.

## 2. "잘 만들면 팔린다"… 순서를 살짝 바꿔볼게요

많이들 이렇게 생각해요. "잘 만들면 알아서 팔리겠지." //

저도 한동안 그렇게 믿었어요. 근데 막상 해보면, 잘 만들어도 아무도 모르는 경우가 진짜 많아요. 세상엔 이미 좋은 물건이 너무 많거든요. //

그래서 순서를 살짝 바꿔보면 좋아요. 다 만들고 나서 사람을 찾는 대신, 만드는 동안 볼 사람을 조금씩 미리 모아두는 거예요. //

이걸 '오디언스 퍼스트'라고 불러요. 오디언스는 그냥 '내 이야기를 봐주는 사람들'이에요. 공연 보러 온 관객 같은 거죠. //

해외엔 '인디해커'라는 사람들이 있어요. 회사도, 직원도 없이 혼자 작은 서비스를 만들어 파는 사람들이에요. //

그중에 피터 레벨스라는 사람이 유명한데요. 혼자 만든 서비스 몇 개로 큰 수익을 낸다고 알려졌어요. 근데 그 사람이 코딩을 제일 잘해서 그렇게 된 게 아니에요. //

이 사람은 만드는 과정을 매일 공개했어요. 잘된 것도, 망한 것도, 매출 숫자까지 다 올렸어요. //

그래서 제품이 세상에 나오기도 전에, 이미 구경하는 사람들이 있었어요. 사람을 먼저 모아두고, 그다음에 물건을 낸 거죠. 순서가 거꾸로였던 거예요. //

이런 비교가 있어요. 한 사람은 6개월 동안 팔로워랑 구독자를 차곡차곡 모았어요. 제품은 좀 거칠었는데, 출시 첫 주에 800명 넘게 왔어요. //

또 한 사람은 3주 동안 혼자 아주 잘 만들었어요. 근데 출시하니까 47명 왔어요. //

이건 제품 완성도 차이만으로는 설명이 안 돼요. 한쪽은 볼 사람을 미리 모아뒀던 거예요. //

물론 우리가 지금 당장 6개월을 쓸 순 없죠. 그래서 크게 안 가요. 큰 채널 만들겠다고 욕심내지 말고, 그냥 오늘 하나 올리는 것부터 시작하면 돼요.

## 3. 그래서 어디에 올려요?

"그럼 어디에 올려야 터져요?" //

이거 제일 많이 물어보시는데, 솔직히 정답 채널은 없어요. 스레드도 좋고, 유튜브도 좋고, 카페도, 오픈채팅도 다 좋아요. 사람만 오면 다 좋은 거예요. //

진짜 중요한 건 "어디냐"가 아니에요. "내가 이걸 계속할 수 있느냐"예요. //

이번 주는 스레드, 다음 주는 블로그, 그다음 주는 유튜브… 이렇게 옮겨 다니면 아무것도 안 쌓여요. 한 번 반짝하고 멈추는 것보다, 6주 동안 꾸준히 굴러가는 게 결국 더 멀리 가요. //

한국이면 이런 곳들이 있어요. 짧게만 짚을게요. 잘 몰라도 괜찮아요, 천천히 가요. //

스레드나 엑스, 옛날 트위터요. 거긴 뭔가 만드는 사람들, 1인 창업자들이 많아요. 디스콰이엇은 IT 제품 좋아하는 사람들이 모이는 곳이고요. //

카카오 오픈채팅은 주제별로 사람이 모여 있어요. 네이버 카페나 블로그는 생활·취미·자영업 쪽이 강하고요. //

유튜브나 숏폼은 검색해서 들어오는 사람들이죠. 크몽 같은 곳은 아예 살 마음 먹고 온 사람들이 있고요. //

이름 다 외우실 필요 없어요. 핵심은 하나예요. 내 손님이 진짜 모여 있는 곳, 그리고 내가 6주는 버틸 수 있는 곳. //

딱 두 군데만 골라서, 6주만 해보는 거예요. //

고를 때 헷갈리면 두 가지만 보세요. 하나, 내 손님이 거기 진짜 있나. 둘, 내가 지치지 않고 계속할 수 있나. 이 두 개가 제일 중요해요.

## 4. 어떻게 꾸준히 하냐면요

꾸준히 하는 법, 두 가지만 기억하면 돼요. //

**첫째, 매일 작게 기록을 남겨요.** 거창하게 말고요. //

처음부터 잘 쓰려고 하면 한 글자도 못 올려요. 그냥 오늘 만든 화면 하나, 오늘 손님한테 들은 말 하나, 오늘 막힌 점 하나. 세 문장이면 충분해요. //

이렇게 만드는 과정을 숨기지 않고 밖에 보여주는 걸 '빌드인퍼블릭'이라고 해요. "공개하면서 만든다"는 뜻이에요. //

7일치 예를 들면 이런 식이에요. 1일차는 내가 보고 있는 손님의 문제, 2일차는 오늘 만든 화면, 3일차는 손님한테 들은 말, 4일차는 막힌 점, 5일차는 고친 점… 7일만 해도 이야깃거리가 쌓여요. //

**둘째, 열 번 유용하고 한 번 알려요.** //

이게 오늘 영상에서 제일 중요한 한 문장이에요. //

갑자기 "저 이거 만들었어요, 써주세요" 하면 사람들이 그냥 지나가요. 그 말은 상대한테 일만 시키는 말이거든요. 읽는 사람이 얻는 게 없어요. //

그래서 먼저 유용한 사람이 되는 거예요. 질문에 답해주고, 내가 겪은 문제를 나눠주고, 도움 되는 얘기를 한 열 번쯤 해요. //

그러다 가끔 한 번, 이렇게요. "저 이런 거 만들었는데, 비슷한 문제 있으면 한번 써보고 어디가 헷갈리는지 알려줄래요?" //

이건 알리는 글이긴 한데, 읽는 사람도 배울 게 있어요. 그래서 광고처럼 덜 보여요. //

비율로 치면 대충 이래요. 만들면서 배운 거 40%, 실험하고 나온 숫자 30%, 제품 이야기 20%, 부탁은 10%. 부탁은 진짜 가끔이에요. //

글재주 없어도 괜찮아요. Claude한테 "내 서비스는 이거고, 손님은 이런 사람이야. 오늘 배운 건 이거고. 광고처럼 안 보이게 짧은 초안 써줘" 하고 시키면 돼요. //

대신 초안 그대로 올리진 말고, 내 말투로 줄여서 고쳐요. AI가 쓴 티가 나면 오히려 신뢰가 떨어지거든요.

## 5. 바이럴은 따라오는 거예요

"한 번 빵 터지면 좋잖아요." 맞아요. 터지면 좋죠. //

근데 터뜨리려고 작정하고 쓴 글은 티가 나요. 그래서 오히려 잘 안 터져요. //

바이럴은 이런 거예요. 매일 꾸준히 쌓다 보면, 그중 하나가 우연히 터지는 거. 매일 올린 50개 중에 하나가 터지는 거지, 딱 하나를 노려서 터지진 않더라고요. //

그러니까 한 방을 노리기보다, 터질 후보를 많이 만들어 두는 게 나아요. 꾸준함이 바이럴의 재료인 거죠. //

그리고 터졌을 때를 위해, "내가 누구고 뭘 만드는 사람인지"가 한눈에 보이게 프로필이랑 기록을 미리 깔아두세요. //

그래야 한 번 터진 게 그냥 흘러가지 않고, 나를 계속 봐주는 사람으로 남아요.

## 6. 이제 첫 1,000원 이야기

자, 여기까지가 '알리기'였어요. 이제 '첫 돈' 얘기. //

이것도 부담 갖지 마세요. 1,000원이어도 괜찮아요. 단돈 천 원이라도, 모르는 사람이 지갑을 여는 그 순간이 진짜 신기하거든요. //

근데 왜 벌써 돈 얘기를 하냐면요. 지난 영상에서 "돈 내고 쓸 것 같아?"를 물었잖아요. //

근데 사람은 다 친절해요. "괜찮으면 쓸 것 같아"라고 말해놓고, 막상 결제창 앞에서는 멈춰요. //

그래서 실제로 돈을 내는 게 훨씬 강한 신호예요. "좋아요"는 백 번도 눌러줘요. 근데 지갑을 여는 건 완전히 달라요. //

좋다고 말한 백 명보다, 진짜 결제한 한 명이 더 많은 걸 알려줘요.

## 7. 가격은 어떻게 정하냐면요

그럼 가격은 얼마로? //

여기서 제일 흔한 실수가, 내 기분으로 정하는 거예요. "내가 이거 만드느라 고생했으니까 이만큼" 하는 거요. //

근데 손님은 내 고생까지 사주진 않아요. 자기 문제가 풀리는 걸 살 뿐이에요. //

그래서 가격은 '대체재'에서 시작해요. 대체재는 손님이 지금 그 문제를 해결하려고 쓰는 다른 방법들이에요. //

경쟁 서비스만 말하는 게 아니라, 직접 손으로 하는 거, 외주 맡기는 거, 이런 것도 다 대체재예요. //

예를 들어 매주 두 시간씩 손으로 하던 일을 내 도구가 10분으로 줄여준다면, 그 두 시간이 가격의 출발점이에요. //

상세페이지를 디자이너한테 맡기면 몇십만 원 드는데, 내 도구가 그걸 대신해준다면 그 외주비가 기준이고요. //

그리고 함정 하나. "아직 부족하니까 싸게 해야지" 하기 쉬운데요. //

너무 싸면 손님이 오히려 의심해요. "이 가격이면 제대로 해주려나? 중간에 사라지는 거 아니야?" 하고요. 미안해서 깎은 가격은 좋은 가격이 아니에요. //

첫 가격은 단순하게 가요. 단건 하나 가격, 아니면 월 하나 가격. 요금제 세 개씩 만들지 마세요. //

손님이 고민할 건 "이 문제를 맡길까 말까" 그거 하나면 돼요. 베이직이냐 프로냐, 그런 거로 머리 쓰게 하지 마세요. //

가격 조사도 혼자 끙끙댈 필요 없어요. Claude한테 "내 손님이 이 문제를 지금 어떻게 해결하는지, 가격이랑 쓰는 시간까지 표로 정리해줘" 하고 시키면 돼요. 마지막에 첫 가격까지 추천해달라고 하고요.

## 8. 결제 버튼 없어도 첫 돈은 받아요

가격 정했으면, 이제 받아야죠. 근데 여기서 많이들 멈춰요. "결제 기능부터 만들어야 하나?" //

안 만들어도 돼요. 결제 페이지 없이, 링크 하나면 첫 돈은 받아요. //

제일 빠른 건 송금 링크예요. 토스나 카카오페이에서, 친구한테 밥값 보내듯이 받는 거요. //

관리 화면에서 상품 이름이랑 가격, 설명만 넣으면 링크가 나와요. 코드 한 줄도 필요 없어요. //

그리고 첫 판매는요, 광고에서 잘 안 나와요. 백 명한테 광고하는 것보다, 딱 맞는 두 명한테 1:1로 제안하는 게 첫 판매에 훨씬 가까워요. //

첫 판매는 노출 싸움이라기보다, 믿음하고 타이밍 싸움이거든요. //

제안하기 전에 하나만 정해요. 내 손님이 개인이냐, 가게나 회사냐. 기준은 간단해요. 누구 지갑에서 돈이 나오느냐. //

개인이면, 지난번 대화를 꺼내요. "지난번에 이거 불편하다고 하셨잖아요, 그거 줄이려고 이렇게 고쳤어요. 이번 주부터 이 가격으로 써볼 수 있게 열어놨는데, 별로면 바로 환불해드릴게요." //

여기서 중요한 건 딱 하나예요. 상대가 했던 말을 내가 기억하고 있다는 거. 그게 매끈한 판매 문구보다 훨씬 세게 와닿아요. //

가게나 회사면, 내가 직접 본 걸 꺼내요. "인스타에서 매주 신메뉴 공지를 손으로 만들어 올리시던데, 제 도구로 하면 메뉴명이랑 사진만 넣으면 초안이 나와요. 2주만 한번 써보실래요?" //

회사는 한 번에 결제보다 2주 시범부터 권해요. 답이 느려도 거절이 아닐 수 있어요. 사장님이 검토 중일 수도 있거든요. 며칠 뒤에 새 소식 한 줄 얹어서 딱 한 번만 더 보내요. //

그리고 거절당해도 괜찮아요. 거절도 데이터예요. //

"비싸서"라고 하면 가격을 다시 보고, "필요 없어서"면 손님이나 문제를 다시 보고, "지금은 아니라서"면 타이밍 문제고요. //

거절은 실패가 아니에요. 다음 가설을 더 뾰족하게 만들어주는 재료예요.

## 9. 부트페이는 팔리고 나서 붙여요

그러다 진짜 팔리기 시작하면, 그때 제대로 된 결제를 붙여요. 순서가 있어요. //

처음엔 송금이나 계좌이체로 손으로 받고요. 좀 더 팔리면 크몽이나 스마트스토어 같은 플랫폼을 쓰고요. //

내 사이트에서 직접 카드 결제를 받고 싶어지면, 그때 'PG'라는 걸 붙여요. //

PG가 뭐냐면, 온라인 결제를 대신 처리해주는 서비스예요. 쇼핑몰에서 결제할 때 뜨는 그 결제창, 그게 PG예요. //

갈아탈 신호는 간단해요. 내 손이 병목이 되는 순간이에요. 입금 확인하느라 늦고, 안내 메시지 복붙하다 틀리고, 환불 처리가 밀리면, 그게 "이제 자동화할 때"라는 신호예요. //

한국은 여기서 살짝 달라요. 해외 글들은 스트라이프라는 걸 많이 권하는데, 한국 카드 결제는 흐름이 좀 달라요. //

카드사 앱으로 넘어가서 인증하고 다시 돌아오고, 네이버페이·카카오페이·토스페이도 많이 쓰고요. 그래서 국내 결제 서비스를 쓰는 게 깔끔해요. //

한국에서는 '부트페이'로 시작하면 편해요. 어떤 PG든 부트페이 하나로 붙일 수 있어서, 나중에 갈아끼울 필요가 없거든요. //

좋은 소식 하나. 이 결제 붙이는 것도 'AI한테 시켜서' 돼요. 지금 우리가 쭉 써온 클로드 코드, 그 창에 그대로요. //

결제 문서를 직접 읽을 필요 없어요. 부트페이 깃허브 주소 하나 주면서 "이 프로젝트에 결제 연동해줘" 하면, AI가 알아서 코드를 붙여줘요. //

근데 딱 하나, 이건 꼭 챙기세요. '서버 검증'이요. //

결제창에 "성공"이라고 떴다고 그냥 끝내면 안 돼요. 내 서버에서 그 결제가 진짜 승인된 게 맞는지 한 번 더 확인해야 해요. //

이게 빠지면, 돈을 안 내고도 낸 척 통과시킬 수 있거든요. //

어렵게 들리죠? 근데 이것도 외울 필요 없어요. AI한테 "결제 성공을 서버에서 다시 검증하는 코드까지 넣어줘. 검증 없이 통과되면 안 돼" 이 한마디면 돼요. //

비용도 잠깐 안심시켜 드리면, 부트페이는 가맹비 없이 시작하고, 붙여두는 것만으로는 돈이 안 나가요. 실제로 결제가 일어날 때만 수수료가 빠져요.

## 10. 오늘 해볼 거

자, 오늘 해볼 거. 부담 없이 딱 세 개만요. 다 못 해도 괜찮아요. //

**하나, 채널 두 개만 골라요.** 내 손님이 있고, 내가 6주는 버틸 수 있는 곳으로요. //

**둘, 가격 하나 정해요.** 단건이든 월이든 하나만. 틀려도 돼요. 첫 가격은 정답이 아니라 실험값이니까요. //

**셋, 송금 링크 하나 만들어서, 딱 맞는 두 명한테 제안 보내요.** 가격이랑 링크, 그리고 "별로면 환불" 같은 부담 빼주는 말 한마디 꼭 넣고요. //

수락이든 거절이든 무응답이든, 짧게 기록만 남기면 돼요. 그것도 다 데이터니까요.

## 11. 마무리 + 다음 영상

오늘 거 정리할게요. //

잘 만들면 알아서 팔린다는 생각에 기대기보다, 볼 사람을 먼저 조금씩 모아두기. 열 번 유용하고 한 번 알리기. 바이럴은 꾸준함 뒤에 따라오는 거. //

첫 돈은 결제 버튼 없이 링크 하나로. 가격은 내 기분 말고 대체재 기준으로. 첫 판매는 광고보다 1:1 제안으로. //

부트페이는 진짜 팔리기 시작하면 그때, 그리고 서버 검증 잊지 말고요. //

다시 말하지만, 오늘 건 보너스였어요. 여기까지 안 와도 정말 괜찮아요. 만들어서 띄워본 것만으로 이미 충분히 멀리 온 거예요. //

다음 영상은 이 시즌의 마지막이에요. 내가 만든 걸 사람들 앞에서 직접 선보이는 '데모나잇'이 뭔지 보여드릴게요. //

그리고 "혼자 여기까지 왔으면 진짜 대단한 건데, 이번엔 마감 정해놓고 같이 해볼 사람?" 하는 챌린지 이야기도 살짝 꺼낼게요. //

부담 갖지 말고, 궁금하면 다음 영상에서 봬요. 오늘도 고맙습니다.

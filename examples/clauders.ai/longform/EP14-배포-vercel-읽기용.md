# [EP14] 읽기용 대본 — 1시간 만에 진짜 주소로 배포하기 (Vercel 전 과정)

> "만들기" 단계의 킬러 영상. 카메라 보고 처음부터 끝까지 읽는 완성 대본. 약 15~18분.
> 핵심: 내 컴퓨터(localhost)를 벗어나 진짜 URL로. 첫 배포는 Vercel + Claude CLI, GitHub 연결. 킬러 장면 = 배포 → URL → 친구한테 카톡 → "이거 진짜 되네?".
> 친절: "로컬에선 되는데 배포 후 안 되면 환경변수부터" 초보 함정 + 요금 걱정 미리 안심.
> 톤: 친절·쉬움·완전 초보 배려. "몰라도 돼요, 천천히." 겁주기·하이프·과장 금지. 비유로 풀어주기.
> docs 근거: build-service/08-deploy.
> 연결: EP13(에러=단서) 한 줄 받기 → EP15(5명한테 보여주고 피드백) 예고.
> `//` = 살짝 쉬는 지점. 그 외엔 자연스럽게 이어서.

## 1. 시작 — 이제 내 컴퓨터 밖으로 나갈 시간이에요

지난 영상에서 우리가 에러랑 친해졌어요. //

빨간 글씨가 떠도 망한 게 아니다, 그건 단서다. 통째로 복사해서 AI한테 주면, 원인이랑 고칠 곳을 같이 찾아준다. 거기까지 해봤어요. //

그래서 지금쯤이면, 내가 만든 게 화면에서 돌아가고 있을 거예요. 버튼도 눌리고, 입력하면 결과도 나오고. //

그런데요, 딱 하나 아쉬운 게 있어요. //

그게 전부 **내 컴퓨터 안에서만** 돌아가요. //

친구한테 "야 나 이거 만들었어" 하고 보여주고 싶은데, 보여줄 방법이 없는 거예요. 내 화면을 직접 보여주거나, 캡처를 찍어 보내는 것 말고는요. //

오늘 우리가 할 일이 바로 그거예요. 내 컴퓨터 안에만 있던 걸, **진짜 인터넷 주소로 꺼내는 것.** //

오늘 영상 끝나면, 이런 순간이 와요. 주소 하나가 생기고, 그걸 친구한테 카톡으로 딱 보내요. 친구가 눌러봐요. 그러면 친구 폰에서 내가 만든 게 진짜로 열려요. //

그 카톡 답장이, 좀 짜릿해요. "어? 이거 AI가 만든 거 맞아? 진짜 되네?" //

겁먹을 거 하나도 없어요. 오늘도 어려운 명령어 외우는 거 아니에요. AI한테 "배포해줘" 하고, 우리가 옆에서 몇 번 눌러주면 돼요. 천천히 같이 가볼게요.

---

## 2. 왜 친구한테는 안 보일까요?

본격적으로 가기 전에, 이거부터 짚고 갈게요. //

왜 내가 만든 건 나만 보이고, 친구는 못 볼까요? //

이게 어려운 컴퓨터 용어 때문에 막막했던 분 많을 거예요. 한번 풀어볼게요. //

지금까지 우리가 만든 걸 확인할 때, 이런 주소를 봤을 거예요. //

```text
localhost:3000
```

이 '로컬호스트'라는 말, 좀 무섭게 생겼죠? 풀면 별거 아니에요. // **'이 컴퓨터'** 라는 뜻이에요. 지금 내가 쓰고 있는, 바로 이 컴퓨터요. //

그러니까 `localhost:3000`은, **"내 컴퓨터 안에서만 열리는 화면"** 이에요. //

집 안에 있는 TV랑 비슷해요. 우리 집 거실에선 잘 나오는데, 옆집 친구는 우리 집 TV를 볼 수 없잖아요. 우리 집 안에만 있으니까요. //

`localhost`가 딱 그거예요. 내 컴퓨터라는 집 안에서만 나오는 화면. //

그래서 친구한테 `localhost:3000` 주소를 그대로 보내봐야, 친구 컴퓨터에선 안 열려요. 친구한테는 '친구 컴퓨터'라는 뜻이 되거든요. //

그럼 어떻게 해야 친구도 볼 수 있냐. //

내 화면을, 누구나 들어올 수 있는 **인터넷 주소**로 옮겨 올려두면 돼요. 우리가 평소에 보는 그런 주소요. //

```text
https://my-service.vercel.app
```

이렇게 생긴 주소요. 이건 우리 집 TV가 아니라, 누구나 채널만 맞추면 볼 수 있는 방송 같은 거예요. 주소만 알면 친구도, 친구의 친구도 들어올 수 있어요. //

이렇게 내 화면을 인터넷 주소로 꺼내서, 누구나 열어볼 수 있게 만드는 일. // 이걸 **'배포'** 라고 불러요. //

용어가 좀 딱딱하죠? 그냥 **"인터넷에 내보내기"** 정도로 생각하시면 돼요. 오늘 우리가 할 게 딱 이거 하나예요.

## 3. 그래서, 어디에 올리면 돼요?

자, 내보내기로 마음먹었어요. 그럼 어디에 올리느냐. //

내 화면을 대신 받아서, 인터넷 주소로 열어주는 회사들이 있어요. 이런 걸 '배포 서비스'라고 해요. //

종류가 꽤 많아요. 버셀, 넷리파이, 클라우드플레어… 이름 들으면 벌써 머리 아프시죠? //

여기서 마음 편하게 하나만 기억하세요. // **처음엔 그거 다 알 필요 없어요.** //

우리처럼 작게 시작하는 사람한테 제일 편한 거, 딱 하나만 고르면 돼요. 그게 **Vercel**, 버셀이에요. //

왜 버셀이냐. 어려운 이유 말고, 우리한테 와닿는 것만 말씀드릴게요. //

**첫째, 무료로 시작할 수 있어요.** // 처음 만들어서 친구 몇 명한테 보여주는 정도는, 돈 한 푼 안 들이고 가능해요. 요금 얘기는 뒤에서 따로 더 안심시켜 드릴게요. //

**둘째, AI랑 같이 쓰기 좋아요.** // Claude한테 "버셀로 배포해줘" 하면, 거의 다 알아서 진행해줘요. 우리가 끼어들 데가 별로 없어요. //

**셋째, 우리가 만든 종류의 웹사이트랑 잘 맞아요.** // 이 채널에서 만드는 그런 화면들, 버셀이랑 궁합이 좋아요. //

그래서 결론은 단순해요. //

```text
처음 만든 웹사이트를 인터넷에 올리고 싶다 → 버셀
```

이거예요. 다른 서비스들은 나중에 필요해지면 그때 보면 돼요. 지금은 버셀 하나로 충분해요. //

이거 몰라도 돼요, 천천히. 지금은 "아, 버셀이라는 데 올리는구나" 정도만 가져가셔도 오늘 영상 절반은 끝난 거예요.

## 4. 배포 전에, GitHub부터 살짝 알고 갈게요

버셀에 올리기 전에, 짝꿍처럼 같이 다니는 게 하나 있어요. **GitHub**, 깃허브예요. //

또 낯선 이름 나왔죠? 천천히 풀게요. //

깃허브는, 쉽게 말하면 **내 코드를 올려두는 인터넷 창고**예요. //

우리가 사진 백업할 때 구글 드라이브에 올려두잖아요. 깃허브가 코드한테는 그 구글 드라이브 같은 거예요. 내가 만든 걸 인터넷 창고에 안전하게 올려두는 거죠. //

그럼 왜 버셀이랑 같이 다니냐. //

버셀이 이 창고를 들여다보거든요. // 내가 깃허브 창고에 새 버전을 올리면, 버셀이 "어, 새 게 올라왔네" 하고 그걸 가져다가 알아서 다시 내보내 줘요. //

이게 왜 좋냐면요. 나중에 뭔가 고치고 싶을 때, 창고에 새로 올리기만 하면 인터넷 주소도 자동으로 바뀌어요. 이건 뒤에서 다시 볼게요. //

지금 우리가 할 일은요. 내가 만든 걸 깃허브 창고에 한 번 올려두는 거예요. //

근데 이것도 손으로 끙끙댈 필요 없어요. Claude한테 그냥 말로 시키면 돼요. //

```text
이 프로젝트를 GitHub에 올려줘.
처음이라서 단계별로 설명하면서 진행해줘.
리포지토리 이름은 my-mvp-service로 해줘.
```

여기서 '리포지토리'는 그냥 **창고 한 칸**이라고 생각하시면 돼요. 내 프로젝트가 들어갈 창고 칸에, 이름을 붙여주는 거예요. //

이렇게 시키면 Claude가 단계별로 안내하면서 올려줘요. 중간에 깃허브 로그인 같은 걸 한 번 해야 할 수도 있는데, 그건 정상이에요. 화면에 나오는 대로 따라가면 돼요. //

혹시 예전에 이미 깃허브에 올린 적 있으면, 이 단계는 건너뛰어도 돼요.

## 5. 진짜 배포 — Claude한테 "버셀로 내보내줘"

자, 창고에 올렸으면 이제 진짜 내보낼 차례예요. 오늘의 핵심 장면이에요. //

방법은 두 가지가 있어요. 하나는 버셀 사이트에 직접 들어가서 마우스로 누르는 방법, 또 하나는 Claude한테 명령으로 시키는 방법이에요. //

우리는 Claude랑 같이 작업하고 있으니까, **Claude한테 시키는 쪽**으로 갈게요. 이게 더 편해요. //

이때 'CLI'라는 말이 나올 텐데요. 또 영어 약자죠? 겁내지 마세요. // 그냥 **검은 창에 명령어로 일을 시키는 방식**이라는 뜻이에요. 우리가 EP3부터 쭉 써온 그 검은 창, 거기서 하는 거예요. 새로 배울 거 없어요. //

Claude한테 이렇게 말해보세요. //

```text
Vercel CLI로 이 프로젝트를 배포해줘.
내가 처음이라서, 단계마다 지금 무엇을 하는지 설명해줘.
인증이 필요하면 내가 해야 할 행동만 알려줘.
배포가 끝나면 마지막에 나온 URL을 알려줘.
```

이렇게 시키면, 보통 이런 순서로 흘러가요. //

```text
1. Claude가 버셀 도구가 깔려 있는지 확인
2. 없으면 알아서 설치
3. 배포 명령 실행
4. "로그인해 주세요" 하고 안내
5. 프로젝트 설정 몇 가지 자동으로 처리
6. 배포 진행
7. 완성된 주소(URL) 출력
```

여기서 딱 한 군데, **우리가 직접 해야 하는 게 있어요.** 바로 4번, 로그인이에요. //

배포 도중에 브라우저가 자동으로 열리거나, 화면에 "여기 눌러서 로그인하세요" 하고 나올 수 있어요. //

이게 에러처럼 보여서 당황하시는 분 많은데요. **전혀 문제 아니에요.** 정상적인 과정이에요. //

생각해보면 당연해요. 인터넷에 내 걸 올리는 거니까, "이거 진짜 네가 맞아?" 하고 한 번 확인하는 거예요. 우리가 어디 가입할 때 본인 확인 하는 거랑 똑같아요. //

그래서 로그인은 사람인 우리가 한 번 해줘야 해요. 한 번만 하면, 그다음부턴 Claude가 이어서 쭉 진행해요. //

자, 그리고 진행하다 보면 'preview'랑 'production'이라는 말이 나올 수 있어요. 이것도 풀어드릴게요. //

```text
preview(프리뷰) = 나 혼자 확인해보는 연습용 주소
production(프로덕션) = 친구한테 보여줄 진짜 대표 주소
```

쉽게 말하면, 프리뷰는 리허설, 프로덕션은 진짜 공연이에요. //

처음엔 이 차이 몰라도 괜찮아요. 친구한테 보여주는 진짜 주소까지 한 번에 내보내고 싶으면, Claude한테 이렇게 한마디만 더 붙이면 돼요. //

```text
Vercel CLI로 production 배포까지 해줘.
환경변수가 빠져 있으면 먼저 확인하고 멈춰줘.
```

뒤에 붙은 '환경변수' 얘기는 잠시 뒤에 자세히 할 거니까, 지금은 그냥 "이렇게 시키면 안전하게 멈춰서 알려주는구나" 정도만 알아두세요.

## 6. 킬러 장면 — 주소가 나왔어요

자, 배포가 끝나면 화면에 이런 주소가 딱 떠요. //

```text
https://my-mvp-service.vercel.app
```

이게요. 방금 우리가 만든, **진짜 인터넷 주소**예요. //

내 컴퓨터 안에만 있던 게, 이제 전 세계 누구나 열어볼 수 있는 주소가 된 거예요. 이거 처음 보면 좀 신기해요. //

근데 친구한테 바로 보내기 전에요. 우리가 먼저 한 번 눌러봐야 해요. //

그 주소를 복사해서, 브라우저 주소창에 붙여넣고 들어가 보세요. 그리고 이걸 체크해보세요. //

```text
첫 화면이 제대로 뜨나?
버튼이 눌리나?
뭔가 입력하면 결과가 나오나?
폰에서도 열어봤을 때 잘 보이나?
```

특히 마지막, **폰으로 한 번 꼭 열어보세요.** // 친구들은 대부분 폰으로 눌러볼 거거든요. 폰에서 깨져 보이면 첫인상이 아쉬워지니까요. //

이 체크리스트도 직접 만들기 귀찮으면, Claude한테 "이 주소에서 확인해야 할 핵심 동작 체크리스트 만들어줘" 하면 우리 프로젝트에 맞게 뽑아줘요. //

자, 여기까지 다 잘 되면요. //

이제 진짜, 친구한테 카톡 보낼 차례예요. //

거창하게 말 안 해도 돼요. 그냥 주소 하나 딱 붙여서, "나 이거 만들었는데 한번 눌러봐" 하고 보내면 끝이에요. //

그러면 잠시 뒤에 답이 와요. //

"어? 진짜 열리네?" // "이거 네가 만든 거야?" // "이거 AI가 만든 거 맞아? 신기하다." //

이 순간을 위해서 우리가 EP3부터 여기까지 온 거예요. //

내 컴퓨터 안에서 나 혼자 보던 게, 처음으로 다른 사람 손에 들어가서 진짜로 작동한 순간. // 이거, 별거 아닌 것 같아도 진짜 큰 한 걸음이에요. //

오늘 영상 보면서 여기까지 오셨으면, 정말 잘하신 거예요.

## 7. 초보 함정 1순위 — "로컬에선 됐는데 배포하니까 안 돼요"

자, 이제 제일 많이들 막히는 데를 미리 짚고 갈게요. //

이거 하나만 알고 가면, 진짜 흔한 함정 하나를 피할 수 있어요. //

배포하고 나서, 이런 일이 생길 수 있어요. //

내 컴퓨터에선 분명히 잘 됐는데, 막상 인터넷 주소로 들어가니까 화면이 깨지거나, 어떤 기능이 안 먹는 거예요. //

이러면 "내가 뭘 잘못했나, 다시 망했나" 싶죠. // 근데 십중팔구, 범인은 하나예요. **'환경변수'** 예요. //

또 어려운 말이죠? 천천히 풀게요. //

우리가 뭔가 만들 때, 가끔 '열쇠' 같은 게 필요해요. // 예를 들어 AI 기능을 쓰려면 'API 키'라는 비밀번호 같은 게 있어야 하고, 데이터를 저장하려면 데이터베이스 주소가 있어야 하고요. //

이런 비밀 값들을, 코드에 그냥 적어두면 위험하니까, **따로 숨겨서 보관해요.** 이렇게 따로 보관하는 비밀 값들을 '환경변수'라고 불러요. //

문제가 여기서 생겨요. //

내가 이 열쇠들을 **내 컴퓨터에만** 넣어뒀거든요. 그러니까 내 컴퓨터에선 당연히 잘 돼요. //

근데 배포한 화면은, 내 컴퓨터에서 도는 게 아니라 **버셀 서버에서** 돌아요. 버셀한테는 그 열쇠를 안 줬어요. //

그러니까 버셀은 문 앞에서 "어, 나 열쇠가 없는데?" 하고 멈추는 거예요. 그래서 로컬에선 되고 배포 후엔 안 되는 거죠. //

해결은 간단해요. **버셀한테도 똑같은 열쇠를 넣어주면** 돼요. //

이것도 Claude한테 물어볼 수 있어요. 어떤 열쇠를 넣어야 하는지부터요. //

```text
이 프로젝트에서 필요한 환경변수를 찾아줘.
내 컴퓨터에 있는 값 중에
Vercel에도 등록해야 하는 값을 목록으로 정리해줘.

단, 비밀 값 자체는 채팅에 출력하지 말고, 이름만 알려줘.
```

마지막 줄, 중요해요. // **비밀 값 자체는 화면에 띄우지 말고 이름만 알려달라**고 하는 거예요. 비밀번호는 어디 적히면 위험하니까, 이름만 확인하고 값은 우리가 직접 넣는 거죠. //

그래서 오늘 딱 하나만 외운다면 이거예요. // **"배포 후에 뭔가 안 되면, 제일 먼저 환경변수를 의심한다."** //

이거 하나 기억하시면, 혼자서도 함정 절반은 피해 가세요.

## 8. 요금 걱정, 미리 풀고 갈게요

여기까지 오면 슬슬 이런 걱정 드시죠. //

"이거 무료라며. 근데 나중에 갑자기 돈 나가는 거 아니야?" //

이 걱정, 너무 당연해요. 그래서 정직하게, 미리 풀고 갈게요. //

먼저 안심되는 얘기부터요. // 우리처럼 처음 만들어서 **친구 다섯 명한테 보여주는 정도는, 무료 범위로 충분해요.** 돈 안 나가요. //

버셀은 'Hobby'라고, 취미용 무료 요금제가 있어요. 처음 시작하는 사람은 여기서 시작하면 돼요. 카드 등록 안 해도 돼요. //

다만, 정직하게 하나 짚을게요. // **"무료로 시작할 수 있다"는 거지, "영원히 무조건 공짜"라는 뜻은 아니에요.** //

이건 겁주려는 게 아니라, 미리 알면 마음이 편해서 말씀드리는 거예요. 이런 경우엔 비용이 생길 수 있어요. //

```text
방문자가 엄청 많아진다
이미지나 영상 파일을 아주 많이 올린다
AI 기능을 굉장히 많이 호출한다
사람들이 많이 써서 사용량이 확 늘어난다
```

보시면 다 **"잘돼서 사람이 몰릴 때"** 생기는 일이에요. // 그러니까 사실 이건 행복한 고민이에요. 그때 가서 유료로 올릴지 보면 돼요. //

참고로 버셀 유료 요금제는, 한 단계 올리면 한 달에 20달러 정도부터 시작해요. // 근데 이건 2026년 봄 기준이고, 요금제는 자주 바뀌어요. 그러니까 실제로 돈 낼 일이 생기면, 그때 버셀 공식 가격 페이지를 한 번 보시는 게 정확해요. //

그리고 더 마음 편한 방법. 배포하기 전에 Claude한테 미리 물어볼 수 있어요. //

```text
이 프로젝트를 Vercel에 배포하려고 해.
지금 기능 기준으로, 비용이 생길 수 있는 부분이 있는지 정리해줘.
친구 5명 테스트에서는 무료 범위로 충분할지도 판단해줘.
```

이렇게 물어보면, 내 프로젝트가 지금 당장 돈 낼 일이 있는지 짚어줘요. //

정리하면 이래요. //

```text
친구 5명한테 보여주기 → 무료로 시작
반응이 좋아서 사람이 늘어남 → 그때 사용량 확인
진짜 많아짐 → 그때 유료 검토
```

지금 단계에서 요금 무서워서 배포를 미룰 이유는 전혀 없어요. 일단 무료로 내보내고, 돈 걱정은 사람이 몰리고 나서 해도 늦지 않아요.

## 9. 배포 후에 고치고 싶으면? (그리고 도메인은 나중에)

배포해서 친구한테 보여줬어요. 그런데 친구가 "여기 오타 있어" 하거나, 내가 봐도 고치고 싶은 데가 생겨요. //

이때가 아까 말한 깃허브랑 버셀 짝꿍이 빛나는 순간이에요. //

흐름이 진짜 단순해요. //

```text
고치고 싶은 걸 Claude한테 수정시킨다
→ 창고(GitHub)에 새로 올린다
→ 버셀이 알아서 새 버전으로 다시 내보낸다
```

내가 버셀에 다시 들어가서 뭘 누를 필요가 없어요. 창고에 올리기만 하면, 같은 주소가 자동으로 최신 버전으로 바뀌어요. //

이것도 Claude한테 한 번에 시킬 수 있어요. //

```text
[고치고 싶은 내용] 고쳐줘.
브라우저에서 확인할 수 있게 실행해보고,
문제 없으면 GitHub에 올려줘.
Vercel 배포가 끝나면 URL에서 확인할 체크리스트도 알려줘.
```

여기서 'commit'이나 'push' 같은 말이 보일 수 있는데요. 이것도 EP12에서 다룬 그 '세이브'랑 같은 식구예요. 그냥 **"고친 걸 창고에 올린다"** 정도로 생각하시면 돼요. 깊게 안 들어가도 돼요. //

혹시 새로 올렸는데 배포가 실패할 때도 있어요. 그래도 당황 마세요. EP13에서 배운 그대로예요. //

버셀이 보여주는 실패 기록, 그걸 통째로 복사해서 Claude한테 주면 돼요. //

```text
Vercel 배포가 실패했어.
아래 기록을 보고 원인을 설명해줘.
최소한으로 고쳐줘.
[기록 붙여넣기]
```

에러는 단서다, 통째로 복사해서 AI한테 준다. 이거 우리 이미 할 줄 알잖아요. //

마지막으로, 한 가지만 미리 안심시켜 드릴게요. //

`my-mvp-service.vercel.app` 같은 주소 보면서, "주소에 vercel이 붙어 있네, 이거 나중에 내 진짜 주소로 바꿀 수 있나?" 싶으실 거예요. //

바꿀 수 있어요. `내서비스.com` 같은 나만의 주소를 붙이는 걸 '도메인 연결'이라고 하는데요. //

근데 이거, **지금 안 해도 돼요.** // 친구 다섯 명한테 보여주는 단계에선, 버셀이 준 기본 주소로 충분해요. 도메인은 서비스가 좀 자리 잡은 다음에, 그때 천천히 붙이면 돼요. //

처음부터 내 도메인 붙이겠다고 거기서 시간 다 쓰지 마세요. 지금은 '일단 내보내서 보여주기'가 백 배 중요해요.

## 10. 마무리 + 다음 영상

자, 오늘 거 정리할게요. //

`localhost`는 내 컴퓨터 안에서만 보이는 화면이라서, 친구한테는 안 보여요. 그래서 우리는 그걸 인터넷 주소로 내보냈어요. 이게 '배포'예요. //

처음 배포는 버셀이 제일 편해요. 무료로 시작할 수 있고, Claude랑도 잘 맞아요. 깃허브라는 창고에 한 번 올려두고, Claude한테 "버셀로 배포해줘" 하면, 로그인 한 번 빼고는 거의 알아서 해줘요. //

그리고 오늘 꼭 가져가실 거 두 개. // 하나, 배포 후에 뭔가 안 되면 **제일 먼저 환경변수를 의심한다.** // 둘, 요금은 사람이 몰리기 전까진 걱정 안 해도 된다. **친구 다섯 명 테스트는 무료로 충분하다.** //

오늘도 보기만 하면 안 바뀌어요. 영상 끄고 나면, 만들어둔 거 아무거나 하나, Claude한테 "버셀로 배포해줘" 하고 시켜보세요. // 주소 하나 받아서 친구한테 카톡 한 번 보내보시는 거예요. 그 "진짜 되네?" 답장 한 번이, 진짜 큰 동기부여가 되거든요. //

자, 그런데요. 친구한테 보여주고 나면, 이게 끝이 아니에요. 오히려 진짜 재밌는 게 여기서부터 시작돼요. //

친구가 "오 신기하다" 하고 넘어가게 두면 안 되거든요. // "이거 또 쓸 것 같아?", "어디가 불편했어?" 이런 진짜 반응을 들어봐야, 내 서비스가 다음 단계로 갈 수 있어요. //

다음 영상이 바로 그거예요. 제목은 **"5명한테 보여주고 피드백 받기"** 예요. //

그냥 "어때?" 하고 묻는 거 말고, 진짜 쓸 만한 피드백을 받는 법. 그리고 아는 사람 말고 모르는 사람한테도 보여줘야 하는 이유까지, 같이 풀어볼게요. //

오늘 진짜 큰 산 하나 넘으셨어요. 내가 만든 게 진짜 주소로 인터넷에 떴잖아요. 그거 아무나 하는 거 아니에요. //

오늘은 그 주소 하나 받아본 걸로 충분해요. 다음 영상에선 친구 반응을 진짜 피드백으로 바꾸는 법을 같이 해볼게요. 그때 봬요.

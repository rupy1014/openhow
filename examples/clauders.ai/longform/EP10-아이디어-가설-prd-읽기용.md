## 1. 시작 — 이제 진짜 '내 걸' 만들 차례예요

지난 영상까지, 우리 꽤 멀리 왔어요. //

작업 환경 만들고, AI 다루는 감 잡고, 지난번엔 내 귀찮은 일 하나를 자동화하는 숙제까지 해봤죠. //

그러니까 '쓰는 법'은 이제 어느 정도 손에 익은 거예요. //

오늘부터는 단계가 하나 바뀌어요. 남이 시키는 걸 따라 하는 게 아니라, 이제 '내 걸' 한번 만들어보는 거예요. //

기억하시죠? 이 채널 로드맵 다섯 칸 중에 네 번째 칸, '만들기'. 드디어 거기 왔어요. //

근데 오늘은 코딩부터 하지 않아요. 화면 만들기는 다음 영상부터예요. 오늘은 그 앞 단계, "그래서 뭘, 왜, 누구를 위해 만들 거냐"를 정리하는 시간이에요. //

이게 제일 안 멋있어 보이는데, 사실 제일 중요한 단계거든요. 천천히 같이 가봐요.

---

## 2. 잠깐, '기획'이라는 말부터 풀고 갈게요

'기획'이라고 하면 좀 부담되시죠? //

뭔가 멋진 기획서를 써야 할 것 같고, 회사에서 보던 두꺼운 문서가 떠오르고. //

그거 몰라도 돼요. 천천히 갈게요. //

오늘 말하는 기획은 그렇게 거창한 게 아니에요. 만들기 전에, 내 생각을 한 번 또렷하게 해보는 거예요. 그게 다예요. //

왜 이걸 하냐면요. AI는 진짜 빠르게 만들어줘요. 근데 내 머릿속이 흐릿한 채로 "알아서 만들어줘" 하면, AI는 빈칸을 자기 마음대로 채워버려요. //

그러면 그럴듯한 게 나오긴 하는데, 내가 원하던 거랑은 미묘하게 다른 게 나와요. //

그래서 만들기 전에 딱 잠깐, 방향만 또렷하게 잡고 가자. 오늘 할 일은 그거예요.

## 3. 제일 흔한 함정부터 알려드릴게요

본격적으로 가기 전에, 초보분들이 제일 많이 빠지는 함정 하나만 짚을게요. //

이런 순서예요. //

좋은 아이디어가 떠올랐다. AI한테 "이거 전체 서비스로 만들어줘" 하고 던진다. 뭔가 나오긴 했다. 근데 이게 누구를 위한 건지, 어디부터 고쳐야 할지 모르겠다. //

이거, AI가 못해서 그런 게 아니에요. 처음에 '뭘 확인하고 싶은지'를 안 좁혀서 그래요. //

여기서 생각의 방향을 살짝 틀어야 해요. //

서비스 만들기는 "내 생각이 맞다"를 증명하는 일이 아니거든요. "이러면 사람들이 좋아할까?"를 작게 만들어서 확인해보는 일이에요. //

이걸 어려운 말로 '린 스타트업'이라고 해요. 용어는 잊으셔도 돼요. 그냥 이 그림만 기억하세요. //

**작게 만든다 → 사람들 반응을 본다 → 그걸로 고친다 → 또 작게 만든다.** //

이 한 바퀴를 계속 빠르게 도는 거예요. //

예전엔 이 한 바퀴 도는 데 몇 달이 걸렸어요. 기획하고, 개발자 구하고, 외주 맡기고. //

근데 지금은 AI 덕분에 그 한 바퀴가 며칠로 줄었어요. 그러니까 더 중요해진 건 "한 번에 완벽하게 만들기"가 아니라, "작게 만들어서 빨리 배우기"예요. //

그래서 오늘은 그 첫 바퀴의 출발점, '가설'을 잡는 거예요.

## 4. 대박 아이디어를, '가설 3줄'로 바꿔요

자, 이제 핵심이에요. //

머릿속 아이디어를 '가설'이라는 걸로 바꿀 거예요. //

'가설'도 어려운 말 같죠? 쉽게 말하면 "이러면 이렇게 될 것 같아"라는 추측이에요. 아직 맞는지 모르니까, 확인해볼 문장. 그게 가설이에요. //

보통 아이디어는 이렇게 흐릿하게 시작해요. //

"영어 공부 앱 만들고 싶어." "쇼핑몰 도구 만들고 싶어." //

이건 아직 '만들고 싶은 것'이지, 가설은 아니에요. //

가설은 이렇게 네 칸으로 쪼개요. //

**누가** 쓸 건지. //
그 사람이 **무슨 문제**를 겪는지. //
그걸 **어떻게** 풀어줄 건지. //
그러면 그 사람이 **무슨 행동**을 할 것 같은지. //

예를 들어볼게요. "영어 공부 앱"을 이렇게 바꾸는 거예요. //

누가 — 출근길에 영어 공부 좀 해보려는 직장인. //
무슨 문제 — 매일 뭘 공부할지 고르는 게 귀찮아서 자꾸 미뤄요. //
어떻게 — 매일 아침에 딱 한 문장이랑 짧은 해설만 보여줘요. //
무슨 행동 — 그러면 일주일 정도는 다시 들어와서 볼 것 같아요. //

이 네 칸을 줄이면 이렇게 세 줄이 돼요. //

"출근길 직장인이, 매일 문장 고르는 게 귀찮아서 공부를 미뤄요. 매일 아침 한 문장만 보여주면, 일주일은 다시 들어올 것 같아요." //

이게 '가설 3줄'이에요. //

쉬워 보이죠? 근데 막상 써보면 은근히 어려워요. 고객은 자꾸 넓어지고, 문제는 내 입장에서만 쓰게 되고, 기대 행동은 "좋아할 것 같아"처럼 흐려지거든요. //

그래서 이건 한 번에 안 나와요. 같은 아이디어를 열 번쯤 다르게 써보는 게 정상이에요. 그게 연습이에요.

## 5. 고객을 좁히는 게 진짜 핵심이에요

네 칸 중에서 제일 중요한 게 첫 칸, '누가'예요. //

초보일수록 여기서 자꾸 이렇게 말해요. //

"이건 모든 직장인이 쓸 수 있어요. 학생도 쓰고, 마케터도 쓰고, 대표도 쓰고." //

그럴 수 있어요. 근데 처음부터 그렇게 잡으면, 아무한테도 정확히 안 꽂혀요. //

좀 좁혀볼게요. //

"영어 공부하는 사람" 말고 → "출근길 10분만 공부하려는 직장인". //
"쇼핑몰 운영자" 말고 → "혼자 스마트스토어에 상품 30개 올리는 1인 셀러". //
"팀장" 말고 → "매주 월요일 회의록 정리하는 다섯 명짜리 팀의 리더". //

훨씬 또렷하죠? //

"좁히면 손님이 줄어드는 거 아니에요?" 하실 수 있는데, 그렇지 않아요. //

처음에 좁히는 건 시장을 포기하는 게 아니라, '누구한테 먼저 보여줄지'를 정하는 거예요. 그 사람이 반응하면, 그다음에 옆 사람으로 넓히면 돼요. //

이렇게 생각하면 쉬워요. 처음부터 100만 명을 상상하지 마세요. 대신 **이걸 매일 써줄 진짜 팬 1,000명은 누구지?** 이걸 상상해보세요. //

신기하게, 그 1,000명을 떠올리는 순간 고객이 확 좁아져요. //

그리고 고객이 좁아지면, 만들 것도 같이 좁아져요. 출근길 직장인이 고객이면, 긴 강의나 커뮤니티나 레벨 시스템 같은 건 일단 다 빼도 되거든요. 아침에 1분 안에 끝나는 경험, 그거 하나만 있으면 돼요.

## 6. 이제 AI랑 '대화'로 PRD 한 장을 만들어요

가설이 잡혔으면, 이걸 'PRD'라는 한 장짜리 문서로 묶을 거예요. //

또 영어 약자 나왔죠? 풀어드릴게요. //

PRD는 Product Requirements Document. 길게 풀면 '제품을 뭘로 만들지 적은 문서'예요. 쉽게는 그냥 **"뭘 만들지 한 장에 정리한 메모"**라고 생각하세요. //

여기서 초보분들이 또 막혀요. 빈 PRD 양식을 딱 펼쳐놓고 "대상 고객은? 핵심 가설은? 시장 진입 전략은?" 이러면 머리가 하얘지거든요. //

그래서 순서를 바꿔요. 양식부터 채우지 말고, **AI랑 먼저 수다부터 떠는 거예요.** //

이렇게 시작하면 돼요. //

"나 출근길에 영어 공부하는 사람들을 위한 서비스를 만들고 싶어. 근데 정확히 뭘 만들지는 모르겠어. 나한테 질문을 하면서, 고객이랑 문제랑 첫 버전 범위를 같이 잡아줘. 아직 코드는 짜지 마." //

여기서 포인트는 "아직 코드는 짜지 마"예요. AI는 시키면 바로 만들려고 하거든요. 지금은 만들 때가 아니라 정리할 때라고 딱 못을 박는 거예요. //

그러면 AI가 거꾸로 질문을 해줘요. //

"이 문제를 제일 자주 겪는 사람이 누구야?" "그 사람은 지금 이걸 어떻게 해결하고 있어?" "하루 중 언제 이 서비스가 필요해?" "첫 버전에 꼭 있어야 하는 기능은 뭐야?" "반대로 없어도 되는 건?" //

이 질문에 하나씩 답하다 보면, 신기하게 내 생각이 정리돼요. //

처음엔 그냥 "영어 공부 앱"이었던 게, 대화하다 보면 "출근길 10분 안에 오늘 문장 하나 보고 완료 체크하는 서비스"처럼 또렷해져요. //

그리고 여기서 한 가지, AI 역할이랑 내 역할이 나뉘어요. //

AI는 방향을 여러 개 제안해줄 수 있어요. "A는 문장 추천, B는 발음 연습, C는 퀴즈." //

근데 그중에 뭘 고를지는, 그건 내가 정해야 해요. "나는 A로 갈게. 발음은 나중에 하고, 첫 버전은 문장 하나랑 해설만 확인할래." //

이 '고르는 일'이 바로 기획이에요. PRD는 AI가 써줄 수 있지만, 무엇을 고를지는 내가 정하는 거예요. //

이렇게 대화로 방향이 어느 정도 잡히면, 그때 이렇게 말해요. //

"지금까지 한 얘기를 바탕으로 prd.md 한 장으로 정리해줘. 서비스 한 줄 설명, 대상 고객, 고객 문제, 핵심 가설, 이번에 만들 기능, 이번에 안 만들 기능, 사용자 흐름, 검증 기준까지 넣어줘. 코드는 아직 짜지 마." //

이렇게 나온 PRD는, 처음부터 "PRD 써줘" 한 거보다 훨씬 좋아요. 왜냐면 내가 이미 대화에서 선택을 다 했으니까요.

## 7. 'MVP'랑 '안 만들 것' — 이게 출시를 살려요

PRD 만들 때 꼭 들어가야 하는 칸이 두 개 있어요. //

하나는 'MVP'. 또 약자죠. Minimum Viable Product. 풀면 '고객한테 보여주고 반응을 볼 수 있는, 가장 작은 첫 버전'이에요. //

작게 만든다는 게 '대충 만든다'는 뜻은 아니에요. 가설 확인에 필요 없는 걸 다 빼는 거예요. //

영어 문장 서비스라면 MVP는 이 정도예요. 오늘 문장 하나 보이고, 짧은 해설 보이고, 완료 버튼 누를 수 있고. 끝. //

로그인, 레벨 시스템, 커뮤니티, 결제, 긴 강의. 이런 건 다 나중으로 미뤄요. //

그래서 두 번째로 중요한 칸이 '안 만들 것' 목록이에요. //

대화하다 보면 기능이 자꾸 늘어나요. "로그인도 있으면 좋겠다, 통계도 있으면 좋겠다, 알림도..." 다 좋아 보이거든요. //

근데 다 넣으면 출시를 못 해요. 만들다 지쳐요. //

그래서 AI한테 이렇게 부탁하세요. "이걸 3일 안에 만들 수 있는 MVP로 줄여줘. 가설 확인에 꼭 필요한 기능이랑, 이번엔 빼도 되는 기능을 나눠줘." //

'안 만들 것'을 적어두는 게, 사실 '만들 것'을 적는 것만큼 중요해요. //

참, 이 단계에서 '와이어프레임'이라는 말도 들으실 거예요. 겁먹지 마세요. 그냥 화면 뼈대예요. 예쁜 디자인 말고, "위에 뭐 있고, 가운데 뭐 있고, 아래 버튼 하나" 이렇게 뭐가 어디 놓이는지만 그린 거예요. 종이에 손으로 그려도 돼요. 오늘은 이런 말이 있다는 것만 알아두면 충분해요.

## 8. 검증 기준은 '감상' 말고 '행동'으로

PRD에서 마지막으로, 제가 제일 강조하고 싶은 칸이에요. //

'검증 기준'. 만들고 나서 "이게 됐는지 안 됐는지 뭘 보고 판단할 거냐"예요. //

여기서 초보분들이 많이 하는 실수가 있어요. 친구한테 보여주고 "어때?"라고 물어보는 거예요. //

그러면 답이 이렇게 와요. "좋네." "깔끔하다." "재밌네." //

고맙긴 한데, 이건 방향을 못 잡아줘요. 다들 예의상 좋다고 해주거든요. //

그래서 검증 기준은 '느낌'이 아니라 '행동'으로 적어야 해요. //

이렇게요. //

"5명한테 링크를 보낸다. 그중 3명 이상이 오늘 문장을 끝까지 본다. 2명 이상이 다음 날 다시 들어온다. 한 명이라도 '이거 매일 보내주면 좋겠다'고 먼저 말한다." //

차이가 느껴지세요? //

"좋아요"는 감상이고, "다시 들어왔다 / 공유했다 / 돈을 냈다"는 행동이에요. 사람은 말로는 좋다고 해도, 행동은 거짓말을 잘 안 하거든요. //

그래서 PRD 받으면 이 칸을 꼭 다시 보세요. 검증 기준이 감상으로 적혀 있으면, AI한테 "이걸 실제 행동으로 바꿔줘"라고 다시 시키면 돼요.

## 9. AI가 준 PRD, 그대로 믿지 말고 한 번 더 봐요

하나만 더요. //

AI가 PRD를 한 장 뚝딱 만들어줘도, 그걸 그대로 믿진 마세요. //

받고 나서 이 질문들로 한 번 훑어보세요. //

고객이 또 너무 넓어지진 않았나? 문제가 진짜 구체적인가? MVP 범위가 너무 크진 않나? '안 만들 것'이 충분히 적혀 있나? 사용자가 쓰는 순서가 다섯 단계 안에 들어오나? 검증 기준이 감상 말고 행동으로 되어 있나? //

이상한 데가 보이면, 바로 고쳐달라고 하면 돼요. //

"고객이 아직 넓어. 출근길 직장인으로 좁혀줘." "MVP가 너무 커. 로그인이랑 통계는 빼줘." //

이렇게 몇 번 주고받으면, 시작하기 충분한 PRD가 돼요. //

그리고 만들기 전에 진짜 마지막으로, 딱 한 번만 더 하면 좋은 게 있어요. 주변 사람한테 말로 해보는 거예요. //

"나 이런 거 생각 중인데. 출근길 직장인이 매일 문장 고르기 귀찮아서 공부 미루잖아. 아침에 한 문장만 보여주면 일주일은 다시 볼 것 같은데. 너라면 써볼 것 같아?" //

이렇게 말해보면 반응이 생각보다 빨리 와요. "별론데?" "그런 거 이미 많지 않아?" "근데 출근길보다 점심에 보면 좋을 듯." //

이 반응, 기분 나빠하지 마세요. 만들기 전에 들은 게 오히려 다행이에요. 코드 한 줄 안 쓰고 가설을 검증한 거니까요.

## 10. 마무리 + 다음 영상

자, 오늘 거 정리할게요. //

오늘은 코딩 한 줄도 안 했어요. 대신 '방향'을 잡았어요. //

대박 아이디어를 가설 세 줄로 바꿨고 — 누가, 무슨 문제, 어떻게, 그래서 무슨 행동. //

고객을 좁혔고, AI랑 대화로 PRD 한 장을 묶었고, 검증 기준을 '감상' 말고 '행동'으로 적었어요. //

그리고 제일 중요한 마음가짐 하나. 처음 가설은 틀려도 돼요. 오히려 빨리 틀린 걸 아는 게 이득이에요. AI가 빠르게 만들어주니까, 틀린 방향으로 오래 가는 것보다 작게 만들어서 빨리 배우는 게 훨씬 나아요. //

이게 아까 말한 그 한 바퀴예요. 작게 만들고, 반응 보고, 고치고, 또 작게 만들고. //

오늘은 그 출발선까지 그은 거예요. 잘하셨어요. //

다음 영상에서는 드디어 화면을 만들어요. "코딩 몰라도 첫 화면 만들기." 식당에 비유하면, 손님이 앉는 자리부터 만들어보는 거예요. "자기소개 페이지 만들어줘" 한 줄로 5분 뒤에 화면이 뜨는 거, 같이 해볼게요. //

오늘 정한 가설 세 줄, 메모장에 꼭 적어두세요. 그게 다음 영상에서 진짜 화면이 되는 첫 재료예요. 거기서 만나요.

# [EP15] 읽기용 대본 — 5명한테 보여주고 피드백 받기 (+ PMF 감)

> 단계 4(만들기)의 피드백·검증 편. 배포까지 끝낸 사람에게 "이제 사람한테 보여줄 차례"를 손잡고 알려주는 완성 대본. 약 12~15분.
> 톤: 친절·쉬움·완전 초보 배려. "몰라도 돼요, 천천히." 겁주기·하이프·과장·사기훅 금지. 비유로 풀어주기.

## 1. 시작 — URL은 생겼는데, 이제 뭐 하죠?

지난 영상에서, 우리 드디어 진짜 주소를 만들었어요. //

내 컴퓨터 안에만 있던 게, 인터넷에 떠서, 친구한테 링크로 보낼 수 있게 됐죠. `vercel` 한 줄 치고, 주소 복사해서, 카톡으로 톡 보내고. 그 순간 좀 짜릿했을 거예요. //

근데 막상 링크를 만들고 나면, 이상하게 손이 멈춰요. //

"이걸 누구한테 보내지?" "보내서 뭐라고 하지?" "별로라고 하면 어떡하지?" //

오늘은 딱 그 다음 한 걸음을 같이 갈 거예요. 만든 걸 사람한테 보여주고, 진짜 피드백을 받는 법. 그리고 요즘 다들 말하는 그 'PMF'라는 게 대체 뭔지. 어려운 말 다 풀어서 천천히 갈게요.

## 2. 먼저, 안심부터 시켜드릴게요

본론 들어가기 전에, 하나만 짚고 갈게요. //

지금까지는 'AI가 도와주는 일'이 많았어요. 화면 만들기, 에러 고치기, 배포하기. 그거 다 AI가 옆에서 거의 다 해줬죠. //

근데 오늘부터 하는 건, AI가 대신 못 해주는 영역이에요. 누가 쓸지, 왜 쓸지, 어떤 걸 좋아할지. 이건 사람이 직접 보고 듣고 판단해야 하는 거거든요. //

그래서 이 단계가, 솔직히 제일 오래 걸려요. 코드 짜는 것보다 더요. //

근데 그게 정상이에요. 못해서가 아니라, 원래 여기가 제일 사람 일이라 그래요. 그러니까 "왜 이건 빨리 안 끝나지?" 싶어도, 몰라도 돼요. 천천히 가면 돼요. 오늘 그 길을 같이 그려볼게요.

## 3. 왜 굳이 보여줘야 하냐면요

만든 사람은요, 자기 걸 객관적으로 못 봐요. //

혼자 만들면 "이거 좋을 거야"라고 자꾸 착각하게 돼요. 내가 만들었으니까, 어디를 어떻게 눌러야 하는지 다 알거든요. //

근데 다른 사람한테 딱 보여주면, 그때 진짜가 나와요. "어, 이거 어디 눌러?" "이게 무슨 뜻이야?" "어… 잘 모르겠는데?" //

이게 아프지만, 제일 중요한 정보예요. //

그리고 한 가지만 분명히 할게요. 피드백은 칭찬받으려고 하는 게 아니에요. //

내 서비스를 누가 좋아하는지, 어떤 사람한테 맞는지, 그걸 배우려고 하는 거예요. //

생각해보세요. 6개월 동안 혼자 만들었는데 아무도 안 쓰는 거랑, 1주 만에 "아, 이 방향이 틀렸구나" 아는 거랑. 어느 쪽이 나아요? 당연히 후자죠. 일찍 알수록 덜 아파요.

## 4. 근데 요즘은 기준이 좀 높아졌어요

여기서 솔직하게 하나 말씀드릴게요. 겁주려는 거 아니에요. 미리 알면 마음이 편해지는 얘기예요. //

몇 년 전만 해도, "AI로 뭔가 만들었어"라고 보여주면 사람들이 "오, 이게 돼? 네가 만들었어? 대단하다" 했어요. //

근데 지금은요, 사람들이 챗GPT도 매일 쓰고, 클로드도 쓰고, 토스도 쓰고, 배달앱도 써요. 잘 만든 걸 매일 보고 살아요. //

그래서 반응이 좀 달라졌어요. 옛날엔 "오, 돌아가네?" 였다면, 지금은 "이거 왜 이렇게 느려?" "글이 왜 이렇게 딱딱해?" 이렇게 나와요. //

이게 나쁜 소식처럼 들릴 수도 있는데, 사실 좋은 소식이에요. 사람들이 솔직하게 반응해준다는 뜻이거든요. 그 반응이 우리한테는 다 힌트예요.

## 5. 누구한테 보여줘요? — 딱 5명이면 돼요

자, 그럼 누구한테 보여주냐. //

복잡한 분석 도구 깔 필요 없어요. 방문자 숫자 보는 대시보드 같은 거, 지금은 안 해도 돼요. //

그냥 사람 5명. 5명한테 직접 보여주고 직접 물어보는 게 먼저예요. //

근데 아무 5명이 아니에요. **내 가설에 맞는 5명**이어야 해요. //

이게 무슨 말이냐면. 예를 들어 내가 '출근길에 영어 공부하고 싶은 직장인'을 위한 앱을 만들었다? 그럼 진짜 그런 직장인한테 보여줘야 해요. 영어 관심 없는 사람한테 보여주면, "음… 난 잘 모르겠어" 하고 끝나요. 그건 내 손님이 아니니까요. //

그리고 한 가지 더. 5명 전부 친한 사람이면 안 돼요. //

최소 2명은 나를 모르는 사람이어야 해요. //

왜냐면 친구나 가족은요, 나 기분 안 상하게 하려고 칭찬을 해줘요. 이걸 '칭찬 편향'이라고 해요. 좋게 말해주는 거죠. 고맙긴 한데, 그건 진짜 시장 반응이 아니에요. //

나를 모르는 사람은, 잘 보이려고 할 이유가 없어요. 그래서 더 솔직해요. 그 솔직한 반응이, 진짜 손님들의 반응에 훨씬 가까워요. (모르는 사람을 어디서 데려오냐고요? 그건 다음 영상에서 따로 다룰게요.)

## 6. 뭐라고 물어봐요? — "어때?" 말고 "또 쓸 것 같아?"

이게 오늘 영상에서 제일 중요한 부분이에요. //

대부분 사람들이 이렇게 물어봐요. "어때? 한번 봐줘." //

근데 "어때?"라고 물으면, 답은 거의 정해져 있어요. "오, 좋은데?" "잘 만들었네." //

기분은 좋죠. 근데 이건 거의 정보가 없어요. //

그래서 질문을 살짝 바꿔야 해요. 두 가지만 기억하세요. //

**첫째, 보낼 때 "솔직하게"를 꼭 넣어요.** //

이렇게요. "나 이런 걸 작게 만들어봤어. 1분만 써보고, 솔직하게 말해줘." //

이 '솔직하게' 한 단어가 진짜 중요해요. 이게 없으면 "좋아~"만 와요. 있으면 "음, 솔직히 여기가 좀…" 하고 진짜가 나와요. //

**둘째, "또 쓸 것 같아?"를 물어봐요.** //

"어땠어?"는 그냥 감상이에요. 우리가 진짜 알고 싶은 건 이거예요. //

"이거, 네 상황에서 또 쓸 것 같아?" //

"비슷한 게 있으면, 이걸 쓸 것 같아, 아니면 그걸 쓸 것 같아?" //

"이건 어떤 사람한테 맞고, 어떤 사람한테는 안 맞을 것 같아?" //

이 질문들이 왜 좋냐면요. 그냥 칭찬으로는 답을 못 해요. 진짜 자기 입장에서 생각해야 답이 나오거든요. 그 답 안에, 내가 배워야 할 게 다 들어 있어요. //

그리고 들은 건 꼭 적어두세요. 거창하게 말고요. //

"지현이는 첫 화면은 바로 알겠는데 입력이 귀찮았대." "민수는 본인은 안 쓸 것 같은데, 매일 루틴 짜는 사람은 좋아할 거래." 이 정도면 충분해요. //

정리하기 귀찮으면, 모은 피드백을 AI한테 던져도 돼요. "이 피드백들 정리해줘. 공통된 불만이 뭔지, 다음에 뭘 고쳐야 할지 같이. 코드는 짜지 말고." 이러면 깔끔하게 묶어줘요.

## 7. 피드백 받으면 제일 하기 쉬운 실수

자, 피드백을 받았어요. 그럼 이제 고쳐야겠죠. //

근데 여기서 거의 모든 사람이 똑같은 실수를 해요. //

피드백을 받으면, 자꾸 '기능을 추가'하고 싶어져요. //

"아, 결제 기능도 넣어야 하나?" "다크모드도 있으면 좋겠는데?" "로그인도 만들까?" //

이게 함정이에요. //

왜냐면 기능 추가는, 사실 좀 도망가는 거거든요. 새 기능 만드는 건 재밌고, 뭔가 하는 것 같으니까요. //

근데 사람들이 진짜 한 말은 보통 이런 거예요. "응답이 좀 느려." "첫 화면이 허전해." "이 글이 무슨 말인지 모르겠어." //

그럼 새 기능 말고, 이미 있는 걸 다듬어야 해요. //

느리다고 했으면 속도부터. 허전하다고 했으면 첫 화면 디자인부터. 문구가 어렵다고 했으면 말부터 쉽게. //

하나를 제대로 좋게 만드는 게, 열 개를 대충 붙이는 것보다 훨씬 나아요. //

아, 그리고 팁 하나. 피드백이 사람마다 다 다르면 헷갈리죠? 기준은 간단해요. 5명 중에 3명 넘게 같은 말을 하면, 그건 진짜예요. 한 명만 한 말은 일단 흘려도 돼요.

## 8. PMF가 대체 뭐예요? — 세 단어로 끝내요

자, 이제 그 유명한 단어들 한번 정리하고 갈게요. MVP, MLP, PMF. //

이거 영어 약자라 처음 보면 무섭게 생겼는데, 뜻은 진짜 단순해요. 세 개를 한 줄로 묶어볼게요. //

**MVP는, "이거 작동하나?"예요.** //

가설을 확인할 수 있는 가장 작은 버전. 예쁘지 않아도 되고, 기능 많을 필요도 없어요. 그냥 "이 문제가 진짜 있나? 사람들이 반응하나?"를 확인할 딱 그만큼이에요. 우리가 지난 영상들에서 만든 게 이거예요. //

**MLP는, "이거 또 쓰고 싶나?"예요.** //

여기서 L이 'Lovable', 좋아할 만한, 이런 뜻이에요. 작아도, 한번 써보고 "오, 이거 괜찮은데?" 소리가 나오는 버전이요. //

이것도 기능이 많다는 뜻이 전혀 아니에요. 오히려 반대예요. 기능은 적어도 되는데, 첫 경험 하나가 좋아야 해요. 첫 화면에서 뭘 할지 바로 알겠고, 결과가 내 상황에 맞고, 다시 들어와볼 마음이 드는. 그 정도요. //

**PMF는, "맞는 손님을 찾았나?"예요.** //

PMF는 'Product-Market Fit', 제품이랑 시장이 딱 맞아떨어진 상태예요. 쉽게 말하면, **내 걸 진짜로 필요로 하는 손님들을 찾은 상태**요. //

PMF가 있으면, 억지로 설명 안 해도 사람들이 알아서 돌아와요. 없으면, 기능을 아무리 추가해도 반응이 미지근해요. //

그러니까 순서가 이래요. 작게 만들어서 작동시키고(MVP), 그걸 다시 쓰고 싶게 다듬고(MLP), 그러면서 맞는 손님을 찾아가는 것(PMF). 우리는 지금 그 길 위에 있는 거예요.

## 9. PMF, 어떻게 아냐면요 — 다시 돌아오는지를 봐요

그럼 "내가 맞는 길로 가고 있나?"는 어떻게 알까요. //

제일 흔한 착각이 이거예요. 사람들이 "좋아요" "잘 만들었네요" 해주면, "오, 됐다!" 하는 거. //

근데 칭찬은요, 신호가 약해요. 말은 쉽거든요. //

진짜 신호는 따로 있어요. 사람들이 **다시 돌아오느냐**예요. 이걸 어려운 말로 '리텐션'이라고 해요. 남아 있는 비율이라는 뜻이에요. //

생각해보면 당연해요. 처음 한 번 써보는 건 그냥 호기심이에요. 신기해서요. //

근데 두 번째로 다시 들어온다? 그건 필요해서예요. //

그래서 숫자도 이렇게 봐야 해요. //

100명이 가입했는데 2주 뒤에 5명만 남았다? 이건 좀 위험한 신호예요. //

반대로 30명이 가입했는데 2주 뒤에도 15명이 계속 쓴다? 이게 훨씬 좋은 거예요. //

가입자 숫자가 중요한 게 아니라, 돌아오는 비율이 중요해요. //

물어보는 것도 좋아요. "이 서비스가 내일 갑자기 없어지면 어떨 것 같아?" 여기서 "어, 좀 아쉬울 것 같은데?"라는 사람이 늘어나면, 좋은 신호예요. //

그리고 꼭 돈만 신호인 건 아니에요. 사람이 자기 시간을 쓰고, 자기 데이터를 넣어보고, 주변에 얘기해주고. 이런 것도 다 "이거 나한테 쓸모 있어"라는 신호예요. 돈은 그중에 제일 센 신호고요.

## 10. 처음부터 100만 명 안 노려도 돼요

마지막으로, 마음 편해지는 얘기 하나 할게요. //

뭔가 만들면, 자꾸 "100만 명이 써야지!" 이런 그림을 그리게 돼요. //

근데 그거, 처음부터 노리는 거 아니에요. //

'1,000명의 진짜 팬'이라는 얘기가 있어요. 진짜 팬은, 네가 만드는 걸 계속 쓰고, 거기에 돈이나 시간을 쓰고, 주변에 말해주는 사람이에요. //

이런 진짜 팬이 1,000명만 있어도, 한 사람당 한 달에 만 원이면 한 달에 천만 원이에요. 혼자 하는 서비스로도 충분한 거죠. //

근데 그 1,000명도 한 번에 오는 게 아니에요. 순서가 있어요. //

먼저 5명. 이 5명이 진짜 좋아하면, 그게 시작이에요. 그다음 50명, 그다음 500명, 그렇게 천천히요. //

그러니까 지금 우리가 5명한테 보여주는 거, 이거 작은 일 아니에요. 천 명으로 가는 그 첫 칸이에요. //

100만 명이 한 번 써보고 떠나는 것보다, 1,000명이 계속 돌아오는 게 훨씬 좋은 거예요. 우리는 그 '계속 돌아오는 소수'부터 찾는 거예요.

## 11. 마무리 + 다음 영상

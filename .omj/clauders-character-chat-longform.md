# 캐릭터 AI 챗 빌드얼롱 통 영상 대본

## Why

clauders.ai `docs/` 커리큘럼은 4주 기수제 **강의용**이다. 챕터 단위로 쪼개져 있고 평어로 쓰였다. 유튜브는 별개 산출물이 필요하다.

기존 유튜브 자산은 두 종류인데 둘 다 "커리큘럼 순서 그대로 쪼갠 것"이다.

- `longform/EP1~17` — 챕터를 15~18분씩 나눈 정주행 시리즈. 한 편만 보면 완결 경험이 없고, 매 편이 다음 편 예고로 닫힌다.
- `shorts/` 104개 — 발견용 단답.

유튜브에서 실제로 도는 건 **하나를 처음부터 끝까지 만드는 통 영상**이다. 부트페이 `손글씨-따라하기.md`가 검증된 포맷을 보여준다: 가입 → 연동 → 서버승인 → 취소 → 웹훅 → 실결제 → 운영을 한 사이클로 완주하고, 개념 설명을 먼저 하지 않고 실행하는 지점에서 짧게 끼워 넣는다.

소재는 캐릭터 AI 챗이다. `_drafts/.../10-캐릭터-AI-챗-만들기.md`가 이미 "첫 프로젝트로 최적"인 이유를 논증해뒀다 — **성과가 빨리 보이는데 배울 것도 많다.** 입력창·응답·캐릭터 성격·화면·배포가 다 걸린다.

그래서 캐릭터챗 하나를 관통 소재로 삼아, `build-service` 커리큘럼(아이디어 → PRD → 기술 → 프론트/백 → Git → 디버깅 → 배포 → 피드백 → 모객 → 첫 결제)을 **한 편으로 취합한다.**

- [validated] 실제 화면 순서대로 따라하는 구성 — 개념 전용 챕터를 두지 않고 실행 지점에서 짧게 설명 → **metric: 14개 챕터 전부 "지금 무엇을 한다"로 열림, 개념 전용 챕터 0개**
- [validated] 캐릭터챗 한 사이클 완주 12구간: MVP 자르기 → 캐릭터 설명문 → PRD 한 장 → 화면(목업) → Git 첫 커밋 → LLM API + 키 숨기기 → 톤 튜닝 루프 → 에러 디버깅 → Vercel 배포 → 지인 피드백 → 스레드 모객 → 결제 링크 첫 돈 → **metric: 전 구간 존재, 복붙 프롬프트 30개 (챕터당 1~4개)**
- [validated] "AI가 구현하고 사람이 확인한다" 구조 — 사람이 직접 챙길 포인트를 실행 지점에서 짚음 → **metric: 확인 지점 4개 (범위 자르기·캐릭터 설명문·API 키 숨기기·돈 받기 전 약속), 13장이 넷을 다시 묶음**
- [validated] 톤은 채널 규칙 그대로: 해요체, 완전 초보, 친절 → **metric: 나레이션 평어 종결 0건 (코드 블록 내 AI 지시 프롬프트는 반말 유지 — EP11 관례), 겁주기·하이프 훅 0건**
- [validated] 낭독 리듬은 EP 시리즈가 아니라 부트페이 통대본 쪽 — 문장을 연결어미로 잇고 2~4문장을 한 문단으로 → **metric: `//` 쉬는 지점 표시 0개, 프로즈 문단 236개 중 한 문장 문단 18개(챕터당 1.3개, 전부 열거·강조 자리)**
- [validated] 촬영 노트 포함 → **metric: 데모 환경·콜드오픈 소재·B롤·자막 키워드·TTS 발음·길이 조절·UI 변동 화면·리스크 5개 항목 존재**

## Not

- 촬영용 데모 앱 코드는 이번에 만들지 않는다. 촬영할 때 실제로 만들면서 녹화한다.
- `longform/EP1~17` 시리즈를 수정하거나 대체하지 않는다. 이 영상은 시리즈 밖 단독편이다.
- 다음편 예고, 시리즈 사다리 CTA를 넣지 않는다.
- 챌린지 판매를 전면에 내세우지 않는다. 담백한 1회 CTA만.
- PG 실연동(부트페이 가맹 심사·웹훅·서버승인)까지 가지 않는다. `12-pg-bootpay.md`의 원칙대로 "결제 링크로 첫 돈 받기"까지다.

## Learnings

### 2026-07-09: seed created (iteration 1)
- **Background**: 커리큘럼은 강의용으로 두고, 유튜브는 캐릭터챗 하나를 처음부터 끝까지 만드는 단독 통 영상으로 간다.
- **사용자 결정 3건**: (1) EP1~17 시리즈와 별개인 단독 자기완결 영상 — 시리즈 대체 아님. (2) 완주 범위는 배포를 넘어 **첫 결제**까지 (모객·결제 링크 포함, 50분+ 감수). (3) 데모 앱 코드는 이번 범위 밖 — 대본만.
- **포맷 판단**: 레퍼런스가 "실촬영 흐름이니 임의로 바꾸지 말 것"을 명시할 만큼 화면 순서 충실도가 핵심. 캐릭터챗 대본도 같은 규율을 따른다 — 개념은 실행 지점에서만.
- **톤 충돌 해소**: 레퍼런스는 합니다체, 채널 규칙은 해요체. 채널 규칙이 이긴다 (`기획-유튜브-전략.md` §2).

### 2026-07-09: 대본 완성 (iteration 1)
- **집필 방식**: 뼈대(비트시트)를 먼저 확정하고 3막을 서브에이전트 병렬로 집필한 뒤 합쳤다. 각 에이전트에게 EP11을 톤 정답지, 부트페이 대본을 포맷 정답지로 먼저 정독시킨 게 톤 일관성의 결정적 요인. 코드가 아니라 톤이 생명인 산문이라 Codex 대신 콘텐츠 에이전트로 위임했다.
- **뼈대에서 바꾼 것 하나**: Git 커밋을 커리큘럼 순서(06, 프론트엔드 뒤)가 아니라 **첫 화면 직후**로 당겼다. 8장 에러 챕터에서 "3번 룰 → 정상 커밋으로 되돌리기"를 하려면 그 앞에 돌아갈 지점이 있어야 한다. 커리큘럼은 챕터 독립이지만 빌드얼롱은 화면 상태가 연속이라 순서가 달라진다.
- **이음새 결함 2건 (합칠 때 발견)**: (1) 9장(배포)이 "오늘 마지막으로"라고 닫아 뒤의 피드백·모객·결제 챕터와 충돌 → "이제"로 교체. (2) 2막에만 챕터 안쪽 `---` 구분선이 들어가 챕터 경계처럼 보임 → 제거. 병렬 집필의 전형적 비용이라 다음에도 스티치 단계를 빼면 안 된다.
- **파는 것의 정직한 정의**: 캐릭터챗 구독을 파는 건 비현실적이라, 스레드 댓글("나도 내 캐릭터 갖고 싶다")의 그 사람에게 **캐릭터챗을 만들어주는 일**을 1~3만 원에 파는 것으로 고정했다. `12-pg-bootpay.md`의 "먼저 팔고, 팔리면 PG" 원칙과 4주 안 실현 가능성을 둘 다 만족하는 유일한 경로.
- **검증**: 나레이션 평어 0건 / 시리즈 의존 표현 0건 (grep 3건은 전부 오탐 — 헤더의 자기 지시문 1건, 사업 모델 단어 '구독' 2건) / 복붙 프롬프트 30개 / 확인 지점 4개 / 촬영 노트 존재.

### 2026-07-09: [signal] 리듬 퇴고 — 톤 정답지와 포맷 정답지를 섞으면 안 된다
- **Signal**: 사용자가 초고를 보고 "왜 이상한 `//` 이런게 들어가있지? 문장간 구조가 너무 짧은데".
- **원인**: 톤 정답지(`EP11-읽기용.md`)의 관례를 포맷 정답지(부트페이 `손글씨-따라하기.md`)에 그대로 옮겼다. EP 시리즈는 **한 문장 = 한 문단 + 끝에 `//`(쉬는 지점)** 라는 낭독 표기를 쓰는데, 부트페이 통대본에는 `//` 가 없고 문장을 연결어미로 길게 이어 2~4문장을 한 문단으로 묶는다. 15분짜리 편에서는 EP 리듬이 맞지만 50분 통 영상에서는 계속 톡톡 끊긴다.
- **규칙**: 서브에이전트에 정답지를 둘 이상 줄 때, **어느 정답지에서 무엇을 가져오는지를 항목별로 못박아야 한다.** "EP11=톤, 부트페이=포맷"만 말하면 표기 관례가 톤 쪽에서 새어 나온다. `//` 같은 표기는 "가져오지 말 것" 목록에 명시.
- **수정**: `//` 278개 제거, 프로즈 문단 321 → 236개, 한 문장 문단은 열거·강조 자리 18개만 남김. 복붙 프롬프트 30개는 글자 단위로 보존 확인. 961줄 → 785줄.
- **부수 발견**: 이 리포의 마크다운 포매터가 연속 `>` 블록인용 줄과 문단 안 soft line break 를 한 줄로 합친다. 헤더는 블록인용 대신 불릿 리스트로, 본문은 문단 하나 = 한 줄로 써야 안정적이다.

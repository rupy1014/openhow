# creator-platform — AX 전문 지식 공간 + 구독자 모으기

## Why

openhow가 DAU/MAU를 쌓으려면 콘텐츠 공급이 운영자 혼자의 몫이면 안 된다. **AX(AI Experience) — AI 사용법, AX 사례, AI 자동화 노하우** 에 집중하는 전문 사이트로, 작가가 자기만의 지식 공간에서 쉽게 쓰고 발행하면 무료 콘텐츠는 메인에 큐레이션되고, 발행자는 자기 구독자를 모으는 구조. 유료 전환은 작가 재량. 형식은 발행자가 정하고, openhow는 쓰기 도구 + 구독자 연결만 제공한다.

## Context

- **기존 인프라**: workspace `blog` 타입이 이미 개인 블로그 역할 가능. 소유자(ownerId), 공개 설정(defaultAccessLevel: public), 커스텀 도메인, 결제(Bootpay) 모두 워크스페이스 단위로 구현됨.
- **현재 갭**: 워크스페이스 생성이 "플랫폼 관리" 느낌. 가입 → "내 공간 만들기" 흐름이 아님. 메인 홈은 운영자가 만든 워크스페이스만 노출.
- **public-blog-home 연동**: 현재 홈은 공개 워크스페이스를 모아 보여주는 구조. 여기에 유저 발행 콘텐츠가 큐레이션되면 UGC 피드가 됨.
- **maily.so 레퍼런스**: 개인 뉴스레터 공간 + 구독자 모으기 + 플랫폼 홈에서 발행자 발견. 핵심은 "발행자 = 가입자"라는 낮은 진입장벽.
- **톤 유도 전략 — AX 큐레이션**: 플랫폼이 AX만 허용하는 건 아님. 누구나 아무 주제로 쓸 수 있지만, 메인 홈 노출은 AX(AI 사용법, AX 사례, 자동화 노하우) 콘텐츠 위주로 큐레이션. "AX 쓰면 메인 탄다" → 작가가 알아서 맞추는 인센티브 구조. 앱스토어 에디터스 초이스와 같은 원리.
- **차별점 — "지식 정리소"**: maily.so는 뉴스레터 특화. openhow는 형식을 강제하지 않음. 오픈클로 매뉴얼(docs), GitHub 정리(wiki), 블로그(blog), 강의 노트(course) 등 — 기존 워크스페이스 타입(7종)이 발행자가 고르는 "포맷"이 됨. 쓰는 사람이 용도를 정한다.
- **작가의 발행 동기**: 무료로 왜 쓰냐 → 자기 브랜딩 + 구독자 모으기 + **`나@openhow.kr`로 구독자에게 직접 도달**. 웹에 글 올리는 건 어디서든 되지만, 이메일 발송이 포함되면 플랫폼에 묶이는 이유가 생김. 유료로 하고 싶으면 Bootpay로 바로 전환 가능.
- **수익 모델과의 관계**: 발행자가 유료 콘텐츠를 설정하면 자체 구독 수익 가능(Bootpay 인프라 있음). 무료 콘텐츠는 메인 노출로 DAU 기여. 플랫폼은 트래픽+수수료 모델 가능.
- **DAU 퍼널 내 위치**: 유튜브(발견) → openhow 홈(큐레이션된 UGC 읽기) → "나도 써볼까"(발행자 전환) → 발행자의 구독자 = openhow DAU
- **기술적 제약**: 워크스페이스 slug 유니크, 문서는 R2 저장, 접근 제어는 document.accessLevel로 이미 동작. 큰 구조 변경 없이 확장 가능.
- **리스크**: UGC 품질 관리 — 아무나 쓰면 메인 품질이 떨어질 수 있음. 큐레이션 정책 필요.

## What

- [ ] **온보딩 리뉴얼**: 프로필(username, 소개) → 공간 포맷 선택 → 첫 글쓰기 직행. "워크스페이스 관리자"가 아니라 "작가"로 시작.
- [ ] **작가 프로필 페이지 `/s/{username}`**: 프로필 헤더 + 내 공간 목록(워크스페이스 카드) + 최근 발행 글 + 구독 버튼/구독자 수. 여러 워크스페이스를 하나의 작가 정체성으로 묶음.
- [ ] **구독(팔로우) 모델**: 작가 단위 구독. 독자가 작가를 구독하면 새 글 알림. 구독자 수 = 작가의 핵심 지표.
- [ ] **메인 홈 큐레이션 확장**: public-blog-home에 UGC 섹션 추가 — 에디터 픽(AX 위주), 인기 글, 새로운 공간, 최신 글. 무료 공개 콘텐츠만 메인 노출 대상.
- [ ] **큐레이션 정책**: 누구나 가입하고 아무 주제로 쓸 수 있지만, 메인 홈 노출은 AX 콘텐츠 위주로 운영자가 큐레이션. 비노출 콘텐츠도 작가 공간 + SEO로 접근 가능. 초기엔 수동 에디터 픽.
- [ ] **user 스키마 확장**: username(유니크), bio, avatarUrl 추가. subscription 테이블 신규.
- [ ] **이메일 발송**: 글 발행 시 `{username}@openhow.kr`로 구독자에게 자동 발송. Resend API + CF Workers. 작가가 플랫폼에서 글 쓰는 핵심 이유.

## Not

- 발행자 간 협업/공동 편집 (기존 team 워크스페이스 영역)
- ~~뉴스레터 이메일 발송~~ → **1차로 승격** (작가가 플랫폼에 묶이는 핵심 이유)
- 발행자에게 요금 부과 (공급을 막으면 안 됨. 돈은 독자에게서)
- 발행자 수익 분배/정산 시스템 (Bootpay 직접 연동은 있으나 플랫폼 수수료 모델은 후순위)
- 기존 운영자 워크스페이스(vibe-coding 등) 구조 변경
- 초대제/승인제 (누구나 쓸 수 있되, 메인 노출만 큐레이션으로 품질 관리)

## Learnings

### 2026-04-15: seed 생성
- **배경**: DAU/MAU 중심 퍼널 논의에서 "콘텐츠 공급 확장" 필요성 도출. 운영자 혼자 콘텐츠를 만드는 구조로는 DAU 엔진이 안 돌아감.
- **핵심 인사이트**: 현재 workspace blog 타입이 기술적으로 개인 블로그 역할 가능. 구조 변경 아닌 UX 리포지셔닝 + 큐레이션 레이어 추가가 핵심.
- **maily.so 참조**: 발행자 진입장벽 최소화 + 구독자 모으기가 발행 동기 + 플랫폼 홈이 발견 채널

### 2026-04-15: 방향 구체화 — "지식 정리소"
- **유저 피드백**: 블로그/뉴스레터로 한정하지 말고, "자기만의 지식 정리소"가 핵심. 오픈클로 매뉴얼이든 GitHub 정리든 뭐든.
- **배운 것**: 기존 워크스페이스 7개 타입(blog/docs/wiki/course/book/team/project)이 "발행자가 고르는 포맷"으로 자연스럽게 매핑됨. 새 타입을 만들 필요 없이, 진입 UX와 포지셔닝만 바꾸면 됨.
- **maily.so와의 차별점**: maily.so = 뉴스레터 특화, openhow = 형식 자유. "쉽게 쓰고 구독자 모으기"는 같되, 쓰는 형태를 강제하지 않음.

### 2026-04-15: 니치 → 큐레이션 톤으로 전환
- **초기 방향**: AX 전문 사이트로 니치를 강제
- **문제**: 작가가 AX 안 쓰겠다면 강제할 방법 없음
- **결정**: 플랫폼은 열어두되, 메인 노출을 AX 위주로 큐레이션. "AX 쓰면 메인 탄다" 인센티브로 톤 유도. 앱스토어 에디터스 초이스와 같은 원리.
- **효과**: 
  - 작가 자유도 유지 (공급 안 막힘)
  - 메인 홈 품질/톤 운영자가 컨트롤
  - 비AX 콘텐츠도 작가 공간 + SEO로 살아있음
- **의도 변경**: Context/What에서 "AX 전문"을 "AX 큐레이션"으로 수정

### 2026-04-15: 품질 정책 결정 — "누구나 쓰되, 메인은 큐레이션"
- **고민**: 발행자에게 돈을 받을지, 무분별하게 받고 싶지 않은 것
- **검토한 옵션**: 초대제 / 신청승인 / 오픈+큐레이션 / 클로더즈 한정
- **결정**: 오픈+큐레이션(3번). 누구나 가입해서 쓸 수 있지만, 메인 홈 노출은 운영자가 고른다.
- **발행자 과금 안 함**: 공급을 막으면 DAU 엔진이 안 돌아감. 돈은 독자 쪽에서 나오는 구조.
- **의도 변경**: What의 UGC 품질 정책을 "큐레이션 정책"으로 구체화. Not에 초대제/승인제/발행자 과금 추가.

### 2026-04-15: maily.so UX 분석 — openhow 적용안
- **시도**: maily.so 홈 + explore 페이지 구조 분석
- **maily.so 홈 구조**:
  - 🎉 새로운 뉴스레터 — 신규 발행자 프로필 카드 (수평 스크롤)
  - 💌 추천 뉴스레터 — 에디터 픽, 큰 카드 + 소개문
  - 🔥 인기있는 레터 — 인기 포스트 (조회수, 날짜, 저자)
  - 👋 새로운 레터 — 최신 포스트 피드
  - 태그 검색
- **maily.so 핵심 패턴**:
  - URL: `maily.so/{username}` (발행자 홈), `maily.so/{username}/posts/{id}` (개별 글)
  - 가입 = 이메일 인증 한 줄. 별도 온보딩 없음.
  - "멤버십" 뱃지 = 유료 콘텐츠. 무료와 유료가 같은 피드에 섞임.
  - SEO 100점 강조 — 검색 유입이 발행자의 핵심 성장 채널
  - 수익화: 유료 멤버십, 콘텐츠 개별 판매, 커피 후원
- **openhow에 적용할 것**:
  - 홈 큐레이션 섹션 구조 (새 공간 / 추천 / 인기 글 / 최신 글) — public-blog-home 확장
  - `openhow.kr/{slug}` = 발행자 공간 (이미 워크스페이스 slug으로 동작)
  - 무료 콘텐츠 → 메인 노출, 유료 → 발행자 공간 내에서만 접근
  - 구독 버튼 + 구독자 수 노출
- **openhow가 가져갈 것 (maily.so)**:
  - 이메일 발송 (`{username}@openhow.kr` → 구독자). 작가가 플랫폼에 묶이는 핵심 가치.
  - Resend API 기반. 초기 무료(100건/일), 스케일 시 $20/월 50K건.
  - DNS: openhow.kr에 SPF/DKIM/DMARC 설정 (Cloudflare).
- **openhow가 안 가져갈 것**:
  - 발송량 과금 (maily 수익원이지만 openhow는 발행자 무료. 스케일 비용은 플랫폼 부담)
  - A/B 테스트, 구독자 그룹 관리, 발송 예약 (이메일 마케팅 도구 영역, 과잉)
  - 발행자 플랜 과금 (베이직/브랜딩/마케팅 3단)
  - AI 채팅
  - 뉴스레터 특화 에디터 (Plate.js가 충분)
- **핵심 차이점 정리**:

  | | maily.so | openhow |
  |--|---------|---------|
  | 형식 | 뉴스레터 only | 블로그/매뉴얼/위키/코스/북 자유 선택 |
  | 배포 | 이메일 발송 + 웹 아카이브 | 웹 퍼스트 (SEO + 메인 큐레이션) |
  | 발행자 동기 | 구독자에게 이메일 보내기 | 지식 정리 + 구독자 모으기 |
  | 수익화 | 멤버십/개별판매/후원 | Bootpay 결제 인프라 (이미 있음) |
  | 타겟 | 뉴스레터 발행자 | AI/개발/지식 정리하는 사람 |

## UX 스토리보드

### 현재 흐름 (AS-IS)
```
비로그인 → PublicBlogHome (운영자 워크스페이스만 노출)
로그인 → WorkspaceHub (내 워크스페이스 카드 그리드)
         └→ 첫 로그인: Onboarding (타입 선택 → 이름 → 대시보드)
         └→ 기존 유저: 워크스페이스 카드 클릭 → /dashboard/{slug}
```
**문제**: "워크스페이스 관리자" 느낌. 작가/발행자 정체성 없음. 프로필 개념 없음. 독자가 작가를 발견/구독할 경로 없음.

### 새 흐름 (TO-BE) — 4개 핵심 여정

#### 여정 1: 독자가 콘텐츠를 발견하고 작가를 구독한다

```
openhow.kr (메인 홈)
├── 히어로: 에디터 픽 (AX 큐레이션)
├── "인기 글" — 조회수 기반 포스트 카드
├── "새로운 공간" — 신규 작가 프로필 카드 (수평 스크롤)
├── "최신 글" — 전체 공개 포스트 피드
└── 태그/카테고리 필터

    ↓ 포스트 클릭

/d/{workspace}/{doc-slug} (아티클 읽기)
├── 본문
├── 작가 프로필 카드 (하단) — 이름, 소개, 구독 버튼, 구독자 수
├── "이 작가의 다른 글"
└── 구독 버튼 → (비로그인이면 로그인 유도)

    ↓ 작가 이름 클릭

/s/{username} (작가 프로필 페이지) ← 신규
├── 프로필 헤더 (이름, 소개, 구독자 수, 구독 버튼)
├── 내 공간 목록 (워크스페이스 카드들)
│   ├── "바이브코딩 매뉴얼" (docs, 12편)
│   ├── "AI 자동화 블로그" (blog, 최신 3편 미리보기)
│   └── "프롬프트 레시피북" (book, 8장)
└── 최근 발행 글 (전체 워크스페이스 통합)
```

**핵심**: `/s/{username}`이 작가의 "홈". 여러 워크스페이스를 하나의 작가 정체성으로 묶음.

#### 여정 2: 새 유저가 가입하고 첫 글을 쓴다

```
메인 홈 → "글쓰기 시작" CTA (또는 로그인 후)
    ↓
가입 (이메일/구글/깃허브) — 현재와 동일
    ↓
첫 방문 온보딩 (리뉴얼)
├── Step 1: 프로필 설정 ← 신규
│   ├── 이름 (가입 시 입력한 것 프리필)
│   ├── 한 줄 소개
│   └── username 설정 → /s/{username} 미리보기
├── Step 2: 첫 공간 만들기
│   ├── "어떤 형태로 쓸까요?"
│   ├── 블로그 / 매뉴얼(docs) / 강의노트(course) / 위키 — 비주얼 카드
│   └── 공간 이름 입력
└── Step 3: 바로 글쓰기
    └── 에디터 페이지로 직행 (빈 문서 + "첫 글을 써보세요")
```

**변경점**: 기존 온보딩에 "프로필 설정" 스텝 추가. 워크스페이스보다 "나"를 먼저 설정.

#### 여정 3: 작가가 새 공간을 추가하고 관리한다


### 여정 5: 독자가 작가 공간에서 구독한다 (maily.so 레퍼런스)

```
/s/{username} 또는 /w/{workspace-slug} (작가 공간)
├── 상단: 구독 폼
│   ├── 비로그인: "이메일로 구독" (이메일 입력 → 가입+구독 한번에)
│   └── 로그인: "구독하기" 버튼 1클릭
├── 작가 프로필
│   ├── 이름, 소개
│   ├── 글 수 | 구독자 수 ← maily.so 핵심 지표
│   └── 응원하기 (후원, 후순위)
├── 카테고리 탭 (워크스페이스 타입에 따라 다름)
│   ├── blog: 카테고리별 필터 (전체 / 카테고리1 / 카테고리2)
│   ├── docs: 섹션별 목차
│   └── course: 챕터 순서
├── 태그 클라우드 (해시태그 필터)
└── 글 목록 (카드 리스트, 날짜·조회수·댓글수)
```

**maily.so에서 배운 점**:
- 구독 폼이 페이지 최상단 + 글 사이사이에 반복 노출 → 전환율 극대화
- 카테고리 탭으로 콘텐츠 분류 → openhow에서는 워크스페이스 타입이 이 역할
- 글 수 + 구독자 수가 작가 신뢰도 지표
- "커피 보내기" 같은 소액 후원 → 유료 멤버십 전 단계 수익화

#### 여정 6: 개별 글 읽기 경험 (maily.so 포스트 페이지)

```
├── 본문
```

**openhow 적용 포인트**:
- 유료 콘텐츠 잠금 UI: 본문 일부 공개 → "구독하면 읽기" (freeSections 인프라 이미 있음)

### maily.so에서 안 가져갈 것 (재확인)

- **이메일 발송 인프라** — maily.so의 핵심이자 수익원 (발송량 과금). openhow는 웹 퍼스트.
- **발행자 과금 (플랜 체계)** — maily.so는 베이직/브랜딩/마케팅 3단계. openhow는 발행자 무료.
- **A/B 테스트, 발송 예약, 구독자 그룹** — 이메일 마케팅 도구. 불필요.
- **AI 채팅 (구독자와 대화)** — 나중에 검토, 1차 아님.

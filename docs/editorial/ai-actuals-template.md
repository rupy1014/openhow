# AI 신기능 follow-along 아티클 템플릿

> 이 템플릿은 **`contentType: tutorial`** 글을 쓸 때 그대로 복붙해서 채우는 편집 규격이다.
> 유튜브가 "이게 뭐다"까지라면, openhow는 **"그래서 그대로 따라하면 된다"**를 책임진다.
> 각 섹션 순서는 고정. 생략 금지. 빈 섹션은 "해당 없음"이라고 쓸지언정 삭제하지 않는다.

---

## 쓰기 전 체크 (인레이크 소스맵)

작성 시작 전 **아래 소스를 최소 3개 이상** 확인하고 본문 `## 소스`에 인용한다.

- [ ] 공식 릴리즈노트 / changelog
- [ ] 공식 블로그·문서 (벤더 1차 자료)
- [ ] 관련 영상 1~2개 (있으면, 없어도 OK)
- [ ] 커뮤니티 시그널 — GitHub issue / Reddit / X / Discord 스레드
- [ ] **실제 실행 로그** (필수) — 이게 빠지면 유튜브와 같아진다

---

## 프런트매터 (frontmatter)

기존 `gpters-seo-flywheel`의 메타 위에 **재현성 4필드**와 **성숙도 스테이지**를 얹는다. 스키마 변경 없이 frontmatter 자유 필드로 기록.

```yaml
---
title: "{기능명} 써봤다 — {한 줄 가치}"
description: "30초 데모 + 따라하기 + 써먹을 시나리오 3"
contentType: tutorial              # gpters-seo-flywheel 표준
ctaType: waitlist                  # none | waitlist | course | apply
topicTags: ["claude-code", "agent", "cli"]   # 3~5개

# --- 재현성 필드 (이 템플릿의 핵심 차별점) ---
maturity: stabilizing              # shipping-soon | stabilizing | decided
verifiedAt: 2026-04-17             # 글쓴이가 실제로 돌려본 날짜
envVersion:                        # 재현 환경 — 도구+버전
  claude-code: "2.1.4"
  node: "22.3.0"
  os: "macOS 15.3"
runtimeSec: 420                    # 전체 따라하기 대략 소요(초)
failureModes:                      # 중간에 걸리기 쉬운 지점 (2~5개)
  - "Node 20 미만에서는 X 명령이 실패"
  - "로그인 미완료 상태에서 Y 단계 진입 시 무한 대기"
---
```

### 성숙도 라벨 (본문 상단 배지)

| 라벨 | 언제 쓰나 | 다음 단계로 언제 승격 |
|------|----------|---------------------|
| **`shipping-soon`** | 릴리즈 직후 ~72시간, 버그·API 변화 잦음 | 주요 이슈 해소 + 72시간 경과 → `stabilizing` |
| **`stabilizing`** | 72시간 ~ 2주, 일부 엣지케이스 불안정 | 핵심 시나리오 3개가 안정 재현 → `decided` |
| **`decided`** | 결론 굳음, "이 기능은 이렇게 쓴다" 확정 | (재승격 없음 — 큰 변화 생기면 새 글) |

원칙: **"살짝 느리게"는 의도된 속도다.** 가능하면 `stabilizing` 단계에서 집필 시작, `decided` 로 올라올 때 재편집해 최종본.

## 본문 고정 섹션 (순서 고정)

### 1) TL;DR (3줄 이내)

- 이 기능으로 **무엇이 달라지나**
- 누구한테 지금 **써먹을 만한가** (사용자 조건)
- 못 쓰는 상황 한 줄 (솔직하게)

> **작성 지침**: 이 글을 다 읽지 않을 독자가 여기서 판단하고 떠나도 손해 없게 쓴다.

---

### 2) 30초 데모

- **GIF 1~2개** 또는 **명령어 → 출력** 한 쌍
- 캡션 두 줄 이내 — "이게 되는 거다" 확신만 주면 됨

> **작성 지침**: 여기가 유튜브 대체 지점. 말 대신 결과를 보여준다.

---

### 3) 사전조건 (Prerequisites)

체크박스 리스트. **"이거 안 깔려있으면 멈춘다"**만 기록. 부드러운 권장 사항은 뺀다.

```markdown
- [ ] Node.js 20 이상 (`node --version`)
- [ ] `claude-code` 2.1.0 이상 설치
- [ ] Anthropic API 키 발급 + `ANTHROPIC_API_KEY` 환경변수
```

> **작성 지침**: 각 항목 옆에 **확인 명령어**를 적어서 독자가 자기 상태를 셀프 체크 가능하게.

---

### 4) 그대로 따라하기 (Step-by-step)

**복붙 가능한 명령/입력/출력**이 핵심. 서술체로 풀어쓰지 말고, 블록 단위로.

```markdown
#### Step 1. {한 줄 행동}

명령:
```bash
claude-code --flag value
```

예상 출력:
```
[2026-04-17 12:00:01] Initialized workspace: ai-actuals
```

**확인 포인트**: `Initialized workspace` 라인이 나와야 정상. 안 나오면 → failureModes #1 참조.
```

각 step은 **명령 → 예상 출력 → 확인 포인트** 3단 반복. 독자가 출력을 비교해서 틀렸는지 바로 알 수 있게.

> **작성 지침**: 자기가 돌린 실제 로그를 복붙하되, 개인 경로·토큰은 마스킹. "이 정도는 알겠지" 가정 금지.

---

### 5) 써먹을 시나리오 3

단순 예시 아니다. **"독자의 일에 어떻게 꽂히나"**를 3개 각도로.

```markdown
#### 시나리오 A — {사용자 유형}의 {상황}
- 언제: ...
- 기존엔: ...
- 이 기능으로: ...
- 기대 효과: ...

#### 시나리오 B — ...
#### 시나리오 C — ...
```

> **작성 지침**: 본인이 실제로 써먹을 상황 1개, 주변 동료 상황 1개, 책 독자/동료 퍼소나 상황 1개 — 이렇게 섞으면 다양성 확보된다. 전부 자기 얘기면 시야 좁음.

---

### 6) 한계·대안

**솔직하게**. 유튜브가 안 하는 부분이 여기. 신뢰도를 여기서 번다.

- 지금 버전에서 안 되는 것 (구체적으로)
- 되지만 불안정한 것
- 다른 도구·방법이 더 나은 상황
- 알려진 이슈 링크 (GitHub issue 번호 등)

> **작성 지침**: "완벽합니다"로 끝나는 글은 2주 뒤 거짓말이 된다. 약점을 먼저 공개하면 수명이 길어진다.

---

### 7) 소스

인레이크 체크리스트에서 확인한 소스를 링크로. 최소 3개.

```markdown
- [공식 릴리즈노트 v2.1.4](https://...)
- [공식 블로그 — 기능 설명](https://...)
- [유튜브 — xxx 채널 리뷰](https://...) (11:30~15:00 구간 참고)
- GitHub issue #1234 — failureMode #2 관련
- 내 실행 로그: `examples/runs/2026-04-17-feature-x.log` (이 저장소 내)
```

> **작성 지침**: 독자가 "이 글 쓴 사람 얼마나 돌려봤나"를 여기서 가늠한다. 소스가 부실하면 전체가 부실해 보임.

## 작성 후 셀프 체크

발행 전 **반드시** 확인:

- [ ] 재현성 4필드 (`verifiedAt`, `envVersion`, `runtimeSec`, `failureModes`) 모두 채움
- [ ] 성숙도 라벨 명시, 현재 단계와 일치
- [ ] 본문 7개 섹션 순서 그대로, 생략 없음
- [ ] "그대로 따라하기" 전 step을 **새 터미널/새 폴더에서 한 번 더 돌려봄** (verifiedAt 갱신)
- [ ] 한계·대안 섹션이 "완벽합니다"로 끝나지 않음
- [ ] 소스 3개 이상, 실행 로그 포함

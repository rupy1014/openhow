# 용어 사전

**모르는 말이 나왔다고 창 닫지 마세요. 여기서 찾으면 돼요.**

- 전부 외울 필요 **없어.** 나올 때마다 한 번씩 찾아보면 저절로 익어요.
- 브라우저에서 `Ctrl + F` (맥은 `⌘ + F`) 누르고 단어를 치면 바로 찾아져요.
- 주제별로 묶어놨어요. 오른쪽 목차에서 골라도 되고.
- 맨 아래 **「나중에 봐도 되는 말」** 은 지금 안 봐도 돼요. 이 자료실엔 거의 안 나오는 말이에요.

그리고 제일 중요한 거 하나. **여기 없는 말이 나오면 AI한테 그냥 물어봐도 돼요.**

```text
지금 나온 "배포"라는 말이 뭔지 초등학생도 알아듣게 설명해줘.
```

## 컴퓨터 기본

내 컴퓨터를 다룰 때 나오는 말들이에요. 자세히는 [💻 컴퓨터 기초](/computer-basics/files-and-folders) 에서 다뤄요.
### 개발자 도구 (Developer Tools)

브라우저에서 `F12` 누르면 옆에 뜨는 창이에요. 만든 웹페이지가 이상할 때 여기서 빨간 에러를 확인해요.

### 경로 (Path)

파일이 어느 폴더 안에 있는지 적은 주소예요.

`내프로젝트/자료/조사내용.md` 처럼 슬래시로 이어져요. 주소에서 시·구·동 나누는 거랑 같아요.

### 디렉토리 (Directory)

폴더랑 똑같은 말이에요. 마우스로 보면 폴더, 명령어로 다루면 디렉토리라고 부를 뿐이에요.

### 로그 (Log)

프로그램이 돌면서 남기는 일지예요. "몇 시에 시작했고, 뭘 했고, 성공했는지 실패했는지"가 적혀요. 문제 생기면 여기부터 봐요.

### 로컬 (Local)

내 컴퓨터를 말해요. "로컬에서 돌아간다" = "내 컴퓨터에서만 된다". 반대는 서버나 클라우드예요.

### 마크다운 (Markdown)

글자 파일인데 기호 몇 개로 제목이랑 목록을 표시하는 형식이에요.

`#` 이 제목, `-` 가 목록, `**` 가 굵게요. 앞으로 제일 많이 보게 될 형식이에요.

### 명령어 (Command)

터미널에 치는 지시예요.

`cd`, `ls`, `npm`, `claude` 같은 것들. 외울 필요 없어, AI가 알려줘요.

### 셸 스크립트 (Shell Script)

터미널 명령어를 파일에 모아둔 거예요. 명령어 네 개를 하나씩 치는 대신 파일 하나 실행하면 순서대로 다 돌아가요.

### 스크립트 (Script)

컴퓨터가 순서대로 실행하는 명령 모음이에요. "이거 하고, 저거 하고, 마지막에 이거 해" 같은 레시피라고 보면 돼요.

### 에디터 (Editor)

글이나 코드를 쓰는 프로그램이에요. 메모장의 고급 버전. VS Code 가 대표적이에요.

### 에러 (Error)

프로그램이 돌다가 문제가 생긴 거예요. **고장이 아니라 컴퓨터가 말을 거는 거야.** 그 문장을 그대로 복사해서 AI한테 주면 돼요.

### 익스텐션 (Extension)

VS Code 에 기능을 추가하는 부품이에요. Claude Code 익스텐션을 깔면 터미널 대신 채팅 패널로 쓸 수 있어요.

### 터미널 (Terminal)

컴퓨터한테 마우스 대신 글자로 시키는 창이에요. 맥은 터미널 앱, 윈도우는 PowerShell. VS Code 안에도 들어 있어요.

### 파일 확장자 (File Extension)

파일 이름 뒤에 붙는 `.md`, `.jpg` 같은 꼬리표예요. 이 파일이 어떤 종류인지 알려줘요. 컴퓨터는 이걸 보고 뭘로 열지 정해요.

### alias (별칭)

긴 명령어에 짧은 이름을 붙여둔 거예요.

`dsclaude` 가 `claude --dangerously-skip-permissions` 의 alias 예요.

### CLI (Command Line Interface)

글자로 명령해서 컴퓨터를 다루는 방식이에요. 주방에 직접 말로 주문하는 쪽. 반대는 GUI.

### CSV

엑셀처럼 표 데이터를 담는 파일이에요. 쉼표로 칸을 나눠요. 엑셀에서도 열리고 프로그램도 읽기 쉬워요.

### GUI (Graphic User Interface)

마우스로 클릭해서 컴퓨터를 다루는 방식이에요. 메뉴판 보고 주문하는 쪽. 우리가 평소 쓰는 그 화면이에요.

### IDE (통합 개발 환경)

편집기 + 터미널 + 파일 목록이 한 화면에 다 있는 작업실이에요. VS Code 가 대표적이에요.

### JSON (제이슨)

설정값이나 데이터를 담는 형식이에요.

`{ "이름": "홍길동", "나이": 30 }` 이렇게 생겼어요. 중괄호랑 따옴표가 많으면 대개 이거예요.

### VS Code

제일 많이 쓰는 무료 코드 편집 프로그램이에요.

Visual Studio Code 의 줄임말. 앞으로 계속 켜두게 될 작업실이에요.

## AI 기본

AI가 어떻게 동작하는지에 대한 말들이에요. 자세히는 [🧠 AI 기초](/ai-basics/what-is-ai) 에서 다뤄요.

### 메모리 (Memory)

파일에 적어둔 장기 기억이에요. 대화는 창을 닫으면 날아가지만, 파일에 적어두면 다음에도 읽어요. `CLAUDE.md` 가 대표적이에요.

### 모델 (Model)

AI 제품 안에 들어 있는 두뇌예요. Claude(제품) 안에 Opus·Sonnet·Haiku(모델)가 있어요. 똑똑할수록 느리고 비싸요.

### 세션 (Session)

AI와의 대화 한 판이에요. 터미널 창 하나가 세션 하나예요. 창을 닫으면 그 대화는 끝나요.

### 소크라테스 질문법

답을 시키는 대신 **질문을 시키는** 방식이에요. "글 써줘" 대신 "잘 쓰려면 뭘 알아야 하는지 나한테 물어봐" 라고 하는 거죠. 결과가 확 달라져요.

### 컨텍스트 (Context)

AI가 지금 보고 있는 내용 전부예요. 대화 내역, 읽은 파일, 지침이 다 들어가요. 짧게 말하면 AI의 단기 기억이에요.

### 컨텍스트 오염

한 대화에 서로 다른 주제가 섞여서 AI가 헷갈리는 상태예요. 쇼핑몰 작업하다가 갑자기 블로그 얘기를 꺼내면 둘을 섞어버려요. 주제가 바뀌면 새 창을 열어요.

### 컨텍스트 윈도우 (Context Window)

AI가 한 번에 볼 수 있는 양이에요. 책상 위에 서류를 쌓는 거랑 같아요. 너무 쌓이면 맨 밑에 있는 건 안 보여요.

### 컴팩트 (/compact)

길어진 대화를 AI가 요약해서 압축하는 기능이에요. 느려지고 비싸지기 시작하면 `/compact` 라고 쳐요. 60~70% 줄여줘요.

### 프롬프트 (Prompt)

AI한테 하는 말이에요. 요청, 지시. "프롬프트를 잘 짜야 한다" = "AI한테 말을 잘 해야 한다".

### 프롬프트 엔지니어링 (Prompt Engineering)

AI한테 말을 잘 하는 기술이에요. 같은 걸 물어도 어떻게 묻느냐에 따라 결과가 달라져요. `CLAUDE.md` 쓰는 것도 여기 들어가요.

### Hallucination (할루시네이션)

AI가 없는 걸 있는 것처럼 말하는 거예요. 거짓말할 의도가 있는 게 아니라, 그럴듯한 패턴을 만들어내는 거예요. 그래서 항상 확인이 필요해요.

### LLM (Large Language Model)

대규모 언어 모델. ChatGPT나 Claude 같은 AI의 기반 기술이에요. 엄청난 양의 글을 학습해서 "이런 말 다음엔 보통 이런 말이 오더라"를 아는 거예요.

### Token (토큰)

AI가 글을 세는 단위예요. 그리고 이게 곧 돈이에요.

한글 1글자가 대략 1~2 토큰. 대화가 길어질수록 매번 다시 읽어서 비싸져요.

## Claude Code와 자동화

Claude Code 를 쓰면서 나오는 말들이에요. 자세히는 [⚡ Claude Code 시작](/claude-code/why-cli) 과 [🤖 업무 자동화](/automation/four-features) 에서 다뤄요.

### 병렬 처리 (Parallel Processing)

여러 작업을 동시에 돌려서 시간을 줄이는 방식이에요. 뉴스 10개를 하나씩 요약하면 느리지만, 동시에 돌리면 빨라요.

### 체인 (Chain)

앞 단계 결과를 다음 단계가 이어받는 방식이에요. 수집 → 걸러내기 → 요약 → 발송처럼 줄줄이 이어지는 흐름이죠.

### 커스텀 커맨드 (Custom Commands)

Claude Code 에서 만드는 나만의 명령어예요.

`.claude/commands/` 폴더에 파일을 두면 `/내명령어` 로 부를 수 있어요. 자주 하는 일의 단축키예요.

### 파이프라인 (Pipeline)

작업을 순서대로 연결해둔 거예요. 공장 조립 라인처럼 앞 단계가 끝나면 다음으로 넘어가요.

### 플랜 모드 (Plan Mode)

바로 실행하지 않고 계획만 세우게 하는 모드예요.

`Shift + Tab` 으로 켜요. 계획을 보고 나서 실행시키면 헛수고가 줄어들어요.

### Agent (에이전트)

특정 일을 맡기는 담당자예요. "이 문서는 이 담당자가 본다"처럼 역할을 나눠두는 거죠. 담당자마다 새 메모장을 받아서 남의 대화에 안 휘둘려요.

### Claude Code

터미널에서 Claude 와 일하는 도구예요. 대화만 하는 게 아니라 내 폴더의 파일을 직접 읽고, 만들고, 고치고, 명령어까지 실행해요.

### CLAUDE.md

Claude Code 한테 이 프로젝트를 설명해두는 파일이에요. 프로젝트 폴더에 두면 알아서 읽어요. "이 프로젝트는 이렇게 작업해줘" 하는 업무매뉴얼이에요.

### dsclaude

`claude --dangerously-skip-permissions` 의 단축 명령어예요.

파일 고칠 때마다 확인을 안 물어봐서 빨라요. 설치 스크립트가 같이 등록해줘요.

### Hook (훅)

특정 순간에 자동으로 실행되게 걸어두는 장치예요. "파일 저장할 때마다 검사해" 같은 걸 사람이 기억 안 해도 되게 만들어요.

### MCP (Model Context Protocol)

AI한테 "손"을 달아주는 규격이에요. 기본 Claude Code 는 내 컴퓨터 안에서만 놀아요. MCP 를 꽂으면 Slack·Notion 같은 바깥 서비스도 다뤄요.

### MCP 서버

MCP 로 연결하는 바깥 도구 하나하나예요. 파일시스템, 브라우저, 데이터베이스 같은 것들. 명령어 한 줄로 붙여요.

### Skills (스킬)

Claude 가 상황을 보고 알아서 꺼내 쓰는 능력이에요. 커스텀 커맨드는 내가 부르지만, 스킬은 AI가 필요할 때 스스로 꺼내 써요.

### Sub-agent (서브 에이전트)

담당자가 부리는 또 다른 작은 담당자예요.

큰 일을 쪼개서 나눠 맡길 때 생겨요. 각자 자기 메모장만 봐요.

## 웹과 서비스 만들기

서비스를 만들 때 나오는 말들이에요. 자세히는 [🛠️ 서비스 만들기](/build-service/overview) 에서 다뤄요.

### 데이터베이스 (Database, DB)

데이터를 정리해서 쌓아두는 창고예요. 엑셀 시트가 여러 장 있는 거라고 보면 돼요. "나중에 다시 봐야 하는 정보"가 생기면 붙여요.

### 디펜던시 (Dependency)

내 프로그램이 돌아가려면 필요한 다른 프로그램들이에요.

`npm install` 하면 이것들이 우르르 설치돼요.

### 라이브러리 (Library)

남이 미리 만들어둔 기능 묶음이에요. 매번 처음부터 안 만들고 가져다 써요. 조립용 부품이라고 보면 돼요.

### 반응형 (Responsive)

화면 크기에 따라 배치가 자동으로 바뀌는 디자인이에요. PC 에서는 넓게, 폰에서는 좁게 보여줘요. "모바일 최적화"랑 비슷한 말이에요.

### 백엔드 (Backend)

화면 뒤에서 처리하는 쪽이에요. 데이터 저장, 계산, 비밀값 다루기가 여기서 일어나요. 눈에 안 보여요.

### 빌드 (Build)

내가 쓴 코드를 컴퓨터가 실제로 돌릴 수 있는 형태로 바꾸는 작업이에요. 재료를 손질해서 바로 먹을 수 있게 만드는 거랑 비슷해요. 배포 직전에 한 번 돌아가요.

### 서버 (Server)

24시간 켜져 있는 남의 컴퓨터예요. 내 컴퓨터를 꺼도 사이트가 살아 있는 건 서버가 대신 켜져 있어서예요.

### 패키지 (Package)

남이 만들어둔 프로그램 조각이에요. "RSS 읽는 도구", "표 변환하는 도구" 같은 게 이미 있어요. `npm install` 로 가져다 써요.

### 프레임워크 (Framework)

만들기 편하게 뼈대를 미리 잡아둔 도구 모음이에요. React, Vue, Next.js 같은 것들. 집 지을 때 골조가 미리 서 있는 거랑 비슷해요.

### 프론트엔드 (Frontend)

고객이 보고 만지는 화면 쪽이에요. 버튼, 입력창, 글씨 배치가 다 여기예요. 반대는 백엔드.

### 환경변수 (Environment Variable)

프로그램한테 따로 건네주는 설정값이에요. API 키 같은 비밀번호를 코드에 직접 안 쓰고 여기 넣어요. 코드가 공개돼도 키는 안 새요.

### API

프로그램끼리 대화하는 창구예요. "날씨 API" 는 날씨 정보를 받아오는 창구. AI 도 API 로 불러 쓸 수 있어요.

### API Key (API 키)

API 를 쓰려면 필요한 비밀번호예요. **절대 남한테 공유하면 안 돼.** 새면 남이 내 돈으로 쓸 수 있어요.

### BaaS (Backend as a Service)

백엔드랑 DB 를 직접 안 만들고 빌려 쓰는 서비스예요. Supabase, Firebase 같은 것들. 로그인·저장 기능을 빨리 붙일 때 써요.

### CSS

웹페이지의 겉모습을 담당해요. 색, 크기, 위치. 옷이라고 보면 돼요.

### HTML

웹페이지의 뼈대를 담당해요. 글, 이미지, 버튼이 어디 놓일지 정해요. 뼈대라고 보면 돼요.

### JavaScript (JS)

웹페이지의 동작을 담당해요. 버튼을 누르면 뭔가 일어나게 하는 게 이거예요. 근육이라고 보면 돼요.

### Node.js

JavaScript 를 브라우저 밖 내 컴퓨터에서 돌리게 해주는 프로그램이에요. Claude Code 가 이걸 깔고 돌아가요. 설치 스크립트가 알아서 깔아줘요.

### npm

프로그램 조각(패키지)을 설치해주는 도구예요. 앱스토어 같은 거예요. `npm install <이름>` 하면 그 조각이 내려와요.

### Supabase (수파베이스)

데이터베이스를 쉽게 쓰게 해주는 서비스예요.

엑셀 시트를 인터넷에 올려두고 프로그램에서 읽고 쓰는 느낌. 무료로 시작할 수 있어요.

## 저장하고 올리기

만든 걸 기록하고 인터넷에 올릴 때 나오는 말들이에요. 자세히는 [Git](/build-service/git) 과 [배포](/build-service/deploy) 에서 다뤄요.

### 깃 (Git)

파일이 언제 어떻게 바뀌었는지 기록해주는 도구예요. "저장" 버튼의 강화판. 망가져도 잘 되던 시점으로 되돌아갈 수 있어요.

### 깃허브 (GitHub)

Git 으로 관리하는 코드를 인터넷에 올려두는 곳이에요. 내 컴퓨터가 고장 나도 코드가 살아 있어요. 백업이자 공유 장소예요.

### 대시보드 (Dashboard)

서비스의 관리 화면이에요. "Vercel 대시보드" = Vercel 관리 페이죠. 웹에서 클릭으로 설정하는 곳이에요.

### 도메인 (Domain)

웹사이트 주소예요.

`google.com` 같은 거요. 사서 내 사이트에 연결할 수 있어요. 급하지 않으면 나중에 해도 돼요.

### 디버깅 (Debugging)

문제를 찾아서 고치는 과정이에요. 에러 메시지를 AI한테 주면 대부분 같이 풀어줘요. 어디서 뭘 하다 났는지도 같이 말해줘요.

### 레포지토리 (Repository)

저장소. 줄여서 "레포". GitHub 에서 프로젝트 하나가 레포 하나예요.

### 리팩토링 (Refactoring)

기능은 그대로 두고 코드만 깔끔하게 정리하는 거예요. 방 구조는 안 바꾸고 정리정돈만 하는 것과 같아요.

### 배포 (Deploy)

내 컴퓨터에만 있던 걸 인터넷에 올려서 남이 볼 수 있게 하는 거예요. 배포를 해야 링크가 생기고, 링크가 있어야 피드백을 받을 수 있어요.

### 슬러그 (Slug)

주소에 쓰는 짧은 영어 이름이에요. "Claude Code 새 기능" → `claude-code-new-feature`. 띄어쓰기랑 특수문자를 뺀 거예요.

### 커밋 (Commit)

Git 에서 "여기까지 정상"이라고 남기는 기록이에요. 저장이랑 비슷한데 기록이 남아요. 기능 하나가 잘 되면 찍어둬요.

### 클라우드 (Cloud)

인터넷 어딘가에 있는 남의 컴퓨터예요. 내 컴퓨터가 아니라 인터넷 상의 서버라는 뜻이에요.

### 푸시 (Push)

내 컴퓨터의 기록을 GitHub 으로 올리는 거예요. 반대는 pull(가져오기).

### 호스팅 (Hosting)

내 웹사이트를 대신 인터넷에 올려두고 켜주는 서비스예요. Vercel 이 대표적인 호스팅 서비스예요.

### clone (클론)

GitHub 에 있는 코드를 내 컴퓨터로 통째로 내려받는 거예요. 처음 한 번만 해요. 그다음부터는 pull.

### pull (풀)

GitHub 에 올라간 최신 내용을 내 컴퓨터로 가져오는 거예요. 다른 사람이 바꾼 걸 받아올 때 써요.

### Vercel

웹사이트를 무료로 올려주는 서비스예요.

GitHub 을 연결하면 코드가 바뀔 때마다 알아서 다시 올려줘요.

## 기획과 비즈니스

뭘 만들지 정하고 파는 단계에서 나오는 말들이에요. 자세히는 [🛠️ 서비스 만들기](/build-service/idea) 와 [📣 팔아보기](/go-to-market/feedback) 에서 다뤄요.

### 가설 (Hypothesis)

"이런 문제가 있고, 이렇게 풀면 사람들이 쓸 거야" 라는 예상이에요. 정답이 아니라 확인해봐야 하는 짐작이에요. 세우고 → 만들고 → 확인하는 게 핵심이에요.

### 레퍼런스 (Reference)

AI한테 "이런 느낌으로 해줘" 하고 보여주는 참고 자료예요. 스크린샷, 비슷한 사이트 주소, 이미죠. 말로 열 줄 설명하는 것보다 하나 보여주는 게 빨라요.

### 린 스타트업 (Lean Startup)

가장 작은 걸 먼저 만들고, 써보게 하고, 고쳐나가는 방식이에요. "완벽하게 만들고 출시" 대신 "빨리 만들고 확인". 이 자료실 전체가 이 흐름이에요.

### 모객 (Distribution)

만든 걸 쓸 사람을 데려오는 일이에요. 사람이 있는 곳으로 직접 가야 해요. "잘 만들면 알아서 온다"는 거의 안 통해.

### 수직 슬라이싱 (Vertical Slicing)

기능 하나를 화면부터 데이터까지 관통해서 끝내는 방식이에요. "로그인 화면만 만들기" 대신 "로그인이 처음부터 끝까지 되게 하기". 한 입씩 끝내는 거예요.

### 스토리보드 (Storyboard)

고객이 서비스를 쓰는 장면을 순서대로 그려본 거예요. 만화 컷처럼 "여기서 이걸 누르면 이렇게 된다"를 나열해요.

### 와이어프레임 (Wireframe)

화면 배치를 대충 그린 스케치예요. 손그림도 돼요. AI한테 보여주면 비슷하게 만들어줘요.

### 인디해커 (Indie Hacker)

혼자나 아주 작은 팀으로 서비스를 만들어 파는 사람이에요. 투자 안 받고 매출로 굴러가는 걸 목표로 해요.

### 정보구조도 (IA, Information Architecture)

서비스 안에 어떤 화면이 있고 어떻게 이어지는지 그린 지도예요. 메뉴 구조라고 생각하면 제일 가까워요.

### B2B / B2C

B2B 는 회사나 가게한테 파는 것, B2C 는 개인한테 파는 거예요. 누구한테 파느냐에 따라 설득하는 말이 완전히 달라져요.

### MLP (Minimum Lovable Product)

"작지만 좋아할 만한 제품". MVP 가 "되기만 하면 된다"면, MLP 는 "또 쓰고 싶어야 한다"예요.

### MVP (Minimum Viable Product)

핵심 기능 하나만 있는 첫 버전이에요. 다 만들고 나서 물어보면 늦어요. 최소한만 만들어서 먼저 물어보는 거예요.

### PG (Payment Gateway)

카드 결제를 대신 처리해주는 중개 서비스예요. 부트페이, 토스페이먼츠 같은 것들. 직접 카드사랑 계약 안 해도 결제를 붙일 수 있어요.

### PMF (Product-Market Fit)

"이거 없으면 곤란한데?" 하는 고객을 찾은 상태예요. 만드는 것보다 여기가 훨씬 오래 걸려요. 배포 뒤부터가 진짜 시작이에요.

### PRD (Product Requirements Document)

"이 서비스는 뭐고, 뭘 하고, 뭘 안 하는지" 적은 기획 문서예요. 한 장이면 충분해요. AI한테 이걸 주면 방향을 잡고 일해요.

### Vibe Coding (바이브 코딩)

AI랑 대화하면서 만드는 방식이에요.

코드를 직접 안 쳐도 AI가 대신 써줘요. 대신 방향은 내가 잡아야 해요.

## 나중에 봐도 되는 말

여기부터는 이 자료실에 거의 안 나와요. **지금 몰라도 아무 문제 없어.** 나중에 어디서 마주쳤을 때 찾아보면 돼요.

### 도커 (Docker)

프로그램을 상자에 담아서 어디서든 똑같이 돌아가게 하는 도구예요. "내 컴퓨터에선 되는데" 문제를 없애줘요.

### 보일러플레이트 (Boilerplate)

프로젝트 시작할 때 쓰는 기본 템플릿이에요. 매번 반복되는 설정이 미리 되어 있어요.

### 엔드포인트 (Endpoint)

프로그램이 요청을 보내는 주소예요. 식당 주소랑 같아요. 주소를 알아야 주문을 넣죠.

### 오케스트레이터 (Orchestrator)

여러 담당자를 상황 보고 골라서 부르는 중앙 조정자예요. 병원 접수 데스크처럼, 들어온 요청을 알맞은 담당자한테 보내요.

### 파싱 (Parsing)

긴 데이터에서 필요한 부분만 골라내는 거예요. 긴 글에서 제목·날짜·링크만 뽑아내는 게 파싱이에요.

### 프록시 (Proxy)

중간에서 대신 전달해주는 서버예요. A가 B한테 직접 말하는 대신 C가 대신 전해주는 구조예요.

### 피드 (Feed)

웹사이트가 새 글 목록을 공개하는 주소예요. 이 주소를 프로그램에 넣으면 새 글을 자동으로 가져와요.

### 헤드리스 (Headless)

화면 없이 뒤에서만 도는 모드예요. 브라우저를 헤드리스로 띄우면 눈엔 안 보이는데 웹페이지를 읽고 조작해요. 자동화에 써요.

### cron (크론)

"매일 아침 7시에 이거 실행해" 같은 예약 도구예요. 알람 시계랑 비슷한데, 알람 대신 프로그램을 깨워요.

### llm-mux

여러 AI 모델한테 요청을 나눠 보내주는 중계 서버예요. 직접 채팅창에 붙여넣는 대신 코드에서 자동으로 요청할 때 써요.

### NotebookLM

구글이 만든 AI 리서치 도구예요. 내가 올린 문서 안에서만 근거를 찾아 답해줘서, 지어내는 게 적고 출처를 같이 보여줘요.

### OpenRouter

여러 AI 모델을 하나의 창구로 쓰게 해주는 서비스예요. 무료 모델도 있어서 이것저것 비교해볼 때 좋아요.

### RAG (Retrieval-Augmented Generation)

AI가 답하기 전에 외부 문서를 찾아보고 참고하는 방식이에요. 전체를 다 읽지 않고 필요한 부분만 찾아서 답해요.

### RSS (알에스에스)

웹사이트가 새 글을 알려주는 방법이에요. 이 주소만 알면 매번 사이트에 안 들어가도 새 글을 가져올 수 있어요. 뉴스 구독 같은 거예요.

### upsert (업서트)

"있으면 고치고, 없으면 새로 만들기"를 한 번에 하는 거예요. update + insert 를 합친 말이에요.

### Webhook (웹훅)

"뭔가 생기면 여기로 알려줘" 하고 등록해두는 주소예요.

슬랙이나 디스코드에 자동으로 메시지를 보낼 때 써요.

## 그래도 모르겠으면

여기 없는 말이거나, 읽어도 감이 안 오면 그냥 AI한테 물어봐요. 그게 제일 빨라요.

```text
"환경변수"가 뭔지 모르겠어. 나는 IT를 전혀 몰라.
초등학생한테 설명하듯이 비유를 들어서 알려줘.
```

이렇게 물어보는 습관이 이 자료실을 끝까지 읽게 만들어줘요.

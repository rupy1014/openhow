## 핵심 요약

이 문서의 핵심은 세 줄이에요.

- **AI는 “똑똑한 앵무새”에 가까워.** 진짜 사람처럼 이해한다기보다, 엄청난 패턴을 바탕으로 그럴듯한 답을 조합해낸다고 보면 돼요.
- AI에는 **만드는 회사 / 우리가 쓰는 제품 / 그 안의 모델**이 있어요. 생각보다 종류가 많고 이름도 자주 바뀌어요.
- **여기서는 Claude Opus를 기본으로 쓸 거야.** 처음엔 제일 똑똑한 모델로 변수 하나를 줄이고, 나중에 익숙해지면 Sonnet, Haiku, 다른 모델로 바꾸거나 더 복잡하게 설정하면 돼요.

처음부터 AI 생태계를 다 외울 필요 없어요.

지금은 딱 이 정도만 잡고 가면 돼요.

```text
AI는 패턴을 잘 조합하는 도구다.
AI 서비스는 회사, 제품, 모델로 나눠서 보면 덜 헷갈린다.
우리는 일단 Claude Opus로 시작한다.
```

## 1. AI는 “똑똑한 앵무새”다

AI를 처음 볼 때 가장 많이 착각하는 게 있어요.

```text
AI가 진짜 이해하고 대답하는 것 같다.
AI가 모든 걸 알고 있는 것 같다.
AI가 말하면 다 맞는 것 같다.
```

근데 그렇게 보면 위험해요.

AI는 사람처럼 세상을 직접 경험하고 이해하는 존재라기보다, 엄청나게 많은 글과 코드, 문서에서 패턴을 배운 도구에 가까워요.

그래서 “똑똑한 앵무새”라는 비유가 좋아요.

앵무새처럼 그냥 따라 한다는 뜻은 아니에요.

정말 많은 패턴을 배웠기 때문에, 사람이 보기엔 꽤 똑똑하게 말하고, 정리하고, 코드를 만들고, 에러를 고칠 수 있어요.

다만 중요한 건 이거예요.

```text
그럴듯하게 말한다고 항상 맞는 건 아니다.
맥락을 잘 주면 훨씬 좋아진다.
틀릴 수 있으니 사람이 확인해야 한다.
```

예를 들어 AI가 이런 일을 잘해요.

```text
긴 글 요약하기
회의록에서 할 일 뽑기
아이디어를 기획서로 정리하기
코드 초안 만들기
에러 메시지 설명하기
비슷한 예시 여러 개 만들기
```

왜 잘하냐면, 이런 패턴을 많이 봤기 때문이에요.

반대로 이런 일은 조심해야 해요.

```text
없는 사실을 있는 것처럼 말하기
최신 정보가 바뀌었는데 예전 기준으로 답하기
내 의도를 잘못 이해하고 엉뚱한 방향으로 만들기
그럴듯하지만 실제로는 동작하지 않는 코드 쓰기
```

그래서 AI를 쓸 때는 이렇게 생각하면 좋아요.

```text
AI는 답을 주는 신이 아니라,
엄청 빠르게 초안을 만들고 같이 고쳐가는 파트너다.
```

이 감각이 있어야 나중에 덜 흔들려요.

AI가 이상한 답을 하면 “AI가 멍청하네”가 아니라 이렇게 보면 돼요.

```text
내가 맥락을 덜 줬나?
지시가 너무 넓었나?
최신 정보 확인이 필요한가?
검증 없이 믿으면 안 되는 부분인가?
```

이게 AI를 다루는 기본 체력이에요.

## 2. 회사 / 제품 / 모델을 구분하자

AI 이름이 너무 많아서 헷갈릴 수 있어요.

```text
OpenAI
ChatGPT
GPT
Anthropic
Claude
Opus
Google
Gemini
Llama
```

처음 보면 전부 같은 말처럼 느껴져요.

근데 이렇게 나누면 쉬워요.

```text
회사 = 만드는 곳
제품 = 우리가 접속해서 쓰는 서비스
모델 = 그 제품 안에서 실제로 답을 만드는 엔진
```

예를 들어요.

| 회사 | 제품 | 모델 |
| --- | --- | --- |
| OpenAI | ChatGPT | GPT 계열 모델 |
| Anthropic | Claude | Opus, Sonnet, Haiku |
| Google | Gemini | Gemini 계열 모델 |
| Meta | Llama | Llama 계열 모델 |

우리가 일상에서 “ChatGPT 쓴다”, “Claude 쓴다”라고 말할 때는 보통 제품 이름을 말하는 거예요.

그 안에는 다시 모델이 있어요.

Claude를 예로 들면 이렇게예요.

```text
Anthropic = 회사
Claude = 제품
Opus / Sonnet / Haiku = 모델
```

이 구조를 알아두면 나중에 이런 말이 나와도 덜 헷갈려요.

```text
이번 작업은 Opus로 하자.
이건 Sonnet으로도 충분해.
Haiku로 요약만 돌리자.
모델을 바꿔보자.
```

즉, Claude라는 제품 안에서도 어떤 모델을 쓰느냐에 따라 성능, 속도, 비용이 달라질 수 있어요.

## 3. AI 도구는 생각보다 종류가 많다

우리가 이 과정에서 주로 쓰는 건 Claude Code예요.

하지만 AI 도구는 Claude Code만 있는 게 아니에요.

대충 이런 분야들이 있어요.

| 카테고리 | 예시 | 하는 일 |
| --- | --- | --- |
| 대화형 AI | ChatGPT, Claude, Gemini | 질문 답변, 글쓰기, 정리 |
| 코딩 에이전트 | Claude Code 같은 도구 | 파일 읽기, 코드 수정, 명령 실행 |
| 이미지 생성 | Midjourney, Flux 등 | 이미지 만들기 |
| 영상 생성 | Veo, Runway 등 | 영상 만들기 |
| 음성 생성 | ElevenLabs 등 | 음성 합성 |
| 문서/업무 도구 | NotebookLM, Gamma 등 | 리서치, 문서, 발표자료 |

처음부터 다 알 필요 없어요.

중요한 건 이거예요.

```text
우리는 “AI 전체 생태계”를 공부하는 게 아니라,
Claude Code로 내 일을 시키고 결과물을 만드는 법을 배운다.
```

그래서 다른 도구들은 “아, 이런 것도 있구나” 정도로 보면 돼요.

나중에 필요해지면 그때 붙이면 돼요.

## 4. Claude 안에도 Opus / Sonnet / Haiku가 있다

같은 Claude라도 모델 등급이 있어요.

쉽게 비유하면 이래요.

| 모델 | 비유 | 잘 맞는 일 |
| --- | --- | --- |
| Opus | 박사급 전문가 | 복잡한 기획, 어려운 코드, 긴 맥락 이해 |
| Sonnet | 경력자 | 일반적인 코딩, 문서 작성, 대부분의 작업 |
| Haiku | 빠른 실무자 | 요약, 분류, 짧은 변환, 가벼운 작업 |

성능이 높을수록 보통 더 느리거나 비용이 더 들 수 있어요.

반대로 가벼운 모델은 빠르고 싸지만, 복잡한 일을 맡기면 부족할 수 있어요.

초보자 입장에서는 처음부터 이걸 다 최적화하려고 하면 오히려 헷갈려요.

```text
이건 Opus?
이건 Sonnet?
이건 Haiku?
비용 아끼려면 어떻게 해야 하지?
```

이런 고민을 초반부터 하면 정작 중요한 감을 놓쳐요.

그래서 여기서는 단순하게 갈 거예요.

```text
처음에는 Claude Opus를 기본으로 쓴다.
```

이유는 하나예요.

처음엔 내가 지시를 못해서 결과가 이상한 건지, 모델이 약해서 이상한 건지 구분하기 어려워요.

그래서 가장 똑똑한 모델을 쓰고 시작하면 변수가 줄어요.

```text
모델이 약해서 헤맨다
→ X

일단 좋은 모델로 시작하고,
내 지시와 작업 방식에 집중한다
→ O
```

나중에 익숙해지면 그때 나누면 돼요.

```text
복잡한 설계 → Opus
일반 구현 → Sonnet
간단한 요약 → Haiku
```

지금은 이 정도만 알고 있으면 충분해요.

## 5. 우리는 Claude Opus로 시작한다

이 과정에서는 기본적으로 Claude Opus를 쓴다고 생각하면 돼요.

정확한 모델 버전명은 시간이 지나면 바뀔 수 있어요.

중요한 건 숫자나 버전 이름을 외우는 게 아니에요.

```text
Opus = Claude에서 가장 강한 쪽의 모델
```

이렇게 이해하면 돼요.

처음부터 모델을 바꾸고, 비용을 최적화하고, 작업별로 나누는 건 나중 일이에요.

지금은 먼저 이런 감을 잡는 게 중요해요.

```text
어떻게 지시하면 결과가 좋아지는지
어디까지 AI가 해주는지
언제 사람이 확인해야 하는지
에러가 나면 어떻게 넘겨야 하는지
```

Opus로 시작하는 건 “제일 비싼 걸 무조건 쓰자”가 아니에요.

초보 단계에서 헷갈릴 변수를 줄이자는 뜻이에요.

나중에 감이 생기면 모델을 바꾸는 건 자유예요.

```text
비용이 부담된다 → Sonnet이나 더 가벼운 모델 검토
단순 요약만 한다 → Haiku 같은 가벼운 모델 검토
다른 도구가 더 맞다 → ChatGPT, Gemini, 다른 코딩 도구 검토
```

도구는 바뀔 수 있어요.

하지만 “AI에게 일을 시키는 감각”은 계속 남아요.

## 6. 모델은 어떻게 바꾸나요?

지금 당장 외울 필요는 없어요.

다만 Claude Code를 쓰다 보면 모델을 바꾸는 메뉴나 명령을 보게 될 수 있어요.

예를 들어 Claude Code에서는 모델 선택 명령이나 설정이 제공될 수 있어요.

```text
/model
```

이런 식으로 모델 목록을 보고 고를 수 있어요.

정확한 방법은 버전이나 환경에 따라 조금씩 바뀔 수 있어요.

그래서 처음엔 이렇게만 알면 돼요.

```text
모델은 바꿀 수 있다.
하지만 입문 단계에서는 Opus 기본으로 가도 된다.
```

AI에게 물어봐도 돼요.

```text
현재 Claude Code에서 어떤 모델을 쓰고 있는지 확인해줘.
모델을 Opus로 바꾸는 방법을 알려줘.
```

이 정도면 충분해요.

## 7. 앞으로 계속 나올 용어

Claude Code로 일을 시작하면 IDE, 터미널, 컨텍스트 같은 단어가 계속 나와요.

처음 들으면 겁나지만, 비유로 보면 어렵지 않아요.

| 개념 | 쉽게 말하면 | 설명 |
| --- | --- | --- |
| IDE | 작업실 | 코드 편집, 검색, 터미널이 모여 있는 도구. 예: VS Code, Cursor |
| 프로젝트 | 집 | 한 덩어리의 작업 전체. 예: 내 웹서비스 폴더 |
| 폴더 | 방 | 관련 파일을 묶어놓은 공간 |
| 파일 | 종이 | 실제 내용이 들어 있는 것. `.md`, `.html`, `.js` 같은 파일 |
| 터미널 | 명령 창 | 컴퓨터에게 글로 명령하는 곳. Claude Code도 여기서 실행돼 |
| 프롬프트 | 지시문 | Claude에게 보내는 “이거 해줘” 요청 |
| 컨텍스트 | 단기 기억 | 지금 대화에서 Claude가 참고하고 있는 내용 |
| 메모리 | 장기 기억 | CLAUDE.md 같은 파일에 남겨두는 프로젝트 지침 |

이 중에서 나중에 제일 중요해지는 건 컨텍스트와 메모리예요.

간단히 말하면 이거예요.

```text
컨텍스트 = 지금 대화에서 기억하는 것
메모리 = 다음에도 계속 참고하라고 파일에 적어둔 것
```

처음엔 이 정도만 잡고 가면 돼요.

## 자주 헷갈리는 포인트

### 그냥 Opus만 쓰면 안 되나요?

돼요. 입문 단계에서는 오히려 그게 편해요. 비용이나 속도가 신경 쓰이기 시작하면 그때 Sonnet, Haiku, 다른 모델을 나눠 쓰면 돼요.

### 모델 이름이 계속 바뀌면 어떡하죠?

괜찮아요. 세부 버전명은 바뀔 수 있어요. 지금은 Opus, Sonnet, Haiku처럼 등급이 있다는 것만 기억하면 돼요.

### AI가 진짜 이해하는 게 아니라면 믿으면 안 되나요?

무조건 믿으면 안 돼요. 하지만 못 쓴다는 뜻도 아니에요. 초안을 만들고, 정리하고, 코드를 고치고, 에러를 설명하는 데는 엄청 유용해요. 대신 사람이 확인해야 해요.

### Claude 말고 ChatGPT 써도 되나요?

가능해요. 다만 이 과정은 Claude Code 기준으로 진행돼요. 한 도구를 제대로 익히면 다른 도구로 옮기는 건 훨씬 쉬워져요.

### 모델 선택보다 중요한 건 뭔가요?

내가 뭘 원하는지 분명히 말하는 것, 결과를 확인하는 것, 틀렸을 때 다시 지시하는 것. 모델보다 이 감각이 먼저예요.

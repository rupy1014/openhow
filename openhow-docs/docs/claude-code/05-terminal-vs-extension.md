# 터미널이랑 익스텐션, 뭐가 다른가요?

이 질문 진짜 많이 받아요. 그래서 물어본 대로 답해줄게요.

## "VS Code에서 터미널로 쓰는 거랑 익스텐션으로 쓰는 거, 뭐가 다른가요?"

VS Code는 똑같이 켜요.

근데 그 안에서 클로드 코드 부르는 길이 두 개예요.

하나는 **아래쪽 까만 터미널 창에** `claude` **치기**.

하나는 **클로드 코드 익스텐션 켜기**. 별 모양(Spark) 아이콘 누르면 옆에 채팅 화면이 떠요.

> 둘 다 똑같은 클로드예요. 똑똑함은 차이 없어요. 다른 건 "생긴 거"뿐이에요.

## "그럼 익스텐션이 뭐가 더 좋은데요?"

마우스로, 화면 보면서 하는 게 편해요.

- 코드 바꿀 때 **나란히(빨강/초록)** 보여줘요. 버튼 누르면 적용돼요.
- 에디터에서 코드 드래그하면, 그 부분을 **자동으로** 클로드한테 넘겨요.
- 대화를 **탭 여러 개**로 띄워요. 이거 시켜놓고 저거 물어보기 좋아요.

눈으로 확인하면서 천천히 가고 싶으면 익스텐션이에요.

## "그럼 터미널은 왜 쓰나요?"

기능이 다 돼요. 그리고 어디서나 똑같아요.

- 슬래시 명령어, 스킬 같은 거 **전부** 돼요.

왜 이게 중요하냐면, 익스텐션은 자주 쓰는 것만 돼요. 전부는 아니거든요.

- VS Code가 아니어도 똑같이 써요. 가볍고 빨라요.

> 근데 터미널로 써도 VS Code 안에서 `claude`를 돌리면, 코드 바뀔 때 diff는 똑같이 화면으로 떠요. 그래서 둘은 섞어 써도 돼요.

## "난 그래서 뭘 써야 하나요?"

- 화면 보면서 천천히 하고 싶어 → 익스텐션.
- 명령어 익숙하고 기능 다 쓰고 싶어 → 터미널.

근데 제일 많이 쓰는 건 **VS Code 터미널에서** `claude` **치기**예요.

기능은 다 쓰면서, diff는 화면으로 보거든요. 둘의 좋은 점만 가져가는 거예요.

## 한 줄 정리

> 같은 클로드예요. 익스텐션은 보기 편하고, 터미널은 다 돼요. VS Code 터미널에서 `claude` 치면 둘 다 가져가요.

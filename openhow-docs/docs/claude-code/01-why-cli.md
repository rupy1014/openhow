# 왜 CLI로 시작하나

## 핵심 요약

Claude Code는 CLI로 Claude라는 AI를 다루는 방식이에요. CLI는 **터미널 창에 글자로 명령을 치는 방식**이라고 생각하면 돼요.  
그리고 이 자료실은 그 방식으로 AI를 써서 실제 결과물까지 만드는 걸 목표로 해요.

처음엔 겁먹을 수 있어도, 막상 해보면 별로 어렵지 않고 원하는 걸 다 할 수 있는 게 **Claude Code**예요.


## 먼저 CLI가 뭐냐

이전 글에서 터미널을 한 번 열어봤죠. 그럼 이제 이 둘만 구분하면 돼요.

- **터미널** = 검은 창, 또는 명령을 입력하는 창
- **CLI** = 그 창에 글자로 명령을 치는 방식
- **Claude Code** = CLI 방식으로 쓰는 AI 도구

예를 들면 이런 거예요.

```bash
dsclaude
```

이건 터미널 창에 글자로 명령을 친 거고, 바로 이런 식으로 쓰는 걸 CLI라고 보면 돼요.

![터미널에서 Claude Code CLI가 실제로 돌아가는 모습](/__content__/images/claude-code-cli-demo.gif)

어렵게 생각할 필요 없어요.

- 터미널은 **창**
- CLI는 **그 창에서 쓰는 방식**
- Claude Code는 **그 방식으로 실제 파일과 폴더를 다루는 도구**

여기서 하나만 더 붙이면 이해가 훨씬 쉬워져요.

Claude Code는 어떤 특정 앱 안에서만 쓰는 도구가 아니에요.  
**터미널만 있으면 거의 어디서든 같은 방식으로 쓸 수 있어요.**

그래서

- 그냥 운영체제의 **기본 터미널**
- **VS Code, Cursor, Antigravity** 같은 IDE 안의 터미널

어디서든 비슷한 감각으로 이어서 사용할 수 있어요.

여기서 **IDE (VS Code, Cursor, Antigravity)**는 개발할 때 쓰는 작업용 프로그램이라고 생각하면 돼요.  
쉽게 말하면 **파일을 보고, 수정하고, 실행하고, 터미널도 함께 여는 앱**이에요.

즉 아주 단순하게 정리하면

- 터미널은 **창**
- CLI는 **그 창에서 일하는 방식**
- Claude Code는 **그 환경 어디에든 붙어서 실제 작업을 해주는 도구**

여기까지만 이해해도 이 글 절반은 끝난 거예요.

## 왜 이 코스는 앱보다 CLI로 시작하냐

핵심은 하나예요.

> **앱은 시작이 쉽고, CLI는 결과물을 끝까지 만들기 쉽다.**

ChatGPT나 Claude 앱은 초보자에게 분명 편해요.

- 브라우저를 열어서 질문하면 답변을 받으니 쉽고
- Cowork나 문서 작업처럼 업무형 흐름에 잘 맞아요

그래서 "완전 초보면 앱부터 써도 되냐?"라고 물으면, 대답은 **그렇다**예요.

그런데 우리가 배우려는 건 단순히 묻고 답받는 사용법이 아니라, **내 폴더에서 실제 결과물을 만드는 흐름**이에요. 그 지점부터는 CLI가 훨씬 강하고 적응되면 편리해질거예요.

## CLI가 강한 이유는 3개만 기억하면 돼요

### 1) 프로젝트 폴더가 바로 작업장이 돼요

CLI에서는 채팅창보다 **내 폴더 자체**가 중심이에요.

- 파일을 읽고
- 새 파일을 만들고
- 기존 파일을 고치고
- 규칙 파일을 남기고
- 그 상태를 계속 이어갈 수 있어요

즉 설명을 듣는 데서 끝나는 게 아니라, **작업 결과가 폴더 안에 바로 쌓여요.**

### 2) 실행까지 한 번에 이어져요

CLI에서는 이런 흐름이 자연스럽게 붙어요.

- 이 폴더 문서 읽어요
- 요약 파일 만들어요
- 이 부분 수정해요
- 테스트 돌려
- Git 상태 확인해요

앱이 정리와 초안에 강하다면, CLI는 **실행과 수정**까지 바로 이어지기 쉬워요.

### 3) Git, 자동화, 배포로 연결되기 쉽다

결과물을 만들다 보면 결국 여기까지 가게 돼요.

- 파일 수정
- 명령 실행
- Git 기록
- 배포 전 확인
- 반복 작업 자동화

이 전체 흐름은 CLI에서 훨씬 자연스러워요.

## 그래서 역할을 이렇게 보면 돼요

| 구분 | 잘 맞는 일 | 자유도 | 고객 |
| --- | --- | --- | --- |
| Claude 웹 | 빠른 질문, 초안, 아이디어 정리 | 낮음 | 초보자 |
| Claude 앱 / Cowork | 친절한 화면, 업무형 작업, 연결 기능 활용 | 중간 | 초보자 | 
| Claude Code (CLI) | 폴더 기반 작업, 파일 수정, 명령 실행, Git, 자동화 | 높음 | 전문가 |

중요한 건 **무조건 CLI가 더 좋다**가 아니에요.

- **쉽게 시작**하려면 앱이 좋고
- **직접 만들고 굴리려면** CLI가 좋아요

결국 결과물을 직접 만들고 이어서 관리하는 쪽까지 가야 하니까, 시작부터 CLI를 배우는 거예요.

## 한 줄로 줄이면

> **초보자는 브라우저나 앱으로 시작하면 좋지만, 우리는 아직 전문가는 아니지만 시작부터 CLI 로 배울거다. 막상 해보면 어렵지 않다.**

## 자주 헷갈리는 포인트

- **"앱이 더 편하면 CLI는 필요 없는 거 아닌가요?"라고 생각해** — 편한 시작과 높은 자유도는 다른 문제예요
- **CLI를 개발자 전용 검은 화면으로만 봐** — 이 코스에서 CLI는 명령 암기보다 AI가 실제로 일하는 작업장에 가까워요
- **Cowork나 Office 연동이 있으면 다 해결된다고 느껴** — 연결 기능은 강하지만, 프로젝트 폴더 기준으로 깊게 만드는 흐름은 여전히 CLI가 강해요
- **처음부터 CLI를 완벽히 알아야 한다고 겁먹어** — 초반엔 명령어 실력보다 "폴더 안에서 AI와 같이 일한다"는 감각이 더 중요해요

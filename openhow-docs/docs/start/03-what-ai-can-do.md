## 핵심 요약

**“AI로 뭘 만들 수 있어요?”라고 물어보면, 나는 결국 두 가지라고 봐요. 시간을 아끼거나, 돈을 벌 가능성을 만드는 것. 회사에서 반복하던 일을 줄여도 좋고, 내가 가진 아이디어를 작은 서비스로 만들어봐도 좋아요. 중요한 건 AI가 모든 걸 대신 결정해주는 게 아니라, 내가 원하는 방향을 말하면 AI가 초안, 구현, 수정, 복구 속도를 크게 올려준다는 거예요.**

유튜브나 SNS를 보면 이런 이야기가 많아요.

```text
AI로 웹사이트 만들었어요
AI로 자동화해서 시간 아꼈어요
AI로 앱 만들어서 수익화했어요
```

그걸 보면 자연스럽게 이런 생각이 들어요.

```text
저게 되나? 나도 해보고 싶은데?
진짜 AI가 다 해주나?
```

결론부터 말하면, AI가 정말 많은 걸 도와줘요.

근데 “내가 아무 생각 없이 앉아 있으면 알아서 돈 되는 서비스를 만들어준다”는 뜻은 아니에요.

AI가 잘 도와주는 건 이런 쪽이에요.

```text
초안 만들기
웹, 앱 서비스 만들기
문서 정리하기
반복 업무 줄이기
에러 고치기
아이디어를 작은 단계로 쪼개기
```

반대로 사람이 해야 하는 일도 있어요.

```text
뭘 만들고 싶은지 정하기
누구를 위한 건지 정하기
결과가 맞는지 확인하기
고객에게 보여주기
피드백을 보고 방향을 다시 잡기
```

그래서 여기서 배우는 건 “AI가 다 해준다”가 아니에요.

**AI가 거의 다 해주는 시대에, 사람이 알아야 하는 나머지 중요한 부분을 배우는 것**에 가까워요.

## 1. 시간을 아끼는 것

가장 먼저 체감되는 건 시간 절약이에요.

회사에서 이런 일 많이 하잖아요.

```text
회의록 정리
보고서 초안 만들기
긴 문서 요약
자료 비교
반복되는 이메일 작성
엑셀/시트 정리
SNS 글 초안 작성
```

이런 일은 AI가 바로 도와줄 수 있어요.

예를 들어 음성 파일을 넣고 이렇게 말할 수 있어요.

```text
이 음성 파일로 회의록 작성해줘.
결정된 내용, 할 일, 담당자, 마감일로 나눠줘.
```

긴 문서를 넣고 이렇게 말할 수도 있어요.

```text
이 문서에서 내가 꼭 봐야 할 핵심만 5줄로 정리해줘.
그리고 실행해야 할 일을 체크리스트로 만들어줘.
```

이건 거창한 서비스가 아니어도 바로 효과가 있어요.

하루에 30분씩 걸리던 일을 5분으로 줄이면, 한 달이면 꽤 큰 시간이 생겨요.

그러니까 AI로 할 수 있는 첫 번째는 이거예요.

```text
내가 반복해서 쓰던 시간을 줄이는 것.
```

## 2. 돈을 벌 가능성을 만드는 것

두 번째는 돈을 벌 가능성을 만드는 거예요.

여기서 말하는 돈은 꼭 처음부터 거창한 창업을 뜻하지 않아요.

```text
나의 스몰 브랜딩 페이지를 만들어서 일을 더 잘 받기
작은 도구를 만들어 지인에게 팔아보기
내 업무 노하우를 자동화 서비스로 만들어보기
반복 업무를 줄여주는 내부 도구 만들기
고객이 겪는 문제를 해결하는 작은 웹서비스 만들기
```

이런 것도 전부 수익화의 시작이 될 수 있어요.

예전에는 뭔가 만들려면 개발자를 구하거나, 외주를 맡기거나, 내가 코딩을 오래 배워야 했어요.

지금은 AI 덕분에 훨씬 작게 시작할 수 있어요.

```text
아이디어를 말한다
→ AI와 기획을 정리한다
→ 화면을 만든다
→ 기능을 붙인다
→ 배포해서 링크를 보낸다
→ 피드백을 받는다
```

이 과정이 예전보다 훨씬 짧아졌어요.

그래서 AI로 할 수 있는 두 번째는 이거예요.

```text
내 아이디어를 작게 만들어서 시장에 물어보는 것.
```

## 3. 둘은 사실 연결돼 있어요

시간을 아끼는 도구가 나중에 돈이 될 수도 있어요.

예를 들어요.

```text
내가 매주 하던 보고서 정리를 자동화했다
→ 동료도 필요하다고 한다
→ 팀에서 쓰는 내부 도구가 된다
→ 비슷한 일을 하는 다른 회사도 필요할 수 있다
```

처음에는 내 시간을 아끼려고 만든 거였는데, 나중에는 다른 사람에게도 필요한 서비스가 될 수 있어요.

반대로 돈을 벌려고 만든 서비스도 결국 누군가의 시간을 줄여주거나 어떤 가치를 제공하게 되는거죠.

```text
고객이 직접 하던 일을 줄여주거나
결정을 더 빨리 하게 해주거나
반복 작업을 대신 처리해주거나
더 좋은 결과를 빨리 얻게 해주거나
```

결국 핵심은 같아요.

```text
누군가의 시간을 아껴주거나,
누군가가 돈을 벌거나 아끼게 도와주는 것.
```

## 4. 그래서 Claude Code를 배워요 

다들 ChatGPT는 한 번쯤 써봤죠?

Claude도 비슷해요. 웹 브라우저나 모바일 앱에서 대화창을 열고 질문하면 답해주는 AI예요.

```text
브라우저에서 claude.ai 접속
또는 Claude 앱 실행
→ 대화창에 질문하고 답변 받기
```

차이가 있다면, Claude는 글쓰기와 긴 문서 이해도 잘하지만 특히 코딩 작업에서도 많이 쓰여요. 코드 설명, 에러 분석, 파일 구조 이해, 리팩토링 같은 작업에 강한 편이에요.

그래서 그냥 Claude만 써도 문서 정리나 아이디어 정리는 할 수 있어요.

그런데 Claude Code는 한 단계 더 들어가요.

Claude Code가 뭐냐면 **터미널 환경**에서 쓰는 Claude예요. 쉽게 말하면 검은 화면에서 내 프로젝트 폴더를 열어두고, Claude가 파일을 읽고 수정하고 명령어를 실행할 수 있게 하는 도구예요.

쉽게 말하면 이거예요.

```text
Claude = 웹/앱에서 대화하면서 생각과 문서를 도와주는 AI
Claude Code = 터미널에서 프로젝트 파일을 직접 보고 만들고 고치는 AI 작업 파트너
```

예를 들어 Claude Code에게 이렇게 말할 수 있어요.

```text
이 아이디어.md 파일을 읽고 기준으로 첫 화면을 만들어줘.
```

```text
이 에러 로그를 보고 원인을 설명하고 고쳐줘.
``` 

물론 완벽하진 않아요.

가끔 잘못 고치기도 하고, 엉뚱한 방향으로 갈 때도 있어요.

그래서 사람이 계속 방향을 잡아야 해요.

```text
뭘 만들지 말해주기
작업 범위 정해주기
결과 확인하기
에러 로그 전달하기
왜 그렇게 고쳤는지 물어보기
```

이게 우리가 배울 핵심이에요.

## 5. 쇼케이스를 보면 제일 빨라

말로 “AI로 이런 걸 만들 수 있어”라고 설명하는 것보다, 이미 만든 결과물을 보는 게 훨씬 빨라요.

클로더즈 쇼케이스에는 비개발자들이 만든 프로젝트들이 모여 있어요.

:::link-card https://clauders.ai/showcase/
:::

처음 볼 때는 “와 대단하다”로만 보지 말고, 이렇게 봐봐요.

```text
이 사람은 어떤 문제를 풀려고 했지?
결과물이 웹이야, 앱이야, 자동화야?
고객이 실제로 누를 수 있는 기능은 뭐지?
AI가 도와줬을 것 같은 부분은 어디지?
나도 이 정도 범위라면 해볼 수 있을까?
```

쇼케이스는 자랑용 페이지라기보다, **내가 손에 쥘 수 있는 결과물의 감각을 잡는 레퍼런스**예요.

(사실 비공개 프로젝트들이 많아서 다 못보여줘서 아쉽기도 해요)

처음에는 남의 프로젝트를 보면서 내 아이디어를 떠올려도 돼요.

```text
아, 나도 내 업무로 저런 도구 만들 수 있겠다
아, 랜딩 페이지 하나는 나도 해볼 수 있겠다
아, 저 사람처럼 작은 문제 하나만 잡아도 되겠구나
```

이 감각이 생기면 시작이 훨씬 쉬워져요.

## 6. 끝까지 가면 뭐가 남나요?

여기서 목표는 “AI 이론을 많이 아는 사람”이 되는 게 아니에요.

손에 잡히는 결과물을 남기는 거예요.

보통 이런 것들이 남아요.

```text
내 프로젝트 아이디어 1개
PRD 1장 (아이디어 문서)
작동하는 화면 1개
핵심 기능 1개
Git 기록
배포 링크
피드백 메모
```

대단한 스타트업을 뚝딱 완성하자는 게 아니에요.

그 대신 이런 경험을 해보자는 거예요.

```text
내가 생각한 문제를
AI와 같이 기획하고
작게 만들고
인터넷에 올려서 사람에게 보여주고
피드백을 받아 다시 고쳐보는 경험
내가 만들걸 좋아해줄 고객을 찾는 경험
```

이 경험을 한 번 해보면 감이 생겨요.

```text
아, AI가 여기까지는 밀어주는구나
아, 내가 말해야 하는 건 이 부분이구나
아, 고객에게 보여주면 생각이 달라지는구나
```

이 감이 생기는 게 중요해요.

## 7. 예시는 두 방향으로 보면 돼요

AI로 할 수 있는 일은 정말 많지만, 처음에는 두 방향으로 보면 돼요.

### 시간을 아끼는 예시

| 예시 | 바로 보이는 결과 | 왜 좋은 첫 경험인가 |
| --- | --- | --- |
| 회의록 정리 | 요약 + 할 일 목록 | 실무에서 바로 써먹기 좋음 |
| 긴 문서 요약 | 핵심 5줄 | 정보 압축 체감 |
| 이메일 초안 | 상황별 문장 후보 | 반복 글쓰기 시간 감소 |
| 자료 비교 | 차이점 표 | 판단이 빨라짐 |
| 업무 체크리스트 | 실행 순서 | 머릿속 정리가 됨 |

### 돈을 벌 가능성을 만드는 예시

| 예시 | 바로 보이는 결과 | 왜 좋은 첫 경험인가 |
| --- | --- | --- |
| 자기소개 페이지 | 배포 링크 1개 | 일을 받을 때 보여줄 수 있음 |
| 랜딩 페이지 | 서비스 소개 화면 | 아이디어를 설명하기 쉬워짐 |
| 작은 웹서비스 MVP | 핵심 기능 1개 | 고객에게 직접 보여줄 수 있음 |
| 자동화 도구 | 반복 업무 감소 | 다른 사람도 필요할 수 있음 |
| 외부 API 연동 데모 | 실제 데이터/AI 결과 | 장난감이 아니라 서비스처럼 보임 |

처음부터 “무조건 돈 벌어야지”로 시작하지 않아도 돼요.

내 시간을 줄이는 도구를 만들다 보면, 그게 다른 사람에게도 필요한 문제일 수 있어요.

## 8. AI가 잘하는 것 / 사람이 해야 하는 것

AI가 잘하는 건 많아요.

```text
초안 만들기
긴 내용 요약하기
여러 안 비교하기
코드 수정하기
에러 원인 후보 제시하기
큰 일을 작은 단계로 쪼개기
```

하지만 사람이 해야 하는 것도 있어요.

```text
내가 뭘 만들고 싶은지 정하기
이게 누구에게 필요한지 판단하기
결과가 맞는지 확인하기
어떤 기능을 빼야 하는지 결정하기
고객에게 보여주기
피드백을 보고 방향 바꾸기
```

그래서 중요한 원칙은 하나예요.

```text
AI는 추진력을 준다.
방향은 사람이 잡는다.
```

이 원칙을 기억하면 돼요.

AI를 잘 쓰는 사람은 “AI가 다 해주겠지”라고 가만히 있는 사람이 아니에요.

AI에게 좋은 방향을 주고, 결과를 확인하고, 다시 요청하는 사람이에요.

## 9. 바로 해볼 수 있는 것

아직 설치 전이라도 Claude나 다른 챗 인터페이스에서 아래 3개 중 하나는 바로 해볼 수 있어요.

```text
내 자기소개를 입력하고 소개 페이지 문구를 만들어달라고 하기
회의록을 넣고 할 일 목록으로 바꿔달라고 하기
내 아이디어를 말하고 1페이지 PRD로 정리해달라고 하기
```

완벽한 결과물이 목표가 아니에요.

먼저 이런 감을 느껴보면 돼요.

```text
아, 이렇게 말하면 초안이 나오는구나
아, 결과가 마음에 안 들면 다시 고치면 되는구나
아, 내가 맥락을 더 줘야 결과가 좋아지는구나
```

이 감이 생기면 다음 장부터 훨씬 편해져요.

## 자주 헷갈리는 포인트

### AI가 진짜 다 해주나요?

아니에요. 많은 부분을 도와주지만 방향과 최종 판단은 사람이 해야 해요. AI는 초안, 구현, 수정, 복구 속도를 올려주는 파트너에 가까워요.

### 코딩을 몰라도 뭔가 만들 수 있나요?

가능해요. 다만 “무엇을 만들지”, “어디까지 만들지”, “결과가 맞는지”는 계속 확인해야 해요. 코드를 몰라도 이 판단은 필요해요.

### 처음부터 돈 벌 수 있나요?

그냥 불가능 하다고 할게요. 가능한 사람도 있겠지만, 처음부터 너무 욕심내지 말아요. 목표를 학습, **완주 경험**에 두자고. 만들고, 배포하고, 보여주고, 피드백받는 흐름을 한 번 끝까지 해보는 게 먼저예요.

### 시간이 아끼는 도구랑 수익화는 완전히 다른 건가요?

완전히 다르지 않아요. 내가 시간을 아끼려고 만든 도구가 다른 사람에게도 필요하면 서비스가 될 수 있어요.

### 처음에는 뭘 떠올리면 되나요?

거창한 아이디어보다 “내가 반복해서 귀찮아하는 일”이나 “주변 사람이 자주 겪는 문제”부터 떠올리면 돼요.
